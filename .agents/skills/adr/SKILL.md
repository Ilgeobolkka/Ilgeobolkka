# ADR — 아키텍처 결정 기록

"왜 이 기술 구조를 선택했지?"에 답하는 기록. 결정 1개 = 파일 1개.
파일명은 `docs/adr/<주제>/NNNN-영어-케밥-제목.md` (한글 경로명은 NFD 이슈로 금지, 제목·본문은 한국어).
주제는 `platform`, `application`, `domain`, `content`, `security`, `frontend` 중 결정의 주된 기술 경계
하나를 선택합니다. 번호는 주제와 관계없이 저장소 전체에서 이어지는 4자리 순번입니다.

## 작성 판정 게이트

ADR은 중요한 내용을 모으는 문서가 아니라 **되돌리기 비싼 기술 선택의 근거**입니다. 새 번호를
부여하기 전에 `rg`로 기존 ADR과 정본 문서를 검색하고 아래 세 질문에 모두 답합니다.

1. 언어·프레임워크·인프라, 데이터 모델, API·모듈 경계 중 어떤 기술 경계를 결정하는가?
2. 실제로 비교한 대안과 선택으로 감수하는 트레이드오프가 있는가?
3. 되돌릴 때 데이터 마이그레이션, 클라이언트 호환, 대규모 코드 변경 또는 인프라 전환 중 하나
   이상의 구체적인 비용이 발생하는가?

세 질문 중 하나라도 답하지 못하면 ADR을 작성하지 않습니다. `중요하다`, `나중에 참고할 수 있다`,
`검증해 두었다`는 이유만으로는 ADR이 아닙니다. 기존 승인 ADR과 같은 결정이면 새 파일을 만들지
않습니다. 기존 결정을 바꿔야 한다면 승인된 본문을 고치지 않고 아래 대체 절차를 따릅니다.

주요 라이브러리도 운영 코드의 표준으로 채택해 넓은 변경 비용이 생길 때만 ADR 대상입니다. 실험,
학습 목표, 빌드 호환성 검증, 테스트 픽스처에서만 쓰는 라이브러리는 구현 컨벤션이나 테스트 전략에
기록합니다.

## ADR이 아닌 문서

가격·기간·사용자 상태 전이 같은 제품 정책은 `docs/prd/`, 현재 HTTP 필드·경로는
`docs/api-spec.md`, 현재 데이터 구조는 `docs/erd.md`, 테스트 절차·판정은
`docs/test-strategy.md`, 실행 명령과 증거는 해당 가이드·`docs/evidence/`에 기록합니다.
환경변수·프로필·실행 설정은 배포 가이드, 코딩 규칙과 제한된 라이브러리 사용법은 구현 컨벤션에
기록합니다. 변수명·파일 위치·작업 번호·Jira 이력은 ADR에 기록하지 않습니다.

## 절차

1. 작성 판정 게이트를 통과시키고 기존 ADR·정본과 중복되지 않는지 확인한다.
2. ADR 대상이 아니면 알맞은 정본을 갱신하고 번호를 부여하지 않는다.
3. 대상이면 모든 주제 폴더의 가장 큰 ADR 번호에 1을 더한 4자리 번호를 사용한다.
4. 결정이 합의된 뒤 아래 템플릿으로 작성하며 상태는 `승인됨`으로 기록한다. 합의 과정의 이견·소수
   의견은 "고려한 대안"에 한 줄로 남긴다.
5. 기존 ADR의 결정을 바꿀 때는 그 ADR의 상태만 `대체됨`으로 수정하고 다른 내용은 그대로 보존한다.
6. 새 ADR은 `승인됨`으로 작성하고 `맥락`에서 대체하는 ADR 번호와 변경 이유를 명시한다.
7. `docs/adr/README.md` 색인에는 기존 ADR과 새 ADR을 모두 남기고, 현행 정본과 저장소의 참조는 새
   ADR을 가리키게 갱신한다.
8. AI 에이전트: 구조에 영향 주는 작업 전에 관련 `승인됨` ADR과 연결된 `대체됨` ADR을 함께 읽는다.
   ADR과 어긋나는 요청을 받으면 해당 ADR을 근거로 먼저 확인 질문한다.

## 템플릿

```markdown
# NNNN. <결정 제목>

- 상태: 승인됨
- 날짜: YYYY-MM-DD

## 맥락

<결정이 필요해진 문제, 관찰한 사실, 제약, 사건의 흐름과 기존 결정의 관계를 필요한 만큼 기록한다.
문장 수는 제한하지 않으며, 서로 다른 쟁점은 문단이나 목록으로 나누고 결정·결과의 내용은 반복하지 않는다.>

## 고려한 대안

<`대안 — 핵심 장점 / 탈락 이유` 형식으로 대안마다 한 줄. 실질 대안이 없었으면 "없음".>

## 결정

<선택한 것과 핵심 근거. "~한다" 단정형.>

## 결과

<좋아지는 것 / 감수하는 것 / 되돌리려면 필요한 비용.>
```

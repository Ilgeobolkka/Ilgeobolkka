# 0004. Java 21과 Spring Boot 4.1.0, Amazon RDS for MySQL을 사용한다

- 상태: 승인됨
- 날짜: 2026-07-22

## 맥락

읽어볼까의 핵심은 페이지 열람 확정, 포인트 차감, 변경 불가능한 포인트 내역, 마지막 열람 위치를 하나의 트랜잭션으로 일관되게 처리하는 것입니다. 중복 요청과 동시 요청에서도 최초 한 번만 차감되도록 데이터베이스의 트랜잭션과 고유 제약을 활용해야 합니다. 구현을 시작하지 않은 신규 프로젝트이므로 현재 Spring Initializr가 기본 제공하는 안정 버전을 사용하고, 운영 데이터베이스의 백업과 장애 복구를 직접 관리하는 부담을 줄입니다.

## 고려한 대안

- Spring Boot 3.5.x: Java 21과 호환되지만 현재 Spring Initializr 선택 목록에서 빠졌고 기존 코드나 라이브러리 제약도 없으므로 제외했습니다.
- Spring Boot 4.0.x: 사용할 수 있는 안정 버전이지만 신규 프로젝트는 Initializr의 최신 기본 안정 버전인 4.1.0에서 시작하기로 했습니다.
- 자체 관리 MySQL을 EC2에 설치: 인스턴스 비용을 세밀하게 조절할 수 있지만 백업, 패치, 모니터링과 장애 복구를 직접 운영해야 하므로 제외했습니다.
- Amazon Aurora MySQL-Compatible: 확장성과 고가용성 기능이 강하지만 초기 MVP의 규모와 비용에 비해 과하므로 제외했습니다.
- PostgreSQL: 동일한 요구사항을 충분히 구현할 수 있지만 이번 프로젝트에서 사용할 Java·Spring 기반 MySQL 경험과 운영 편의성을 우선해 제외했습니다.
- 인메모리 데이터베이스만 사용: 테스트는 빠르지만 MySQL의 잠금, 인덱스, 고유 제약과 SQL 차이를 검증할 수 없어 최종 통합 검증 수단으로 사용하지 않습니다.

## 결정

- 백엔드는 Java 21과 Spring Boot 4.1.0을 사용합니다.
- 운영 관계형 데이터베이스는 Amazon RDS for MySQL 8.x를 사용합니다.
- 데이터베이스 연결에는 Spring Boot가 관리하는 MySQL Connector/J와 기본 HikariCP 연결 풀을 사용합니다.
- 스키마 변경은 Flyway 마이그레이션으로 관리하고, 운영 환경에서 Hibernate의 자동 스키마 변경을 사용하지 않습니다.
- 로컬 개발과 통합 테스트도 MySQL 8.x를 사용해 운영 환경과의 SQL 및 트랜잭션 차이를 줄입니다.
- 데이터베이스 문자 집합은 `utf8mb4`, 애플리케이션과 데이터베이스의 기준 시간대는 UTC로 통일합니다.
- 운영 접속 정보는 코드나 저장소에 기록하지 않고 환경 변수 또는 AWS Secrets Manager로 주입합니다.
- RDS는 공개 인터넷에 직접 노출하지 않고 애플리케이션 보안 그룹에서만 접근하도록 제한합니다. 저장 데이터 암호화, 전송 구간 TLS, 자동 백업을 활성화합니다.

## 결과

- 포인트 차감과 내역 생성, 열람 확정, 마지막 위치 갱신을 하나의 데이터베이스 트랜잭션으로 구현합니다.
- 사용자·도서·페이지별 최초 1회 차감은 애플리케이션 검사만이 아니라 데이터베이스 고유 제약으로도 보장합니다.
- Spring Boot 4.1이 관리하는 Spring Framework 7과 관련 라이브러리를 기준으로 의존성 호환성을 확인합니다.
- RDS의 자동 백업, 스냅샷, 모니터링 기능을 활용할 수 있지만 사용량이 적어도 AWS 비용이 발생합니다.
- 애플리케이션의 동시 처리량은 RDS의 최대 연결 수와 HikariCP 풀 크기에 제한되므로 부하 수준에 맞게 풀을 조정해야 합니다.
- Java 21의 가상 스레드는 필요할 때 별도로 검증해 활성화하며, 가상 스레드가 데이터베이스 연결 수를 늘려주지는 않습니다.
- 가용 영역 구성, 읽기 복제본, RDS Proxy와 Aurora 전환은 실제 트래픽과 가용성 요구가 생긴 뒤 별도로 결정합니다.

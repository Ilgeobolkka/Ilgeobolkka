# 0011. Poppler로 페이지 이미지를 변환하고 비공개 S3에 저장한다

- 상태: 대체됨 (→ 0012)
- 날짜: 2026-07-23
- 결정자: 사용자

## 맥락

ADR-0002에 따라 원본 PDF를 브라우저에 제공하지 않고 모든 페이지를 이미지로 사전 변환해야 합니다.
초기 데이터 100권은 총 5,939페이지이므로 변환 결과가 재현 가능해야 하고, 운영 배포 교체나 수평 확장에도
이미지가 유실되지 않아야 합니다. 변환 도구와 로컬·운영 저장소의 기준을 먼저 정해 후속 배치 변환과
업로드 구현이 같은 계약을 따르게 합니다.

## 고려한 대안

- Java PDF 라이브러리로 애플리케이션 실행 중 변환 — Java 코드 안에서 처리할 수 있지만 요청 지연과
  런타임 자원 사용이 커지고 사전 변환 요구에도 맞지 않아 제외합니다.
- ImageMagick과 Ghostscript — 다양한 출력 형식을 지원하지만 도구 조합과 보안 설정이 늘어나며,
  현재 필요한 PDF 래스터 변환에는 과해 제외합니다.
- Poppler `pdftoppm`과 PNG — 글자와 선을 손실 없이 보존하지만 샘플 본문 페이지가 260KB로,
  동일 조건의 JPEG 191KB보다 커서 전체 저장·전송량이 증가하므로 제외합니다.
- 애플리케이션 서버의 로컬 디스크만 사용 — 로컬 개발은 단순하지만 운영 배포 교체와 다중 인스턴스에서
  파일의 지속성과 일관성을 보장하기 어려워 운영 저장소로는 제외합니다.
- 공개 S3 버킷 — 정적 자산 제공은 단순하지만 현재 페이지 이미지만 허가된 독자에게 제공한다는
  ADR-0002의 접근 경계를 우회할 수 있어 제외합니다.

## 결정

- PDF 페이지 변환 도구는 Poppler의 `pdftoppm`을 사용합니다.
- 변환은 애플리케이션 요청 처리와 분리된 사전 배치 작업으로 수행합니다.
- 페이지 이미지는 150 DPI, RGB JPEG, 품질 85를 기본 출력 계약으로 사용합니다.
- 표지는 별도 원본을 만들지 않고 첫 페이지 변환 결과를 사용합니다.
- 로컬 개발과 변환 검증은 Git에서 제외된 로컬 파일시스템을 사용합니다.
- 운영 페이지 이미지는 Amazon S3의 전용 비공개 버킷에 저장합니다.
- S3 Block Public Access를 모두 활성화하고 저장 데이터는 기본 서버 측 암호화를 사용합니다.
- 브라우저가 버킷이나 원본 PDF에 직접 접근하지 않도록 애플리케이션이 인증·열람 조건을 확인한 뒤
  현재 페이지 이미지만 제공합니다.
- 객체 키와 로컬 디렉터리는 같은 논리 규칙을 사용하되, 구체적인 경로와 업로드 절차는 후속 작업에서
  정의합니다.

## 결과

- 운영 애플리케이션 인스턴스를 교체하거나 여러 대로 늘려도 페이지 이미지가 유지됩니다.
- PDF 변환 실패를 배포 전에 발견할 수 있고, 런타임 요청에서 PDF 렌더링 비용이 발생하지 않습니다.
- 샘플 한글 본문은 150 DPI·품질 85에서 읽을 수 있는 선명도를 유지했고 PNG보다 파일 크기가 작았습니다.
- JPEG는 손실 압축이므로 작은 글자나 도표가 많은 실제 도서에는 별도 품질 검증이 필요합니다.
- S3 저장량과 요청에 따른 AWS 비용이 발생하고, 운영 배포에는 버킷과 최소 권한 IAM 구성이 필요합니다.
- S3의 공개 접근 차단과 암호화 기준은
  [Amazon S3 보안 모범 사례](https://docs.aws.amazon.com/AmazonS3/latest/userguide/security-best-practices.html)를
  따릅니다.

# 0012. 표지를 분리하고 페이지 이미지 품질을 검증한다

- 상태: 승인됨
- 날짜: 2026-07-23
- 결정자: 사용자

## 맥락

ADR-0011은 PDF 첫 페이지 변환 결과를 표지로 재사용하기로 했지만, 표지는 동의 전에 상세 화면에서
노출되고 PDF 페이지는 동의 후 최초 열람 시 50P를 차감합니다. 같은 자산이 표지이자 과금 대상 1페이지가
되면 모든 페이지 과금과 동의 전 뷰어 진입 금지 계약의 경계가 흐려집니다. 또한 JPEG 품질 85 선택은
단일 샘플의 파일 크기와 육안 확인에만 근거해 전체 100권에 적용할 품질 게이트와 실패 시 대안이
필요합니다.

## 고려한 대안

- PDF 첫 페이지를 표지로 재사용 — 별도 자산이 필요 없지만 동의 전에 노출되는 표지와 과금 페이지가
  같아지므로 제외합니다.
- 첫 PDF 페이지를 과금 페이지 수와 `pageNumber`에서 제외 — 표지 재사용은 가능하지만 무료·과금 제외
  페이지가 없다는 PRD와 ERD·테스트 계약을 함께 바꿔야 하므로 제외합니다.
- Java PDF 라이브러리로 요청 중 변환 — 애플리케이션 안에서 처리할 수 있지만 요청 지연과 런타임 자원
  사용이 커지고 사전 변환 요구에 맞지 않아 제외합니다.
- PNG를 기본 형식으로 사용 — 글자와 선을 손실 없이 보존하지만 검증 샘플이 JPEG보다 36% 커서,
  JPEG 품질 게이트를 먼저 적용하고 실패 시 전환하는 대안으로 남깁니다.
- 애플리케이션 서버의 로컬 디스크만 사용 — 로컬 개발은 단순하지만 운영 배포 교체와 다중 인스턴스에서
  파일 지속성과 일관성을 보장하기 어려워 운영 저장소로는 제외합니다.
- 공개 S3 버킷 — 정적 자산 제공은 단순하지만 인증·열람 조건을 우회할 수 있어 제외합니다.

## 결정

- 표지는 PDF 페이지와 다른 별도 이미지 자산으로 준비하고 `Book.coverImagePath`가 그 경로를 가리킵니다.
- 표지는 PDF 변환 파이프라인의 입력·출력과 페이지 번호에서 제외하며 `totalPageCount`에도 영향을 주지
  않습니다.
- PDF의 모든 페이지는 `1`부터 `totalPageCount`까지 연속된 과금 페이지로 유지합니다.
- PDF 페이지 변환 도구는 Poppler의 `pdftoppm`을 사용하고 애플리케이션 요청과 분리된 사전 배치로
  실행합니다.
- 기본 출력은 150 DPI, RGB JPEG, 품질 85로 합니다.
- 로컬은 Git에서 제외된 파일시스템, 운영은 Block Public Access와 기본 서버 측 암호화를 적용한
  Amazon S3 전용 비공개 버킷에 저장합니다.
- 전체 100권의 모든 페이지가 오류 없이 변환되고 변환 이미지 수가 `totalPageCount`와 일치해야 합니다.
- 도서마다 첫·중간·마지막 페이지를 뽑은 300장을 실제 출력 크기의 100%와 200%로 확인합니다. 한글
  자소·문장부호·가는 선이 뭉개지거나 JPEG 블록·테두리 번짐 때문에 본문과 도표를 구분할 수 없는
  페이지가 하나라도 있으면 실패입니다.
- 품질 85가 실패하면 전체 표본을 품질 92로 다시 변환해 같은 기준으로 검증합니다. 품질 92도 실패하면
  페이지별 형식을 섞지 않고 전체 데이터셋을 PNG로 전환합니다.
- 브라우저가 S3나 원본 PDF에 직접 접근하지 않도록 애플리케이션이 인증·열람 조건을 확인한 뒤 현재
  페이지 이미지만 제공합니다.
- 객체 키와 로컬 디렉터리는 같은 논리 규칙을 사용하되 구체적인 경로와 업로드 절차는 후속 작업에서
  정의합니다.

## 검증 근거

- 샘플: SCRUM-49 합성 도서 데이터에서 복사한
  `docs/adr/evidence/0012/book_001.pdf`의 3페이지
- 원본 SHA-256: `af434962fde401334f08c2df5afd1979b1f049b9efeda6790637779c839c2fd7`
- 변환 도구: Poppler `pdftoppm` 26.05.0
- JPEG 명령:
  `pdftoppm -f 3 -l 3 -singlefile -r 150 -jpeg -jpegopt quality=85,optimize=y,progressive=y docs/adr/evidence/0012/book_001.pdf book_001-page-003`
- PNG 명령:
  `pdftoppm -f 3 -l 3 -singlefile -r 150 -png docs/adr/evidence/0012/book_001.pdf book_001-page-003`
- 결과: JPEG 195,313바이트, PNG 266,163바이트로 JPEG가 70,850바이트(약 26.6%) 작았습니다.
- 육안 판정: 875×1,241픽셀 원본 해상도에서 한글 자소와 문장부호를 구분할 수 있고 글자 획을 가리는
  블록이나 번짐이 없었습니다.

## 결과

- 상세 화면의 표지와 과금 페이지가 분리되어 기존 PRD·ERD·테스트 계약을 변경하지 않습니다.
- 별도 표지 이미지 100개를 페이지 변환 전에 준비하고 메타데이터 경로와 연결해야 합니다.
- 품질 선택 근거를 같은 원본과 명령으로 재현할 수 있고 전체 변환 전에 실패 기준을 적용할 수 있습니다.
- 품질 92 또는 PNG로 전환하면 저장·전송량이 늘지만 페이지별 확장자를 섞지 않아 경로 계약은
  단순하게 유지됩니다.
- 운영 애플리케이션 인스턴스를 교체하거나 여러 대로 늘려도 페이지 이미지가 유지되지만 S3 저장량과
  요청에 따른 AWS 비용, 최소 권한 IAM 구성이 필요합니다.
- S3의 공개 접근 차단과 암호화 기준은
  [Amazon S3 보안 모범 사례](https://docs.aws.amazon.com/AmazonS3/latest/userguide/security-best-practices.html)를
  따릅니다.

# 0013. 실제 뷰어 크기로 페이지 이미지 품질을 검증한다

- 상태: 대체됨 (→ 0014)
- 날짜: 2026-07-23
- 결정자: 사용자

## 맥락

ADR-0012는 표지와 과금 페이지를 분리하고 JPEG 품질 게이트를 도입했지만, 원본 이미지의 100%와
200% 크기만 확인하도록 했습니다. 실제 뷰어는 확대·축소를 제공하지 않고 페이지 너비에 맞춰 표시하므로,
원본에서 읽을 수 있는 이미지도 모바일 화면에서는 읽기 어려울 수 있습니다. 또한 첫·중간·마지막 페이지만
검사하면 작은 글자와 복잡한 도표가 있는 위험 페이지를 놓칠 수 있고, 별도 표지 준비와 메타데이터 연결의
후속 작업 책임도 명확하지 않습니다.

## 고려한 대안

- 원본 이미지의 100%와 200% 크기만 검사 — 압축 흔적은 자세히 볼 수 있지만 실제 사용자에게 보이는
  축소 크기의 가독성을 보장하지 못하므로 제외합니다.
- 모든 페이지를 사람이 검사 — 누락 가능성은 가장 낮지만 전체 100권을 반복 검증하는 비용이 커서
  대표 페이지와 위험 페이지를 함께 검사합니다.
- 첫·중간·마지막 페이지만 검사 — 선택은 단순하지만 작은 글자·표·도표·가는 선이 있는 페이지를
  놓칠 수 있어 위험 페이지 표본을 추가합니다.
- 표지 작업을 별도 하위 작업으로 분리 — 책임은 가장 명확하지만 기존 SCRUM-222와 SCRUM-223의 범위에
  포함할 수 있어 새 작업을 만들지 않습니다.

## 결정

- 표지는 PDF 페이지와 다른 별도 이미지 자산으로 준비하고 `Book.coverImagePath`가 그 경로를 가리킵니다.
- 표지는 PDF 변환 파이프라인의 입력·출력과 페이지 번호에서 제외하며 `totalPageCount`에도 영향을 주지
  않습니다.
- PDF의 모든 페이지는 `1`부터 `totalPageCount`까지 연속된 과금 페이지로 유지합니다.
- PDF 페이지 변환 도구는 Poppler의 `pdftoppm`을 사용하고 애플리케이션 요청과 분리된 사전 배치로
  실행합니다.
- 기본 출력은 150 DPI, RGB JPEG, 품질 85로 합니다.
- 로컬은 Git에서 제외된 파일시스템, 운영은 Block Public Access와 기본 서버 측 암호화를 적용한
  Amazon S3 전용 비공개 버킷에 저장합니다.
- 전체 100권의 모든 페이지가 오류 없이 변환되고 변환 이미지 수가 `totalPageCount`와 일치해야 합니다.
- 도서마다 첫 페이지, `ceil(totalPageCount / 2)`로 계산한 중간 페이지, 마지막 페이지를 대표 표본으로
  선정합니다.
- 각 도서에서 작은 글자가 가장 많은 페이지, 표·도표가 가장 복잡한 페이지, 가장 가는 선이 있는 페이지를
  위험 표본으로 추가합니다. 같은 페이지가 여러 조건에 해당하면 중복 검사하지 않습니다. 선정된 표본의
  페이지 번호를 기록하고, 해당 요소가 없어 표본을 생략한 조건은 제외 이유를 품질 검증 결과에 기록합니다.
- 대표 표본과 위험 표본은 원본 이미지의 100% 크기에서 압축 흔적을 확인하고, 실제 뷰어 구현에서
  `360×800` 모바일과 `1280×800` 데스크톱 뷰포트의 초기 페이지 너비 맞춤 상태로 가독성을 확인합니다.
  뷰어의 최소 지원 너비가 360px보다 작으면 그 최소 너비를 모바일 검증에 사용합니다.
- 한글 자소·문장부호·가는 선이 뭉개지거나 JPEG 블록·테두리 번짐 때문에 본문과 도표를 구분할 수 없는
  페이지가 하나라도 있으면 실패입니다.
- 품질 85가 실패하면 전체 표본을 품질 92로 다시 변환해 같은 기준으로 검증합니다. 품질 92도 실패하면
  페이지별 형식을 섞지 않고 전체 데이터셋을 PNG로 전환합니다.
- 브라우저가 S3나 원본 PDF에 직접 접근하지 않도록 애플리케이션이 인증·열람 조건을 확인한 뒤 현재
  페이지 이미지만 제공합니다.
- 객체 키와 로컬 디렉터리는 같은 논리 규칙을 사용하되 구체적인 경로와 업로드 절차는 SCRUM-222에서
  정의합니다.
- SCRUM-222에서 별도 표지 이미지 100개를 준비·업로드하고, SCRUM-223에서 각 표지의
  `Book.coverImagePath` 연결과 누락 여부를 검증합니다.

## 검증 근거

- 샘플: SCRUM-49 합성 도서 데이터에서 복사한
  `docs/adr/evidence/0012/book_001.pdf`의 3페이지
- 원본 SHA-256: `af434962fde401334f08c2df5afd1979b1f049b9efeda6790637779c839c2fd7`
- 변환 도구: Poppler `pdftoppm` 26.05.0
- JPEG 명령:
  `pdftoppm -f 3 -l 3 -singlefile -r 150 -jpeg -jpegopt quality=85,optimize=y,progressive=y docs/adr/evidence/0012/book_001.pdf book_001-page-003`
- PNG 명령:
  `pdftoppm -f 3 -l 3 -singlefile -r 150 -png docs/adr/evidence/0012/book_001.pdf book_001-page-003`
- 결과: JPEG 195,313바이트, PNG 266,163바이트로 JPEG가 70,850바이트(약 26.6%) 작았습니다.
- 육안 판정: 875×1,241픽셀 원본 해상도에서 한글 자소와 문장부호를 구분할 수 있고 글자 획을 가리는
  블록이나 번짐이 없었습니다.
- 실제 뷰어 크기 검증은 뷰어 구현 후 전체 100권 변환 전에 수행하고 결과에 뷰포트, 페이지 번호,
  판정과 실패 시 재변환 형식을 기록합니다.

## 결과

- 상세 화면의 표지와 과금 페이지가 분리되어 기존 PRD·ERD·테스트 계약을 변경하지 않습니다.
- 원본 크기에서 보이는 품질뿐 아니라 확대 기능이 없는 실제 모바일·데스크톱 뷰어의 가독성을
  검증합니다.
- 대표 페이지의 계산식과 위험 페이지 선정·기록 규칙이 생겨 품질 검증을 반복할 수 있습니다.
- 별도 표지의 준비·업로드·메타데이터 연결 책임을 SCRUM-222와 SCRUM-223에서 추적합니다.
- 품질 92 또는 PNG로 전환하면 저장·전송량이 늘지만 페이지별 확장자를 섞지 않아 경로 계약은
  단순하게 유지됩니다.
- 운영 애플리케이션 인스턴스를 교체하거나 여러 대로 늘려도 페이지 이미지가 유지되지만 S3 저장량과
  요청에 따른 AWS 비용, 최소 권한 IAM 구성이 필요합니다.
- S3의 공개 접근 차단과 암호화 기준은
  [Amazon S3 보안 모범 사례](https://docs.aws.amazon.com/AmazonS3/latest/userguide/security-best-practices.html)를
  따릅니다.

# 0017. 도서 가격을 공개하고 누적 사용액 도달 시 소장으로 전환한다

- 상태: 대체됨 (→ 0018)
- 날짜: 2026-07-23

## 맥락

ADR-0003은 페이지 과금 정확성만 검증하기 위해 도서 가격을 두지 않고 모든 첫 열람 페이지에 50P를 차감하기로 했습니다. 그러나 독자가 책 전체에 얼마까지 사용할지 알 수 없고, 충분히 많은 페이지를 읽으면 일반적인 전체 책 가격보다 더 많은 포인트를 쓸 수 있습니다. 도서 가격을 미리 공개하고 해당 도서에 사용한 포인트가 가격에 도달하면 온라인 소장으로 전환해, 조금씩 읽는 선택이 전체 가격을 초과하지 않도록 정책을 변경합니다.

## 고려한 대안

- 도서 가격을 계속 숨기고 페이지당 50P만 과금 — 기존 MVP 범위는 단순하지만 독자가 총지출 상한을 알 수 없고 소장 전환을 제공할 수 없어 제외했습니다.
- 50P씩 차감해 도서 가격 이상이 되면 소장 — 계산은 단순하지만 마지막 차감이 공개 가격을 초과할 수 있어 제외했습니다.
- 마지막 페이지에도 50P를 차감하고 초과분을 별도 환급 — 차감과 환급 내역이 동시에 생겨 잔액·내역·소장 전환 검증이 불필요하게 복잡해 제외했습니다.
- 누적 사용 포인트를 매번 `PointLedger`에서 합산 — 별도 상태가 없다는 장점은 있지만 동시 확정 요청에서 가격 상한을 지키기 위한 집계 잠금이 복잡해 제외했습니다.

## 결정

### 제품 정책

- 문서와 화면에서는 소장 기준으로 공개하는 값을 **도서 가격**이라고 부릅니다. 도서의 제작비나 공급가를 뜻하는 원가와 구분합니다.
- 모든 도서는 양의 정수인 `pricePoints`를 가지며 목록과 상세 화면에 공개합니다. 1P는 향후 PG 연동 시 1원과 같은 비율입니다.
- 페이지 기본 단가는 계속 50P입니다.
- 독자·도서별 누적 사용 포인트 `spentPoints`는 그 도서에서 성공한 페이지 차감액의 합계입니다.
- 소장 전 미확정 페이지의 실제 차감액은 `min(50P, pricePoints - spentPoints)`입니다.
- `spentPoints`가 `pricePoints`에 도달하면 마지막 차감과 같은 트랜잭션에서 `ownedAt`을 기록합니다.
- 소장한 도서는 아직 열람 확정하지 않은 페이지도 잔액 검사와 포인트 차감 없이 열람할 수 있습니다. 열람 확정과 마지막 위치는 계속 기록할 수 있습니다.
- 소장은 서비스 안에서 모든 페이지를 읽는 권한입니다. 원본 PDF 다운로드, 인쇄, 오프라인 이용 권한은 포함하지 않습니다.
- MVP에서는 도서 가격 변경과 할인을 지원하지 않습니다.

### 데이터 계약

- `Book`에 `price_points INT NOT NULL`을 추가하고 `price_points > 0`을 보장합니다.
- `LibraryEntry`에 `spent_points INT NOT NULL DEFAULT 0`과 nullable `owned_at DATETIME(6)`을 추가합니다.
- 애플리케이션 트랜잭션은 `0 <= spent_points <= Book.price_points`와 `owned_at IS NOT NULL` iff `spent_points = Book.price_points`를 보장합니다. 서로 다른 테이블의 값을 비교해야 하므로 MySQL `CHECK`만으로 대신하지 않습니다.
- `PointLedger`의 차감 `amount`는 마지막 잔여액 차감 때문에 1P부터 50P까지가 될 수 있습니다. 소장 후 열람 확정에는 차감 내역을 생성하지 않습니다.
- 기존 `V1__create_core_domain_tables.sql`은 수정하지 않고 후속 Flyway migration에서 필드와 제약을 추가합니다.

ADR-0007의 `Book`에 전체 책 가격 컬럼을 두지 않는 결정과 `LibraryEntry`에 누적 사용 포인트를 두지 않는 결정은 이 데이터 계약으로 대체합니다. 그 밖의 엔티티, 관계와 고유 제약은 ADR-0007을 유지합니다.

### 차감과 소장 전환 순서

기존 ADR-0008의 세션 검증, 6초 검증과 `ConfirmedPage` 중복 확인 원칙을 유지하면서, 차감이 필요한 요청은 다음 순서로 처리합니다.

1. `ReadingSession` 행을 잠그고 세션 토큰·도서·현재 페이지와 6초 경과를 검증합니다.
2. 이미 열람 확정된 페이지면 차감 없이 성공 응답을 반환합니다.
3. 현재 `LibraryEntry`가 소장 상태면 `ConfirmedPage`와 마지막 위치만 기록하고 차감 없이 성공 응답을 반환합니다.
4. 소장 전이면 `PointAccount` 행을 잠가 같은 독자의 포인트 차감 요청을 직렬화합니다.
5. 잠금 뒤 `ConfirmedPage`와 `LibraryEntry`를 다시 조회합니다. 그 사이 페이지가 확정됐거나 도서가 소장됐다면 차감하지 않습니다.
6. `min(50P, pricePoints - spentPoints)`로 실제 차감액을 계산하고 잔액을 검증합니다.
7. 포인트 잔액 차감, `PointLedger` 생성, `ConfirmedPage` 생성, `spentPoints` 증가, 필요하면 `ownedAt` 기록, 마지막 열람 위치 갱신을 하나의 트랜잭션에서 처리합니다.

잠금 순서는 항상 `ReadingSession` → `PointAccount` → `LibraryEntry`로 통일합니다. 같은 독자의 서로 다른 페이지나 서로 다른 도서 확정 요청도 `PointAccount`에서 직렬화되므로 포인트 잔액과 도서 가격 상한을 함께 보호할 수 있습니다.

### 화면과 API 계약

- 도서 목록과 `GET /api/books`, 책 상세와 `GET /api/books/{bookId}`는 공개 `pricePoints`를 포함합니다.
- 로그인한 독자의 책 상세에는 `spentPoints`, `remainingPoints`, `owned`를 표시합니다. 서버 렌더링 화면은 같은 도서·서재 조회 유스케이스에서 이 값을 가져옵니다.
- 최초 열람 동의는 페이지당 최대 50P, 마지막 잔여액만 차감한다는 사실, 가격 도달 시 소장된다는 사실을 알립니다. 내부 6초 판정 기준은 계속 노출하지 않습니다.
- `OpenReadingSessionResponse`와 `MoveReadingPageResponse`는 `owned`, `nextChargePoints`를 포함합니다. 이미 확정된 페이지나 소장 도서는 `nextChargePoints=0`입니다.
- `ConfirmReadingResponse`는 기존 `deductedAmount`, `balanceAfter`에 `spentPoints`, `remainingPoints`, `owned`를 추가합니다.
- `GetLibraryResponse`의 항목은 기존 값에 `pricePoints`, `spentPoints`, `remainingPoints`, `owned`를 추가합니다.
- 소장 전 미확정 페이지 진입 시 잔액이 `nextChargePoints`보다 적으면 기존과 같이 422로 차단합니다. 이미 확정된 페이지와 소장한 도서는 잔액과 관계없이 진입을 허용합니다.

ADR-0008의 고정 50P 차감, 50P 미만 잔액 차단, 가격 없는 도서 응답 계약은 이 화면·API 계약으로 대체합니다. 그 밖의 엔드포인트, 세션 검증, 오류 형식과 HTTP 상태 계약은 ADR-0008을 유지합니다.

## 결과

- 독자는 읽기 전에 도서 가격을 알고, 페이지 사용액이 그 가격을 초과하지 않는다는 상한을 신뢰할 수 있습니다.
- 가격이 50P의 배수가 아니면 마지막 차감액이 1P~49P가 되므로 고정 50P만 가정하던 테스트와 응답 표시를 변경해야 합니다.
- `Book`, `LibraryEntry`, 열람 확정 트랜잭션, 도서·서재 응답과 초기 데이터에 구현 변경이 필요합니다.
- 소장 상태는 별도 주문이나 구매 내역이 아니라 페이지 차감의 누적 결과로 설명됩니다. 포인트 내역 합계와 `spentPoints`도 서로 일치해야 합니다.
- 향후 도서 가격 변경, 할인, 환불 또는 소장 취소를 도입하려면 가격 기준 시점과 기존 독자 보호 정책을 별도 ADR로 결정해야 합니다.

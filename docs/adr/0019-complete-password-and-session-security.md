# 0019. 비밀번호와 웹 세션 보안 계약을 완성한다

- 상태: 승인됨
- 날짜: 2026-07-23

## 맥락

ADR-0015는 Spring Security 서버 세션과 CSRF 보호를 선택했지만 비밀번호 인코더, 입력 규칙, 비활성
만료 시간, 브라우저의 CSRF 토큰 전달과 열람 세션 정리 시점을 미정으로 남겼습니다. 이메일·비밀번호
인증을 구현하기 전에 저장·오류·세션 수명을 일관된 계약으로 고정해야 합니다.

## 고려한 대안

- 평문 또는 빠른 단방향 해시 저장 — 유출 시 대입 공격에 취약해 제외합니다.
- Argon2 전용 인코더 — 메모리 기반 방어에 유리하지만 현재 MVP에 추가 암호화 의존성이 필요해 제외합니다.
- JWT access·refresh token — 서버 세션을 선택한 ADR-0015보다 토큰 갱신·폐기 흐름이 복잡해 제외합니다.
- Remember Me — 편의성은 높지만 장기 자격 증명 수명과 탈취 대응이 추가되어 제외합니다.
- 로그인 오류에서 이메일 존재 여부 구분 — 사용자는 원인을 알기 쉽지만 계정 존재 여부를 노출해 제외합니다.

## 결정

- 이메일은 앞뒤 공백을 제거하고 `Locale.ROOT` 기준 소문자로 정규화한 뒤 저장·조회합니다.
- 정규화한 이메일에 DB 고유 제약을 적용하고 중복 가입은 `409 EMAIL_ALREADY_EXISTS`로 거부합니다.
- 비밀번호는 최소 8자, UTF-8 최대 64바이트입니다.
- 영문, 숫자, 공백이 아닌 ASCII 특수문자를 각각 하나 이상 포함해야 하며 한글 등 다른 문자는 추가로 허용합니다.
- 비밀번호를 정규화하거나 최대 길이에 맞춰 자르지 않습니다.
- Spring Security `DelegatingPasswordEncoder`를 사용하고 신규 비밀번호는 BCrypt 형식으로 저장합니다.
- 원문 비밀번호는 DB, 로그, 이벤트와 오류 응답에 남기지 않습니다.
- 존재하지 않는 이메일과 비밀번호 불일치는 모두 `401 INVALID_CREDENTIALS`와 같은 사용자 메시지로 응답합니다.
- 로그인 성공 시 세션 ID를 교체하고 마지막 요청 후 2시간 동안 활동이 없으면 세션을 만료합니다.
- 로그아웃 시 `HttpSession`, 세션 쿠키와 독자의 도메인 `ReadingSession`을 무효화합니다.
- 자동 로그인과 Remember Me, 로그인 횟수 제한과 계정 잠금은 MVP에서 제공하지 않습니다.
- Spring Security CSRF 보호를 회원가입·로그인·로그아웃을 포함한 모든 상태 변경 요청에 적용합니다.
- Thymeleaf 폼은 hidden field, JavaScript `fetch`는 페이지의 meta 태그에서 읽은 CSRF 토큰을 헤더로 전송합니다.
- 로그인과 로그아웃으로 CSRF 토큰이 폐기되면 새 화면을 렌더링해 새 토큰을 사용합니다.
- 로컬·시연 계정은 운영에서 생성하지 않고 비밀번호는 환경변수로만 주입합니다.

### 오류 계약

| 상황 | HTTP 상태 | 오류 코드 |
| --- | --- | --- |
| 이메일·비밀번호 입력 규칙 위반 | 400 | `INVALID_INPUT` |
| 정규화한 이메일 중복 | 409 | `EMAIL_ALREADY_EXISTS` |
| 이메일 또는 비밀번호 불일치 | 401 | `INVALID_CREDENTIALS` |
| 인증 세션 없음·만료 | 401 | `AUTHENTICATION_REQUIRED` |
| CSRF 토큰 없음·불일치 | 403 | `INVALID_CSRF_TOKEN` |

공개 오류 코드는 예외 클래스 이름에서 자동으로 만들지 않고 명시적인 값으로 고정합니다.

## 결과

- 비밀번호 원문과 계정 존재 여부 노출을 막고 서버 세션의 생성·만료·폐기 수명이 명확해집니다.
- 로그인·로그아웃과 JavaScript API 요청도 같은 CSRF 보호를 적용합니다.
- 2시간 비활성 만료는 독서 흐름을 유지하지만 공용 기기에서는 사용자가 명시적으로 로그아웃해야 합니다.
- 로그인 제한과 계정 잠금이 없어 반복 로그인 공격 방어는 운영 공개 전 별도 보안 결정이 필요합니다.

# 0020. 현재 페이지 이미지는 애플리케이션이 인증 후 전달한다

- 상태: 승인됨
- 날짜: 2026-07-23

## 맥락

ADR-0014는 원본 PDF와 S3를 비공개로 두고 애플리케이션이 현재 페이지 이미지만 제공하기로 했지만,
ADR-0008은 응답에 `pageImageUrl`만 두고 실제 이미지 요청의 인증·세션·캐시 계약을 정하지 않았습니다.
이전 탭이나 공유된 URL로 다른 페이지에 접근하지 못하도록 같은 출처의 구체적인 전달 경계를 결정해야 합니다.

## 고려한 대안

- S3 공개 URL — 구현은 단순하지만 인증과 현재 페이지 조건을 우회하므로 제외합니다.
- 짧게 만료되는 S3 사전 서명 URL — 애플리케이션 전송량은 줄지만 발급 후 만료 전까지 이전 URL을 재사용할 수 있어 제외합니다.
- 이미지 URL에 `sessionToken` 쿼리 파라미터 포함 — `<img>`에서 직접 사용할 수 있지만 토큰이 로그와 브라우저 기록에 남을 수 있어 제외합니다.
- 애플리케이션이 인증 후 이미지 바이트 전달 — 매 요청을 검증할 수 있고 기존 same-origin 배포와 비공개 S3 결정을 유지해 선택합니다.

## 결정

- `GET /api/reading-sessions/current/page-image`가 현재 페이지의 이미지 바이트를 반환합니다.
- 브라우저는 `fetch`로 이미지를 요청하고 반환된 Blob URL을 뷰어 이미지에 연결합니다.
- 요청은 로그인 세션 쿠키와 `X-Reading-Session-Token`, `X-Reading-Page-Number` 헤더를 포함합니다.
- 서버는 인증된 `readerId`, 현재 `ReadingSession.sessionToken`, 현재 `bookId`와 `currentPageNumber`를 함께 검증합니다.
- 세션 행이 없으면 404, 토큰 또는 예상 페이지가 현재 세션과 다르면 409로 거부합니다.
- 검증이 끝난 뒤 로컬 파일시스템 또는 비공개 S3에서 현재 한 페이지의 바이트만 읽어 반환합니다.
- S3 객체 키, 버킷 주소와 원본 PDF 경로는 응답에 포함하지 않습니다.
- 응답 `Content-Type`은 실제 데이터셋의 `image/jpeg` 또는 `image/png`, 캐시는 `Cache-Control: private, no-store`로 고정합니다.
- 페이지 이동 시 이전 fetch를 중단하고 기존 Blob URL을 해제합니다. 늦게 도착한 응답은 요청 세대와 페이지 번호가 다르면 표시하지 않습니다.
- 표지는 과금 페이지와 별도 공개 자산이며 이 엔드포인트의 대상이 아닙니다.

`OpenReadingSessionResponse`와 `MoveReadingPageResponse`는 더 이상 직접 사용할 S3 또는 애플리케이션
`pageImageUrl`을 반환하지 않습니다. 세션 토큰, 현재 페이지, 열림 시각, 확정 여부와 과금 상태를 반환하고
브라우저는 고정된 이미지 엔드포인트를 별도로 호출합니다.

## 결과

- 이미지 요청마다 로그인·현재 세션·현재 페이지를 검증해 이전 탭과 이전 페이지 요청을 거부할 수 있습니다.
- 브라우저와 로그에 S3 주소나 세션 토큰 쿼리 파라미터가 남지 않습니다.
- 애플리케이션이 이미지 전송 대역폭을 부담하며 S3 장애와 스트리밍 오류 처리가 필요합니다.
- 트래픽이 커져 사전 서명 URL이나 CDN이 필요해지면 현재 페이지 권한과 URL 재사용 위험을 새 ADR로 재검토합니다.

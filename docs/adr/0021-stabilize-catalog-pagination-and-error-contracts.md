# 0021. 검색·페이지네이션·오류 응답 계약을 고정한다

- 상태: 승인됨
- 날짜: 2026-07-23

## 맥락

ADR-0008은 핵심 엔드포인트를 정했지만 포인트 내역의 페이지 크기, 동률 정렬, 빈 검색어와 SQL
와일드카드 처리, 범위 초과 페이지, 로그인 여부에 따른 상세 응답과 오류 코드의 안정성을 미정으로
남겼습니다. 클라이언트가 구현 세부사항에 의존하지 않도록 목록과 오류 계약을 완성해야 합니다.

## 고려한 대안

- 클라이언트가 페이지 크기와 정렬을 지정 — 유연하지만 현재 고정 화면에 불필요한 입력 검증과 성능 범위를 추가해 제외합니다.
- 범위 초과 페이지를 404로 응답 — 자원 부재를 명확히 하지만 비어 있는 컬렉션 탐색과 구분할 이점이 작아 제외합니다.
- 로그인 여부에 따라 진행 필드를 생략 — 바디 크기는 줄지만 응답 스키마가 달라져 제외합니다.
- 예외 클래스 이름에서 오류 코드 생성 — 구현은 단순하지만 클래스 리팩터링이 공개 API 변경이 되어 제외합니다.

## 결정

### 목록과 검색

- 도서 목록과 포인트 내역의 `page`는 1부터 시작합니다.
- `page`가 0 이하이면 `400 INVALID_INPUT`으로 거부합니다.
- 전체 페이지 수보다 큰 양수에는 `200 OK`, 빈 `items`, 요청한 `page`, `totalPages`, `totalCount`를 반환합니다.
- 도서 목록·검색은 10권, 포인트 내역은 10개로 페이지 크기를 고정하고 클라이언트가 크기를 바꿀 수 없습니다.
- 도서 목록·검색은 `title ASC, id ASC`, 포인트 내역은 `occurredAt DESC, id DESC`로 정렬합니다.
- 검색어는 앞뒤 공백을 제거하고 빈 값이면 전체 목록을 조회합니다.
- 제목 또는 저자에 대해 대소문자 구분 없는 부분 일치 검색을 적용합니다.
- `%`, `_`는 SQL 와일드카드가 아니라 사용자가 입력한 일반 문자로 이스케이프합니다.

응답 배열 필드 이름은 도서 목록 `books`, 포인트 내역 `entries`로 유지합니다. 페이지 메타데이터는
배열과 같은 최상위 응답에 둡니다.

### 도서 상세

- `GET /api/books/{bookId}`는 로그인 없이 호출할 수 있습니다.
- 기본 도서 정보는 로그인 여부와 관계없이 같은 필드로 반환합니다.
- 비로그인 응답의 `readingProgress`는 `null`입니다.
- 로그인 응답은 `readingProgress(confirmedPageCount, ownershipThresholdPageCount, owned)`를 반환합니다.
- 아직 읽지 않은 로그인 독자는 `confirmedPageCount=0`, 계산된 기준 페이지 수, `owned=false`를 받습니다.
- 가격, 최대 총 차감 포인트와 소장까지 남은 페이지 수는 반환하지 않습니다.

### 오류 응답

- 오류 바디의 `code`는 명시적인 `ErrorCode` 값이며 예외 클래스 이름에서 자동 생성하지 않습니다.
- `message`는 사용자에게 노출 가능한 한국어 설명이고 시크릿·토큰·비밀번호를 포함하지 않습니다.
- Bean Validation과 쿼리 파라미터 형식 오류는 `400 INVALID_INPUT`으로 통일합니다.
- 인증 오류는 ADR-0019, 세션 충돌은 ADR-0008, 잔액 부족은 `422 INSUFFICIENT_POINT`를 따릅니다.
- 필드 단위 오류 배열은 MVP에 추가하지 않습니다.

## 결과

- 같은 정렬값에서도 안정적으로 페이지를 이동하고 검색 특수문자가 의도치 않은 전체 검색을 만들지 않습니다.
- 비로그인·로그인 상세의 응답 모양이 고정되어 클라이언트 분기가 단순해집니다.
- 오류 코드가 Java 클래스명과 분리되어 내부 리팩터링이 API 호환성을 깨뜨리지 않습니다.
- 페이지 크기와 정렬 선택이 필요해지면 새 API 버전 또는 후속 ADR로 확장해야 합니다.

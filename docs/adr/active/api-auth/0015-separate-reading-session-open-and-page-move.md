# 0015. 열람 세션 생성과 페이지 이동 API를 분리한다

- 상태: 승인됨
- 날짜: 2026-07-24

## 맥락

새 뷰어를 여는 동작은 기존 열람 세션을 무효화하고 새 토큰을 발급하지만, 페이지 이동은 현재 세션을 유지한 채 현재 페이지와 열람 시작 시각만 바꿉니다.
두 동작을 하나의 API에 합치면 요청 필드에 따라 세션 교체 여부와 검증 규칙이 달라지고, 프런트엔드가 이미 사용한 뒤에는 경로를 다시 나누는 비용이 생깁니다.
이 결정은 승인된 ADR-0008에서 분리했으며, 상세 엔드포인트와 필드는 [`API 명세`](../../../api/api-contract.md)가 정본입니다.

## 고려한 대안

- 하나의 변경 API와 `isNewSession` 플래그 —
  경로 수는 줄지만 같은 요청이 플래그에 따라 토큰 발급과 페이지 이동이라는 서로 다른 결과를 만들어 계약을 이해하고 검증하기 어렵습니다.
- 세션 생성과 페이지 이동 API 분리 — 경로가 하나 늘지만 각 요청의 조건·부수효과·응답 의미가 한 가지로 고정됩니다.

## 결정

### 선택한 기술

새 열람 세션은 `POST /api/books/{bookId}/reading-sessions`,
현재 세션의 페이지 이동은 `PATCH /api/reading-sessions/current/page`로 분리합니다.

### 핵심 근거

- **상태 전이** — 분리 방식은 새 토큰 발급·기존 세션 무효화와 현재 세션 내 페이지 변경을 각각 표현합니다.
  플래그 방식은 이 차이를 요청 바디 안에 숨겨, 누락하거나 반대로 보냈을 때의 영향이 세션 전체 교체로 커집니다.
- **검증 범위** — 세션 생성은 도서·최초 동의·진입 페이지를 확인하고, 페이지 이동은 활성 토큰과 현재 세션을 확인합니다.
  분리하면 각 API가 자기 동작에 필요한 조건만 요구할 수 있습니다.
- **HTTP 의미** — 새 세션을 시작해 기존 상태를 교체하는 처리를 `POST`로 요청하고,
  현재 세션의 페이지 일부를 바꾸는 처리를 `PATCH`로 요청하는 방식은 [RFC 9110의 POST](https://www.rfc-editor.org/rfc/rfc9110.html#section-9.3.3)와 [RFC 5789의 PATCH](https://www.rfc-editor.org/rfc/rfc5789.html#section-2)에 어긋나지 않습니다.
  다만 HTTP 표준이 반드시 분리를 요구하는 것은 아니며, 이 프로젝트의 상태 모델을 드러내기 위한 선택입니다.
- **변경 비용** — 프런트엔드는 세션 생성 응답에서 받은 토큰으로 이후 페이지 이동을 호출합니다.
  하나의 API로 합쳤다가 다시 분리하면 요청 조건과 오류 처리를 함께 변경해야 하므로 구현 전에 경계를 고정합니다.

## 결과

- 세션 생성과 페이지 이동의 요청·응답·오류 조건을 독립적으로 검증할 수 있습니다.
- 클라이언트가 두 경로를 구분해 호출해야 합니다.
- `POST`가 새 리소스 URI를 생성하는지 현재 세션 교체 결과를 반환하는지는 성공 HTTP 상태와 함께 API 명세에서 구현 전에 확정합니다.
- 실제 구현에서 두 동작이 항상 같은 조건과 응답을 갖는다고 확인되면 통합 여부를 새 ADR로 재검토합니다.

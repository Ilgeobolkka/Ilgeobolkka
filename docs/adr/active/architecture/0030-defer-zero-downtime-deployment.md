# 0030. MVP에서는 서비스 중단을 허용하는 단일 환경 배포를 사용한다

- 상태: 승인됨
- 날짜: 2026-07-25

## 맥락

MVP 목표는 2026-08-04까지 핵심 페이지 대여 흐름을 실제 환경에서 검증하는 것입니다.
아직 지속적인 외부 트래픽과 가용성 목표가 없으므로 무중단 배포를 위해 같은 운영 환경을 두 벌 유지하는 비용과 설정이 제품 검증보다 앞설 이유가 없습니다.

## 고려한 대안

- 블루·그린 배포 — 즉시 전환과 빠른 롤백이 가능하지만 애플리케이션 환경을 두 벌 유지하고 데이터베이스 호환 마이그레이션을 설계해야 합니다.
- 롤링 배포 — 여분 인스턴스로 순차 교체할 수 있지만 최소 두 인스턴스와 버전 혼재 시 API·스키마 호환이 필요합니다.
- 단일 환경 중단 배포 — 배포 중 사용할 수 없지만 서버와 데이터베이스를 최소 구성으로 유지하고 절차를 단순화할 수 있습니다.

## 결정

### 선택한 기술

개발·MVP 검증 단계에서는 기존 애플리케이션을 내리고 새 버전을 배포하는 단일 운영 환경을 사용하며 짧은 서비스 중단을 허용합니다.
최소 한 대의 애플리케이션 환경과 한 RDS 데이터베이스로 구성하고, 발표 또는 실제 운영에서 중단 허용 시간이 생기면 롤링과 블루·그린을 새 ADR에서 비교합니다.

### 핵심 근거

- **현재 가용성 요구 — 중단 배포 vs 무중단**: 외부 유료 사용자의 연속 서비스 수준 목표가 아직 없어 중단 비용을 측정할 근거가 없습니다.
- **인프라 비용 — 단일 환경 vs 블루·그린**: 사용하지 않는 두 번째 환경을 상시 유지하지 않아 MVP 예산을 데이터베이스와 핵심 서버에 집중할 수 있습니다.
- **변경 복잡도 — 한 버전 실행 vs 롤링 혼재**: 구버전과 신버전이 같은 스키마를 동시에 사용하는 호환 배포를 이번 일정에 설계하지 않아도 됩니다.
- **도입 시점 — 필요 기반 vs 선제 도입**: 실제 트래픽, 허용 중단 시간과 롤백 요구가 생기면 비용을 수치로 비교해 방식을 선택할 수 있습니다.

## 결과

- 배포 중 서비스가 잠시 중단됨을 검증 참여자에게 사전 안내해야 합니다.
- 배포 전 데이터베이스 백업과 실패 시 이전 애플리케이션 버전으로 되돌리는 절차는 중단 배포에서도 필요합니다.
- 무중단 배포가 필요해지면 인스턴스 비용뿐 아니라 Flyway의 하위 호환 마이그레이션과 세션 유지 방식까지 함께 결정해야 합니다.

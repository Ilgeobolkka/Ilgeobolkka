# 0019. 페이지를 열 때 잉크를 즉시 차감한다

- 상태: 승인됨
- 날짜: 2026-07-25

## 맥락

기존 6초 체류 기준은 실제 독서를 정확히 측정하지 못하면서 프론트엔드 타이머, 서버 경과 검증과 별도 확정 요청을 요구했습니다.
팀은 사용자가 요청한 페이지를 제공하는 시점을 명확한 이용 시작으로 정하고, 차감 결과를 페이지 표시 전에 알 수 있는 단순한 흐름이 필요하다고 판단했습니다.

## 고려한 대안

- 서버 기준 6초 뒤 차감 — 짧은 진입은 보호하지만 실제 읽기 여부를 보장하지 못하고 확정 요청과 실패 복구가 복잡합니다.
- 다음 페이지 이동 시 이전 페이지 차감 — 뷰어를 닫은 마지막 페이지의 차감 시점이 불명확하고 이전·다음 요청이 결제 의미까지 갖게 됩니다.
- 읽기 완료 버튼으로 차감 — 시점은 명시적이지만 페이지마다 독서 흐름을 끊고 누르지 않은 열람을 처리할 수 없습니다.
- 페이지 제공 전에 즉시 차감 — 우발적으로 연 페이지도 과금될 수 있지만 동의 화면과 잔액·만료일 표시로 규칙을 사전에 알릴 수 있고 요청과 과금 결과가 일치합니다.

## 결정

### 선택한 기술

유효한 페이지 대여가 없는 독자가 페이지를 열도록 요청하면, 백엔드는 페이지 콘텐츠를 제공하기 전에 1잉크를 즉시 차감합니다.
6초 타이머와 별도의 열람 확정 요청을 사용하지 않습니다.

### 핵심 근거

- **예측 가능성 — 즉시 차감 vs 6초 판정**: 즉시 차감은 성공 응답이 곧 대여 시작을 뜻합니다.
  6초 방식처럼 페이지는 보였지만 차감은 아직 되지 않은 중간 상태가 없습니다.
- **실패 처리 — 제공 전 차감 vs 다음 이동 시 차감**: 잉크 부족이나 서버 실패를 현재 페이지 제공 전에 확정할 수 있습니다.
  다음 이동 방식이 만드는 마지막 페이지와 앱 종료의 모호함이 없습니다.
- **구현 범위 — 한 요청 vs 타이머와 확정 요청**: 프론트엔드는 체류 시간을 판정하지 않고,
  백엔드는 한 트랜잭션 안에서 대여와 차감을 끝낼 수 있어 2026-08-04 MVP 일정에 적합합니다.
- **사용자 보호 — 사전 동의와 결과 표시**: 우발적 페이지 이동 위험은 도서별 최초 동의, 잉크 부족 차단, 성공 응답의 잔액·만료 시각 표시로 완화합니다.

## 결과

- 페이지 열기 API는 과금이 일어날 수 있는 명령이며 단순 콘텐츠 조회로 취급하지 않습니다.
- 페이지 콘텐츠는 차감과 대여 기록이 커밋된 뒤에만 제공합니다.
- 우발적으로 연 페이지도 대여가 시작될 수 있으므로 차감 정책을 최초 동의 화면에 명확히 표시해야 합니다.
- 이 결정은 6초 열람 확정을 정한 ADR-0001을 대체합니다.

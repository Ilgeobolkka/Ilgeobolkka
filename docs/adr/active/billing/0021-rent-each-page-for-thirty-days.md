# 0021. 각 페이지를 차감 시점부터 30일 동안 대여한다

- 상태: 승인됨
- 날짜: 2026-07-25

## 맥락

페이지를 한 번 차감한 뒤 영구히 읽게 하면 낮은 페이지 가격으로 소장 권한까지 제공하는 의미가 됩니다.
사용자가 다시 읽을 수 있는 기간은 명확해야 하고, 서로 다른 날에 연 페이지의 권리가 한꺼번에 끝나지 않도록 페이지별로 계산해야 합니다.

## 고려한 대안

- 한 번 차감한 페이지의 영구 재열람 — 구현은 단순하지만 이용권을 사실상 소장권으로 바꾸고 재대여 정책을 만들 수 없습니다.
- 도서를 처음 연 시점부터 책 전체에 공통 30일 — 만료일 표시는 단순하지만 나중에 처음 연 페이지의 실사용 기간이 짧아집니다.
- 달력 날짜 기준으로 30번째 날 자정 만료 — 설명은 익숙할 수 있지만 시작 시각에 따라 실제 이용 시간이 달라집니다.
- 각 페이지의 차감 성공 시각부터 정확히 30일 — 페이지마다 만료일이 달라지지만 사용자가 지불한 시점부터 같은 기간을 보장합니다.

## 결정

### 선택한 기술

각 페이지의 잉크 차감이 성공한 백엔드 서버 시각을 `startedAt`으로 저장하고 `expiresAt = startedAt + 30일`로 계산합니다.
서버 현재 시각이 `expiresAt`보다 이르면 추가 차감 없이 재열람하고, 같거나 늦으면 1잉크를 차감해 새 대여 기록을 만듭니다.

### 핵심 근거

- **권리 범위 — 페이지별 vs 도서별**: 과금 단위가 원본 PDF 한 페이지이므로 대여 기간도 같은 페이지 단위로 맞추는 것이 사용자가 받은 권리와 일치합니다.
- **기간 공정성 — 정확한 30일 vs 달력 날짜**: 시작 시각을 보존하면 어느 시간에 열어도 같은 기간을 제공합니다.
- **판정 일관성 — 서버 시간 vs 클라이언트 시간**: 기기 시각 조작과 시간대 차이에 영향을 받지 않고 동시 요청이 같은 기준 시각을 사용합니다.
- **재대여 감사 — 새 기록 vs 기존 만료일 덮어쓰기**: 재대여마다 별도 기록을 만들면 각 1잉크 차감과 대여 기간을 연결해 설명할 수 있습니다.

## 결과

- 한 도서 안에서도 페이지마다 만료 시각이 다르므로 프론트엔드는 페이지별 만료 시각을 표시해야 합니다.
- 대여 이력이 계속 쌓이며 보존·조회 인덱스를 데이터 모델에서 고려해야 합니다.
- 사용하지 않은 잉크의 유효기간은 이 결정과 별도이며 아직 정하지 않았습니다.
- 페이지를 소장으로 전환하는 정책은 별도 결정 전까지 제공하지 않습니다.

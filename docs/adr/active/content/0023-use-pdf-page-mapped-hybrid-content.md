# 0023. 원본 PDF 페이지에 대응하는 혼합 콘텐츠를 제공한다

- 상태: 승인됨
- 날짜: 2026-07-25

## 맥락

모든 페이지를 이미지로 제공하면 원본 배치는 보존되지만 모바일에서 작은 글자를 읽기 어렵고 검색·접근성 개선도 제한됩니다.
반대로 모든 내용을 텍스트로 추출하면 표, 수식, 삽화와 복잡한 배치가 깨질 수 있으며 화면 리플로우가 원본 PDF 페이지라는 과금 단위를 바꾸어서는 안 됩니다.

## 고려한 대안

- 원본 PDF 전체 제공 — 구현은 단순하지만 전체 파일 다운로드와 권한 없는 페이지 접근을 막기 어렵습니다.
- 모든 페이지 이미지 — 배치 충실도는 높지만 작은 글자의 모바일 가독성, 접근성과 전송량에 불리합니다.
- 모든 페이지 텍스트 추출 — 반응형 표시는 쉽지만 표·수식·삽화와 읽기 순서를 신뢰성 있게 보존하기 어렵습니다.
- 원본 페이지별 텍스트·이미지 혼합 — 변환과 렌더링 유형은 늘지만 페이지 경계와 콘텐츠 특성을 함께 보존할 수 있습니다.

## 결정

### 선택한 기술

원본 PDF를 브라우저에 직접 제공하지 않고 각 원본 페이지를 하나의 `BookPage`로 변환합니다.
일반 본문은 텍스트, 구조 보존이 필요한 표·수식·삽화는 이미지, 추출이 어렵거나 배치 자체가 중요한 페이지는 전체 페이지 이미지로 저장합니다.
한 페이지에 두 방식이 필요하면 혼합 콘텐츠로 저장하며, 권한을 확인한 뒤 요청한 `BookPage` 하나만 제공합니다.

### 핵심 근거

- **과금 경계 — 원본 페이지 매핑 vs 화면 리플로우**:
  텍스트가 화면에서 여러 영역으로 나뉘어도 모두 같은 원본 페이지 번호에 속하게 하여 글자 크기가 잉크 사용량을 바꾸지 않습니다.
- **표현 정확도 — 혼합 방식 vs 텍스트 전용**:
  문단은 반응형 텍스트의 장점을 얻고 구조가 깨지는 부분만 이미지로 보존할 수 있습니다.
- **가독성과 전송량 — 선택적 이미지 vs 전체 이미지**:
  모든 페이지를 래스터 이미지로 보내지 않아 일반 본문의 확대·접근성 개선 여지를 남깁니다.
- **접근 통제 — 페이지 단위 제공 vs 원본 PDF 제공**:
  백엔드가 대여를 확인하기 전에는 페이지 콘텐츠 경로를 노출하지 않으며 한 번의 요청으로 전체 책을 받는 계약을 만들지 않습니다.

## 결과

- 변환 파이프라인과 뷰어가 `TEXT`, `IMAGE`, `HYBRID` 유형을 처리해야 합니다.
- 원본 PDF 페이지 수와 `BookPage` 수·번호를 적재 게이트에서 검증해야 합니다.
- 개별 이미지 저장과 화면 캡처는 완전히 막지 않으며 DRM은 MVP 범위가 아닙니다.
- 이 결정은 모든 페이지를 이미지로 제공한 ADR-0002를 대체합니다.

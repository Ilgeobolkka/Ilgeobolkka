# 0025. 잉크·페이지 대여·변환 콘텐츠를 별도 엔티티로 모델링한다

- 상태: 승인됨
- 날짜: 2026-07-25

## 맥락

기존 모델의 `ConfirmedPage`는 사용자·도서·페이지를 유일하게 만들어 영구 최초 1회 차감만 표현했고, 페이지 자산은 정적 이미지 경로로 계산했습니다.
새 정책은 같은 페이지의 여러 재대여 이력, 각 대여의 만료 시각, 잉크 내역과 텍스트·이미지 혼합 페이지를 저장해야 합니다.

## 고려한 대안

- 기존 `ConfirmedPage`의 시각만 갱신 — 컬럼 변경은 적지만 과거 재대여와 차감의 연결을 잃고 “최초 1회” 고유 제약의 의미가 달라집니다.
- 현재 대여 한 행과 별도 이력 없음 — 유효성 조회는 단순하지만 사용자가 어떤 차감으로 어떤 기간을 얻었는지 사후 설명할 수 없습니다.
- 잉크 내역만 두고 대여 만료 시각을 계산 — 차감 이력은 남지만 지급 내역과 페이지 차감을 구분해 최신 유효 대여를 조회하는 책임이 원장에 섞입니다.
- `InkAccount`, `InkLedger`, `PageRental`, `BookPage` 분리 — 엔티티는 늘지만 잔액, 변경 불가능한 내역, 기간 권리와 변환 콘텐츠의 책임이 분명합니다.

## 결정

### 선택한 기술

현재 목표 스키마는 [`docs/data/erd.md`](../../../data/erd.md)를 정본으로 사용합니다.

- `InkAccount`는 독자별 현재 잔액과 잠금 대상을 가집니다.
- `InkLedger`는 잉크 지급·차감과 차감 후 잔액을 변경 없이 보존합니다.
- `PageRental`은 차감 내역 하나와 시작·만료 시각을 연결하며 재대여마다 새 행을 만듭니다.
- `BookPage`는 원본 PDF 페이지 번호와 `TEXT`, `IMAGE`, `HYBRID` 콘텐츠를 연결합니다.
- `Book`은 카테고리, 원본 PDF 내부 경로와 원본 기준 전체 페이지 수를 가집니다.
- `ReadingSession`, `ReadingConsent`, `LibraryEntry`는 단일 세션, 최초 동의와 마지막 열람 위치를 각각 관리합니다.

### 핵심 근거

- **재대여 이력 — 여러 `PageRental` 행 vs 기존 고유 `ConfirmedPage`**: 재대여마다 시작·만료와 차감 내역을 잃지 않고 보존할 수 있습니다.
- **잔액 동시성 — `InkAccount` 저장 잔액 vs 원장 합계 매번 계산**: 한 계정 행을 잠가 서로 다른 페이지의 동시 차감을 직렬화하고, 원장 합계는 불변식 검증에 사용합니다.
- **책임 분리 — 대여와 원장 분리 vs 원장 단독**: 대여 유효성 조회가 지급 내역까지 섞인 원장을 해석하지 않고 기간 권리 자체를 조회합니다.
- **페이지 변환 — `BookPage` 엔티티 vs 정적 이미지 경로**: 콘텐츠 유형과 텍스트를 저장하면서 원본 페이지 번호의 유일성과 전체 페이지 수 일치를 데이터로 검증할 수 있습니다.
- **미결정 정책 — 잉크 묶음 미도입 vs 선제적 `InkLot`**: 사용하지 않은 잉크의 유효기간과 차감 순서가 정해지지 않았으므로 만료 묶음 모델을 미리 만들지 않습니다.

## 결과

- 기존 V1 마이그레이션과 스키마 테스트는 이 목표 모델과 다르며 후속 구현 작업에서 새 마이그레이션과 테스트로 갱신해야 합니다.
- `PageRental`의 활성 상태는 별도 상태값이 아니라 서버 현재 시각과 `expiresAt` 비교로 판단합니다.
- 재대여 이력 증가에 대비해 `(reader_id, book_id, page_number, expires_at)` 조회 인덱스가 필요합니다.
- 이 결정은 영구 확정 페이지와 이미지 경로 계산을 정한 ADR-0007을 대체합니다.

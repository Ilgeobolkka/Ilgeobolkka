# 0004. same-origin JSON API 경계를 유지한다

- 상태: 승인됨
- 날짜: 2026-07-26

## 맥락

Thymeleaf 화면과 브라우저 JavaScript가 같은 Spring Boot 실행물에서 도메인 유스케이스를 사용합니다.
화면 구현이 Controller 내부 규칙이나 저장소 위치에 의존하지 않도록 JSON API, 오류와 페이지 콘텐츠
전달 경계를 안정적으로 정의해야 합니다. 현재 경로·필드 자체는 별도 API 명세에서 한 곳만 관리합니다.

## 고려한 대안

- 화면 Controller가 도메인 객체를 직접 렌더링하고 JSON API를 두지 않음 — 동적 뷰어와 오류 처리가 화면 구현에 결합되어 제외합니다.
- 모든 성공 응답을 공통 래퍼로 감쌈 — 형식은 통일되지만 현재 클라이언트에 불필요한 계층이 생겨 제외합니다.
- 클라이언트가 페이지 크기와 임의 정렬을 지정 — 유연하지만 입력·성능 계약이 넓어져 제외합니다.
- 저장소 URL을 페이지 응답에 포함 — 전송은 단순하지만 권한 검증과 비공개 저장소 경계를 우회해 제외합니다.

## 결정

- 브라우저가 호출하는 JSON API는 same-origin Spring Boot 실행물의 `/api/**` 아래에 둡니다.
- 외부 인바운드 요청은 PortOne V2 웹훅 한 경로만 허용하고, 브라우저 세션·CSRF 대신 웹훅 서명과 서버
  재조회로 검증합니다. 결제 경계는 [ADR-0012](../platform/0012-use-portone-v2-test-payments.md)를 따릅니다.
- HTML Controller와 REST Controller는 같은 Facade를 호출하며 서로를 HTTP로 호출하지 않습니다.
- 성공 응답은 엔드포인트별 DTO를 최상위 JSON 바디로 반환합니다.
- 오류는 명시적인 `code`와 사용자 공개용 `message`를 가진 공통 바디로 반환합니다.
- 인증 독자는 요청 값이 아니라 서버 세션의 `Principal`에서 식별합니다.
- 목록 크기와 기본 정렬은 서버가 고정하고 안정적인 동률 정렬을 포함합니다.
- 페이지 상태 변경과 콘텐츠 바이트 전달을 분리해 콘텐츠 요청마다 현재 권한을 다시 검증합니다.
- 현재 경로·요청·응답·상태 코드의 정본은 [API 계약](../../api-spec.md)입니다.

## 결과

- Thymeleaf 화면과 브라우저 JavaScript가 같은 도메인 계약을 공유할 수 있습니다.
- 저장소 구조와 예외 클래스 이름을 바꿔도 공개 API를 독립적으로 유지할 수 있습니다.
- API 계약을 바꾸면 화면 JavaScript와 회귀 테스트를 함께 변경해야 합니다.
- 외부 클라이언트나 별도 프런트엔드가 생기면 버전 관리와 CORS 경계를 다시 결정해야 합니다.

# 0014. OpenAI와 MySQL로 AI 잉크 경로를 구현한다

- 상태: 승인됨
- 날짜: 2026-08-05

## 맥락

AI 잉크 경로는 독서 목적에 맞는 페이지 후보를 찾고 선수 개념·중복·순서를 고려한 구조화 경로를 만들어야
합니다. 이 기능은 별도 AI 플랫폼이 아니라 기존 Spring Boot·MySQL 단일 실행물에 추가하는 2차 MVP이며,
지원 범위는 [AI 경로 콘텐츠 코퍼스](../../ai-route-content-corpus.md)의 한 권 단위 페이지 집합입니다.

목적과 페이지 분석 텍스트의 의미 유사도 계산에는 임베딩이 필요하고, 후보를 경로로 구성할 때는 구조화된
모델 출력이 유용합니다. 하지만 모델 출력은 신뢰 경계 밖에 있으므로 도서·콘텐츠 버전·검색 후보·선수 관계·
예산을 서버가 다시 검증해야 합니다. 콘텐츠 외부 전송 권리와 공급자 데이터 보관 조건도 지원 활성화 전에
확인해야 합니다.

현재 규모에서는 한 요청이 한 권의 페이지 벡터만 비교합니다. 별도 벡터 검색 인프라, 런타임 승인 제어면,
격리 평가 데이터베이스와 독립 holdout 운영은 구현·운영 비용이 사용자 경로 생성·저장·열람 흐름의 가치보다
큽니다. 다만 OpenAI 공급자와 임베딩 표현을 바꾸면 전체 벡터 재생성, 품질 회귀와 연동 코드 전환이 필요하므로
기술 결정으로 기록합니다.

## 고려한 대안

- 규칙 기반 키워드 검색만 사용 — 외부 전송과 모델 비용은 없지만 목적의 의미 유사도와 경로 역할·순서 구성이
  약해 제품 가설을 검증하기 어려워 제외합니다.
- OpenAI와 별도 벡터 데이터베이스 사용 — 대규모 근사 검색에는 적합하지만 현재 한 권 단위 규모에 새로운
  인프라·운영 경계를 추가하므로 제외합니다.
- OpenAI와 기존 MySQL 사용 — 현재 실행물 안에서 임베딩 보존, 정확 비교와 구조화 경로 생성을 구현할 수 있어
  선택합니다.
- 별도 평가 DB·독립 holdout·런타임 승인 해시·주기적 원격 증명을 함께 도입 — 감사 가능성은 높지만 2차 MVP에
  과한 제어면이므로 제외합니다.

## 결정

- OpenAI 연동은 애플리케이션 인터페이스 뒤에 격리하고 페이지·목적 임베딩과 Responses API의 구조화된
  출력을 사용합니다.
- 기본 임베딩 모델은 `text-embedding-3-small`, 기본 경로 모델은 `gpt-5.6-terra`입니다. 콘텐츠 버전에
  임베딩 모델과 차원을 묶고 다른 프로필의 벡터를 비교하지 않습니다.
- 페이지 임베딩은 기존 MySQL에 저장하고 한 권의 후보 벡터는 애플리케이션 메모리에서 정확 비교합니다.
  별도 벡터 데이터베이스를 도입하지 않습니다.
- 모델 출력은 검색 후보와 검증된 선수 페이지 집합 안의 구조화된 값만 허용합니다. 서버가 도서·콘텐츠 버전·
  페이지·순서·선수 관계·예산을 검증하며 구체적인 생성 정책은
  [AI 잉크 경로 PRD](../../prd/ai-ink-route.md#경로-생성-정책)를 따릅니다.
- OpenAI 요청은 응답 상태 저장을 요청하지 않고, 외부 전송 권리와 적용 데이터 보관 조건을 확인한 콘텐츠만
  지원합니다. 현재 근거와 재확인 조건은
  [OpenAI 데이터 정책 프로필](../../evidence/openai-data-policy/README.md)을 따릅니다.
- 콘텐츠 적재·평가·일반 생성은 같은 전용 OpenAI 프로젝트를 사용합니다. 비용 보호와 런타임 설정은
  [배포 가이드](../../deployment.md#openai-데이터비용-제어), 계정별 제품 한도는
  [PRD](../../prd/ai-ink-route.md#생성-횟수와-실패)에서 관리합니다.
- 품질 평가는 저장소에서 버전 관리하는 대표 목적을 같은 애플리케이션의 비웹 경로로 실행합니다. 별도 평가
  DB, 독립 holdout 폐기 절차, 다중 승인 해시와 평가 JAR 바이트 고정은 사용하지 않습니다. 재평가 조건과
  출시 수치는 [PRD의 품질과 출시 기준](../../prd/ai-ink-route.md#품질과-출시-기준)을 따릅니다.

## 결과

- 기존 Spring Boot·MySQL 경계 안에서 후보 검색, 경로 생성과 저장을 구현하고 검증할 수 있습니다.
- 모델 출력 검증, 콘텐츠 권리 확인, 최소 데이터 전송과 기본 비용 보호를 유지하면서 별도 AI 인프라와 승인
  제어면을 운영하지 않습니다.
- 평가 데이터가 개발자에게 보이므로 결과는 독립적인 통계 추정이 아니라 MVP 품질 회귀 기준으로만
  해석합니다.
- 콘텐츠 규모가 한 권 단위 정확 비교의 비용을 넘거나 다중 인스턴스 비용 공격·규제 감사 요구가 관측되면
  별도 벡터 검색, 전역 실행 제어와 독립 평가를 새 결정으로 검토합니다.
- 공급자·임베딩 모델·벡터 저장 구조를 되돌리거나 바꾸려면 연동 코드 전환, 전체 임베딩 재생성, 데이터
  migration과 품질 회귀가 필요합니다.

# 0015. AI 잉크 경로의 신뢰·비용·평가 경계를 강화한다

- 상태: 승인됨
- 날짜: 2026-08-05

## 맥락

이 결정은 [ADR-0014](./0014-use-openai-and-mysql-for-ai-route-generation.md)를 대체합니다. OpenAI와
MySQL을 사용하고 평가한 실행물·생성 설정·공개 승인값을 결합하는 기존 구조는 유지하지만, 구현 전
리뷰에서 모델 출력 신뢰, 서비스 전체 비용, 멱등 결과와 출시 평가의 경계를 더 닫아야 했습니다.

구조화된 모델 출력이 같은 도서와 콘텐츠 버전에 존재하는지만 확인하면, 검색하지 않은 유효 페이지도
추천에 포함될 수 있습니다. 모델은 신뢰 경계 밖에 있으므로 서버가 실제 요청에 제공한 후보와 검증된 선수
관계에서 계산한 페이지 집합으로 출력 범위를 제한해야 합니다.

계정별 생성 한도만으로는 공개 회원가입에서 여러 계정을 사용한 서비스 전체 비용을 제한할 수 없습니다.
프로세스별 카운터도 재시작과 수평 확장으로 초기화됩니다. 공급자의 월간 비용 차단선은 필요하지만 적용
전파 중 소액을 초과할 수 있으므로, 모든 애플리케이션 인스턴스가 공유하는 데이터베이스 기반 실행 한도도
필요합니다. 구체적인 한도와 제품 오류는
[AI 잉크 경로 PRD](../../prd/ai-ink-route.md#생성-횟수와-실패), 운영 증거는
[배포 가이드](../../deployment.md#openai-데이터비용-제어)에서 관리하고, 구현 시 HTTP 응답은
[API 계약](../../api-spec.md)에 반영합니다.

경로를 만들 수 없다는 정상 결과를 현재 권한으로 매번 다시 계산하면, 대여나 소장 상태가 바뀐 뒤 같은
멱등 요청의 응답이 달라집니다. 최초 결과를 스냅샷으로 보존해야 하며, 구체적인 상태·보존 기간은
[저장과 생명주기](../../prd/ai-ink-route.md#저장과-생명주기)에서 관리하고 구현 데이터 구조는
[ERD](../../erd.md)에 반영합니다.

같은 평가 목적을 프롬프트·후보 정책 조정과 출시 판정에 반복 사용하면 평가셋에 맞춘 조정이 일어날 수
있습니다. 개발·회귀 데이터와 출시용 미관측 holdout을 분리하고, 실행물·생성 설정·콘텐츠 출처·평가 계약과
holdout의 정체성을 접근 전에 함께 봉인해야 합니다. 구체적인 데이터 규모·배정·지표·실행 절차는
[AI 경로 콘텐츠 코퍼스](../../ai-route-content-corpus.md#잠금-holdout-품질-평가-조건),
[품질과 출시 기준](../../prd/ai-ink-route.md#품질과-출시-기준)과
[테스트 전략](../../test-strategy.md#8-변환과-ai-경로-품질-확인)에서 관리합니다.

공급자 요청의 처리 티어를 암묵값에 맡기면 같은 생성 설정으로 기록한 평가와 공개 요청이 서로 다른 처리
조건을 사용할 수 있습니다. 출시 지연 증거를 재사용하려면 요청한 처리 티어와 실제 응답 티어를 모두
고정하고 검증해야 합니다. 현재 공급자 계약은
[OpenAI Responses API](https://developers.openai.com/api/reference/resources/responses/methods/create)를
따릅니다.

## 고려한 대안

- 같은 도서·콘텐츠 버전 존재 여부만 출력 검증 — 구현은 단순하지만 모델이 검색 경계를 벗어난 페이지를
  선택할 수 있어 제외합니다.
- 계정별 한도만 유지 — 정상 사용자 간 격리는 되지만 다계정 사용과 재시작·다중 인스턴스에서 서비스 전체
  비용을 제한하지 못해 제외합니다.
- 공급자 비용 차단선만 사용 — 월간 누적 비용은 제한하지만 전파 지연과 일일 서비스 보호를 해결하지 못해
  제외합니다.
- 애플리케이션 전역 한도만 사용 — 일일 실행 수는 제한하지만 월간 누적 비용에 대한 독립 차단선이 없어
  제외합니다.
- 경로 생성 불가 결과를 현재 권한으로 재계산 — 저장은 단순하지만 같은 멱등 요청의 응답이 달라져
  제외합니다.
- 개발 데이터와 출시 평가 데이터를 함께 사용 — 운영은 단순하지만 반복 조정에 의한 평가 과적합을 막을 수
  없어 제외합니다.
- 실행물과 생성 설정만 고정하고 평가 — 콘텐츠 출처나 평가 계약을 결과에 맞춰 바꾼 뒤 같은 holdout을
  재사용할 수 있어 제외합니다.
- 공급자 처리 티어를 암묵값에 맡김 — 프로젝트 설정에 따라 평가와 공개 요청의 실제 처리 조건이 달라질 수
  있어 제외합니다.

## 결정

- ADR-0014에서 정한 OpenAI 공급자, 기본 임베딩·경로 모델, MySQL 벡터 저장, 데이터 제어, 전용 프로젝트와
  격리 평가 데이터베이스 구조는 이 결정에서 명시적으로 강화한 부분을 제외하고 유지합니다.
- 모델 출력의 허용 범위는 목적 검색 후보와 같은 도서·콘텐츠 버전의 검증된 선수 관계에서 서버가 계산한
  페이지 집합으로 제한합니다. 허용 범위 밖 출력은 같은 책의 유효 페이지라도 실패 폐쇄합니다. 현재 출력·
  경로 검증 계약은 [경로 생성 정책](../../prd/ai-ink-route.md#경로-생성-정책)을 따릅니다.
- 계정별 보호와 별도로 모든 공개 애플리케이션 인스턴스가 공유하는 데이터베이스 기반 외부 실행 한도를
  두고, 같은 전용 OpenAI 프로젝트에 공급자 월간 비용 차단선을 함께 적용합니다. 한도 소비·복구와 제품 오류의
  현재 계약은 PRD에, 구현 HTTP 응답은 API 계약에, 설정·변경·증거 절차는 배포 가이드에 둡니다.
- 정상적인 경로 생성 불가 결과도 최초 응답을 스냅샷으로 보존해 같은 멱등 요청에 재현합니다. 상태 전이의
  현재 계약은 PRD에서 관리하고 구현 저장 필드는 ERD에 반영합니다.
- 개발·회귀 데이터와 출시 판정용 미관측 holdout을 분리합니다. holdout을 열기 전에 평가 실행물, 생성 설정,
  콘텐츠 출처, 평가 계약과 holdout 정체성을 함께 봉인하고, 관측 뒤 이 경계 중 하나라도 바꾸면 새 미관측
  holdout으로 다시 평가합니다. 데이터 규모·품질 임계값·배정·판정 절차는 콘텐츠 코퍼스와 테스트 전략에서
  관리합니다.
- 평가와 공개 요청은 명시적으로 같은 공급자 처리 티어를 사용하고 실제 응답 티어도 일치하는지 검증합니다.
  생성 설정이나 공개 배포 조건이 달라지면 기존 품질·지연 증거를 재사용하지 않습니다. 현재 제품 조건과
  운영 절차는 PRD·배포 가이드에서 관리하고 구현 HTTP 응답은 API 계약에 반영합니다.

## 결과

- 모델이 같은 책에 존재하지만 검색하지 않은 페이지를 추천 경로에 넣을 수 없습니다.
- 여러 계정, 재시작과 다중 인스턴스에서도 애플리케이션 실행 한도를 공유하고, 공급자 월간 비용 차단선으로
  독립적인 누적 비용 경계를 둡니다. 대신 데이터베이스 카운터와 운영 증거를 관리해야 합니다.
- 경로 생성 불가 결과도 멱등하게 재현되지만, 보존 기간 동안 결과 스냅샷을 함께 관리해야 합니다.
- 개발·회귀 데이터와 잠금 holdout을 별도로 제작하고 평가 경계를 봉인해야 하므로 운영 비용이 늘어납니다.
  대신 프롬프트·후보 정책과 출시 지표가 같은 데이터에 과적합되는 위험을 줄입니다.
- 평가와 공개 요청의 처리 조건이 달라지면 기존 지연 증거를 재사용할 수 없어 배포 자유도가 줄어듭니다.
- 되돌리려면 공유 실행 한도와 멱등 스냅샷의 데이터 구조, 공급자 비용 차단선, 평가 데이터 거버넌스와 공개
  승인 절차를 함께 마이그레이션해야 합니다.

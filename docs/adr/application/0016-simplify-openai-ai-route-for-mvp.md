# 0016. 구현 우선 AI 잉크 경로를 선택한다

- 상태: 승인됨
- 날짜: 2026-08-05

## 맥락

이 결정은 [ADR-0015](./0015-harden-openai-ai-route-generation.md)를 대체합니다. AI 잉크 경로는 별도 AI
플랫폼을 운영하는 제품이 아니라 기존 Spring Boot·MySQL 애플리케이션에 추가하는 2차 MVP 기능입니다.
시연 범위는 비소설 90권이고, 목표는 설계 통제 장치를 전시하는 것이 아니라 사용자가 경로를 생성하고 저장해
실제로 읽을 수 있는 흐름을 완성하는 것입니다.

ADR-0015는 실행 JAR·생성 설정·평가 출처·공급자 정책의 다중 해시, 1시간 원격 증명, 별도 평가 DB,
잠금 holdout, 애플리케이션 전역 실행 한도와 공급자 처리 티어 고정을 결합했습니다. 이 구조는 강한 감사
가능성을 제공하지만 구현·운영 경계를 크게 늘리고, 현재 규모에서 검증하려는 사용자 가치보다 비용이 큽니다.

모델 출력은 신뢰할 수 없고 외부 전송 권리와 데이터 보관 조건은 확인해야 합니다. 이 두 경계는 유지하되,
런타임 승인 제어면과 별도 평가 인프라 없이 기존 애플리케이션과 일반 배포·테스트 절차에서 검증할 수 있어야
합니다.

## 고려한 대안

- ADR-0015의 강화 구조 유지 — 감사 경계는 가장 강하지만 2차 MVP 구현·운영 비용이 기능 가치보다 커
  제외합니다.
- 모델 출력을 그대로 저장하고 공급자 기본 설정만 사용 — 구현은 가장 작지만 검색 범위·예산·콘텐츠 권리를
  서버가 보장하지 못해 제외합니다.
- 기존 Spring Boot·MySQL 안에서 필수 경계만 구현 — 새 인프라 없이 출력 검증·권리 확인·기본 비용 보호를
  제공할 수 있어 선택합니다.

## 결정

- OpenAI 연동은 애플리케이션 인터페이스 뒤에 격리하고, 페이지·목적 임베딩과 구조화된 Responses API 출력을
  사용합니다.
- 페이지 분석과 독서 목적 임베딩의 기본 모델은 `text-embedding-3-small`이며, 콘텐츠 버전에 모델과 차원을
  함께 묶어 다른 프로필의 벡터를 비교하지 않습니다.
- 경로 구성의 기본 모델은 `gpt-5.6-terra`이며 `/v1/responses`의 구조화된 출력을 사용합니다.
- 한 권의 최대 72개 페이지 벡터는 기존 MySQL에서 읽어 애플리케이션 메모리에서 정확 비교합니다. 별도 벡터
  데이터베이스를 도입하지 않습니다.
- 모델 출력은 검색 후보와 검증된 선수 페이지 집합 안의 구조화된 값만 허용하며, 서버가 도서·페이지·순서·
  예산을 다시 검증합니다.
- OpenAI 요청은 `store=false`를 사용하고 외부 전송 권리와 데이터 보관 조건을 확인한 콘텐츠만 지원합니다.
  확인한 공급자 정책과 사용자 안내 근거는
  [OpenAI API 데이터 보관 정책 확인 근거](../../evidence/openai-data-policy/2026-08-05.md)에 날짜와 출처를
  남기고 출시 전 다시 확인합니다.
- 비용 보호는 계정별 일일 생성 횟수와 전용 OpenAI 프로젝트의 월간 지출 한도로 제한합니다. 별도
  애플리케이션 전역 카운터와 런타임 승인값을 만들지 않습니다.
- 평가 데이터는 Git에서 버전 관리하는 도서별 대표 목적 90개로 구성하고 같은 애플리케이션의 비웹 평가로
  실행합니다. 별도 평가 DB, 미관측 holdout 폐기 절차, 다중 승인 해시와 평가 JAR 바이트 고정은 사용하지
  않습니다.
- 모델·프롬프트·후보 정책을 바꾸면 대표 목적 90개를 다시 평가합니다. 일반 코드 변경이나 공급자 처리 티어
  차이만으로 기존 평가를 무효화하지 않습니다.

## 결과

- AI 경로를 기존 단일 실행물과 MySQL 안에서 구현하고 검증할 수 있습니다.
- 모델 출력 검증, 콘텐츠 권리, 사용자 데이터 최소 전송과 비용 상한은 유지합니다.
- 별도 정책 증명 작업, 평가 DB 수명주기, 전역 실행 카운터와 승인 해시를 구현·운영하지 않습니다.
- 평가 데이터가 개발자에게 보이므로 독립적인 통계적 출시 추정치가 아니라 MVP 품질 회귀 기준으로만
  해석합니다.
- 더 큰 콘텐츠 규모, 다중 인스턴스 비용 공격 또는 규제 감사 요구가 생기면 관측된 문제를 근거로 별도
  제어면과 독립 평가를 새 ADR에서 검토합니다.

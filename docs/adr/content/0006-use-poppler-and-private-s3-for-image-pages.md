# 0006. 이미지 페이지는 Poppler로 사전 변환하고 비공개 S3에 저장한다

- 상태: 승인됨
- 날짜: 2026-07-23

## 맥락

원본 배치를 보존해야 하는 페이지는 이미지 콘텐츠가 필요하지만 요청 시점에 PDF를 렌더링하면 지연과
자원 사용이 커집니다. 운영 인스턴스의 로컬 디스크는 배포 교체와 수평 확장에서 지속성을 보장하지
못하며, 공개 저장소 URL은 페이지 권한 검증을 우회할 수 있습니다.

## 고려한 대안

- Java PDF 라이브러리로 요청 중 변환 — 애플리케이션 코드 안에서 처리할 수 있지만 요청 지연과 런타임 자원 사용이 커 제외합니다.
- ImageMagick과 Ghostscript — 다양한 형식을 지원하지만 현재 PDF 래스터 변환에 필요한 도구 조합과 설정이 늘어 제외합니다.
- 운영 서버 로컬 디스크 — 단일 인스턴스에서는 단순하지만 교체·확장 시 파일 지속성을 보장하지 못해 제외합니다.
- 공개 S3 또는 장기 사전 서명 URL — 전송은 단순하지만 현재 독자·세션·페이지 권한을 매 요청 검증할 수 없어 제외합니다.
- Poppler 사전 변환과 비공개 S3 — 변환을 배포 전에 검증하고 저장소를 애플리케이션 권한 경계 뒤에 둘 수 있어 선택합니다.

## 결정

- `IMAGE` 페이지는 Poppler `pdftoppm`을 사용하는 사전 배치에서 변환합니다.
- 표지는 원본 PDF 페이지와 분리된 공개 메타데이터 자산으로 관리합니다.
- 로컬은 Git에서 제외된 파일시스템, 운영은 Block Public Access와 암호화를 적용한 전용 비공개 S3 버킷을 사용합니다.
- 브라우저에는 S3 버킷·객체 키와 원본 PDF 경로를 제공하지 않습니다.
- 변환 형식·품질 기준과 검증 증거는 [콘텐츠 변환과 품질 검증](../../content-conversion.md)에서 관리합니다.
- 페이지별 `TEXT`·`IMAGE` 선택과 전달 경계는 [ADR-0011](./0011-align-page-content-with-source-pdf.md)를 따릅니다.

## 결과

- 운영 인스턴스를 교체하거나 여러 대로 늘려도 이미지 자산이 유지됩니다.
- 요청 경로에서 PDF 렌더링 비용을 제거하고 배포 전에 변환 실패를 찾을 수 있습니다.
- 애플리케이션이 이미지 전송 대역폭과 S3 장애 처리를 부담합니다.
- 변환 도구나 저장소를 바꾸면 전체 이미지 재생성과 배포 경로 검증이 필요합니다.

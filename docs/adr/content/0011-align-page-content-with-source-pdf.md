# 0011. 원본 PDF 페이지와 연결한 텍스트·이미지 콘텐츠를 제공한다

- 상태: 대체됨 ([ADR-0013](./0013-define-page-content-and-public-ai-fixture-boundary.md))
- 날짜: 2026-07-26

## 맥락

화면 크기와 표시 방식이 바뀌어도 대여·접근 권한의 페이지 단위는 원본 PDF와 일치해야 합니다. 모든
페이지를 이미지로 만들면 텍스트 접근성과 표시 유연성을 잃고, 모든 페이지를 텍스트로 추출하면 표·수식·
삽화와 복잡한 배치가 깨질 수 있습니다. 원본 파일과 내부 저장소를 노출하지 않고 권한이 있는 현재
페이지 하나만 제공해야 합니다.

## 고려한 대안

- 원본 PDF 전체를 브라우저에 제공 — 다운로드와 페이지 권한 우회를 막을 수 없어 제외합니다.
- 모든 페이지를 이미지로 제공 — 배치 충실도는 높지만 텍스트 접근성과 표시 유연성을 잃어 제외합니다.
- 모든 페이지를 텍스트로 추출 — 표·수식·삽화와 원본 배치를 보존할 수 없어 제외합니다.
- 페이지 내부에서 텍스트·이미지 블록을 조합 — 품질은 높지만 변환·편집 모델이 커져 초기 MVP에서 제외합니다.
- 페이지별 `TEXT` 또는 `IMAGE` — 원본 페이지 단위를 유지하면서 콘텐츠 특성에 맞게 제공할 수 있어 선택합니다.

## 결정

- `Book.totalPageCount`와 `BookPage` 수는 원본 PDF 페이지 수와 같아야 합니다.
- 각 `BookPage`는 같은 번호의 원본 PDF 페이지와 일대일로 연결합니다.
- 일반 본문은 `TEXT`, 원본 배치 보존이 필요한 페이지는 전체 페이지 `IMAGE`로 저장합니다.
- 초기 MVP에서 한 페이지의 형식은 `TEXT` 또는 `IMAGE` 중 하나입니다.
- 원본 PDF와 이미지 저장소는 비공개로 유지합니다.
- 콘텐츠 Controller는 로그인 세션, 현재 `ReadingSession`과 온라인 소장 또는 활성 대여 권한을 확인합니다.
- 한 요청에는 현재 페이지 콘텐츠 하나만 반환하고 내부 경로를 노출하지 않습니다.
- 개인 열람 콘텐츠에는 `Cache-Control: private, no-store`를 적용합니다.
- 변환·품질 절차는 [콘텐츠 변환과 품질 검증](../../content-conversion.md), HTTP 형식은
  [API 계약](../../api-spec.md)을 따릅니다.

## 결과

- 화면 표시가 바뀌어도 원본 PDF 페이지 번호가 안정된 권한 단위로 남습니다.
- 일반 본문은 텍스트 접근성을 얻고 복잡한 페이지는 원본 배치를 이미지로 보존합니다.
- 변환 파이프라인이 페이지별 형식 판정과 텍스트 읽기 순서 검증을 부담합니다.
- 페이지 내부 혼합 콘텐츠, OCR 보정 편집과 더 강한 DRM은 별도 기술 결정이 필요합니다.

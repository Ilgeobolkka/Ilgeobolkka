# 0015. Poppler는 산출물 동일성을 확인한 버전 집합으로 허용한다

- 상태: 승인됨
- 날짜: 2026-08-13

## 맥락

[ADR-0006](./0006-use-poppler-and-private-s3-for-image-pages.md)이 이미지 페이지를 Poppler 사전 배치로
변환하기로 정한 뒤, 변환기는 실행 파일 버전을 정확히 한 값과 비교해 다르면 거부해 왔습니다. 같은
PDF에서 같은 바이트가 나오는 것이 콘텐츠 배치 식별자와 결정적 결과 manifest의 전제이기 때문입니다.

이 단일 값 고정이 배포판 시차와 부딪혔습니다. 개발 로컬은 Homebrew에서 Poppler를 받는데 그쪽 최신은
26.08.0이고, CI는 conda-forge에서 받는데 그쪽 최신은 26.07.0입니다. 기준을 26.08.0으로 올리자 CI가
설치할 수 있는 버전이 없어 실제로 Poppler를 쓰는 변환·적재 검증 두 건이 CI에서만 실패했습니다.
기준을 26.05.0으로 되돌리면 반대로 로컬에서 변환 배치를 돌릴 수 없습니다. 어느 한 값을 고르든 로컬과
CI가 동시에 만족할 수 없는 상태입니다.

한편 26.05.0과 26.08.0이 같은 산출물을 낸다는 것은 이미 확인돼 있습니다. 같은 표본의 JPEG·PNG 바이트
수와 픽셀 크기가 같았고, 26.05.0으로 만들어 둔 배치의 이미지 100장도 전부 바이트 단위로 동일했습니다.
즉 결정성이라는 목적은 두 버전 모두에서 이미 성립합니다. 막고 있던 것은 목적이 아니라 "값이 하나여야
한다"는 표현 방식이었습니다.

## 고려한 대안

- 단일 버전 고정 유지 + CI에서 26.08.0을 소스 빌드 — 계약 문구를 그대로 두지만 CI 시간과 실패 지점이 늘고, conda-forge가 따라오면 걷어내야 할 임시 설비라 제외합니다.
- 기준을 conda-forge 최신인 26.07.0으로 하향 — CI는 통과하지만 로컬 Homebrew가 26.08.0이라 로컬 변환·적재가 막히고, 26.07.0 산출물 비교 근거도 새로 만들어야 해 제외합니다.
- 버전 검사 자체를 제거하고 산출물 SHA 비교로만 판정 — 시차 문제는 사라지지만 어떤 버전이 통과했는지 기록이 남지 않고 결정적 입력 계약이 느슨해져 제외합니다.
- 산출물 동일성을 확인한 버전들의 집합을 허용 — 결정성 근거를 그대로 유지하면서 배포판 시차를 흡수할 수 있어 선택합니다.

## 결정

- 변환기는 Poppler 실행 파일 버전이 **허용 목록에 있는지**로 판정하고, 목록 밖 버전은 변환을 시작하기
  전에 거부합니다.
- 허용 목록에는 같은 표본을 다시 변환해 `pdftoppm` 이미지와 `pdftotext` 텍스트가 모두 바이트 단위로
  같음을 확인한 버전만 넣습니다. 현재 목록은 26.05.0과 26.08.0입니다.
- 비교 근거가 없는 버전은 최신이라도 넣지 않습니다. 26.07.0을 넣지 않은 이유가 이것입니다.
- 한 배치는 한 툴체인으로 변환합니다. `pdftotext`와 `pdftoppm`의 버전이 서로 다르면 둘 다 목록 안이어도
  거부합니다. 확인한 것은 같은 버전끼리의 동일성이지 혼합 조합이 아니기 때문입니다.
- 배치 재사용 판정은 결과 manifest에서 Poppler 버전 필드를 제외하고 비교하며, 기존 배치에 기록된 버전이
  허용 목록에 있는지는 따로 확인합니다. 같은 산출물을 버전 문자열 때문에 다시 만들지 않기 위해서입니다.
- 목록과 비교 절차의 정본은 [콘텐츠 변환과 품질 검증](../../content-conversion.md#이미지-변환-기준)이며,
  보존된 검증 근거도 같은 문서에 둡니다.

## 결과

- 로컬과 CI가 서로 다른 배포판을 쓰면서도 같은 계약 아래 변환을 검증합니다. 배포판 시차가 생길
  때마다 계약을 흔들지 않고 검증된 버전을 하나 더할 수 있습니다.
- 결정성 근거는 그대로입니다. 목록에 드는 조건이 "최신"이 아니라 "같은 산출물 확인"이므로, 버전을
  더하는 비용은 여전히 표본 재변환과 비교입니다.
- 허용 값이 둘 이상이므로 결과 manifest에 기록한 Poppler 버전을 읽지 않고는 어떤 버전으로 만든
  배치인지 알 수 없습니다. 기록은 이미 남기고 있으므로 추가 작업은 없지만, 재현할 때 그 값을 봐야
  합니다. 재사용된 배치의 기록은 먼저 게시한 실행의 버전입니다.
- CI는 여전히 conda-forge 26.05.0 한 값으로 설치·확인합니다. 목록의 다른 값은 로컬 실행과 단위
  테스트로만 검증되므로, CI에서 버전을 바꾸려면 [워크플로](../../../.github/workflows/ci.yml)의 설치
  버전도 함께 고쳐야 합니다.
- 단일 고정으로 되돌리려면 로컬·CI 중 한쪽의 Poppler 조달 경로를 바꿔야 하고, 이미 적재한 콘텐츠의
  재현 조건과 CI 설정을 함께 수정해야 합니다.

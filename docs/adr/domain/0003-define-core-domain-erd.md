# 0003. 핵심 권한과 결제 상태를 관계형 데이터 모델로 관리한다

- 상태: 승인됨
- 날짜: 2026-07-26

## 맥락

잉크 잔액, 페이지 대여, 온라인 소장과 결제 내역은 동시·중복 요청에서도 서로 모순되지 않아야 합니다.
현재 값만 저장하면 감사와 재시도 근거를 잃고, 모든 값을 원장에서 매번 계산하면 잠금과 조회 비용이
복잡해집니다. 원본 PDF 페이지와 서비스 콘텐츠의 대응도 데이터베이스 제약으로 확인할 수 있어야 합니다.

## 고려한 대안

- 잉크 잔액을 원장 합계로만 계산 — 상태 중복은 없지만 동시 차감의 음수 방지와 조회 비용이 복잡해 제외합니다.
- 페이지별 현재 대여 한 행만 유지 — 조회는 단순하지만 만료 후 재대여 이력과 차감 원인을 보존할 수 없어 제외합니다.
- 페이지 콘텐츠 경로를 규칙으로만 계산 — 단순하지만 페이지별 `TEXT`·`IMAGE` 형식과 변환 결과를 저장할 수 없어 제외합니다.
- 결제와 소장 권한을 한 행으로 관리 — 행 수는 줄지만 결제 검증 사실과 부여된 권한의 책임을 분리할 수 없어 제외합니다.

## 결정

- `InkAccount`에 현재 잔액을 저장하고 `InkLedger`에 모든 지급·차감 원인을 변경 불가능하게 기록합니다.
- `PageRental`은 과거 기간을 보존하며 같은 독자·도서·페이지의 여러 대여 기간을 허용합니다.
- `BookPage`가 원본 PDF 페이지 번호와 `TEXT` 또는 `IMAGE` 콘텐츠를 일대일로 연결합니다.
- `InkPurchase`와 `OwnershipPayment`는 서버가 발급한 결제 식별자를 고유 제약으로 보호하고
  `PENDING`, `PAID`, `FAILED` 상태와 완료 시각을 보존합니다.
- `OwnershipPayment`와 `BookOwnership`을 분리해 결제 검증 사실과 기간 없는 접근 권한을 각각 보존합니다.
  `PENDING`·`FAILED`에는 권한이 없으므로 두 엔티티의 관계는 선택적입니다.
- `ReadingSession`은 독자당 현재 세션 한 행과 서버 발급 UUID `viewerSessionId`를 유지하고,
  `LibraryEntry`는 독자·도서당 한 행으로 유지합니다.
- 현재 엔티티·필드·관계와 제약의 정본은 [ERD](../../erd.md)입니다.

## 결과

- 잔액·원장·대여·결제·권한을 트랜잭션과 고유 제약으로 함께 보호할 수 있습니다.
- 현재 잔액처럼 중복 저장한 값은 원장과 일치하는지 지속적으로 검증해야 합니다.
- 과거 대여와 결제 이력이 누적되므로 보존·조회 비용이 발생합니다.
- 엔티티 관계를 바꾸면 Flyway 마이그레이션과 기존 데이터 전환이 필요합니다.

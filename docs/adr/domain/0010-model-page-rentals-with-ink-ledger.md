# 0010. 페이지 대여를 기간 이력과 잉크 원장으로 모델링한다

- 상태: 승인됨
- 날짜: 2026-07-26

## 맥락

페이지 접근 권한은 온라인 소장 또는 유효한 페이지 대여로 발생합니다. 대여는 만료 후 다시 시작할 수
있고 같은 요청의 동시 실행과 응답 유실 뒤 재시도에서도 잉크 차감과 권한 기록이 한 번만 생겨야 합니다.
현재 잔액, 변경 불가능한 차감 근거와 과거 대여 기간을 함께 보존할 구조가 필요합니다.

## 고려한 대안

- 페이지마다 영구 권한 한 행을 저장 — 만료 후 재대여와 과거 기간을 표현할 수 없어 제외합니다.
- 현재 대여 기간만 덮어씀 — 조회는 단순하지만 과거 차감과 대여 이력의 연결을 잃어 제외합니다.
- 잉크 잔액을 원장 합계로만 계산 — 별도 상태는 없지만 동시 차감의 음수 방지와 잠금 범위가 복잡해 제외합니다.
- 분산 락으로 모든 페이지 열기를 직렬화 — 단일 MySQL MVP에 인프라와 실패 모드가 과해 제외합니다.
- 계정 행 잠금 후 권한 재조회 — 한 독자의 신규 차감을 직렬화하고 MySQL 트랜잭션 안에서 수렴할 수 있어 선택합니다.

## 결정

- `InkAccount`에 현재 잔액을 저장하고 신규 차감 전에 행을 잠급니다.
- `InkLedger`는 지급과 대여 차감을 변경 불가능한 내역으로 보존합니다.
- `PageRental`은 시작·만료 시각을 가진 기간 이력이며 같은 페이지의 여러 기간을 허용합니다.
- 페이지 열기에서 온라인 소장과 활성 대여를 먼저 확인하고, 권한이 없을 때만 `InkAccount`를 잠급니다.
- 계정 잠금 뒤 온라인 소장과 활성 대여를 다시 조회해 동시 요청과 재시도를 기존 권한으로 수렴시킵니다.
- 여전히 권한이 없을 때만 잔액 변경, 원장, 대여와 마지막 위치를 하나의 트랜잭션으로 저장합니다.
- 온라인 소장 완료도 같은 독자의 `InkAccount`를 잠가 새 페이지 대여와 순서를 정합니다. 소장이 먼저면
  차감하지 않고, 대여가 먼저면 1잉크 대여 뒤 소장하며 완료된 대여는 환급하지 않습니다.
- 콘텐츠는 트랜잭션 커밋 뒤에만 제공합니다.
- 가격·차감량·대여 기간·권한 상태 전이는 [제품 정책](../../prd/product-policy.md), 현재 엔티티는
  [ERD](../../erd.md)를 따릅니다.

## 결과

- 잉크만 차감되거나 대여만 생성되는 부분 성공을 막을 수 있습니다.
- 같은 페이지의 동시 요청과 응답 유실 재시도가 하나의 유효 권한으로 수렴합니다.
- 독자별 신규 대여가 계정 행에서 직렬화되어 한 독자의 병렬 요청에 경합이 생길 수 있습니다.
- 경합이 실제 병목이 되면 측정 결과를 근거로 잠금 범위나 원자적 갱신 방식을 다시 결정해야 합니다.

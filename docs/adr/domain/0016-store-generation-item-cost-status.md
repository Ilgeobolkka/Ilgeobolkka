# 0016. 생성 항목의 추가 비용 상태를 저장한다

- 상태: 승인됨
- 날짜: 2026-08-14

## 맥락

AI 경로 생성 결과의 `additionalCostStatus`는 생성에 사용한 권한 사본과 같아야 하며, 임시 결과를 다시
조회해도 현재 권한으로 바뀌지 않아야 합니다. 경로 조립기는 생성 transaction에서 읽은 소장·활성 대여
상태로 각 항목의 비용 상태를 이미 계산합니다.

생성 시각과 `book_ownership`·`page_rental` 이력으로 이 값을 나중에 재구성할 수 있지만, 이력의 업무
시각은 transaction 커밋 순서를 나타내지 않습니다. 권한 조회 당시 보이지 않았던 transaction이 그보다
이른 `created_at` 또는 `rented_at`을 가진 채 나중에 커밋되면, 재조회는 생성에 사용하지 않은 권한까지
포함합니다. MySQL의 과거 MVCC read view를 시각만으로 다시 여는 기능도 없습니다.

이 상태를 저장하면 생성 항목마다 값 하나가 중복되지만 임시 결과 보관 기간은 15분이고, 저장 경로로
전환하면 생성 항목은 삭제됩니다. 정확한 생성 결과 재현이 짧은 기간의 중복 저장보다 중요합니다.

## 고려한 대안

- 생성 시각과 소장·대여 이력으로 재구성 — 컬럼은 늘지 않지만 업무 시각과 커밋 순서가 달라 실제 생성
  transaction의 권한 사본을 재현할 수 없어 제외합니다.
- 권한 생성과 AI 경로 생성을 공통 잠금으로 직렬화 — 상태 저장은 피하지만 외부 호출 전 준비 과정이 페이지
  열기·소장 결제와 경합하고 모든 writer가 같은 잠금 규칙을 지켜야 하므로 제외합니다.
- 조립된 항목의 추가 비용 상태 저장 — 생성에 실제 사용한 값을 그대로 반환하고 조회에서 권한 이력이
  필요하지 않아 선택합니다.

## 결정

`ai_route_generation_item.additional_cost_status`에 `ONE_INK`, `ACTIVE_RENTAL`, `OWNED` 중 생성 조립기가
계산한 값을 저장합니다. 생성 결과 API는 이 컬럼을 그대로 반환하며 소장·대여 이력으로 재계산하지 않습니다.
기존 임시 항목은 마이그레이션 당시 사용 가능한 생성 시각과 권한 이력으로 한 번만 backfill합니다.

## 결과

- 동시 권한 transaction의 커밋 순서와 무관하게 생성에 실제 사용한 추가 비용 상태를 재조회할 수 있습니다.
- 생성 결과 조회에서 소장·대여 이력 쿼리가 사라지고 항목 수에 따른 추가 조회도 없습니다.
- 임시 생성 항목마다 비용 상태가 중복 저장되며 조립 결과에서 Entity까지 값을 빠뜨리지 않고 전달해야 합니다.
- 이 결정을 되돌리려면 컬럼 제거 마이그레이션과 재구성 또는 새 스냅샷 모델이 필요합니다.

# 0003. 포인트 원장과 전역 페이지 단가를 사용한다

- 상태: 대체됨 (→ 0020)
- 날짜: 2026-07-22

## 맥락

페이지마다 실제 PG 결제를 호출하면 소액 결제 비용과 실패 처리가 핵심 독서 경험을 압도합니다.
읽어볼까는 결제로 미리 충전되는 포인트를 페이지 열람에 사용하며, MVP에서는 PG 대신 더미 포인트 지급으로 과금 흐름을 검증합니다.

## 고려한 대안

- 페이지마다 실제 결제: 소액 결제 수수료와 외부 결제 실패가 커서 제외했습니다.
- 관리자가 포인트를 수동 충전: 향후 PG 성공 후 자동 충전이라는 운영 모델과 달라 제외했습니다.
- 책별 페이지 단가: 가격 계산과 운영 정책보다 최초 1회 과금 정확성에 집중하기 위해 제외했습니다.

## 결정

- 실제 결제와 페이지 과금을 분리하고 페이지에는 포인트를 사용합니다.
- 향후 PG 결제 성공 시 1원 = 1P 비율로 포인트를 자동 충전합니다.
- MVP의 모든 책과 모든 페이지에는 전역 고정 단가 50P를 적용합니다.
- 책별 페이지 가격과 전체 책 가격은 두지 않습니다.
- 모든 포인트 지급과 차감을 변경 불가능한 내역으로 남깁니다.
- MVP에는 PG, 관리자 수동 충전, 백오피스를 포함하지 않습니다.

## 결과

- 일반 회원가입 사용자는 0P로 시작하고 MVP 시연은 더미 계정을 사용합니다.
- 포인트 잔액은 지급과 차감 내역의 합계로 설명할 수 있어야 합니다.
- PG와 책별 가격을 도입할 때에는 별도의 제품 및 데이터 계약 결정이 필요합니다.

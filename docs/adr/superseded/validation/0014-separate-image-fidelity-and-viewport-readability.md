# 0014. 페이지 이미지 충실도와 뷰포트 가독성을 분리 검증한다

- 상태: 대체됨 (→ 0024)
- 날짜: 2026-07-23

## 맥락

ADR-0013은 실제 뷰어 크기의 가독성 검증을 추가했지만, 압축·래스터 변환으로 생긴 품질 저하와 페이지를 화면 너비에 맞추면서 글자가 작아지는 문제를 같은 실패로 취급했습니다.
전자는 JPEG 품질이나 출력 형식을 바꿔 개선할 수 있지만, 후자는 PNG로 전환해도 글자의 표시 크기가 바뀌지 않습니다.
또한 위험 표본을 고르는 기준이 검사자의 주관에 따라 달라질 수 있으므로, 검증 대상을 고정해 반복 가능한 품질 게이트로 만들어야 합니다.

## 고려한 대안

- 모든 품질 실패를 JPEG 품질 상향과 PNG 전환으로 해결 — 절차는 단순하지만 화면에서 글자가 너무 작은 문제를 해결하지 못하므로 제외합니다.
- 모든 페이지를 사람이 검사 — 누락 가능성은 가장 낮지만 전체 100권을 형식별로 반복 검증하는 비용이 커서 고정된 대표·위험 표본을 사용합니다.
- 위험 표본을 검증할 때마다 다시 선정 — 새 문제를 발견할 가능성은 있지만 결과를 재현하기 어려워 최초 선정 결과를 버전 관리하는 manifest로 고정합니다.
- 모바일 가독성 실패 시 확대·축소를 바로 추가 — 읽기 문제는 해결하지만 MVP 제외 범위와 API·UI 계약을 함께 바꾸므로, 먼저 합성 PDF의 글자 크기와 지면 구성을 수정합니다.

## 결정

### 자산과 저장

- 표지는 PDF 페이지와 다른 별도 이미지 자산으로 준비하고 `Book.coverImagePath`가 그 경로를 가리킵니다.
- 표지는 PDF 변환 파이프라인의 입력·출력과 페이지 번호에서 제외하며 `totalPageCount`에도 영향을 주지 않습니다.
- PDF의 모든 페이지는 `1`부터 `totalPageCount`까지 연속된 과금 페이지로 유지합니다.
- PDF 페이지 변환 도구는 Poppler의 `pdftoppm`을 사용하고 애플리케이션 요청과 분리된 사전 배치로 실행합니다.
- SCRUM-221은 검증 근거와 같은 Poppler 26.05.0을 사용합니다.
  버전을 바꾸려면 같은 샘플의 변환 결과와 품질 판정을 다시 기록합니다.
- 기본 출력은 150 DPI, RGB JPEG이며 `-jpegopt quality=85,optimize=y,progressive=y`를 사용합니다.
- 로컬은 Git에서 제외된 파일시스템, 운영은 Block Public Access와 기본 서버 측 암호화를 적용한 Amazon S3 전용 비공개 버킷에 저장합니다.
- 브라우저가 S3나 원본 PDF에 직접 접근하지 않도록 애플리케이션이 인증·열람 조건을 확인한 뒤 현재 페이지 이미지만 제공합니다.

### 변환 완전성

- 품질 표본으로 이미지 형식·DPI·JPEG 품질을 먼저 확정한 뒤 전체 100권을 같은 설정으로 변환합니다.
- 전체 페이지가 오류 없이 변환되고 도서별 변환 이미지 수가 `totalPageCount`와 일치해야 합니다.
- 객체 키와 로컬 디렉터리는 같은 논리 규칙을 사용하되 구체적인 경로와 업로드 절차는 SCRUM-222에서 정의합니다.
- SCRUM-222에서 별도 표지 이미지 100개를 준비·업로드하고, SCRUM-223에서 각 표지의 `Book.coverImagePath` 연결과 누락 여부를 검증합니다.

### 품질 표본

- SCRUM-221에서 `bookId`, `sourceSha256`, `category`, `pageNumber`, `reason` 열을 가진 품질 표본 manifest를 버전 관리합니다.
- 도서마다 첫 페이지, `(totalPageCount + 1) / 2`의 정수 나눗셈으로 계산한 중간 페이지, 마지막 페이지를 각각 `first`, `middle`, `last` 범주로 기록합니다.
- PDF 전체를 한 번 훑어 작은 글자, 빽빽한 표·도표, 가는 선을 대표하는 페이지를 각각 `small-text`, `dense-graphic`, `thin-line` 범주로 기록합니다.
  같은 페이지가 여러 범주에 해당해도 범주별 행은 유지하고 실제 이미지 검사는 한 번만 합니다.
- 특정 위험 요소가 없는 도서는 `pageNumber`를 비우고 `reason`에 제외 근거를 기록합니다.
  품질 검증을 시작한 뒤에는 원본 PDF의 SHA-256이 바뀌거나 새 위험 페이지를 발견한 경우에만 manifest 변경 사유를 코드 리뷰로 확인하고 갱신합니다.

### 이미지 충실도

- 모든 표본을 원본 PDF와 변환 이미지의 100% 및 200% 크기로 나란히 확인합니다.
- 한글 자소·문장부호·가는 선이 원본과 다르게 뭉개지거나 JPEG 블록·테두리 번짐으로 본문·표·도표의 내용을 구분할 수 없으면 이미지 충실도 실패입니다.
- JPEG 품질 85가 실패하면 표본을 `quality=92,optimize=y,progressive=y`로 다시 변환합니다.
  품질 92도 실패하면 표본을 150 DPI PNG로 전환합니다.
- 150 DPI PNG도 실패하면 표본을 200 DPI PNG로 다시 변환합니다.
  200 DPI PNG도 실패하면 변환 결과를 채택하지 않고 배치를 중단한 뒤 원본 PDF와 Poppler 변환 조건을 다시 결정합니다.
- 표본이 통과한 설정으로만 전체 데이터셋을 변환합니다.
  전체 변환 후 설정이 표본과 다르거나 도서별 이미지 수가 `totalPageCount`와 다르면 결과를 채택하지 않습니다.
- 한 데이터셋 안에서 DPI, 품질 또는 이미지 형식을 페이지별로 섞지 않습니다.

### 뷰포트 가독성

- 이미지 충실도를 통과한 표본을 실제 뷰어의 초기 페이지 너비 맞춤 상태로 확인합니다.
  모바일은 `360×800`, 데스크톱은 `1280×800` 뷰포트를 사용하고, 최소 지원 너비가 360px보다 작으면 그 너비도 추가합니다.
- 브라우저 확대 없이 본문과 문장부호를 읽거나 표·도표의 내용을 구분할 수 없으면 뷰포트 가독성 실패입니다.
- 뷰포트 가독성이 실패하면 이미지 품질이나 형식을 바꾸지 않고 해당 합성 PDF의 글자 크기와 지면 구성을 수정합니다.
  수정한 PDF의 SHA-256과 품질 표본을 갱신하고 변환 완전성, 이미지 충실도, 뷰포트 가독성을 다시 검증합니다.
  페이지 수가 바뀌면 SCRUM-223의 `totalPageCount`도 함께 갱신하고 검증합니다.
- PDF를 수정해도 가독성 기준을 만족할 수 없으면 해당 자산을 채택하지 않습니다.
  확대·가로 스크롤 등 뷰어 동작을 바꾸려면 PRD·테스트 계약과 이 결정을 새 ADR로 함께 변경한 뒤 다시 검증합니다.

### 검증 근거

#### 완료된 검증

- 샘플: SCRUM-49 합성 도서 데이터에서 복사한 `docs/adr/evidence/page-image-quality/book_001.pdf`의 3페이지
- 원본 SHA-256: `af434962fde401334f08c2df5afd1979b1f049b9efeda6790637779c839c2fd7`
- 변환 도구: Poppler `pdftoppm` 26.05.0
- JPEG 명령: `pdftoppm -f 3 -l 3 -singlefile -r 150 -jpeg -jpegopt quality=85,optimize=y,progressive=y docs/adr/evidence/page-image-quality/book_001.pdf book_001-page-003`
- PNG 명령: `pdftoppm -f 3 -l 3 -singlefile -r 150 -png docs/adr/evidence/page-image-quality/book_001.pdf book_001-page-003`
- 결과: JPEG 195,313바이트, PNG 266,163바이트로 JPEG가 70,850바이트(약 26.6%) 작았습니다.
- 육안 판정: 875×1,241픽셀 원본 해상도에서 한글 자소와 문장부호를 구분할 수 있고 글자 획을 가리는 블록이나 번짐이 없었습니다.

#### 후속 검증

- SCRUM-221에서 manifest와 이미지 충실도 판정 결과를 남기고, SCRUM-386에서 실제 뷰어 구현 후 뷰포트 가독성을 검증합니다.
  두 작업은 전체 100권을 최종 적재하기 전에 완료합니다.

## 결과

- 상세 화면의 표지와 과금 페이지가 분리되어 기존 PRD·ERD·테스트 계약을 변경하지 않습니다.
- 압축·래스터 변환 실패와 화면 표시 크기 실패를 원인에 맞는 절차로 해결합니다.
- 대표·위험 표본과 선정 이유가 고정되어 형식이나 DPI를 바꿔도 같은 페이지로 비교할 수 있습니다.
- 변환·충실도 검증은 SCRUM-221, 실제 화면 가독성 검증은 SCRUM-386에서 추적해 뷰어 구현 전 작업을 막지 않습니다.
- 품질 상향으로 저장·전송량이 늘 수 있지만 전체 데이터셋의 경로와 제공 계약은 일관되게 유지됩니다.
- 실제 뷰어에서 읽기 어려운 합성 PDF는 초기 데이터로 채택하지 않으며, 뷰어 계약을 몰래 확장하지 않습니다.
- 운영 애플리케이션 인스턴스를 교체하거나 여러 대로 늘려도 페이지 이미지가 유지되지만 S3 저장량과 요청에 따른 AWS 비용, 최소 권한 IAM 구성이 필요합니다.
- S3의 공개 접근 차단과 암호화 기준은 [Amazon S3 보안 모범 사례](https://docs.aws.amazon.com/AmazonS3/latest/userguide/security-best-practices.html)를 따릅니다.

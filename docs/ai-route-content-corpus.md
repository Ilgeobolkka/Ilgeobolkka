# AI 경로 콘텐츠 코퍼스

이 문서는 [AI 잉크 경로 2차 MVP](./prd/ai-ink-route.md)를 검증하기 위한 시연 도서 재제작과 정답 평가
데이터의 정본입니다. 기존 PDF 변환·권리·공개 fixture 경계는
[콘텐츠 변환과 품질 검증](./content-conversion.md)과
[ADR-0013](./adr/content/0013-define-page-content-and-public-ai-fixture-boundary.md)을 따릅니다.

## 범위

- 기존 도서 ID, 제목, 저자, 카테고리와 소개를 유지합니다.
- 소설 카테고리 10권은 기존 콘텐츠를 유지하고 AI 경로를 지원하지 않습니다.
- 소설을 제외한 90권의 본문과 PDF를 새로 제작합니다.
- 기존 3~5페이지 본문은 새 본문의 소재 참고용으로만 사용하며 페이지를 그대로 보존하지 않습니다.
- 새 코퍼스는 `ai-route-v2` 콘텐츠 버전이며 기존 운영 콘텐츠 수정 기능이 아니라 시연 fixture의 새
  버전입니다. 초기 100권·400페이지 fixture는 이전 버전의 재현 입력으로 보존합니다.
- `ai-route-v2` manifest는 새 비소설 90권과 이전 버전 PDF·SHA-256을 그대로 쓰는 소설 10권을 합친
  100권 전체를 기록합니다. 전체 페이지 수는 manifest의 도서별 페이지 수 합계로 계산합니다.
- `ai-route-v2`는 대여·소장·내역이 없는 새 시연 DB에 전체 적재합니다. 이전 시연 DB의 콘텐츠를 제자리에서
  바꾸지 않습니다. 초기 manifest로 새 시연 DB를 만드는 되돌리기는 후보 DB가 HTTP 트래픽을 받기 전에만
  허용합니다. 한 번이라도 HTTP 트래픽을 받아 사용자 기록이 생긴 DB를 폐기하거나 이전 manifest의 새 DB로
  교체하는 롤백은 금지하며, 해당 콘텐츠 버전 마이그레이션은 2차 MVP 범위 밖입니다.

## 도서 제작 기준

- 새로 제작하는 비소설 90권은 각각 원본 PDF 기준 48~72페이지입니다.
- 최소 6개 장을 가지며 장과 절의 순서를 명시합니다.
- 한 책 안에 핵심 개념, 선수 개념, 적용 사례, 반례 또는 한계와 결론 역할의 페이지를 포함합니다.
- 같은 개념을 표현만 바꿔 반복하지 않고, 중복 후보를 평가할 수 있는 제한된 유사 페이지는 의도와
  근거를 메타데이터에 표시합니다.
- 표·수식·도표·삽화처럼 배치 보존이 필요한 이미지 페이지를 포함합니다.
- 모든 페이지는 화면용 `TEXT` 또는 `IMAGE` 콘텐츠와 별개로 비공개 AI 분석 텍스트를 가집니다.
- 이미지 페이지의 분석 텍스트는 원본 추출 또는 OCR과 사람 검수로 작성하며 API에 노출하지 않습니다.
- 실제 작품을 모방하거나 인용하지 않는 새 AI 시연 콘텐츠만 사용합니다.
- 파일별 권리 상태와 개인정보 부재를 확인한 뒤 Git fixture로 반입합니다.

## 구조 메타데이터

각 도서와 페이지에는 최소한 다음 분석 메타데이터를 만듭니다.

- 도서·콘텐츠 버전별 AI 경로 상태
- 장·절과 원본 PDF 페이지 번호
- 페이지의 주요 개념과 보조 개념
- 먼저 알아야 하는 개념과 페이지 관계 0개 이상. 선수 페이지가 없는 루트는 빈 목록
- 페이지 역할: 선수 개념, 핵심 개념, 사례, 반론, 결론
- 원문·결론·수치·사례 결과를 포함하지 않고 사람 검수를 통과한 공개 가이드 주제
- 의미상 중복되는 페이지 그룹 소속 0개 이상. 의미상 고유한 페이지는 빈 목록
- 텍스트 길이 또는 이미지 복잡도에 따른 예상 독서 시간 입력값
- 외부 AI 전송 권리, 적용할 기본·Modified Abuse Monitoring·Zero Data Retention 제어와 비-ZDR
  프롬프트 파생 캐시 최대 24시간 허용 여부
- 콘텐츠·권리·보관 조건 검증을 통과한 `EVALUATABLE`과, 품질 게이트 뒤에만 켜는 `PUBLIC`을 포함한
  도서·콘텐츠 버전별 `UNSUPPORTED`, `EVALUATABLE`, `PUBLIC` 상태

구조 메타데이터 중 화면 공개가 합의되지 않은 값은 외부 API에 제공하지 않습니다.

선수 관계는 같은 도서·콘텐츠 버전 안에서 `선수 페이지 -> 의존 페이지` 방향 그래프로 해석합니다. 모든
참조 페이지가 존재해야 하고 다른 도서·콘텐츠 버전을 가리킬 수 없으며, 자기 참조와 방향 순환이 없어야
합니다. 적재 전 위상 정렬로 전체 페이지를 방문할 수 있는지 검증하고 하나라도 실패하면 해당 콘텐츠 버전의
외부 호출과 DB 변경을 시작하지 않습니다.

## 정답 평가 데이터

각 지원 도서에는 대표 독서 목적 3개를 만듭니다. 90권 전체의 평가 목적은 270개입니다.

각 목적은 다음을 정의합니다.

- 목적 문장
- 전체 목적을 안정 정렬한 순번으로 배정한 고정 평가 시나리오
- 반드시 포함해야 할 필수 개념 1개 이상
- 포함하면 좋은 개념·사례·반론·결론
- 먼저 배치해야 할 선수 관계
- 무관한 페이지와 의미가 중복된 페이지
- 참고할 수 있는 기대 페이지 번호
- 허용 가능한 다른 페이지와 읽기 순서

정답 데이터는 실제 추천 요청의 후보 검색이나 경로 구성 입력에 사용하지 않고 자동 평가와 회귀 테스트에만
사용합니다. 정확한 페이지 번호 일치가 아니라 개념 충족 여부를 우선 판정합니다.

270개 목적 전체에는 필수 선수 관계가 1개 이상 있어야 합니다. 목적별 필수 선수 관계는 0개일 수 있지만,
전체가 0개이면 선수 순서 위반률을 검증할 수 없으므로 평가 코퍼스가 완전하지 않은 것으로 판정합니다.

### 고정 품질 평가 조건

- 270개 목적을 `(bookId ASC, purposeId ASC)`로 안정 정렬하고 0부터 센 순번을 부여합니다. 순번을 27로
  나눈 나머지에 1을 더한 번호의 평가 전용 독자에게 목적을 배정합니다. 평가 독자 27명은 각각 15잉크 이상을
  보유하고 한 UTC 날짜에 서로 다른 목적 10개씩만 실행해 운영의 계정당 정상 결과 10회 한도를 그대로
  지킵니다. 같은 도서의 목적 3개는 서로 다른 독자에게 배정되며 한 독자는 같은 도서의 목적을 둘 이상 받지
  않습니다. 배치는 목적 실행 전에 270개 배정의 중복·누락, 독자별 10개와 `(readerId, bookId)` 유일성을
  자동 검증하고 하나라도 다르면 권한 데이터를 만들기 전에 실패합니다.
- 목적별 소장·활성 대여는 아래 고정 시나리오에 맞춰 만들고 배정표와 초기 권한 상태를 평가 입력에
  기록합니다. 각 독자·도서에는 그 독자에게 배정한 한 목적의 시나리오가 선언한 권한만 있어야 하며 다른
  평가 목적에서 만든 소장·대여가 섞이면 평가를 시작하지 않습니다.
- 전체 평가는 아직 HTTP 트래픽을 받지 않는 공개 후보 시연 DB를 트랜잭션 일관 스냅샷으로 복제한 접근 제한
  평가 DB에서 시작합니다. 두 DB는 같은 MySQL 버전·스키마 마이그레이션을 사용하고 콘텐츠 manifest SHA,
  콘텐츠 배치 ID, 도서·페이지·분석 메타데이터·임베딩의 정규화 해시와 마이그레이션 체크섬으로 만든
  `evaluationSourceHash`가 일치해야 합니다. 고정 시나리오가 선언한 평가용 잉크·원장·대여·소장·결제는
  평가 DB에만 만들고, 그 밖의 당일 생성 요청·경로·권한 기록이 없어야 합니다. 목적별 고정 계정 배정과
  멱등 키를 평가 입력에 기록해 반복 실행 조건을 재현합니다.
- 평가 직전에 전용 OpenAI 프로젝트의 원격 상태를 갱신해 프로젝트 ID·실효 데이터 제어와 캐시 허용 정책의
  `openAiPolicyHash`를 확정합니다. 조직 관리자는 같은 조직·프로젝트의 학습용 데이터 공유 비활성을
  `dataSharingDisabledEvidence`로 별도 확인합니다. 경로 모델·추론 설정·프롬프트·구조화 출력 스키마·후보
  선택·서버 경로 정책과 평가·배포에 공통으로 쓸 패키징 JAR의 SHA-256 `generationArtifactHash`를 정규화한
  `generationConfigHash`로 확정하며 평가 중 바꾸지 않습니다. 평가 배치는 공개 서버에 배포할 해당 JAR
  바이트로 실행합니다. 콘텐츠 요구 조건이나 적재 때 사용한 정책과 다르거나 1시간 원격 증명이 만료됐거나
  데이터 공유 확인 증거가 없으면 평가를 시작하지 않습니다.
- 공개 후보 DB에 콘텐츠 완전성, 외부 전송 권리와 데이터 보관 조건을 통과한 버전을 비소설
  `EVALUATABLE`, 소설 `UNSUPPORTED`로 적재한 뒤 평가 DB를 복제합니다. 비웹 `ai-route-evaluation` 배치는
  평가 DB에서 `PUBLIC` 상태 검사만 우회하고 운영 생성 서비스의 후보 검색·경로 구성·서버 검증과 계정별
  생성 횟수를 그대로 사용합니다. 공개 후보 DB와 평가 DB 모두 일반 HTTP 생성 요청을 받지 않습니다.
- 위 안정 정렬의 순번을 7로 나눈 나머지에 따라 다음 시나리오를 배정합니다. 앞의 네 시나리오는 각각
  39개, 뒤의 세 시나리오는 각각 38개 목적을 가집니다.
  `0`은 비소장·예산 0과 정답 데이터가 지정한 활성 대여, `1`은 비소장·무대여·예산 5, `2`는
  비소장·무대여·예산 10, `3`은 비소장·무대여·예산 15, `4`는 온라인 소장·빠른 5페이지, `5`는 온라인
  소장·균형 10페이지, `6`은 온라인 소장·깊이 15페이지입니다. 예산 0의 활성 대여 페이지는 잉크 차감 없이
  유효한 경로를 만들 수 있도록 정답 데이터에 고정하고, 별도의 0잉크·무대여 `NO_ROUTE`와 최소 필요 잉크
  안내는 [테스트 전략](./test-strategy.md)의 기능·경계 테스트에서 검증합니다. 평가용 대여는 대응 잉크 원장,
  소장은 검증된 평가용 테스트 결제와 일관된 상태로 평가 DB에만 만들고 개별 삭제하지 않으며, 정제 증거
  보존 뒤 평가 DB 전체를 폐기합니다.
- 비율을 계산하기 전에 전체 필수 개념 수, 모든 평가 경로의 추천 페이지 수와 전체 필수 선수 관계 수가 각각
  1 이상인지 검증합니다. 하나라도 0이면 해당 비율을 0으로 대신 계산하지 않고 평가 실패로 기록하며 정제
  평가 증거 보존과 `PUBLIC` 전환을 진행하지 않습니다.
- 필수 개념 포함률은 270개 목적의 전체 필수 개념 수를 분모, 추천 경로가 포함한 필수 개념 수를 분자로
  계산합니다.
- 무관·중복 비율은 모든 평가 경로의 추천 페이지 수를 분모로 사용합니다. 분자는 정답 데이터가 무관하다고
  판정한 추천 페이지와, 같은 의미 중복 그룹에서 추천 순서상 첫 페이지를 제외한 추가 추천 페이지의 합집합
  크기입니다. 한 페이지가 무관과 중복에 모두 해당해도 한 번만 셉니다.
- 선수 순서 위반률은 270개 목적의 정답 데이터가 선언한 모든 필수 선수 관계 수를 분모로 사용합니다. 각
  관계의 의존 개념·대체 허용 페이지가 추천되지 않았거나, 의존 항목은 추천됐지만 필수 선수 개념·대체 허용
  페이지가 누락됐거나 뒤에 배치되면 해당 관계를 위반 1건으로 계산합니다. 관련 경로 없음도 그 목적의 필수
  선수 관계를 모두 위반한 것으로 계산합니다.
- 목적 유용성은 270개 경로를 두 명이 독립적으로 `유용` 또는 `유용하지 않음`으로 판정하고, 불일치는
  세 번째 검수자가 확정합니다. 최종 `유용` 경로 수를 270으로 나눕니다.
- 7개 평가 시나리오별 최종 `유용` 비율도 각각 계산하고 모든 시나리오가 PRD의 최소 비율을 통과해야 합니다.
- 관련 경로 없음 결과는 필수 개념 포함 0개와 `유용하지 않음`으로 계산합니다.
- 도서별 대표 목적 3개의 최종 유용성 판정과 잉크 예산 초과·선차감·무단 본문 노출 건수를 기록하고,
  [AI 잉크 경로 PRD의 품질과 출시 기준](./prd/ai-ink-route.md#품질과-출시-기준)으로 판정합니다.
- 270개 요청의 서버 측 전체 처리 시간을 오름차순으로 정렬한 257번째 값을 95백분위로 기록하고, 20초 초과
  실패 건수와 함께 같은 PRD 기준으로 판정합니다.
- 배치는 각 고정 목적의 식별자·문장·평가 시나리오와 사용자에게 표시한 페이지 순서·역할·가이드를 Git 제외
  경로의 접근 제한된 임시 검수 산출물에 기록합니다. OpenAI 요청·응답 원문과 비공개 분석 텍스트는 기록하지
  않습니다.
  산출물은 지정한 두 검수자와 불일치 담당 검수자만 읽을 수 있으며 최종 판정 완료까지, 최대 7일만
  보관합니다. 7일 안에 검수가 끝나지 않으면 산출물을 삭제하고 평가 DB 전체를 폐기한 뒤 공개 활성화 없이
  새 평가 DB에서 전체 평가를 다시 실행합니다.
- 구현에서 추가할 `fixtures/ai-route/evaluation-contract-paths.txt`는 정답 데이터 디렉터리, 시나리오
  배정·지표 계산 코드 디렉터리, 사람 판정 기준, PRD 품질 임계값 문서와 이 목록 파일 자체를 저장소 상대
  경로로 고정합니다. 평가 실행 전 목록에 든 모든 경로에 미커밋·미추적 변경이 없는지 확인하고 정확한 Git
  커밋 SHA를 `evaluationGitRevision`으로 기록합니다. 공개 전환은 평가 리비전의 목록 파일과 현재 목록
  파일이 먼저 같은지 확인한 뒤 목록의 각 파일·디렉터리 내용이 모두 같은지 비교합니다. 저장소 전체가 같은
  커밋일 필요는 없습니다. 런타임 구현은 수동 버전 규칙이나 이 목록에 의존하지 않고 평가한 전체 JAR의
  `generationArtifactHash`로 결합합니다. 목록 밖 저장소 변경 뒤 JAR을 다시 빌드하면 해시가 달라져 재평가가
  필요하고, 기존 평가 JAR을 바이트 그대로 배포할 때만 전환을 막지 않습니다.
- 평가 실행에는 콘텐츠 Git 리비전, `evaluationGitRevision`, 임베딩 모델·경로 모델·추론
  설정·프롬프트·출력 스키마·후보 선택·서버 경로 정책, `evaluationSourceHash`,
  `generationArtifactHash`, `generationConfigHash`, `openAiPolicyHash`,
  `dataSharingDisabledEvidence` 식별자와 실행 시각을 기록하고, 정답 데이터는 런타임 후보 검색과 경로 구성에
  전달하지 않습니다. 최종 사람 판정 뒤
  목적 식별자·평가 시나리오·표시 페이지 번호와 순서·역할·공개 가이드·자동 지표의 분자와 분모·최종 검수
  판정을 정제 평가 산출물로 만들어 접근 제한된 배포 증거 저장소에 보존합니다. 독서 목적 문장과 OpenAI
  요청·응답 원문·비공개 분석 텍스트·평가 계정 식별자는 영구 증거에 넣지 않습니다. 정제 평가 산출물을 다시
  읽어 내용과 SHA-256을 검증한 뒤에만 임시 검수 산출물을 삭제하고 평가 DB 폐기·부재 검증과 공개 활성화를
  진행합니다.

## 생성·검수 순서

1. 기존 메타데이터에서 책의 주제와 독자 수준을 확정합니다.
2. 비소설 도서별 48~72페이지를 충족하는 장·절, 개념 지도와 선수 관계를 먼저 설계합니다.
3. 페이지별 역할·공개 가이드 주제와 대표 목적 3개의 정답 평가 데이터를 작성합니다.
4. 본문과 이미지 원고를 생성하고 원본 PDF를 조립합니다.
5. 기존 콘텐츠 배치로 `TEXT`·`IMAGE` 페이지를 변환합니다.
6. 모든 페이지의 AI 분석 텍스트·임베딩 입력과 공개 가이드 주제를 서로 분리해 검수합니다.
7. PDF 페이지 수·번호, 변환 콘텐츠, 분석 텍스트와 평가 데이터의 연결을 검증합니다.
8. 비소설 90권을 `EVALUATABLE`, 소설 10권을 `UNSUPPORTED`로 공개 후보 시연 DB에 적재하고, 트랜잭션
   일관 스냅샷으로 평가 DB를 복제해 `evaluationSourceHash` 일치를 확인합니다. 평가 DB의
   `ai-route-evaluation` 배치로 대표 목적을 평가하고 임시 검수 산출물로 사람 판정을 완료합니다. PRD의 모든
   품질·출시 기준을 통과하면 `evaluationGitRevision`과 `evaluationSourceHash`를 포함한 정제 평가 증거를
   보존하고 읽기 검증합니다.
   임시 산출물을 삭제하고 평가 DB 전체를 폐기해 둘의 부재를 확인합니다. 평가 DB의 잉크·원장·대여·소장·
   결제와 런타임 상태를 애플리케이션 삭제 경로로 개별 삭제하지 않습니다. 공개 후보 DB에서
   평가 계약 경로의 현재 파일 내용이 평가 증거의 `evaluationGitRevision`과 같고 공개 전환 작업의 JAR
   바이트에서 다시 계산한 `generationArtifactHash`, `evaluationSourceHash`, `generationConfigHash`와
   `openAiPolicyHash`가 평가 증거와 같은지 검증한 뒤 같은 트랜잭션에서 평가 Git 리비전과 두 승인 해시를
   저장하며 비소설 90권을 `PUBLIC`로 전환합니다. 평가한 JAR을 다시 빌드하지 않고 공개 서버에 그대로
   배포합니다. 평가 데이터가 들어간 DB는 공개하지 않고 전환한 공개 후보 DB만 시연 서버에 연결하며 소설
   10권은 `UNSUPPORTED`를 유지합니다.

## 완료 조건

- 소설을 제외한 90권이 모두 48~72페이지이고 최소 6개 장을 가집니다.
- 각 도서의 PDF 페이지 수, 변환 페이지 수와 분석 페이지 수가 일치합니다.
- 모든 이미지 페이지에 검수한 분석 텍스트가 있습니다.
- 모든 지원 페이지에 원문·결론·수치·사례 결과가 없는 검수된 공개 가이드 주제가 있습니다.
- 모든 페이지에 선수 관계·중복 그룹 소속 목록 필드가 하나씩 있고 구성원은 각각 0개 이상입니다. 모든 선수
  관계는 같은 도서·콘텐츠 버전의 존재하는 페이지만 가리키며 자기 참조와 방향 순환이 없습니다.
- 각 도서에 독립적인 대표 목적 3개와 개념 중심 정답 평가 데이터가 있습니다.
- 각 목적에 필수 개념이 1개 이상 있고 270개 목적 전체에 필수 선수 관계가 1개 이상 있습니다.
- 270개 목적은 `(bookId ASC, purposeId ASC)` 순번으로 평가 독자 27명에게 각각 10개씩 배정되고,
  `(readerId, bookId)`가 유일해 한 목적의 소장·대여가 다른 목적에 영향을 주지 않습니다.
- 정답 평가 데이터가 런타임 추천 입력과 분리되어 있습니다.
- 공개 fixture 권리·개인정보 검사를 통과합니다.
- 외부 전송 권리나 데이터 보관 조건이 누락·거부된 표본은 Embeddings API 호출과 지원 상태 활성화 전에
  거부됩니다.
- 적재·평가·공개 서버 시작 직전 전용 OpenAI 프로젝트의 원격 상태가 갱신되고, 콘텐츠 요구 조건과 일치하는
  `openAiPolicyHash`와 1시간 증명 만료 시각이 증거에 남습니다. 조직 관리자가 확인한 같은 조직·프로젝트의
  `dataSharingDisabledEvidence`도 각 단계의 배포 증거에 남습니다.
- `EVALUATABLE`인 공개 후보 DB와 평가 DB에서는 일반 HTTP 생성 요청이 거부되고, 평가 DB의 비웹 평가
  배치만 운영 생성 서비스를 호출합니다.
- 비소설 90권 전체가 콘텐츠 완전성과 [AI 잉크 경로 PRD의 품질·출시 기준](./prd/ai-ink-route.md#품질과-출시-기준)을
  통과해야 합니다. 정제 평가 증거의 보존·읽기 검증을 마친 뒤 임시 검수 산출물을 삭제하고 평가 DB 전체를
  폐기해 둘의 부재를 검증합니다. 평가 계약 경로의 현재 파일 내용이 `evaluationGitRevision`과 같고 평가한
  JAR의 `generationArtifactHash`, 공개 후보 DB의 `evaluationSourceHash`, `generationConfigHash`와
  `openAiPolicyHash`가 평가 증거와 같음을 확인한 같은 트랜잭션에서 평가 Git 리비전과 두 승인 해시를 저장하고
  비소설 90권을 `PUBLIC`로 일괄 활성화합니다. 평가 JAR은 다시 빌드하지 않고 공개 서버에 그대로 배포하고,
  소설 10권은 `UNSUPPORTED`를 유지합니다. 평가 데이터가 들어간 DB는 공개하지 않습니다.

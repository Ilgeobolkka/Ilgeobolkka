# book-014 「한 잔의 온도가 남긴 것」 설계

[에세이 카테고리 계획](./essay-category-plan.md)의 14번을 만든 근거다. 정책·검증 계약은
[AI 경로 콘텐츠 코퍼스](../../ai-route-content-corpus.md)를 따르고, 이 문서는 그 계약 안에서 내린
선택과 이유만 적는다. 에세이 카테고리 네 번째 권이다.

## 대상 도서

- `bookId` 14, 카테고리 에세이. 제목·저자·소개는 `src/main/resources/demo/books.json`의 기존 값을
  유지한다 (저자 「가상 작가 014」, 소개 「차 한 잔에서 시작된 생각을 엮은 가상 에세이입니다」).
- `totalPageCount`는 5 → **50**으로 재제작했다.
- 화자는 이름 없는 「나」이고 무대는 가상의 부엌이다. 실존 상표·찻집·인물과 연결되지 않는다.

## 개념 범위

계획 문서가 이 권에 배정한 온도 변화, 짧은 의례(차 한 잔), 식어감과 사색, 붙잡을 수 없는 순간을 핵심
주제로 썼다.

- 11(느린 아침)과 갈리는 자리가 이 권의 조건이다. 11은 아침 전체의 리츄얼과 태도로서의 느림을 다루고,
  14는 한 잔이 식는 사십 분에만 머문다. 시간 단위가 다르고, 더 중요하게는 **이 권에서 시간은 태도가
  아니라 잔 안에서 저절로 흘러가는 것**이다. 화자가 속도를 고르지 않는다.
- 12·13·19의 관찰은 밖을 본다. 14는 손안의 것 하나를 보고 감각의 축이 시각이 아니라 촉각(온도)이다.
  그래서 이 권에는 「본다」는 말보다 「잡는다·댄다」는 말이 훨씬 자주 나온다.
- 15의 소음, 16의 대화, 17의 감정 정리, 18의 실패, 20의 친절은 핵심 개념으로 쓰지 않았다.

## 이 책의 뼈대

「온도는 시간을 읽는 눈금일 뿐이고 재려던 것은 온도가 아니었다」가 이 권의 결론이고, 그 결론이 드러나는
순서가 구조다.

- 1장이 잔을 시간의 단위로 세우고, 2장이 그 단위를 읽을 눈금(손이 나눈 여섯 칸)을 만든다.
- 3장이 눈금이 고르지 않다는 것을, 4장이 가장 좋은 자리가 지나가고 나서야 정해진다는 것을 다룬다.
  4.1은 2.3(마시기 좋은 때)과 3.1(식어감)이 둘 다 있어야 성립해서 이 권에서 선수가 둘인 유일한 절이다.
- 6.1이 같은 조건의 열 잔이 서로 달랐다는 4.2의 결과를 받아 「고정한 쪽은 잔이고 달라진 쪽은 나」라고
  적는다. 여기서 이 책이 온도를 재는 책이 아니라는 것이 분명해진다.
- 7.1이 1.1을 지나온 언어로 다시 말하고, 눈금은 다 쓰고 나면 남지 않는다는 데서 닫는다.

## 장 구성 (50페이지, 목차 1 + 본문 49)

```
1장 물이 끓는 동안            p2–8    PREREQUISITE  한 잔의 시간·끓이는 동안·잔이 정하는 것
2장 온도라는 눈금             p9–15   CORE          온도의 눈금·몸이 재는 온도·마시기 좋은 때
3장 식어 가는 동안            p16–23  CORE·COUNTER  식어감·식는 속도·되데우기
4장 붙잡을 수 없는 것         p24–30  CORE·COUNTER  붙잡을 수 없는 순간·되풀이의 실패·식은 채로 마시기
5장 한 해의 잔들              p31–37  EXAMPLE       한 줄 서식·버린 잔·잔을 늘어놓기
6장 온도로 설명되지 않는 것   p38–44  COUNTERPOINT  온도 밖의 것·습관이 된 의례·마실 수 없는 날
7장 한 잔의 온도가 남긴 것    p45–50  CONCLUSION    눈금이 남긴 것·잔에 남는 물음
```

이미지 4개: p8(잔이 정하는 길이), p11(손이 나눈 여섯 칸), p18(앞의 오 분과 뒤의 오 분),
p37(한 해의 잔들). 생성 스크립트는 [`figures014.py`](./tools/figures014.py)다.

네 도표에서 축의 방향을 고정했다 — 세로는 언제나 위가 뜨겁고 아래가 미지근하며, 가로는 언제나 왼쪽이
부은 직후이고 오른쪽이 사십 분 뒤다. 이 권의 주장이 「앞이 빠르고 뒤가 느리다」이므로 축이 뒤집히면
네 장을 이어서 읽을 수 없다.

중복 그룹 1개: `one-cup-as-a-unit` = [2, 45]. 잔을 시간의 단위로 삼겠다고 정하는 1.1 첫 페이지와, 한 해를
지나고 그 결정 하나가 나머지를 정했다고 다시 말하는 7.1 첫 페이지다. 재진술 페이지(45)에는 선수를 두지
않았다. 짝(2)을 선수로 걸면 45를 고른 경로에 2가 반드시 따라와 중복 그룹 규칙을 어기기 때문이며,
12·13번과 같은 처리다.

## 선수 관계 설계

1.1에서 셋으로 갈라진다. 1.2(끓이는 동안) → 2장·6.3, 1.3(잔) → 5장, 그리고 1.1 → 6.2다. 2장과 3장은
2.1에서 다시 갈라져 각각 끝까지 내려가고, 4.1이 두 갈래를 받아 합친다.

- 어느 후보 페이지도 선수 폐쇄가 10페이지를 넘지 않는다.
- 폐쇄 5페이지 이하인 후보 페이지가 여섯 개 장을 덮는다 (기준 3개 장). 4장만 최소 폐쇄가 7인데,
  4.1이 두 갈래를 합치는 절이라 구조상 그렇게 된다.
- 후보 페이지 49개 전부가 폐쇄 15페이지 이하다 (기준 75%).

예산 15 시나리오라 다른 권보다 사슬을 깊게 잡았다. 2장과 3장을 각각 세 절 사슬로 두고 4.1이 둘을
받도록 한 것이 그 결과다.

## 검증

`corpus_lib.validate_book()` → `validate_fragment.py` → `merge_fragments.py` → `validate_manifest.py`를
차례로 통과했다.

- 50페이지(48~72), 7개 장(최소 6), 내용 역할 5종 모두 사용
- `TEXT` 본문 45페이지가 357~515자(평균 413.4자, 합계 18,604자)로 전량 345자 이상
- `estimatedReadingSeconds`에 60초로 눌린 페이지가 하나도 없음
- `FRONT_MATTER`(목차)와 `aiRouteCandidatePage=false`가 정확히 일치
- 선수 관계가 후보 제외 페이지를 가리키지 않음, 위상 정렬로 50페이지 전체 방문
- PDF 페이지 50개, 텍스트 46개, 이미지 4개(p8,11,18,37) — `pdfcheck.py`로 확인
- PDF 규격: A4, 687,588 bytes, PDF 1.4
- PDF SHA-256: `4ea3eb173775ce6348b134307bb67b62516254612f1c7ae9609d82c1f685cc00`

초고는 페이지당 289~452자(평균 339자)였다. 마흔다섯 페이지 전부에 `EXTRA` 문단을 더했고 페이지마다
다른 내용을 담았다. PDF는 Chrome Headless 출력이므로 다시 생성하면 바이트와 SHA-256이 달라질 수 있다.

## 평가 케이스: 비소장·예산 15 시나리오

| 필드 | 값 |
| --- | --- |
| `caseId` | `case-book-014` |
| `purpose` | 이 책을 사지는 않았고, 차 한 잔을 앞에 두고 앉아 있는 짧은 시간이 왜 어떤 날은 남고 어떤 날은 그냥 지나가는지 알고 싶다 |
| `owned` / `maxAdditionalInk` / `depth` | `false` / `15` / `null` |
| `requiredConcepts` | 한 잔의 시간, 끓이는 동안, 온도의 눈금, 몸이 재는 온도, 마시기 좋은 때, 식어감, 식는 속도, 붙잡을 수 없는 순간 |
| `helpfulConcepts` | 잔이 정하는 것, 되데우기, 되풀이의 실패, 식은 채로 마시기, 온도 밖의 것 |
| `referencePageNumbers` | 2, 5, 9, 12, 14, 16, 19, 22, 24, 27, 29, 38 |
| `irrelevantPageNumbers` | 31~34 (공책을 어떻게 쓰고 버린 잔을 어떻게 세는지) |

예산 15는 일곱 시나리오 가운데 가장 넉넉한 축이라 두 갈래를 끝까지 따라가는 경로로 잡았다. 눈금
쪽(2.1 → 2.2 → 2.3)과 식어감 쪽(3.1 → 3.2 → 3.3)이 각각 끝까지 내려가고 4.1이 둘을 받는다. 씨앗은
4.2·4.3·6.1 세 개이고 선수 폐쇄가 열두 페이지가 된다. 세 자리가 남지만 목적이 「왜 어떤 날은 남는가」라
6장의 첫 절(온도 밖의 것)까지만 넣고 나머지는 대체 페이지로 돌렸다.

무관은 5.1·5.2 두 절이다. 두 절의 어느 문단도 이 사례의 필수·도움 개념을 주제로 삼지 않아 절째 뺐다.
같은 5장이라도 5.3은 무관이 아니다 — 잔들을 늘어놓는 이야기가 `한 잔의 시간`과 `식은 채로 마시기`를
직접 다루기 때문이다.

대체 페이지는 폐쇄가 상한 15 이하인 열다섯 개다. 정답 페이지 각각의 같은 절 짝을 중심으로 골랐고,
5장은 무관이라 빼고 7장은 결론이라 뺐다.

## 재현 조건

1. `python3 build014.py` — 원고와 조각 생성 (PDF SHA 없이 실행하면 자리표시자를 넣는다)
2. `python3 figures014.py pdfbuild014` — 도표 4개 SVG 생성
3. Chrome Headless로 각 SVG를 794×1123 PNG로 렌더링
4. `python3 build_pdf_generic.py 14 8,11,18,37 pdfbuild014` — 조판 HTML 생성
5. Chrome Headless `--print-to-pdf`로 PDF 출력, `pdfcheck.py`로 구성 확인
6. PDF를 `fixtures/content/ai-route-v2/pdfs/`에 두고 SHA-256을 인자로 `build014.py` 재실행
7. `merge_fragments.py 14`로 정본에 병합

## 검수

- 도표 네 장을 PNG로 렌더링해 눈으로 확인했고 넷 다 고쳤다.
  - p18에서 「남아 있는 온도」 곡선을 뺐다. 지수적으로 식는 경우 구간별 강하량과 잔여 온도가 같은
    모양이라, 두 개를 겹쳐 그리니 곡선이 막대 끝을 따라가 같은 값을 두 번 그린 그림이 됐다. 막대만
    남기고 본문에서 곡선 문장을 지웠다.
  - p11의 여섯 칸 이름표가 앞쪽 좁은 칸에서 서로 겹쳐 읽히지 않았다. 기울여 달고 본문에도 기울여
    달았다고 적었다.
  - p08은 잔 세 개 그림이 세로축 이름표(뜨겁다)를 덮었고 「마시기 좋은 구간」 이름표가 곡선 위에
    얹혀 있었다. 잔을 왼쪽 바깥 가운데로 내리고 띠 이름표를 축 바깥으로 뺐다.
  - p37은 표가 너무 넓어 왼쪽 대괄호 설명이 화면 밖으로 잘렸다. 막대 폭을 줄이고 대괄호를 표 오른쪽으로
    옮겼다.
- 5.3에 「잔이 시간을 만든 것이 아니라 시간이 잔을 골랐다」는 뒤집힘을 남기고 1.3 본문은 고치지 않았다.
  나중에 알게 된 것을 앞에 가져다 놓으면 처음에 무엇을 생각했는지가 사라지므로, 뒤집힘 자체를 5.3에
  적는 편을 골랐다.
- 리뷰에서 지적받아 고친 것 하나. 이 권의 개념 이름을 이 권의 것으로 바꿨다. 「기록의 규칙」·「남는
  물음」·「남은 것」을 「한 줄 서식」·「잔에 남는 물음」·「눈금이 남긴 것」으로 바꿨다. 세 자리에 아홉 권이
  똑같은 이름을 쓰고 있었는데, 이름이 겹치면 개념 이름만 보고 어느 권의 것인지 가릴 수 없고 카테고리 안에서
  개념이 서로 다르다는 것도 드러나지 않는다.
- 또 하나. `main()`에 `EXTRA`의 인덱스가 도표 페이지를 가리키면 멈추는 단언을 넣었다. 016에서 실제로 났던
  사고라, 다음 권에서 조용히 되풀이되지 않게 소리 나는 자리를 만들어 두었다.
- 한 해 도표의 값을 만드는 방식을 바꿨다. 나머지 연산으로 칸을 고르면 그려지는 개수가 본문이 센 값과
  어긋나는데, p37이 그러고 있었다. 부은 잔 오백열둘, 버린 잔 스물여섯, 되데운 잔 열하나가 5장 본문의 값이다.
  이제 본문 수치를 상수로 두고 그 수만큼 정확히 고른 뒤 단언으로 확인한다.
- 수치 전수 검사에서 하나 더 나왔다. 6.3은 잔을 비워 둔 날이 한 해에 예순 날쯤이라고 세는데 p37 도표는 빈
  날을 서른셋만 그리고 있었다. 도표를 예순에 맞추고, 두 잔을 다 채운 날이 이백일곱이 되므로 5.3의
  「절반쯤」을 「절반을 조금 넘는다」로 고쳤다. 예순 날을 「다섯 날에 하루 꼴」이라 적은 것도 「여섯 날에
  하루 꼴」로 바로잡았다.

## 권리·개인정보

본문과 도표는 실존 작품을 인용·번역·모방하지 않고 이 fixture를 위해 새로 작성했다. 특정 차 상표·찻집·
인물과 연결되지 않는 일반적인 가상 일상이며 개인정보를 포함하지 않는다.

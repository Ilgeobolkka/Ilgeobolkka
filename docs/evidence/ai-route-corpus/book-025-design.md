# book-025 「구름의 형성과 강수의 물리」 설계

[과학 카테고리 계획](./science-category-plan.md)의 25번을 만든 근거다. 정책·검증 계약은
[AI 경로 콘텐츠 코퍼스](../../ai-route-content-corpus.md)를 따르고, 이 문서는 그 계약 안에서 내린
선택과 이유만 적는다.

## 대상 도서

- `bookId` 25, 카테고리 과학. 저자·소개는 `src/main/resources/demo/books.json`의 기존 값을 유지한다.
- 제목은 `ai-route-v2` manifest의 `books[].title`이 정본이며 이 문서의 제목과 같다.
- 실존 관측소·연구자·사례를 옮기지 않는다. 무대는 가상의 「비늘재 기상 관측소」, 인물은 새봄과 지호다.
  021·023·024·026·027의 인물과 겹치지 않는다.

## 개념 범위

계획 문서가 정한 범위(구름 형성, 구름 분류, 강수 과정, 관측 도구)를 그대로 따른다.

- 029(기후 데이터)는 자료를 읽는 방법론이다. 025는 **현상 자체의 물리**만 다루므로 이동평균도 추세
  분리도 나오지 않는다. 5장의 관측도 자료 처리가 아니라 무엇을 어떻게 보는가에 머문다.
- 022(파동)가 정의한 반사·굴절은 다시 설명하지 않는다. 레이더는 「되돌아오는 신호를 쓰는 장치」로만
  다루고 반사의 원리를 세우지 않는다.
- 024(빛의 속도)가 다룬 왕복 시간 측정도 되풀이하지 않는다. 5.2에서 되돌아오는 데 걸린 시간으로 거리를
  안다는 한 문장에 그친다.
- 023(미생물)이 다룬 물질순환과는 겹치지 않는다. 025의 물은 상태만 바꿀 뿐 생물을 거치지 않는다.

## 장 구성 (50페이지, 목차 1 + 본문 49)

```
1장 보이지 않는 물          p2–11   PREREQUISITE  공기 속의 물·담을 수 있는 양·이슬점·붙잡을 자리·보는 도구
2장 구름이 생기는 방식      p12–19  CORE          상승과 냉각·올려 보내는 힘·구름의 높이·사라지는 구름
3장 구름을 갈라 부르는 법   p20–26  CORE          높이에 따른 갈래·모양에 따른 갈래·이름 읽기·갈래의 한계
4장 떨어질 만큼 커지기      p27–34  CORE          떨어지는 조건·합쳐지는 성장·얼음의 성장·떨어지는 형태
5장 비늘재 관측소의 한 철   p35–40  EXAMPLE       관측 계획·관측 절차·값의 해석·기록 남기기
6장 잘못 읽기 쉬운 자리     p41–46  COUNTERPOINT  구름의 오해·예보 읽기·측정의 한계
7장 결론                     p47–50  CONCLUSION    종합과 남는 물음
```

1장이 세 조건(물, 식는 일, 붙잡을 자리)을 세우고 2장이 식히는 방법을, 4장이 커지는 방법을 다룬다. 3장의
분류는 그 사이에 놓여 2장의 결과를 부르는 이름을 정하고 4장에서 그 이름이 다시 쓰인다.

이미지 6개: p7(물은 그대로인데 그릇이 작아진다), p15(올라가는 길은 넷), p23(두 축으로 자리를 정한다),
p30(따라잡으면 합쳐진다), p37(네 도구가 보는 자리), p44(같은 양, 다른 일). 여섯 도표에서 색 쓰임을
고정했다 — 보이지 않는 물은 옅은 파랑, 보이는 물방울은 짙은 파랑, 얼음은 회청색, 올라가는 흐름은 주황
화살표다. 생성 스크립트는 [`figures025.py`](./tools/figures025.py)다.

중복 그룹 1개: `invisible-water-first` = [2, 47]. "맑은 하늘에도 공기 안에 물이 있고 구름은 그 물이
상태를 바꾼 것"이라는 명제를 1.1에서 세우고 7.1에서 책을 지나온 언어로 재진술한다. 재진술 페이지(47)에는
선수를 두지 않았다. 짝(2)을 선수로 걸면 47을 고른 경로에 2가 반드시 따라와 중복 그룹 규칙을 어기기
때문이며, book-021·023·024·026·027과 같은 처리다.

## 선수 관계 설계

1.1 → 1.2 → 1.3의 사슬을 세우고 1.3에서 셋이 갈라진다. 1.4(붙잡을 자리), 1.5(보는 도구), 2.1(상승과
냉각)이다. 4.1(떨어지는 조건)은 1.4에, 4.3(얼음의 성장)은 3.1(높이에 따른 갈래)에 붙였다. 얼음 이야기가
높이 분류에 붙는 것은 이 책의 논리 그대로다 — 어느 높이에 있느냐가 그 구름 안이 물인지 얼음인지를
정하기 때문이다.

- 어느 후보 페이지도 선수 폐쇄가 10페이지를 넘지 않는다.
- 폐쇄 5페이지 이하인 후보 페이지가 여섯 개 장을 덮는다 (기준 3개 장).
- 후보 페이지 49개 전부가 폐쇄 15페이지 이하다 (기준 75%).

## 검증

`corpus_lib.validate_book()` → `validate_fragment.py` → `merge_fragments.py` → `validate_manifest.py`를
차례로 통과했다.

- 50페이지(48~72), 7개 장(최소 6), 내용 역할 5종 모두 사용
- `TEXT` 본문 43페이지가 345~499자(평균 387자, 합계 16,677자)로 전량 345자 이상
- `estimatedReadingSeconds`에 60초로 눌린 페이지가 하나도 없음
- `FRONT_MATTER`(목차)와 `aiRouteCandidatePage=false`가 정확히 일치
- 선수 관계가 후보 제외 페이지를 가리키지 않음, 위상 정렬로 50페이지 전체 방문
- PDF 페이지 50개, 텍스트 44개, 이미지 6개(p7,15,23,30,37,44) — `pdfcheck.py`로 확인
- PDF 실제 SHA-256이 manifest의 `pdfSha256`과 일치

초고는 39페이지여서 최소 48페이지에 못 미쳤다. 절마다 두 번째 페이지가 필요한 자리를 골라 열한 페이지를
더했다. 하한(345자)에 걸린 스물한 페이지에는 `EXTRA` 문단을 더했는데, 026에서 적은 이유대로 **페이지마다
다른 내용**을 담았다. 같은 형태의 마무리 문장을 여러 페이지에 붙이면 예술 6권에서 겪은 문구 겹침이
되풀이된다.

## 평가 케이스: 비소장·예산 0 시나리오

| 필드 | 값 |
| --- | --- |
| `caseId` | `case-book-025` |
| `purpose` | 이 책을 사지는 않았고 이미 열어 둔 페이지만으로, 맑던 하늘에 구름이 생기는 조건이 무엇인지 정리해 두고 싶다 |
| `owned` / `maxAdditionalInk` / `depth` | `false` / `0` / `null` |
| `activeRentalPageNumbers` | 2, 4, 6, 8, 12 (정답 경로와 같음) |
| `requiredConcepts` | 공기 속의 물, 담을 수 있는 양, 이슬점, 붙잡을 자리, 상승과 냉각 |
| `helpfulConcepts` | 구름의 높이, 사라지는 구름, 떨어지는 조건 |
| `referencePageNumbers` | 2, 4, 6, 8, 12 |
| `irrelevantPageNumbers` | 26(갈래의 예외), 33(닿는 형태), 40(기록 절차), 43~44(비가 온다는 말) — 구름이 **생기는** 조건만 보려는 이 목적과 무관하고, 이 케이스의 필수·도움 개념을 태그로도 문단 주제로도 쓰지 않는다 |

`allowedAlternativePageNumbers`는 빈 배열이다. 예산이 0이라 활성 대여가 곧 정답 경로이고 새로 열 수 있는
페이지가 하나도 없다. 무엇을 적어 넣어도 어느 배분으로도 고를 수 없는 죽은 값이 되므로 비워 두었다.

처음에는 5장의 관측 절차(35~36, 38~40)를 무관 페이지로 두었으나 바꿨다. 개념표만 보면 관측 절차와 값의 해석뿐이지만, 이 절들의 본문은 지상에서 잰 이슬점으로 구름 바닥 높이를 계산하는 이야기여서 필수 개념을 정면으로 다룬다. 무관 페이지는 개념표와 문단 주제를 모두 보고 골라야 한다.

예산 0은 추가로 잉크를 쓸 수 없는 시나리오이므로 정답 경로 전체가 이미 대여된 페이지여야 한다. 그래서
`activeRentalPageNumbers`를 정답 경로와 같게 두었다. 기존 예산 0 케이스(book-011·049·061)와 같은
처리다.

경로 다섯 페이지는 이 책이 세운 세 조건을 정확히 덮는다. 공기 속의 물(2) → 담을 수 있는 양(4) →
이슬점(6)의 사슬 위에 붙잡을 자리(8)와 상승과 냉각(12)이 얹힌다. 구름이 생기려면 이 셋이 다 필요하다는
1.4의 결론이 경로 모양에 그대로 남아 있다.

도움 개념 셋은 모두 경로 밖이다. 예산이 없는 시나리오라 이미 열어 둔 다섯 페이지 너머로는 갈 수 없기
때문이다. 대체 페이지로 보완할 수도 없으므로, 이 케이스에서 도움 개념은 목적에 이어지기는 하지만 이 배분
안에서는 닿을 수 없는 자리라는 뜻으로만 남는다.

## 재현 조건

1. `python3 build025.py` — 원고와 조각 생성 (PDF SHA 없이 실행하면 자리표시자를 넣는다)
2. `python3 figures025.py pdfbuild025` — 도표 6개 SVG 생성
3. Chrome Headless로 각 SVG를 794×1123 PNG로 렌더링
4. `python3 build_pdf_generic.py 25 7,15,23,30,37,44 pdfbuild025` — 조판 HTML 생성
5. Chrome Headless `--print-to-pdf`로 PDF 출력, `pdfcheck.py`로 구성 확인
6. PDF를 `fixtures/content/ai-route-v2/pdfs/`에 두고 SHA-256을 인자로 `build025.py` 재실행
7. `merge_fragments.py`로 정본에 병합

정답 경로·무관 페이지·대체 페이지는 절 이름에서 페이지 번호를 찾아 `main()`에서 계산한다. 페이지를
더하거나 빼도 번호를 손으로 고칠 필요가 없게 하려는 것이고, 이 권부터 쓰는 방식이다.

## 검수

- 7장을 다시 썼다. 아홉 권의 결론이 「구분은 넷이다 — 첫째…넷째」와 「답하지 못한 물음을 세 갈래로」와
  「장비 없이 확인할 수 있는 것이 있다」라는 같은 네 자리를 쓰고 있었다. 이 권의 7장은 맑은 하늘을 두고 네 물음을 순서대로 던지는 형태로 바꿨다.
- 5.4도 다시 썼다. 여섯 권이 「…이 끝나면 남는 것은 묶음이다」로 열고 「버린 회차도 남긴다 — 남은 것만 보면
  매끄러웠던 것처럼 보인다」로 이어지는 같은 틀이었다. 이 권에서 실제로 되살릴 수 없는 것이 무엇인지에서
  다시 출발하고, 빠진 회차가 결과를 **어느 쪽으로** 기울이는지까지 적었다.
- 여섯 도표를 PNG로 렌더링해 눈으로 확인했고 다섯을 고쳤다. p44는 첫 그래프의 축 이름이 제목 자리까지
  올라가 겹쳤고 두 색칠 넓이가 실제로 같지 않았다 — 배치를 다시 잡고 넓이가 같아지도록 높이를 계산해서
  그렸다. p30은 세 단계를 위아래로 늘어놓아 화살표가 방울에서 멀어졌다 — 나란히 놓았다. p15는 부제가 칸에
  가려졌고 지면선이 지형에 덮였으며 밑면 높이 안내가 첫 칸 위에 얹혔다 — 순서를 바꾸고 안내를 아래 설명으로
  내렸다. p23과 p37은 도표 안 부제가 제목과 같은 문장이었다.
- 도표 여섯 장의 `IMAGE` 페이지 본문을 렌더링 결과와 한 줄씩 맞춰 다시 썼다. AI 경로에서는 이 본문이 그림을
  대신하므로 어긋나면 그대로 오답이 된다. p30은 세 단계를 나란히 놓은 뒤에도 본문이 「세로 방향의 긴 통로」를
  그대로 적고 있어 그림과 방향이 반대였고, p23은 격자의 머리말을 가로축 양 끝 이름표로 적고 있었다.
- 5.3의 어긋남 원인을 고쳤다. 「바람이 강한 날 아래위가 섞여 지상 값이 덩이의 값과 달랐다」고 적었으나, 1.5는
  바람이 세면 섞여서 지상 값이 더 멀리까지 통한다고 말한다. 섞이면 지상 공기가 오히려 메말라 계산한 바닥이
  높게 나오므로 낮게 나왔다는 관측과도 부호가 반대였다. 원인을 잔잔한 날의 얕은 물기 층으로 바꿨고, 이어지는
  5.3 둘째 페이지의 「바람이 약한 날/강한 날」도 함께 뒤집었다.
- 공개 가이드 주제와 비공개 분석 텍스트를 서로 다른 문장으로 적었고, 주제문에 숫자를 쓰지 않았다.
- 본문·도표·평가 데이터에 실존 인물·작품·단체가 등장하지 않는다.

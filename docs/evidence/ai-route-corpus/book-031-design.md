# book-031 「모래도시의 백 년 기록」 설계

[역사 카테고리 계획](./history-category-plan.md)의 31번을 만든 근거다. 정책·검증 계약은
[AI 경로 콘텐츠 코퍼스](../../ai-route-content-corpus.md)를 따르고, 이 문서는 그 계약 안에서 내린
선택과 이유만 적는다.

## 대상 도서

- `bookId` 31, 카테고리 역사. 저자·소개는 `src/main/resources/demo/books.json`의 기존 값을 유지한다.
- 제목은 `ai-route-v2` manifest의 `books[].title`이 정본이며 계획 문서의 제목과 같다.
- 실존 국가·왕조·사료를 옮기지 않는다. 무대는 가상의 사막도시 국가 붉은모래성이고 통치자 칭호는
  성주, 사료는 다섯 성주 백 년을 적은 「붉은모래 연대기」다. 연구자는 소하이며 021·022·023·024·
  026·027·028·034·044·065의 인물과 겹치지 않는다.

계획이 정한 범위(편년체 서술, 사료로서의 연대기, 통치자 계보로 시대 구분, 사건의 인과 연쇄)가 모두
들어갔다. 평가 시나리오도 계획대로 「비소장 · 예산 0」이다.

## 개념 범위

이 책이 다루는 것은 사료의 종류가 아니라 **서술 형식 자체**다. 다른 역사 권이 장부·벽화·서신 같은
사료 유형의 해석법을 다루는 데 비해, 31은 해를 단위로 줄을 세우는 형식이 무엇을 담고 무엇을 흘리는지를
본다. 그래서 이 책에는 사료 유형을 가리키는 낱말이 거의 없고 대신 칸·줄·순서라는 말이 반복된다.

같은 카테고리에서 사료를 읽는 권과 경계를 두었다.

- 34(장부)는 수치와 결락을 다룬다. 31은 수치를 다루지 않는다. 도표에도 눈금과 숫자를 넣지 않았다.
- 33(의례)과 38(벽화)은 문자 아닌 사료를 읽는다. 31의 사료는 처음부터 끝까지 글이다.
- 32와 40은 쇠퇴의 원인을 다루지만 31은 원인을 말할 수 있는 조건 자체를 다룬다.

## 장 구성 (49페이지, 목차 1 + 본문 48)

```
1장 한 해에 한 줄            p2–7    PREREQUISITE  편년체·기록의 선택·기록자의 자리
2장 해를 믿을 수 있는가      p8–15   CORE          기년·결년·중복 기사·후대 가필
3장 백 년을 토막 내기        p16–23  CORE          계보 구분·구분의 자의성·대안 구분·연호
4장 앞뒤와 까닭              p24–31  CORE          연쇄·선후와 인과·인과의 조건·복합 원인
5장 붉은모래 백 년을 따라 읽기 p32–38  EXAMPLE       읽기 절차·사건 재구성·연표 만들기·읽기 기록
6장 줄 밖으로 밀려난 것      p39–46  COUNTERPOINT  연대기의 침묵·승자의 기록·단일 사료·연대기의 쓸모
7장 백 년 뒤에 읽는 사람에게 p47–49  CONCLUSION    편년체·구분의 자의성·기록자의 자리
```

7장은 다른 권의 결론과 다르게 짰다. 이 책이 다룬 도구를 이 책 자신의 구성에 적용해, 본문의 전개
순서가 인과 사슬이 아니라 조건 관계임을 4장의 자로 다시 확인한다. 형식을 다룬 책이 자기 형식에 같은
자를 대지 않으면 그 자를 남에게 댈 수 없다는 것이 이 장의 취지다.

이미지 6개: p5(한 해에서 한 줄로), p13(두 줄이 한 사건일 때), p19(같은 백 년, 두 가지 자),
p27(붙어 있다는 것만으로는), p33(첫 스무 해의 모양), p41(누가 적었는가에 따라). 생성 스크립트는
[`figures031.py`](./tools/figures031.py)다.

중복 그룹 1개: `blank-year-is-not-empty` = [11, 40]. "적히지 않은 해가 아무 일 없던 해는 아니다"를
2.2에서 결년 처리 규칙으로 세우고 6.1에서 자료 전체 수준으로 다시 쓴다. 40의 선수 폐쇄는
[2, 4, 39, 40]이라 짝인 11을 지나지 않는다. 지나면 40을 고른 경로에 11이 반드시 따라와 중복 그룹
규칙을 어긴다.

## 선수 관계 설계

1.1이 뿌리이고 1.2·1.3·2.1이 곧바로 거기 붙는다. 2.2·2.3은 2.1에 붙고 2.4만 1.3(기록자의 자리)에서
이어진다 — 가필을 가려내는 첫 실마리가 적는 사람이 아는 것의 범위이기 때문이다.

3장은 3.1이 2.1에 붙고 3.2 → 3.3이 사슬을 이루며 3.4는 2.1에 직접 붙는다. 4장만 4.1 → 4.2 → 4.3 →
4.4의 한 줄 사슬이다. 앞 절을 건너뛰면 다음 절이 서지 않는 유일한 장이고, 이 사례의 정답 경로가
그 사슬을 탄다.

5장은 5.1이 2.1에, 5.2가 4.2에, 5.3이 3.1에 붙는다. 실제로 읽는 일마다 필요한 바닥이 다르다.
6장은 뒤에 있지만 앞 장에 직접 붙였다 — 6.1은 1.2, 6.2는 1.3, 6.3은 2.3, 6.4는 4.1이다. 반례는 그
주장이 세워진 자리에서 읽어야 뜻이 서고, 6장을 5장 뒤에 사슬로 이으면 폐쇄가 예산 안에 들어오지 못한다.

- 어느 후보 페이지도 선수 폐쇄가 7페이지를 넘지 않는다.
- 폐쇄 5페이지 이하인 후보 페이지가 일곱 개 장을 모두 덮는다 (기준 3개 장).
- 후보 페이지 48개 전부가 폐쇄 15페이지 이하다 (기준 75%).

## 검증

`corpus_lib.validate_book()` → `validate_fragment.py` → `merge_fragments.py` → `validate_manifest.py`를
차례로 통과했다.

- 49페이지(48~72), 7개 장(최소 6), 내용 역할 5종 모두 사용
- `TEXT` 본문 42페이지가 347~381자(평균 361자, 합계 15,190자)
- `estimatedReadingSeconds`에 60초로 눌린 페이지가 하나도 없음
- `FRONT_MATTER`(목차 p1)와 `aiRouteCandidatePage=false`가 정확히 일치
- 선수 관계가 후보 제외 페이지를 가리키지 않음, 위상 정렬로 49페이지 전체 방문
- PDF 페이지 49개, 텍스트 43개, 이미지 6개(p5,13,19,27,33,41) — `pdfcheck.py`로 확인
- PDF 실제 SHA-256이 manifest의 `pdfSha256`과 일치

## 평가 케이스: 비소장·예산 0 시나리오

| 필드 | 값 |
| --- | --- |
| `caseId` | `case-book-031` |
| `purpose` | 이 책을 사지는 않았고 이미 열어 둔 페이지만으로, 해마다 적은 기록에서 사건의 앞뒤와 까닭을 어떻게 가려 읽는지 정리해 두고 싶다 |
| `owned` / `maxAdditionalInk` / `depth` | `false` / `0` / `null` |
| `requiredConcepts` | 편년체, 기년, 연쇄, 선후와 인과, 인과의 조건 |
| `helpfulConcepts` | 기록의 선택, 결년, 중복 기사, 복합 원인 |
| `referencePageNumbers` | 2, 8, 24, 26, 28 |
| `activeRentalPageNumbers` | 2, 8, 24, 26, 28 (정답 경로와 같음) |
| `irrelevantPageNumbers` | 20·21(물로 나눈 백 년), 22·23(연호), 37(읽기 기록), 41·42(승자의 기록) |

예산이 0이라 새로 열 수 있는 페이지가 하나도 없다. 그래서 정답 경로 전체가 이미 대여된 페이지여야
하고, **대체 페이지는 빈 배열이다.** 무엇을 적어 넣어도 어느 배분으로도 고를 수 없는 죽은 값이 된다.
book-025와 같은 처리다.

정답 경로는 4장의 사슬 하나다. 편년체(2)에서 기년(8)으로 가고, 거기서 연쇄(24) → 선후와 인과(26) →
인과의 조건(28)으로 이어진다. 다섯 페이지로 다섯 필수 개념을 모두 덮는다. 이 사례가 이렇게 짧게
끝나는 것은 4장이 이 책에서 유일하게 한 줄로 이어진 장이기 때문이다.

무관은 절 단위로 골랐다. 물로 나눈 백 년과 연호는 시대를 나누는 다른 자를 다루고, 읽기 기록은
판단을 남기는 절차이며, 승자의 기록은 누가 적었는가의 문제다. 넷 다 앞뒤와 까닭을 가려 읽는 이
목적 밖이고 필수·도움 개념을 primary로 달지 않는다.

## 재현 조건

1. `python3 build031.py` — 원고와 조각 생성 (PDF SHA 없이 실행하면 자리표시자를 넣는다)
2. `python3 figures031.py pdfbuild031` — 도표 6개 SVG 생성
3. Chrome Headless로 각 SVG를 794×1123 PNG로 렌더링
4. `python3 build_pdf_generic.py 31 5,13,19,27,33,41 pdfbuild031` — 조판 HTML 생성
5. Chrome Headless `--print-to-pdf`로 PDF 출력, `pdfcheck.py`로 구성 확인
6. PDF를 `fixtures/content/ai-route-v2/pdfs/`에 두고 SHA-256을 인자로 `build031.py` 재실행
7. `merge_fragments.py 31`로 정본에 병합

## 검수

- 초고는 42개 `TEXT` 페이지 가운데 24페이지가 하한에 걸렸다. 문단을 새로 붙이지 않고 마지막 문단을
  늘려 고쳤다. 두 번째 확인에서 두 페이지가 남아 한 번 더 늘렸다.
- 도표 여섯 장을 PNG로 렌더링해 눈으로 확인했고 셋을 고쳤다. p5는 세 번째 통로 이름을 사선이
  가로질렀고 통로 안이 비어 있어 「지난다」가 보이지 않았다 — 통과하는 표시를 통로 안에 그리고
  연결선을 모두 수직으로 폈다. p27은 둘째 상자의 글이 상자 밖으로 넘쳤다 — 줄바꿈을 직접 잡았다.
  p33은 위쪽 절반이 비어 있었다 — 막대를 키우고 전체를 올렸다.
- 도표 본문과 그림이 어긋난 자리를 둘 고쳤다. p13은 본문이 「해 표시가 붙은 가로줄」이라 했는데
  그림에 해 표시가 없어 그림에 넣었고, p19는 괄호가 띠 아래에 있는데 본문이 위라고 적어 본문을
  고쳤다.
- 다른 권과 겹치는 일곱 어절이 둘 있었다. 도표 설명의 상투 문구(`숫자와 비율은 없다`, `세로 막대
  스무`)라 034와 겹쳤고 표현을 바꿔 0으로 만들었다.
- `ContentBatchConverterTest`의 코퍼스 재고 단언 세 개를 갱신했다. 도서 43→44, 페이지 1749→1798,
  이미지 199→205다. 페이지 수를 manifest 합계(1758)로 계산했다가 틀렸다 — 소설 10권의 40페이지는
  manifest가 아니라 PDF에서 나온다. 테스트가 그 실수를 잡았다.
- 공개 가이드 주제와 비공개 분석 텍스트를 서로 다른 문장으로 적었고, 주제문에 숫자를 쓰지 않았다.
- 본문·도표·평가 데이터에 실존 인물·작품·단체가 등장하지 않는다.

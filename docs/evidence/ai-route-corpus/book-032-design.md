# book-032 「지도에서 사라진 항구들」 설계

[역사 카테고리 계획](./history-category-plan.md)의 32번을 만든 근거다. 정책·검증 계약은
[AI 경로 콘텐츠 코퍼스](../../ai-route-content-corpus.md)를 따르고, 이 문서는 그 계약 안에서 내린
선택과 이유만 적는다.

## 대상 도서

- `bookId` 32, 카테고리 역사. 저자·소개는 `src/main/resources/demo/books.json`의 기존 값을 유지한다.
- 제목은 `ai-route-v2` manifest의 `books[].title`이 정본이며 계획 문서의 제목과 같다.
- 실존 국가·항구·해도를 옮기지 않는다. 무대는 가상의 청강만과 그 연안의 세 항구 여울항·조개항·
  달빛항, 셋을 묶었던 만안동맹이다. 연구자는 단이이며 앞선 권들의 인물과 겹치지 않는다.

계획이 정한 범위(무역로 변화, 지형 변화로 인한 쇠퇴, 항구 간 경쟁, 지도 사료의 시간차 대조)가 모두
들어갔다. 평가 시나리오도 계획대로 「비소장 · 예산 5」다.

## 개념 범위

이 책의 축은 **여럿을 나란히 놓는 일**이다. 31이 서술 형식을 다루고 34가 수치 사료를 다루는 데 비해,
32는 대상이 여럿일 때만 할 수 있는 일을 다룬다. 그래서 이 책에서 가장 자주 나오는 말은 기준·단위·
맞춤이고, 결론은 언제나 "무엇이 다른가"까지만 간다.

계획이 지정한 경계를 지켰다.

- 40도 쇠퇴를 다루지만 원인이 조약 재협상이라는 정치적 결정이다. 32의 원인은 강의 퇴적과 새 뱃길이라
  사람이 정한 것이 아니다. 본문에 조약이나 국경이 한 번도 나오지 않는다.
- 34(장부)는 한 고을의 수치를 깊이 판다. 32는 값을 맞출 수 없어 방향만 견주는 자리가 많고, 그 차이를
  5.2에서 본문에 직접 적었다.

## 장 구성 (49페이지, 목차 1 + 본문 48)

```
1장 셋을 나란히 놓기          p2–7    PREREQUISITE  비교의 기준·비교 단위·시간 맞추기
2장 지도라는 사료             p8–15   CORE          지도의 시점·사본과 원본·지도의 생략·시간차 대조
3장 물길이 바꾼 것            p16–23  CORE          퇴적·수심과 선박·항구 이동·준설의 한계
4장 셋의 엇갈림               p24–31  CORE          항구 간 경쟁·신항로·만안동맹·단계적 쇠퇴
5장 세 항구를 실제로 견주기   p32–38  EXAMPLE       견줌의 절차·항목 맞추기·불일치 처리·견줌 기록
6장 견줌이 속이는 자리        p39–46  COUNTERPOINT  표본의 한계·지도의 잔존·단일 원인·비교의 쓸모
7장 만 하나를 덮으며          p47–49  CONCLUSION    비교의 기준·표본의 한계·비교의 쓸모
```

6장을 다른 권보다 무겁게 잡았다. 사례가 셋뿐인 비교사에서는 방법 자체가 만들어 내는 착시가 가장 큰
위험이라, 표본의 한계·자료의 잔존·단일 원인 세 가지를 각각 한 절씩 두었다. 특히 6.3의 둘째 페이지는
원인을 늘리는 쪽의 위험(조건 수가 사례 수에 가까워지면 설명이 되풀이가 된다)을 다뤄, 반례 장이
한쪽으로만 기울지 않게 했다.

이미지 6개: p5(같은 만, 세 자리), p11(열 장이 네 묶음), p19(얕아지면 큰 배부터),
p25(하나가 줄면 하나가 는다), p36(어긋난 칸을 다루는 법), p42(남은 쪽만 자세하다). 생성 스크립트는
[`figures032.py`](./tools/figures032.py)다.

중복 그룹 1개: `same-bay-different-conditions` = [25, 47]. "같은 만에 있었다는 것이 같은 조건을 뜻하지
않는다"를 4.1의 도표에서 세 곡선으로 세우고 7.1에서 책 전체의 결론으로 다시 쓴다. 47의 선수 폐쇄는
[2, 16, 18, 20, 24, 47]이라 짝인 25를 지나지 않는다. 지나면 47을 고른 경로에 25가 반드시 따라와 중복
그룹 규칙을 어긴다.

## 선수 관계 설계

1.1이 뿌리이고 1.2·1.3·2.1·3.1이 곧바로 거기 붙는다. 2장은 2.1에서 셋으로 갈라져 얕게 퍼진다.

3장만 사슬이다. 3.1 → 3.2로 가고 **3.3은 3.1과 3.2 둘을 함께 선수로 가진다.** 항구가 옮겨 갔다는 것은
모래가 쌓였다는 사실만으로 서지 않고 얕아져서 배가 못 들어온다는 사실 위에 선다. 3.4와 4.1이 3.3에서
이어져 이 사례의 정답 경로가 그 사슬을 탄다.

4.2·4.3·5장·6.1은 모두 1.2(비교 단위)에 붙는다. 견주는 일마다 필요한 바닥이 세 항구를 어떻게 묶느냐
하나뿐이기 때문이다. 6장의 나머지는 각자 겨냥하는 자리에 붙였다 — 6.2는 2.1, 6.3은 4.1, 6.4는 1.1이다.

- 어느 후보 페이지도 선수 폐쇄가 7페이지를 넘지 않는다.
- 폐쇄 5페이지 이하인 후보 페이지가 일곱 개 장을 모두 덮는다 (기준 3개 장).
- 후보 페이지 48개 전부가 폐쇄 15페이지 이하다 (기준 75%).

## 검증

`corpus_lib.validate_book()` → `validate_fragment.py` → `merge_fragments.py` → `validate_manifest.py`를
차례로 통과했다.

- 49페이지(48~72), 7개 장(최소 6), 내용 역할 5종 모두 사용
- `TEXT` 본문 42페이지가 344~379자(평균 359자, 합계 15,096자)
- `estimatedReadingSeconds`에 60초로 눌린 페이지가 하나도 없음
- `FRONT_MATTER`(목차 p1)와 `aiRouteCandidatePage=false`가 정확히 일치
- 선수 관계가 후보 제외 페이지를 가리키지 않음, 위상 정렬로 49페이지 전체 방문
- PDF 페이지 49개, 텍스트 43개, 이미지 6개(p5,11,19,25,36,42) — `pdfcheck.py`로 확인
- PDF 실제 SHA-256이 manifest의 `pdfSha256`과 일치

## 평가 케이스: 비소장·예산 5 시나리오

| 필드 | 값 |
| --- | --- |
| `caseId` | `case-book-032` |
| `purpose` | 이 책을 사지는 않았고, 같은 만에 있던 세 항구가 왜 서로 다른 길을 갔는지 큰 틀만 보고 싶다 |
| `owned` / `maxAdditionalInk` / `depth` | `false` / `5` / `null` |
| `requiredConcepts` | 비교의 기준, 퇴적, 수심과 선박, 항구 이동, 항구 간 경쟁 |
| `helpfulConcepts` | 지도의 시점, 시간차 대조, 신항로, 단계적 쇠퇴 |
| `referencePageNumbers` | 2, 16, 18, 20, 24 |
| `allowedAlternativePageNumbers` | 3, 17, 19, 21, 26 |
| `irrelevantPageNumbers` | 10·11(사본과 원본), 12·13(지도의 생략), 37(견줌 기록), 41·42(지도의 잔존) |

정답 경로는 선수 전이 폐쇄와 같고 5페이지여서 예산 5에 꼭 맞는다. 비교의 기준(2)에서 퇴적(16)으로
가고, 퇴적에서 수심과 선박(18)이 갈라지며, 둘을 함께 선수로 가지는 항구 이동(20)을 지나 항구 간
경쟁(24)에 닿는다. 다섯 페이지로 다섯 필수 개념을 모두 덮는다.

**4.1의 짝인 25는 대체 페이지에 넣지 않았다.** 선수 폐쇄가 6페이지라 예산 5로는 어느 배분으로도 고를
수 없다. 넣으면 죽은 값이 된다. 나머지 정답 네 자리는 짝이 모두 상한 안에 들어 대체에 넣었고, 26은
도움 개념인 `신항로`가 primary이며 폐쇄가 3페이지다.

무관은 절 단위로 골랐다. 사본 판별과 지도의 생략은 지도라는 사료를 다루는 절차이고, 견줌 기록은
판단을 남기는 방법이며, 지도의 잔존은 자료가 남는 방식이다. 넷 다 세 항구가 왜 갈렸는지를 묻는 이
목적 밖이고 필수·도움 개념을 primary로 달지 않는다.

## 재현 조건

1. `python3 build032.py` — 원고와 조각 생성 (PDF SHA 없이 실행하면 자리표시자를 넣는다)
2. `python3 figures032.py pdfbuild032` — 도표 6개 SVG 생성
3. Chrome Headless로 각 SVG를 794×1123 PNG로 렌더링
4. `python3 build_pdf_generic.py 32 5,11,19,25,36,42 pdfbuild032` — 조판 HTML 생성
5. Chrome Headless `--print-to-pdf`로 PDF 출력, `pdfcheck.py`로 구성 확인
6. PDF를 `fixtures/content/ai-route-v2/pdfs/`에 두고 SHA-256을 인자로 `build032.py` 재실행
7. `merge_fragments.py 32`로 정본에 병합

## 검수

- 초고는 42개 `TEXT` 페이지 가운데 40페이지가 하한에 걸렸다. 31번보다 심했다. 마지막 문단을 늘리는
  방식으로 두 차례 손봤고 한 페이지가 더 남아 세 번째로 고쳤다.
- 도표 여섯 장을 PNG로 렌더링해 눈으로 확인했고 둘을 고쳤다. p19는 첫 단면부터 큰 배가 바닥에 닿아
  본문의 「셋 다 닿지 않는다」와 어긋났다 — 모래 두께와 배의 잠긴 깊이를 다시 잡아 단계마다 한 척씩
  닿게 만들고, 물건 이름이 단계마다 흐려지도록 바꿔 도표의 요지가 그림에 드러나게 했다. p11은
  이름표가 상자를 덮고 연결선이 서로 엇갈렸다 — 지도를 한 줄로 펴고 묶음별로 붙여 선이 엇갈리지
  않게 했다.
- p11과 p19의 본문도 그림에 맞춰 다시 썼다. 그림을 고친 뒤 본문을 그대로 두면 어긋난 채 남는다.
- 다른 권과 겹치는 일곱 어절이 없다.
- `ContentBatchConverterTest`의 코퍼스 재고 단언을 갱신했다. 도서 44→45, 페이지 1798→1847,
  이미지 205→211이다.
- 공개 가이드 주제와 비공개 분석 텍스트를 서로 다른 문장으로 적었고, 주제문에 숫자를 쓰지 않았다.
- 본문·도표·평가 데이터에 실존 인물·작품·단체가 등장하지 않는다.

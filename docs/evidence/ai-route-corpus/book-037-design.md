# book-037 「바람길 상인의 연대기」 설계

[역사 카테고리 계획](./history-category-plan.md)의 37번을 만든 근거다. 정책·검증 계약은
[AI 경로 콘텐츠 코퍼스](../../ai-route-content-corpus.md)를 따르고, 이 문서는 그 계약 안에서 내린
선택과 이유만 적는다.

## 대상 도서

- `bookId` 37, 카테고리 역사. 저자·소개는 `src/main/resources/demo/books.json`의 기존 값을 유지한다.
- 제목은 `ai-route-v2` manifest의 `books[].title`이 정본이며 계획 문서의 제목과 같다.
- 실존 교역로·상단·문서를 옮기지 않는다. 무대는 가상의 바람길과 다로 상단, 거점 소금성·비단마을·
  향료항이다. 035부터 연구자 인물을 두지 않으며 이 권도 그대로 따른다.

계획이 정한 범위(대상 조직, 교역로의 위험과 보험 관행, 신용장 같은 금융장치, 교역로 흥망과 경제)가
모두 들어갔다. 평가 시나리오도 계획대로 「소장 · DEEP」이다.

## 개념 범위

이 책의 축은 **길을 줄이는 것이 아니라 짐을 줄이는 것**이다. 3장과 4장의 장치들이 모두 같은 방향을
가리킨다 — 잃을 양을 줄이는 것이 아니라 크게 잃을 가능성을 줄이고, 나르는 거리를 줄이는 것이 아니라
나르는 무게를 없앤다.

계획이 지정한 경계를 지켰다.

- 32(항구)도 교역로의 흥망을 다루지만 원인이 지형과 항로다. 37의 주인공은 상인의 조직과 금융장치이고,
  32에 나오는 퇴적·수심 같은 말이 이 책에는 한 번도 나오지 않는다.
- 34(장부)는 국가가 징수를 위해 만든 장부를 읽는다. 37의 장부는 상단이 몫을 나누려고 만든 것이라
  적는 목적이 다르고, 그래서 적히는 항목도 다르다.

## 장 구성 (49페이지, 목차 1 + 본문 48)

```
1장 짐을 싣기 전에            p2–7    PREREQUISITE  대상 조직·교역로의 위험·화물 선택
2장 상단이라는 짜임           p8–15   CORE          출자와 몫·역할 분담·분배 규칙·분쟁 처리
3장 위험을 나누는 법          p16–23  CORE          분산·위험 분담·보상 관행·선도 거래
4장 짐 없이 오가는 것         p24–31  CORE          운반 비용·신용 증서·신용의 근거·원격 결제
5장 소금성에서 향료항까지     p32–38  EXAMPLE       왕복 추적·비용 계산·검산·출처 표시
6장 장부가 감추는 것          p39–46  COUNTERPOINT  성공 편향·비장부 거래·단절기 기록·상업 사료의 쓸모
7장 바람이 바뀐 뒤            p47–49  CONCLUSION    신용의 근거·성공 편향·상업 사료의 쓸모
```

3.3 둘째 페이지가 이 권의 매듭이다. 보상 약정은 **가릴 수 있는 손실만 덮는다.** 세 갈래 가운데
빼앗김만 들어 있고 상함과 늦어짐은 빠져 있다. 뒤 시기로 갈수록 늦어짐이 커졌는데 그것을 덮는 장치는
끝내 나오지 않았고, 이 빈자리가 6.3의 쇠퇴 설명으로 이어진다.

이미지 6개: p5(잃는 방식 셋), p11(몫을 받는 자리와 삯을 받는 자리), p19(혼자 질 때와 나누어 질 때),
p25(무엇을 실어 나르는가), p33(한 벌로 남은 왕복), p42(장부 안과 밖). 생성 스크립트는
[`figures037.py`](./tools/figures037.py)다.

중복 그룹 1개: `paper-travels-lighter` = [27, 47]. "길을 줄이는 것이 아니라 짐을 줄이는 것이 이 장치의
뜻이다"를 4.2에서 신용 증서의 원리로 세우고 7.1에서 책 전체의 결론으로 다시 쓴다. 47의 선수 폐쇄가
26을 지나므로 짝을 4.2의 **둘째** 페이지에 두었다. 첫 페이지에 두었을 때 `validate_book`이
중복 그룹 충돌로 막았다.

## 선수 관계 설계

1.1이 뿌리이고 1.2·1.3·2.1·6.1·6.4가 곧바로 거기 붙는다. 2장은 2.1에서 2.2·2.3이 갈라지고 2.4는
2.3에서 이어진다.

**3.2와 4.3이 각각 선수를 둘 가진다.** 3.2(위험 분담)는 3.1(분산)과 2.3(분배 규칙)을 함께 건다 —
여럿이 나누어 지려면 짐이 나뉘어 있어 누구 몫이 얼마나 상했는지 셀 수 있어야 하고 나누는 규칙이 미리
정해져 있어야 한다. 4.3(신용의 근거)은 4.2(신용 증서)와 2.1(출자와 몫)을 함께 건다.

3장과 4장이 각각 사슬이고 이 사례의 정답 경로가 두 사슬을 모두 탄다. DEEP 사례라 상한이 15라서
두 갈래를 함께 담을 수 있었다.

- 어느 후보 페이지도 선수 폐쇄가 9페이지를 넘지 않는다.
- 폐쇄 5페이지 이하인 후보 페이지가 일곱 개 장을 모두 덮는다 (기준 3개 장).
- 후보 페이지 48개 전부가 폐쇄 15페이지 이하다 (기준 75%).

## 검증

`corpus_lib.validate_book()` → `validate_fragment.py` → `merge_fragments.py` → `validate_manifest.py`를
차례로 통과했다.

- 49페이지(48~72), 7개 장(최소 6), 내용 역할 5종 모두 사용
- `TEXT` 본문 42페이지가 344~375자(평균 357자, 합계 15,002자)
- `estimatedReadingSeconds`에 60초로 눌린 페이지가 하나도 없음
- `FRONT_MATTER`(목차 p1)와 `aiRouteCandidatePage=false`가 정확히 일치
- 선수 관계가 후보 제외 페이지를 가리키지 않음, 위상 정렬로 49페이지 전체 방문
- PDF 페이지 49개, 텍스트 43개, 이미지 6개(p5,11,19,25,33,42) — `pdfcheck.py`로 확인
- PDF 실제 SHA-256이 manifest의 `pdfSha256`과 일치

## 평가 케이스: 소장·DEEP 시나리오

| 필드 | 값 |
| --- | --- |
| `caseId` | `case-book-037` |
| `purpose` | 이 책을 소장하고 있는데, 먼 길을 오간 상단이 위험과 셈을 어떤 장치로 다뤘는지 깊이 있게 훑어보고 싶다 |
| `owned` / `maxAdditionalInk` / `depth` | `true` / `null` / `DEEP` |
| `requiredConcepts` | 대상 조직, 위험 분담, 보상 관행, 신용 증서, 원격 결제 |
| `helpfulConcepts` | 교역로의 위험, 분배 규칙, 분산, 신용의 근거 |
| `referencePageNumbers` | 2, 4, 6, 8, 12, 16, 18, 20, 24, 26, 28, 30 |
| `allowedAlternativePageNumbers` | 3, 5, 7, 9, 13, 17, 19, 21, 25, 27, 29, 31 |
| `irrelevantPageNumbers` | 14·15(분쟁 처리), 37(출처 표시), 41·42(비장부 거래), 43·44(단절기 기록) |

정답 경로는 선수 전이 폐쇄와 같고 **12페이지**이며 DEEP 상한 15 안에 든다.
1.1에서 갈라진 두 갈래가 각각 3장과 4장의 사슬을 타고 끝까지 간다. 위험을 나누는 쪽은 분산(16) →
위험 분담(18) → 보상 관행(20)으로, 짐을 줄이는 쪽은 운반 비용(24) → 신용 증서(26) → 신용의 근거(28)
→ 원격 결제(30)로 이어진다.

대체 페이지도 열둘로 이 코퍼스에서 가장 많다. 정답 열두 자리의 짝이 모두 DEEP 상한 안에 들어
하나도 빠지지 않았다.

무관은 절 단위로 골랐다. 분쟁 처리는 상단 안의 절차이고, 출처 표시는 셈을 남기는 방법이며, 비장부
거래와 단절기 기록은 자료가 비는 방식이다. 넷 다 위험과 셈의 장치를 훑는 이 목적 밖이고 필수·도움
개념을 primary로 달지 않는다. 2.4와 5.4는 본문에서도 다른 장과 곧바로 이어지지 않는다고 밝혔다.

## 재현 조건

1. `python3 build037.py` — 원고와 조각 생성 (PDF SHA 없이 실행하면 자리표시자를 넣는다)
2. `python3 figures037.py pdfbuild037` — 도표 6개 SVG 생성
3. Chrome Headless로 각 SVG를 794×1123 PNG로 렌더링
4. `python3 build_pdf_generic.py 37 5,11,19,25,33,42 pdfbuild037` — 조판 HTML 생성
5. Chrome Headless `--print-to-pdf`로 PDF 출력, `pdfcheck.py`로 구성 확인
6. PDF를 `fixtures/content/ai-route-v2/pdfs/`에 두고 SHA-256을 인자로 `build037.py` 재실행
7. `merge_fragments.py 37`로 정본에 병합

## 검수

- PR 리뷰에서 「정답 12페이지가 가장 길다」가 틀린 것을 확인해 지웠다. 15페이지인 사례가 다섯
  건이다. 「대체 열둘이 가장 많다」는 사실이어서 그대로 두고 범위만 밝혔다.
- 중복 그룹을 4.2 **첫** 페이지에 달았다가 `validate_book`에 막혔다. 7.1의 선수 폐쇄가 4.2 첫
  페이지를 지나기 때문이다. 둘째 페이지로 옮기고 그 페이지 끝에 명제를 한 번 더 적었다.
- 초고 42쪽 가운데 41쪽이 하한에 걸려 마지막 문단을 늘리는 방식으로 세 차례에 나눠 고쳤다.
- 도표 여섯 장을 PNG로 렌더링해 눈으로 모두 확인했고 하나를 고쳤다. p33은 이름표 넷이 서로 겹쳤다 —
  자리 이름과 자료 이름을 위아래로 갈라 놓고 시작 표시의 화살표를 옮겼다.
- **도표 본문 네 곳이 그림과 어긋나 고쳤다.** p25는 두 길을 좌우로 놓았다고 적었는데 실제로는
  위아래이고, p05는 시기별 무게를 세로 띠라 했는데 가로 줄이며, p33은 되돌아오는 선이 옅다고 했으나
  한 고리로 이어져 있고, p42는 화살표가 오른쪽을 향한다고 했으나 아래를 향한다.
- 다른 권과 겹치는 일곱 어절이 넷 있었고 모두 036과 겹쳤다. 도표의 좌우 대비 설명과 7.2의 맺음
  문장이다. 표현을 바꿔 0으로 만들었다.
- `ContentBatchConverterTest`의 코퍼스 재고 단언을 갱신했다. 도서 48→49, 페이지 1994→2043,
  이미지 229→235이다.
- 공개 가이드 주제와 비공개 분석 텍스트를 서로 다른 문장으로 적었고, 주제문에 숫자를 쓰지 않았다.
- 본문·도표·평가 데이터에 실존 인물·작품·단체가 등장하지 않는다.

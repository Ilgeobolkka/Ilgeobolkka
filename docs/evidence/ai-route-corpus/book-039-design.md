# book-039 「한밤의 인쇄소 혁명」 설계

[역사 카테고리 계획](./history-category-plan.md)의 39번을 만든 근거다. 정책·검증 계약은
[AI 경로 콘텐츠 코퍼스](../../ai-route-content-corpus.md)를 따르고, 이 문서는 그 계약 안에서 내린
선택과 이유만 적는다.

## 대상 도서

- `bookId` 39, 카테고리 역사. 저자·소개는 `src/main/resources/demo/books.json`의 기존 값을 유지한다.
- 제목은 `ai-route-v2` manifest의 `books[].title`이 정본이며 계획 문서의 제목과 같다.
- 실존 도시·인쇄소·인쇄물을 옮기지 않는다. 무대는 가상의 도시 다인성과 그곳의 은자 인쇄소,
  활자공이라 불린 장인들이다. 035부터 연구자 인물을 두지 않으며 이 권도 그대로 따른다.

계획이 정한 범위(필사에서 인쇄로의 전환, 활자 기술의 확산, 인쇄물과 검열·여론, 기술 확산에 대한
사회적 저항)가 모두 들어갔다. 평가 시나리오도 계획대로 「소장 · QUICK」이다.

## 개념 범위

이 책의 축은 **손이 따라올 수 없는 수가 만들어졌다**는 것이다. 인쇄의 효과를 부수가 아니라
**같음**에서 찾는다 — 같지 않으면 여럿이어도 서로 다른 글이고, 서로를 가리킬 수도 없다.

계획이 지정한 경계를 지켰다.

- 다른 권들이 남은 자료를 읽는 방법을 다루는 데 비해 39는 자료를 만들어 내는 기술 자체를 다룬다.
  1.3(필사의 어긋남)만 사료 비판과 닿는데, 그것도 인쇄가 오류를 없애는 것이 아니라 일괄화한다는
  대비를 세우기 위한 것이다.
- 38(벽화)은 남은 것이 만들어진 방식을 묻고, 39는 만드는 방식이 바뀌면 남는 것이 어떻게 달라지는지를
  묻는다. 6.2가 두 권이 만나는 자리다.

## 장 구성 (49페이지, 목차 1 + 본문 48)

```
1장 베껴 쓰던 시절        p2–7    PREREQUISITE  필사의 값·읽는 사람의 수·필사의 어긋남
2장 활자가 하는 일        p8–15   CORE          활자의 원리·조판·동일 복본·활자의 재료
3장 기술은 어떻게 번졌나  p16–23  CORE          기술의 이동·숙련·입지·인쇄물의 값
4장 찍힌 것을 누가 막는가 p24–31  CORE          복본과 통제·사전 검열·사후 회수·여론의 형성
5장 다인성의 한 인쇄소    p32–38  EXAMPLE       작업 순서·판의 흔적·유통 경로·작업 기록
6장 기술이 겪은 것        p39–46  COUNTERPOINT  필사 노동의 저항·인쇄물의 잔존·발행과 독서·기술사의 쓸모
7장 잉크가 마른 뒤        p47–49  CONCLUSION    여론의 형성·인쇄물의 잔존·기술사의 쓸모
```

4.1이 이 권의 매듭이다. 흩어진 장을 붙들 수 없게 되자 통제가 **글에서 만드는 자리로** 옮겨 간다 —
판과 인쇄소와 사람은 흩어지지 않기 때문이다. 그래서 발행처를 적게 하는 제도가 내용을 보지 않고도
작동한다. 이 옮김이 4장 전체의 줄기이고 이 사례의 정답 경로가 여기서 끝난다.

3.4의 낱장 이야기가 이 권의 두 번째 축이다. 값이 내려가 늘어난 것은 책이 아니라 **그전에는 아예
없던 자리**인 낱장이었고, 그 낱장이 가장 적게 남았다. 이 어긋남이 6.2와 7.2로 이어진다.

이미지 6개: p7(같은 책 세 벌), p15(쇠와 나무가 견디는 만큼), p20(인쇄소가 자리 잡은 곳),
p26(찍기 전에 거치는 문), p37(한 판이 남긴 셈), p44(찍힌 수와 읽힌 수). 생성 스크립트는
[`figures039.py`](./tools/figures039.py)다.

036에서 도입한 권 전용 도표 문장 틀을 이어 쓴다. 이 권은 첫 문장을 "맨 위 줄 밑에 '…'라는 짧은 말이
붙어 있다"로, 끝 문장을 "찍은 수와 값은 눈금으로 옮기지 않았다. 그림 맨 밑 줄에 '…'가 적혀 있다"로
고정했다.

중복 그룹 1개: `copies-outrun-the-hand` = [13, 47]. "손이 따라올 수 없는 수가 만들어진 것이 이
기술의 핵심이다"를 2.3에서 동일 복본의 실질로 세우고 7.1에서 책 전체의 결론으로 다시 쓴다. 47의
선수 폐쇄는 [2, 8, 12, 24, 30, 47]이라 짝인 13을 지나지 않는다.

## 선수 관계 설계

1.1이 뿌리이고 1.2·1.3·2.1·6.1·6.4가 곧바로 거기 붙는다. 2장은 2.1에서 2.2·2.3이 갈라지고 2.4는
2.2에서 이어진다. 3장은 2.1에서 3.1로 가고 3.2·3.3이 3.1에 붙으며 3.4만 2.3에 붙는다. 4장은
2.3 → 4.1에서 시작해 4.2 → 4.3의 사슬과 4.4가 갈라진다.

**선수가 둘인 절이 하나도 없다.** QUICK 사례에 맞춘 선택이다. 정답 경로를 짧게 유지하려면
갈래가 모이는 자리가 없어야 한다.

6장은 뒤에 있지만 앞 장에 직접 붙였다 — 6.1과 6.4는 1.1, 6.2는 1.3, 6.3은 3.4다.

- 어느 후보 페이지도 선수 폐쇄가 7페이지를 넘지 않는다.
- 폐쇄 5페이지 이하인 후보 페이지가 일곱 개 장을 모두 덮는다 (기준 3개 장).
- 후보 페이지 48개 전부가 폐쇄 15페이지 이하다 (기준 75%).

## 검증

`corpus_lib.validate_book()` → `validate_fragment.py` → `merge_fragments.py` → `validate_manifest.py`를
차례로 통과했다.

- 49페이지(48~72), 7개 장(최소 6), 내용 역할 5종 모두 사용
- `TEXT` 본문 42페이지가 344~386자(평균 360자, 합계 15,125자)
- `estimatedReadingSeconds`에 60초로 눌린 페이지가 하나도 없음
- `FRONT_MATTER`(목차 p1)와 `aiRouteCandidatePage=false`가 정확히 일치
- 선수 관계가 후보 제외 페이지를 가리키지 않음, 위상 정렬로 49페이지 전체 방문
- PDF 페이지 49개, 텍스트 43개, 이미지 6개(p7,15,20,26,37,44) — `pdfcheck.py`로 확인
- PDF 실제 SHA-256이 manifest의 `pdfSha256`과 일치

## 평가 케이스: 소장·QUICK 시나리오

| 필드 | 값 |
| --- | --- |
| `caseId` | `case-book-039` |
| `purpose` | 이 책을 소장하고 있는데, 인쇄 기술이 무엇을 바꿨는지 핵심만 짧게 짚고 싶다 |
| `owned` / `maxAdditionalInk` / `depth` | `true` / `null` / `QUICK` |
| `requiredConcepts` | 필사의 값, 활자의 원리, 동일 복본, 복본과 통제 |
| `helpfulConcepts` | 읽는 사람의 수, 필사의 어긋남, 조판, 기술의 이동 |
| `referencePageNumbers` | 2, 8, 12, 24 |
| `allowedAlternativePageNumbers` | 3, 5, 6, 9, 10, 13, 16, 25 |
| `irrelevantPageNumbers` | 14·15(활자의 재료), 37(작업 기록), 41·42(인쇄물의 잔존), 43·44(발행과 독서) |

정답 경로는 선수 전이 폐쇄와 같고 4페이지여서 QUICK 상한 5 안에 든다. 필사의 값(2) → 활자의
원리(8) → 동일 복본(12) → 복본과 통제(24)의 한 줄기 사슬이다.

**폐쇄를 일부러 4로 잡았다.** 38번은 폐쇄가 상한과 같은 5라 마지막 정답 페이지의 짝(27)이 폐쇄
6이 되어 대체에서 빠졌다. 39번은 폐쇄를 하나 줄여 정답 네 자리의 짝(3, 9, 13, 25)이 모두 상한 5
안에 들어온다. 같은 QUICK/예산 상한이라도 폐쇄 깊이를 어디에 두느냐로 답 표의 모양이 달라진다는
것을 두 권이 나란히 보이게 했다.

대체 여덟 가운데 넷은 정답의 짝이고 나머지 넷(5, 6, 10, 16)은 도움 개념 넷의 첫 페이지다.

**도표 페이지는 정답과 대체에서 뺐다.** 코퍼스에는 도표를 정답이나 대체에 넣은 사례가 스물셋
있어 강제되는 규칙은 아니다. 38·39·40 세 권에서 일관되게 고른 방침이고, 도표의 본문은
독자에게 닿지 않아 읽을거리로 권하기에 맞지 않다고 보았다.

무관은 절 단위로 골랐다. 활자의 재료는 만드는 재료이고, 작업 기록은 셈을 남기는 방법이며,
인쇄물의 잔존과 발행과 독서는 자료가 걸러진 방식이다. 넷 다 인쇄가 무엇을 바꿨는지를 짧게 짚는 이
목적 밖이고 필수·도움 개념을 primary로 달지 않는다. 2.4와 6.2와 6.3은 본문에서도 앞뒤 장의 흐름과
곧바로 이어지지 않는다고 밝혔다.

## 재현 조건

1. `python3 build039.py` — 원고와 조각 생성 (PDF SHA 없이 실행하면 자리표시자를 넣는다)
2. `python3 figures039.py pdfbuild039` — 도표 6개 SVG 생성
3. Chrome Headless로 각 SVG를 794×1123 PNG로 렌더링
4. `python3 build_pdf_generic.py 39 7,15,20,26,37,44 pdfbuild039` — 조판 HTML 생성
5. Chrome Headless `--print-to-pdf`로 PDF 출력, `pdfcheck.py`로 구성 확인
6. PDF를 `fixtures/content/ai-route-v2/pdfs/`에 두고 SHA-256을 인자로 `build039.py` 재실행
7. `merge_fragments.py 39`로 정본에 병합

## 검수

- 초고 42쪽 전부가 하한에 걸려 마지막 문단을 늘리는 방식으로 세 차례에 나눠 고쳤다.
- **장 구성을 짜다가 1.3에 페이지를 하나 더 넣어 본문이 49쪽이 되었다.** 세 번째 페이지를 덜어
  48쪽으로 맞췄고, 그 결과 이미지 자리가 계획대로 [7, 15, 20, 26, 37, 44]가 되었다.
- 도표 여섯 장을 PNG로 렌더링해 눈으로 모두 확인했고 다섯을 고쳤다. p07은 이름표가 둘째 벌 위에
  겹쳐 오른쪽으로 옮겼고, p15와 p37은 그림이 위쪽에만 몰려 세로로 폈다. p20은 종이 길이 종이
  마을에 닿지 않고 이름표가 성벽과 겹쳤다. p26은 '문' 표시가 첫째 네모 안으로 들어가 네모 사이를
  벌렸다. p44는 맨 위 띠의 화살표가 화면 밖으로 나갔고 아래 세 띠의 점선 테두리가 채움에 묻혀
  보이지 않았다 — 띠 너비를 줄이고 테두리를 따로 그렸다.
- **도표 본문 한 곳을 그림에 맞춰 고쳤다.** p26은 점선 화살표의 이름표가 「그 위에」 있다고 적었는데
  실제로는 화살표 끝이다.
- 도표에 넣었던 「왼쪽에서 오른쪽으로 갈수록 늦게 나온 장이다」 한 줄을 지웠다. 본문에 없는 설명인
  데다 가로축이 견디는 정도이지 인쇄 순서가 아니어서 잘못 읽힐 수 있다.
- 다른 권과 겹치는 일곱 어절이 하나도 없다. 도표 틀을 미리 정한 뒤로 036·038에 이어 세 번째다.
- `ContentBatchConverterTest`의 코퍼스 재고 단언을 갱신했다. 도서 50→51, 페이지 2092→2141,
  이미지 241→247이다.
- 공개 가이드 주제와 비공개 분석 텍스트를 서로 다른 문장으로 적었고, 주제문에 숫자를 쓰지 않았다.
- 본문·도표·평가 데이터에 실존 인물·작품·단체가 등장하지 않는다.

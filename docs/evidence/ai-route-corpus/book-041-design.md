# book-041 「분업과 비교우위: 교환은 왜 이익인가」 설계·검수 근거

SCRUM-485 90권 확장의 두 번째 도서입니다. book-047과 달리 이 문서부터는 `corpus_lib.py`(같은
디렉터리의 `.claude`가 아니라 세션 스크래치패드에 있던 빌더, 저장소에는 산출물만 반영)로 페이지
번호·선수 관계·검증을 자동 생성했습니다. 절 식별자로 선수 관계를 걸어 두면 페이지를 끼워 넣어도
번호가 스스로 재계산되므로, book-047처럼 페이지 번호를 손으로 다시 매기는 작업이 필요 없습니다.

## 개념 범위

분업, 특화, 절대우위·비교우위, 생산가능곡선, 교환의 이익, 시장 조율, 분업의 한계. book-047(가격·수요·공급·균형·탄력성·가격규제·시장실패)과 개념이 겹치지 않습니다. 카테고리 전체 배분은
[`economics-category-plan.md`](./economics-category-plan.md)에 있습니다.

## 장 구성 (52페이지, 목차 1 + 본문 51)

```
1장 왜 혼자 다 만들지 않는가        p2–9    PREREQUISITE  분업
2장 잘하는 일에 집중하기: 특화      p10–16  CORE          특화
3장 비교우위                        p17–30  CORE          절대우위·비교우위·생산가능곡선
4장 교환이 만드는 이익              p31–38  CORE          교환의 이익
5장 시장이 분업을 조율하는 방식     p39–45  CORE          시장조율
6장 분업의 그늘                     p46–50  COUNTERPOINT  분업의 한계
7장 빵집에서 세계 무역까지          p51–52  CONCLUSION    비교우위·교환의 이익
```

이미지 4개: p7(분업 생산 흐름도), p19(비교우위 계산표), p24(생산가능곡선), p42(분업 사슬 도표).

제작 당시 p20·p52를 `gains-need-exchange` 중복 그룹으로 묶었지만 p20이 p52의 전이적 선수라, 선수
폐쇄를 모두 포함하면서 그룹당 한 페이지만 두라는 계약을 동시에 만족할 수 없었습니다. p52는 p20의 단순
대체가 아니라 앞선 비교우위·교환 조건을 종합하는 결론이므로 중복 표시를 제거하고 선수 관계는 유지합니다.

## 도표 좌표

두 사람(갑·을)의 생산가능곡선은 book-047의 수요·공급 그래프와 달리 **같은 시장을 나타내는 것이
아니라 서로 다른 개인의 독립된 제약**이라, 축을 공유하지 않고 각자의 최대 생산량에 맞춰 독립적으로
그렸습니다. 처음에는 book-047처럼 공유 축으로 그렸으나 을의 곡선이 구석에 작게 찌그러져 렌더링
후 다시 손봤습니다.

## 검증

`corpus_lib.validate_book()`로 생성 즉시 검증했고, 별도로 일반화한 `validate_manifest.py`로
book-047과 함께 manifest 전체를 재검증했습니다. PDF는 Chrome Headless로 조립했고 페이지 구조를
직접 파싱해 대조했습니다.

- 52페이지, 목차 1 + 본문 51, 최소 6개 장(7개), 내용 역할 5종 모두 사용
- `FRONT_MATTER`(목차)와 `aiRouteCandidatePage=false`가 정확히 일치
- 선수 관계가 후보 제외 페이지를 가리키지 않음, 위상 정렬로 52페이지 전체 방문
- PDF 페이지 52개, 텍스트 48개, 이미지 4개(p7,19,24,42) — 페이지 구성 파싱으로 확인
- PDF 실제 SHA-256이 manifest와 일치

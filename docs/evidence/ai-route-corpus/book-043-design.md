## 개념 범위

매출·비용·이익 구분, 현금흐름표, 고정비·가변비(손익분기점 포함), 재고관리.
[`economics-category-plan.md`](./economics-category-plan.md)가 미리 정한 배분을 그대로 따랐고,
047(가격이론)·041(분업·비교우위)·042(거래비용·신뢰)과 개념이 겹치지 않는 회계·재무 영역입니다.

## 장 구성 (53페이지, 목차 1 + 본문 52)

```
1장 장부의 시작: 매출과 비용을 나누는 이유   p2–9    PREREQUISITE  매출·비용 구분
2장 이익은 어떻게 남는가                    p10–18  CORE          매출총이익·순이익
3장 돈이 들어오고 나가는 때: 현금흐름표      p19–27  CORE/COUNTERPOINT  현금흐름표
4장 무슨 일이 있어도 나가는 돈: 고정비       p28–33  CORE          고정비
5장 파는 만큼 늘어나는 돈: 가변비와 손익분기점 p34–41 CORE/EXAMPLE  가변비·손익분기점
6장 재고가 많으면 항상 좋을까                p42–48  COUNTERPOINT  재고관리
7장 결론: 열두 가게의 공통 장부              p49–53  CONCLUSION    전체 개념 통합
```

모든 사례는 가상 인물(빵집 다은, 꽃집 은서, 정육점 태호, 분식집 세연)과 가상 상점가("열두 가게")를
배경으로 하며, 실존 기업·인물을 모방하지 않습니다.

이미지 4개: p16(매출·비용·이익 흐름 폭포형 도표), p25(현금흐름표 예시 표), p38(손익분기점
그래프), p48(재고 보유비용·부족비용 저울질 그래프).

제작 당시 p19·p51을 `profit-not-cash` 중복 그룹으로 묶었지만 p19가 p51의 직접 선수입니다. p51은 p19를
대체하는 반복 페이지가 아니라 여러 장의 장부 흐름을 종합하는 결론이므로 중복 표시를 제거하고 선수 관계는
유지합니다.

## 원고 제작 경위

이 도서의 페이지 원고는 세션 스크래치패드에 남아 있던 이전 시도의 `build.py`를 검수 후
재사용했습니다. 재사용 전 다음을 확인·보강했습니다.

- `corpus_lib.validate_book()`이 검사하지 않는 항목인 TEXT 본문 글자수를 별도로 집계한 결과
  평균 479자·최소 397자로 정본이 요구하는 500~700자 하한에 미달하는 페이지가 36개였습니다.
  각 페이지의 서사 흐름에 맞는 문장 1~2개를 덧붙여 전량 500자 이상(최종 500~628자, 평균
  542자)으로 보강했습니다. 새 문장은 기존 명제를 표현만 바꿔 반복하지 않고, 인물의 후속
  행동이나 구체적 결과처럼 실제로 추가 정보를 주는 내용으로만 채웠습니다.
- 원본 설계는 그대로 유지: 5종 `contentRole`(PREREQUISITE/CORE/EXAMPLE/COUNTERPOINT/CONCLUSION)
  모두 사용, 최소 6개 장(7개 장), 이미지 4개. 제작 당시 중복 그룹 1개는 선수 폐쇄 불변식 보강으로
  제거했습니다.

## 검증

`corpus_lib.validate_book()`으로 생성 즉시 검증했고, `validate_fragment.py`로 fragment
단독 검증(공유 manifest.json 미접근)을 통과했습니다.

- 53페이지(목차 1 + 본문 52), 최소 6개 장(7개), 내용 역할 5종 모두 사용
- TEXT 본문 글자수 500~628자(평균 542자), 모두 3문단 이상
- `FRONT_MATTER`(목차)와 `aiRouteCandidatePage=false`가 정확히 일치
- 선수 관계가 후보 제외 페이지를 가리키지 않음, 위상 정렬로 53페이지 전체 방문
- PDF 페이지 53개, 텍스트 49개, 이미지 4개(p16,25,38,48) — `pdfcheck.py` 페이지 구성 파싱으로 확인
- PDF 실제 SHA-256이 fragment와 일치

## 재현 조건

PDF는 Chrome Headless로 조립한 것이라 재생성하면 바이트가 달라져 SHA-256이 바뀝니다. 재생성 시
`manifest.json`의 `pdfSha256`과 이 문서의 값을 함께 갱신해야 합니다.

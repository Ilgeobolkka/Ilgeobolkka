# book-044 「소비자잉여와 후생의 측정」 설계

[경제 카테고리 계획](./economics-category-plan.md)의 44번을 만든 근거다. 정책·검증 계약은
[AI 경로 콘텐츠 코퍼스](../../ai-route-content-corpus.md)를 따르고, 이 문서는 그 계약 안에서 내린
선택과 이유만 적는다.

이 문서는 책을 만든 뒤에 썼다. 아래의 수치와 구조는 현재 정본에서 그대로 확인한 것이고, 당시의
의도가 남아 있지 않은 자리는 지어내지 않았다.

## 대상 도서

- `bookId` 44, 카테고리 경제. 저자·소개는 `src/main/resources/demo/books.json`의 기존 값을 유지한다.
- 제목은 `ai-route-v2` manifest의 `books[].title`이 정본이며 계획 문서의 제목과 같다.
- 실존 인물·기업·연구를 옮기지 않는다. 무대는 가상의 문구점이고 주인은 서윤이다.

계획이 적은 범위(소비자잉여, 생산자잉여, 총잉여, 준거점과 손실회피)가 모두 들어갔다. 소비자잉여는
2장, 생산자잉여는 3장, 총잉여는 4장, 준거점과 손실회피는 6장이다. 계획 문서에는 평가 케이스의 형태가
적혀 있지 않고 진행 표시(**완료**)만 있어 대조할 대상이 없다.

## 개념 범위

이 책의 축은 **재는 절차**다. 목적문이 "값을 조금 내려 볼 참인데 손님이 얻는 몫이 얼마나 늘어나는지
순서대로 재는 방법"을 묻는다. 그래서 1장에서 지불용의를 세우고, 2장에서 그것과 값의 차이를 잉여라
부르고, 5장에서 실제로 재는 순서를 밟는다. 3·4장은 그 자를 파는 쪽과 시장 전체로 넓히는 자리다.

같은 카테고리에서 수요를 다루는 권과 경계를 두었다.

- 47(수요곡선)은 곡선 자체가 무엇이고 어떻게 움직이는지를 다룬다. 044는 그 곡선이 나타내는 후생을
  다루며, 곡선을 계단으로 그려 사람마다 다른 지불용의가 쌓인 결과로만 쓴다.

## 장 구성 (49페이지, 목차 1 + 본문 48)

```
1장 값어치를 매긴다는 것        p2–7    PREREQUISITE  지불용의·가격과 가치의 구분·지불용의의 분포
2장 사는 쪽이 남기는 몫         p8–14   CORE          소비자잉여·소비자잉여의 합·가격 변화와 잉여·넓이 해석
3장 파는 쪽이 남기는 몫         p15–22  CORE          수용가격·생산자잉여·잉여와 이익의 구분·잉여의 변동
4장 두 몫을 더하면              p23–30  CORE          총잉여·교환의 이익·사중손실·잉여의 분배
5장 실제로 재어 보기            p31–38  EXAMPLE       잉여 측정 절차·지불용의 조사·가격 실험
6장 계산이 어긋나는 순간        p39–46  COUNTERPOINT  준거점·손실회피·보유효과·측정의 한계
7장 무엇을 재고 무엇을 남기나   p47–49  CONCLUSION    잉여 측정 절차·측정의 한계
```

이미지 6개: p5(하나의 값, 여러 값어치), p9(한 사람의 잉여), p18(두 계단이 만나는 자리),
p24(옮겨 가는 몫과 사라지는 몫), p37(하루치 계산표), p42(대칭이 아닌 반응). 생성 스크립트는
[`figures044.py`](./tools/figures044.py)다.

중복 그룹 1개: `measure-same-way` = [38, 49]. "얻은 숫자는 아랫값 하나일 뿐이고 남길 것은 다시 잴 수
있는 방식이다"를 5.5에서 문구점 계산의 마무리로 세우고 7.3에서 책 전체의 물음으로 다시 쓴다. 두
페이지 모두 선수가 5.1(31) 하나이고 서로를 지나지 않는다. 한쪽이 다른 쪽의 폐쇄에 들어가면 뒤엣것을
고른 경로에 앞엣것이 반드시 따라와 중복 그룹 규칙을 어긴다.

## 선수 관계 설계

1.1이 뿌리이고 1.2·1.3·2.1이 곧바로 거기 붙는다. 2.3·2.4는 2.1에 붙고 2.2만 2.1과 1.3 둘을 선수로
가진다 — 한 사람에서 여러 사람으로 넘어가려면 사람마다 선이 다르다는 사실이 먼저 있어야 한다.

3장은 1.2(값과 값어치의 구분)에서 갈라져 3.1 → 3.2의 사슬을 이루고 3.3·3.4가 3.2에 붙는다. 4.1은
2.1과 3.2 둘을 선수로 가진다. 총잉여는 두 몫을 더한 것이라 어느 한쪽만으로는 서지 않는다.

5장은 5.1이 2.1에, 5.2가 1.1에, 5.3이 2.3에 붙는다. 재는 방법마다 필요한 바닥이 달라서다 — 물어봐서
알아내는 값은 지불용의만 있으면 되고, 값을 바꿔 보고 아는 값은 값이 내려갈 때 몫이 어떻게 되는지를
먼저 알아야 한다.

6장은 뒤에 있지만 앞 장에 직접 붙였다 — 6.1은 1.1, 6.4는 4.1이고 6.2·6.3만 6.1에서 이어지는 사슬이다.
반례는 그 주장이 세워진 자리에서 읽어야 뜻이 선다.

- 어느 후보 페이지도 선수 폐쇄가 8페이지를 넘지 않는다.
- 폐쇄 5페이지 이하인 후보 페이지가 여섯 개 장을 덮는다 (기준 3개 장).
- 후보 페이지 48개 전부가 폐쇄 15페이지 이하다 (기준 75%).

## 검증

`corpus_lib.validate_book()` → `validate_fragment.py` → `merge_fragments.py` → `validate_manifest.py`를
차례로 통과했다.

- 49페이지(48~72), 7개 장(최소 6), 내용 역할 5종 모두 사용
- `TEXT` 본문 42페이지가 373~565자(평균 439자, 합계 18,455자)
- `estimatedReadingSeconds`에 60초로 눌린 페이지가 하나도 없음
- `FRONT_MATTER`(목차 p1)와 `aiRouteCandidatePage=false`가 정확히 일치
- 선수 관계가 후보 제외 페이지를 가리키지 않음, 위상 정렬로 49페이지 전체 방문
- PDF 페이지 49개, 텍스트 43개, 이미지 6개(p5,9,18,24,37,42) — `pdfcheck.py`로 확인
- PDF 실제 SHA-256이 manifest의 `pdfSha256`과 일치

## 평가 케이스: 소장·BALANCED 시나리오

| 필드 | 값 |
| --- | --- |
| `caseId` | `case-book-044` |
| `purpose` | 가게 값을 조금 내려 볼 참인데, 그때 손님이 얻는 몫이 얼마나 늘어나는지 순서대로 재는 방법을 익히고 싶다 |
| `owned` / `maxAdditionalInk` / `depth` | `true` / `null` / `BALANCED` |
| `requiredConcepts` | 지불용의, 소비자잉여, 소비자잉여의 합, 가격 변화와 잉여, 잉여 측정 절차 |
| `helpfulConcepts` | 지불용의의 분포, 잉여의 넓이 해석, 가격 실험, 지불용의 조사 |
| `referencePageNumbers` | 2, 6, 8, 10, 12, 14, 31, 35, 38 |
| `allowedAlternativePageNumbers` | 3, 9, 11, 13, 32, 33, 36, 37 |
| `irrelevantPageNumbers` | 17~22(생산자잉여 세 절), 43·44(같은 물건 다른 값) |

정답 경로는 선수 전이 폐쇄와 같고 9페이지여서 BALANCED 상한 10 안에 든다. 사슬이 아니라 두 번
갈라지는 나무다. 지불용의(2)에서 지불용의의 분포(6)와 소비자잉여(8)가 갈라지고, 8에서 다시 가격
변화(12)·넓이 해석(14)·문구점의 하루(31)가 갈라진다. 합(10)만 선수가 둘이라 6과 8을 모두 지나야
닿고, 가격 실험(35)은 12에서, 마무리(38)는 31에서 이어진다.

목적이 "순서대로 재는 방법"이라 5장이 정답에 들어간다. 이 코퍼스에서 사례 장이 정답 경로에 들어가는
드문 경우다. 다른 권에서는 5장이 대개 무관으로 빠지지만, 여기서는 재는 절차 자체가 필수 개념
(`잉여 측정 절차`)이라 뺄 수 없다.

무관은 3장의 세 절(3.2·3.3·3.4)과 6.3이다. 이 목적은 사는 쪽이 얻는 몫만 묻고 파는 쪽은 묻지 않는다.
3.1(받아들일 수 있는 최저선)은 무관에 넣지 않았다 — 1.2에서 이어지는 자리이고 값과 값어치의 구분을
파는 쪽에서 다시 보는 페이지라 이 목적의 바닥과 맞닿아 있다. 6.3은 같은 물건에 다른 값이 매겨지는
보유효과를 다루는데, 이는 잉여를 재는 절차가 아니라 그 절차가 흔들리는 자리라 뺐다. 모두 절 단위로
골랐다 — 한 절을 무관과 무관 아님으로 가르면 무관이 아닌 페이지가 무관 페이지를 선수로 밟아야만
닿는 자리가 생긴다.

## 재현 조건

1. `python3 build044.py` — 원고와 조각 생성 (PDF SHA 없이 실행하면 자리표시자를 넣는다)
2. `python3 figures044.py pdfbuild044` — 도표 6개 SVG 생성
3. Chrome Headless로 각 SVG를 794×1123 PNG로 렌더링
4. `python3 build_pdf_generic.py 44 5,9,18,24,37,42 pdfbuild044` — 조판 HTML 생성
5. Chrome Headless `--print-to-pdf`로 PDF 출력, `pdfcheck.py`로 구성 확인
6. PDF를 `fixtures/content/ai-route-v2/pdfs/`에 두고 SHA-256을 인자로 `build044.py` 재실행
7. `merge_fragments.py --replace 44`로 정본에 병합

## 검수

- 정답 페이지 아홉 자리 가운데 1.3(6)만 같은 절 짝이 대체 페이지에 없다. 나머지는 2→3, 8→9, 10→11,
  12→13, 31→32, 35→36으로 짝이 들어가 있고, 2.4(14)와 5.5(38)는 한 페이지짜리 절이라 짝이 없다.
  7은 `지불용의의 분포`가 primary라 도움 개념을 그대로 덮고 선수 폐쇄도 3페이지여서 상한 안에 든다.
  **아직 고치지 않았다.** 022에서 같은 자리를 고쳤으므로 같은 판단을 여기에도 적용할 수 있다.
- 공개 가이드 주제와 비공개 분석 텍스트를 서로 다른 문장으로 적었고, 주제문에 숫자를 쓰지 않았다.
- 본문·도표·평가 데이터에 실존 인물·작품·단체가 등장하지 않는다.

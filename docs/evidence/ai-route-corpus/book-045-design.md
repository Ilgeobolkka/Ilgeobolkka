# book-045 「화폐와 신용창조의 구조」 설계·검수 근거

SCRUM-485 90권 확장, 경제 카테고리 7/10입니다. [book-044](./book-044-design.md)가 세운 두 표준
(원고 생성 스크립트 보존, 본문 500자 하한)을 따랐고, [book-046](./book-046-design.md)과 한 묶음으로
제작했습니다.

## 개념 범위

화폐, 화폐의 기능, 통화량, 유통속도, 예금, 신용창조, 지급준비, 인출 쇄도, 인플레이션,
기대 인플레이션, 공급 충격, 물가지수. 카테고리 계획이 정한 배분(화폐의 기능, 통화량, 신용창조,
인플레이션 기초)을 따랐습니다.

042(거래비용·계약)와 인접해 보이는 1장은 경계를 분명히 두었습니다. 042의 거래비용은 상대가 약속을
지킬지 모르는 문제이고, 045의 짝 맞추기는 서로 원하는 것이 맞물리지 않는 문제입니다. 041(교환의
이익)이 교환이 왜 이익인지를 다룬 반면 045는 그 교환을 성사시키는 매개 자체를 다룹니다. 047의
가격이론과도 층위가 다릅니다. 047은 한 시장의 값이 정해지는 과정이고, 045는 값을 적는 단위 자체가
움직일 때의 이야기입니다.

## 장 구성 (53페이지, 목차 1 + 본문 52)

```
1장 짝이 맞아야 오가던 시절        p2–9    PREREQUISITE  화폐·화폐의 기능
2장 얼마나 도는가: 통화량          p10–18  CORE          통화량·유통속도
3장 예금에서 대출로: 신용창조       p19–25  CORE          예금·신용창조
4장 믿음이 흔들릴 때               p26–33  COUNTERPOINT  인출 쇄도·지급준비
5장 물가가 오른다는 것             p34–41  EXAMPLE       인플레이션·기대
6장 돈으로 설명되지 않는 것         p42–48  COUNTERPOINT  공급 충격·물가지수
7장 결론: 화폐는 약속이다          p49–53  CONCLUSION    전체 개념 통합
```

배경은 가상 마을 "돌마루"와 가상 인물(세운, 유하, 도현, 나경, 진서)이며 실존 지역·기관·인물을
모방하지 않습니다.

이미지 6개: p8(화폐의 세 기능과 각각이 요구하는 성질), p14(지급 수단을 즉시성 순으로 세우고 좁은
돈·넓은 돈을 괄호로 표시), p23(신용창조가 도는 계단), p30(찾으러 온 집 수와 내줄 수 있는 몫),
p38(넓은 돈 증가율과 물가 상승률의 열 해 기록), p46(품목별 상승률과 가중 평균). 돈 쪽을 파랑,
물가·물건 쪽을 붉은 계열로 고정해 여섯 도표에서 같은 뜻으로 씁니다.

중복 그룹 1개: `money-is-a-promise` = [5, 51]. "화폐의 값어치는 물건이 아니라 사람들 사이의 약속에서
나온다"는 명제를 1.2에서 세우고 7.2에서 책 전체를 지나온 언어로 재진술합니다.

## 선수 관계 설계

1.3(화폐의 세 기능)을 2·5장의 뿌리로, 1.2(화폐의 정의)를 3·7장의 뿌리로 두어 장 사이의 사슬을
짧게 유지했습니다. 어느 후보 페이지도 선수 폐쇄가 11페이지를 넘지 않습니다.

- 폐쇄 5페이지 이하인 후보 페이지가 여섯 개 장을 덮습니다 (기준 3개 장).
- 후보 페이지 52개 전부가 폐쇄 15페이지 이하입니다 (기준 75%).

## 검증

`corpus_lib.validate_book()` → `validate_fragment.py` → `merge_fragments.py` →
`validate_manifest.py` → `selftest.py` 순으로 모두 통과했습니다.

- 53페이지(목차 1 + 본문 52), 7개 장, 내용 역할 5종 모두 사용
- `TEXT` 본문 46페이지가 501~541자(평균 520자, 합계 23,934자)로 전량 500자 이상
- `FRONT_MATTER`(목차)와 `aiRouteCandidatePage=false`가 정확히 일치
- 선수 관계가 후보 제외 페이지를 가리키지 않음, 위상 정렬로 53페이지 전체 방문
- PDF 페이지 53개, 텍스트 47개, 이미지 6개(p8,14,23,30,38,46) — `pdfcheck.py`로 확인
- PDF 실제 SHA-256이 manifest의 `pdfSha256`과 일치

## 평가 케이스: 소장·QUICK 시나리오

| 필드 | 값 |
| --- | --- |
| `caseId` | `case-book-045` |
| `purpose` | 이 책을 소장하고 있는데, 시간이 없어 화폐가 무엇이고 신용창조가 어떻게 일어나는지 핵심만 빠르게 훑고 싶다 |

문제(2)에서 화폐의 정의(4)로, 예금(19)에서 대출이 예금을 만드는 과정(21, 22)으로 이어집니다.

## 재현 조건

이 권에는 빌드 스크립트가 없습니다. 원고 `book-045-manuscript.json`과 정본
`manifest.json`·`evaluation.json`이 원본이고, 고칠 때는 이 파일들을 직접 고칩니다.

조판은 `python3 tools/build_pdf_generic.py 45 8,14,23,30,38,46 pdfbuild045`로 원고에서 다시 할 수
있습니다. 다만 그 디렉터리에 도표 PNG(`fig-08.png` 등)가 있어야 합니다. 도표 생성 스크립트가
없고 `pdfbuild045/`는 `.gitignore`로 제외돼 있어, 저장소만으로는 도표를 다시 만들 수 없습니다.

PDF는 Chrome Headless 렌더링이라 다시 만들면 SHA-256이 바뀌므로 `manifest.json`의
`pdfSha256`을 함께 갱신해야 합니다.

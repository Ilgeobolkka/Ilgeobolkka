# book-046 「공공재정과 조세의 원리」 설계·검수 근거

SCRUM-485 90권 확장, 경제 카테고리 8/10입니다. [book-045](./book-045-design.md)와 한 묶음으로
제작했으며 같은 두 표준(원고 생성 스크립트 보존, 본문 500자 하한)을 따랐습니다.

## 개념 범위

세입, 세출, 예산제약, 조세, 누진세, 역진세, 직접세, 간접세, 조세 귀착, 예산 배분, 기회비용,
징수 비용, 공채, 예산 성과. 카테고리 계획이 정한 배분(공공재정, 조세의 종류, 예산제약, 정부의
기회비용)을 따랐습니다.

048(공공재와 공유자원)과 가장 가깝지만 다루는 물음이 다릅니다. 048은 어떤 것이 왜 시장에서
만들어지지 않는지를 재화의 성질로 설명하고, 046은 이미 걷기로 한 돈을 어떤 구조로 걷고 무엇에
나눌지를 다룹니다. 그래서 046에는 무임승차가 개념으로 등장하지 않고, 048에는 조세 귀착이나 세율
구조가 등장하지 않습니다. 047(가격이론)의 가격 개입과도 다릅니다. 047은 값에 손대는 이야기이고
046은 예산의 우선순위를 정하는 이야기입니다.

## 장 구성 (51페이지, 목차 1 + 본문 50)

```
1장 무엇으로 무엇을 하는가       p2–9    PREREQUISITE  세입·세출·예산제약
2장 걷는 방법: 조세의 종류        p10–18  CORE          과세 대상·세율 구조·귀착
3장 쓰는 방법: 예산 배분          p19–25  CORE          우선순위·기회비용
4장 걷는 일이 남기는 자국         p26–32  COUNTERPOINT  행동 변화·징수 비용
5장 한들군의 예산 회의            p33–39  EXAMPLE       실제 회의·차입·사후 평가
6장 숫자가 말해 주지 않는 것       p40–46  COUNTERPOINT  투입과 성과·순부담
7장 결론: 예산은 우선순위를 적은 문서다 p47–51 CONCLUSION 전체 개념 통합
```

배경은 가상 행정구역 "한들군"과 가상 인물(소연, 태식, 미르, 강우, 하람)이며 실존 지역·기관·인물을
모방하지 않습니다.

이미지 6개: p8(세입 갈래에서 하나의 통을 거쳐 세출 갈래로 나가는 흐름), p14(비례·누진·역진 세 선),
p23(같은 총액을 다르게 나눈 세 배분안), p30(세목별 걷은 금액과 걷는 데 든 몫), p37(시설을 쓰는
기간과 갚는 기간), p44(형편별로 내는 몫과 받는 몫). 걷는 쪽을 붉은 계열, 쓰는 쪽을 푸른 계열로
고정해 여섯 도표에서 같은 뜻으로 씁니다.

중복 그룹 1개: `budget-constraint-restated` = [6, 49]. "더 쓰려면 어디선가 덜 써야 한다"는 조건을
1.3에서 세우고 7.2에서 책 전체를 지나온 언어로 재진술합니다. 재진술 페이지(49)의 선수는 짝(6)이
아니라 **짝의 부모(4)**로 겁니다. 짝을 선수로 걸면 49를 고른 경로에 6이 반드시 따라와 중복 그룹
규칙을 어기기 때문이며, book-045·book-048도 같은 방식입니다.

## 선수 관계 설계

1.2(세입과 세출)를 2장의 뿌리로, 1.3(예산제약)을 3·5·6장의 뿌리로 두었습니다. 어느 후보 페이지도
선수 폐쇄가 8페이지를 넘지 않습니다.

- 폐쇄 5페이지 이하인 후보 페이지가 여섯 개 장을 덮습니다 (기준 3개 장).
- 후보 페이지 50개 전부가 폐쇄 15페이지 이하입니다 (기준 75%).

## 검증

`corpus_lib.validate_book()` → `validate_fragment.py` → `merge_fragments.py` →
`validate_manifest.py` → `selftest.py` 순으로 모두 통과했습니다.

- 51페이지(목차 1 + 본문 50), 7개 장, 내용 역할 5종 모두 사용
- `TEXT` 본문 44페이지가 500~546자(평균 517자, 합계 22,779자)로 전량 500자 이상
- `FRONT_MATTER`(목차)와 `aiRouteCandidatePage=false`가 정확히 일치
- 선수 관계가 후보 제외 페이지를 가리키지 않음, 위상 정렬로 51페이지 전체 방문
- PDF 페이지 51개, 텍스트 45개, 이미지 6개(p8,14,23,30,37,44) — `pdfcheck.py`로 확인
- PDF 실제 SHA-256이 manifest의 `pdfSha256`과 일치

## 평가 케이스: 비소장·예산 10 시나리오

| 필드 | 값 |
| --- | --- |
| `caseId` | `case-book-046` |
| `purpose` | 이 책을 사지는 않았고, 세금이 어떤 구조로 걷히고 그 돈이 어떤 기준으로 나뉘는지 큰 틀만 보고 싶다 |

| `helpfulConcepts` | 누진세, 조세 귀착, 기회비용 |
| `referencePageNumbers` | 2, 4, 5, 6, 10, 12, 17, 19, 20, 21 |
| `irrelevantPageNumbers` | 35~37(차입), 45~46(회계연도 밖의 비용) — 큰 틀만 보려는 이 목적과 무관 |

정답 경로는 선수 전이 폐쇄와 같고 정확히 10페이지여서 예산 10을 남김없이 씁니다. 세입 정의(2, 4)와
세출 정의(5), 예산제약(6)에서 갈라져, 걷는 쪽으로는 과세 대상(10)·세율 구조(12)·귀착(17)으로, 쓰는
쪽으로는 우선순위(19, 20)와 기회비용(21)으로 이어집니다. 세율 구조는 12·13 두 페이지가 같은 개념을
같은 깊이로 다루므로 12만 넣고 13은 `allowedAlternativePageNumbers`로 옮겼습니다 — 필수 개념 `세출`을
`primaryConcepts`로 가진 페이지는 5뿐이라 예산 10 안에 자리를 만들어야 했습니다.

## 재현 조건

이 권에는 빌드 스크립트가 없습니다. 원고 `book-046-manuscript.json`과 정본
`manifest.json`·`evaluation.json`이 원본이고, 고칠 때는 이 파일들을 직접 고칩니다.

조판은 `python3 tools/build_pdf_generic.py 46 8,14,23,30,37,44 pdfbuild046`로 원고에서 다시 할 수
있습니다. 다만 그 디렉터리에 도표 PNG(`fig-08.png` 등)가 있어야 합니다. 도표 생성 스크립트가
없고 `pdfbuild046/`는 `.gitignore`로 제외돼 있어, 저장소만으로는 도표를 다시 만들 수 없습니다.

PDF는 Chrome Headless 렌더링이라 다시 만들면 SHA-256이 바뀌므로 `manifest.json`의
`pdfSha256`을 함께 갱신해야 합니다.

`initial-v1` fixture와 같은 Chrome Headless 경로를 썼습니다. Poppler는 이 환경에 없어 변환·검증에
사용하지 않았고, 페이지 구성 검증은 PDF 객체를 직접 파싱해 수행했습니다.

## 이미지 페이지를 이미지로 만든 이유

[콘텐츠 변환과 품질 검증](../../content-conversion.md)은 "추출 결과가 비어 있거나 표·수식·삽화나
복잡한 배치"를 `IMAGE`로 변환한다고 정합니다. 도표를 벡터 SVG로 넣으면 PDF에 실제 텍스트가 남아
추출 결과가 비지 않으므로 `TEXT`로 분류될 수 있습니다.

그래서 도표 6개는 제목까지 포함해 페이지 전체를 하나의 PNG로 만들어 배치했습니다. 해당 페이지의
콘텐츠 스트림에는 텍스트 연산자가 없고 이미지 그리기 연산자만 남습니다. `initial-v1`이 카테고리 PNG를
A4 페이지에 넣은 방식과 같은 판단입니다.

## 도표 좌표 기준

세 그래프가 같은 축과 같은 선을 공유하도록 수요와 공급을 하나의 식으로 고정했습니다.

```
수요 D: p = 5000 - 10q      공급 S: p = 10q      교점 (250개, 2500원)
축: 수량 100~400개, 가격 1000~4000원
```

이 기준에서 3000원의 초과공급과 2000원의 초과수요가 각각 100개, 1800원 가격상한의 초과수요가
140개로 떨어집니다. 본문과 도표 명세의 수치를 이 값으로 맞췄습니다.

## 검증

### PDF 구조

PDF 객체를 파싱해 확인했습니다. 루트 `/Pages`에서 `/Kids`를 재귀로 걸어 페이지 순서를 얻고, 각
페이지의 콘텐츠 스트림을 풀어 연산자를 확인했습니다.

| 확인 | 기대 | 결과 |
| --- | --- | --- |
| `/Type /Page` 객체 수 | 57 | 57 |
| 루트 `/Pages`의 `/Count` | 57 | 57 |
| 텍스트 연산자(`Tj`/`TJ`)가 있는 페이지 | 51 | 51 |
| 이미지 연산자만 있는 페이지 | 8, 13, 21, 27, 39, 46 | 일치 |
| 내용이 없는 페이지 | 0 | 0 |

### fixture 정합

`manifest.json`·`evaluation.json`·원고를 정본 요건에 대해 검사했습니다. **72개 항목 전부 통과**이며
주요 항목은 [`fixtures/content/ai-route-v2/README.md`](../../../fixtures/content/ai-route-v2/README.md)의
검증 결과에 있습니다. ③단계에서 추가한 항목은 다음 세 가지입니다.

- `pdfSha256`이 소문자 hex 64자
- PDF 파일이 존재하고 0바이트를 넘음
- PDF 파일의 실제 SHA-256이 `manifest.json`의 `pdfSha256`과 일치

## 재현 조건

PDF를 다시 만들면 Chrome 버전·폰트·렌더링 차이로 바이트가 달라져 SHA-256도 바뀝니다. 이 파일럿의
PDF는 고정 입력이며, 다시 만들 경우 `manifest.json`의 `pdfSha256`을 함께 갱신하고 이 문서의 값도
바꿔야 합니다.

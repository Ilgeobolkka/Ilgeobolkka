## 개념 범위

배제성, 경합성, 사유재, 클럽재, 공유자원, 공공재, 무임승차, 공유지의 비극, 혼잡, 이용 규칙,
혼잡 요금. [`economics-category-plan.md`](./economics-category-plan.md)가 정한 배분(배제성·경합성
매트릭스, 네 분류, 공유지의 비극)을 따랐습니다.

047과의 구분은 카테고리 계획이 미리 적어 둔 그대로입니다. 047은 공공재를 시장실패의 한 사례로
배제불가능성만 다루고, 048은 두 축의 조합 전체와 경합성이 있는 공유자원에 집중합니다. 044(잉여)와도
겹치지 않습니다. 044는 거래가 남기는 몫의 크기를 재고, 048은 그 거래가 아예 성립하지 않거나 값을
매길 수 없는 자리를 다룹니다.

## 장 구성 (53페이지, 목차 1 + 본문 52)

```
1장 두 가지 물음                    p2–9    PREREQUISITE  배제성·경합성
2장 네 칸: 사유재·클럽재·공유자원·공공재 p10–18  CORE          네 분류
3장 공공재가 모자라게 공급되는 이유    p19–25  CORE          무임승차
4장 공유자원과 공유지의 비극          p26–33  COUNTERPOINT  공유지의 비극·혼잡
5장 칸을 옮기는 방법                p34–41  EXAMPLE       울타리·이용 규칙·혼잡 요금
6장 분류가 흔들리는 자리             p42–48  COUNTERPOINT  분류의 가변성
7장 결론: 무엇을 먼저 물을 것인가     p49–53  CONCLUSION    전체 개념 통합
```

모든 사례는 가상 마을 "여울마을"과 가상 인물(명주, 도경, 유나, 한결, 소림)을 배경으로 하며, 실존
지역·인물·단체를 모방하지 않습니다.

이미지 6개: p8(빈 이×이 교차표), p14(같은 표를 여울마을 사례로 채운 것), p23(두 집의 부담 여부에
따른 네 결과), p30(이용자 수에 따른 전체 수확과 한 사람 몫), p38(세 가지 관리 방식 비교),
p46(두 축 평면 위의 위치). p8·p14·p46은 같은 두 축을 같은 방향으로 씁니다 — 오른쪽으로 갈수록 막기
쉽고 위로 갈수록 많이 줄어듭니다.

중복 그룹 1개: `traits-belong-to-situation` = [5, 51]. "막을 수 있는지는 물건이 아니라 수단과
형편에 달렸다"는 명제를 1.2에서 처음 세우고 7.2에서 책 전체를 지나온 언어로 재진술합니다.

## 선수 관계 설계

1.5(두 물음의 독립성)를 2·6·7장의 공통 뿌리로 두고, 3·4·5장은 각각 2장의 해당 칸에서 갈라져 나옵니다.
어느 후보 페이지도 선수 폐쇄가 12페이지를 넘지 않습니다.

- 폐쇄 5페이지 이하인 후보 페이지가 1·2·6장 세 개 장을 덮습니다 (기준 3개 장).
- 후보 페이지 52개 전부가 폐쇄 15페이지 이하입니다 (기준 75%).

## 검증

`corpus_lib.validate_book()` → `validate_fragment.py` → `merge_fragments.py` →
`validate_manifest.py` → `selftest.py` 순으로 모두 통과했습니다.

- 53페이지(목차 1 + 본문 52), 7개 장, 내용 역할 5종 모두 사용
- `TEXT` 본문 46페이지가 503~542자(평균 520자, 합계 23,947자)로 전량 500자 이상
- `estimatedReadingSeconds`가 90~100초에 분포하고 60초 하한에 눌린 페이지가 없음
- `FRONT_MATTER`(목차)와 `aiRouteCandidatePage=false`가 정확히 일치
- 선수 관계가 후보 제외 페이지를 가리키지 않음, 위상 정렬로 53페이지 전체 방문
- PDF 페이지 53개, 텍스트 47개, 이미지 6개(p8,14,23,30,38,46) — `pdfcheck.py`로 확인
- PDF 실제 SHA-256이 manifest의 `pdfSha256`과 일치

## 평가 케이스: 소장·BALANCED 시나리오

| 필드 | 값 |
| --- | --- |
| `caseId` | `case-book-048` |
| `purpose` | 이 책을 소장하고 있는데, 공공재와 공유자원이 무엇이 어떻게 다른지 개념과 사례를 균형 있게 훑어보고 싶다 |
| `owned` / `maxAdditionalInk` / `depth` | `true` / `null` / `BALANCED` |
| `requiredConcepts` | 배제성, 경합성, 공공재, 공유자원 |
| `helpfulConcepts` | 무임승차, 공유지의 비극, 사유재 |
| `referencePageNumbers` | 2, 4, 6, 9, 10, 15, 17, 19, 26, 28 |
| `irrelevantPageNumbers` | 31~33, 39~41 (혼잡과 혼잡 요금 — 두 칸의 차이를 잡으려는 이 목적과 무관) |

정답 경로는 선수 전이 폐쇄와 같고 정확히 10페이지여서 BALANCED 상한을 남김없이 씁니다. 두 물음
정의(4, 6)에서 독립성(9)을 거쳐 네 칸 중 셋(10, 15, 17)으로 갈라지고, 각 칸의 대표 문제(19 무임승차,
26·28 공유지의 비극)로 이어집니다.

시나리오는 가장 적게 쓰인 축 중 하나인 소장·BALANCED를 골랐습니다. 병합 후 12건의 분포는 예산 0·5·15와
BALANCED·DEEP이 각 2건, 예산 10과 QUICK이 각 1건입니다.

## 재현 조건

이 권에는 빌드 스크립트가 없습니다. 원고 `book-048-manuscript.json`과 정본
`manifest.json`·`evaluation.json`이 원본이고, 고칠 때는 이 파일들을 직접 고칩니다.

조판은 `python3 tools/build_pdf_generic.py 48 8,14,23,30,38,46 pdfbuild048`로 원고에서 다시 할 수
있습니다. 다만 그 디렉터리에 도표 PNG(`fig-08.png` 등)가 있어야 합니다. 도표 생성 스크립트가
없고 `pdfbuild048/`는 `.gitignore`로 제외돼 있어, 저장소만으로는 도표를 다시 만들 수 없습니다.

PDF는 Chrome Headless 렌더링이라 다시 만들면 SHA-256이 바뀌므로 `manifest.json`의
`pdfSha256`을 함께 갱신해야 합니다.

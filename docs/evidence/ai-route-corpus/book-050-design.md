# book-050 「경제 데이터를 읽는 법: 상관과 인과」 설계·검수 근거

SCRUM-485 90권 확장, 경제 카테고리 9/10입니다. [book-044](./book-044-design.md)가 세운 두 표준
(원고 생성 스크립트 보존, 본문 500자 하한)을 따랐습니다.

## 범위와 제목을 바꾼 경위

카테고리 계획의 원래 항목은 「물가지수와 경제 데이터 해석」이고 개념 범위는 "물가지수, 인플레이션
계산, 상관과 인과, 표본편향"이었습니다. 그런데 앞서 만든 [book-045](./book-045-design.md)가 물가를
화폐 현상으로 다루면서 5~6장에서 물가지수의 구성(장바구니, 가중치 선택, 평균이 덮는 것, 품목별
상승률 차이)을 이미 상당히 다뤘습니다. 그대로 두면 같은 개념을 표현만 바꿔 반복하지 말라는 정본
기준에 걸립니다.

그래서 50번의 범위를 **상관·인과·표본편향**으로 좁히고 물가지수 구성은 45번에 남겼습니다. 제목도
범위에 맞게 바꿨으며, 갱신한 제목의 정본은 이 문서와 `ai-route-v2` manifest의 `books[].title`입니다.
카테고리 계획 표도 함께 고쳤습니다.

책 안에서 물가나 지수를 예로 들지 않은 것도 같은 이유입니다. 사례는 상권 방문객 수, 배달 건수,
사고 건수, 조명 시간, 매출로만 구성했습니다.

## 과학 29번과의 경계 (앞으로 만들 권에 대한 메모)

[`science-category-plan.md`](./science-category-plan.md)의 book-029 「기후 데이터를 읽는 방법」은
개념 범위에 "상관과 인과, 표본편향"이 들어 있어 이 책과 정면으로 겹칩니다. 50번을 먼저 만들었으므로
**29번을 만들 때 그 두 개념을 다시 가르치지 않도록** 범위를 좁혀야 합니다.

29번에 남는 것: 기후 자료의 평균과 이동평균, 날씨와 기후의 구분, 관측 지점과 기간에 따른 자료의
성질, 장기 추세와 단기 변동의 분리. 곧 기후 자료 자체의 다루기이며, 추론의 일반 규칙은 50번이
맡습니다. 이 메모는 과학 카테고리 계획 문서에도 적어 두었습니다.

## 개념 범위

자료 정의, 측정 절차, 상관, 교란변수, 역인과, 비교집단, 표본편향, 무응답편향, 생존편향, 자기선택,
자연실험, 구간 선택, 기저효과, 지표 왜곡.

## 장 구성 (53페이지, 목차 1 + 본문 52)

```
1장 숫자가 오기까지              p2–9    PREREQUISITE  자료 정의·측정 절차
2장 함께 움직인다는 것            p10–18  CORE          상관의 방향과 세기
3장 원인이라고 말하려면           p19–25  CORE          교란변수·역인과·비교집단
4장 누가 표본에 들어왔는가        p26–33  COUNTERPOINT  무응답·생존·자기선택
5장 실제로 읽어 보기             p34–41  EXAMPLE       세 사례·자연실험
6장 다루는 사람이 만드는 왜곡      p42–48  COUNTERPOINT  구간 선택·기저효과·지표 왜곡
7장 결론: 자료는 세상을 본 기록이다 p49–53  CONCLUSION    다섯 물음
```

배경은 가상 상권 "새들목"과 가상 인물(예린, 만수, 다율, 준영, 하경)이며 실존 지역·상호·인물을
모방하지 않습니다.

이미지 6개: p8(현상에서 표까지의 단계와 각 단계에서 빠지는 것), p14(같은 요약값을 갖는 네 가지
점그림), p23(상관이 관측됐을 때 가능한 네 구조), p30(빠진 자리가 고른 경우와 몰린 경우),
p38(같은 점그림에 두 설명을 얹은 그림), p46(같은 자료에서 세 구간을 잘라 낸 그림). 자료·관측을
파랑, 원인·경고를 붉은 계열로 고정해 여섯 도표에서 같은 뜻으로 씁니다.

도표의 점 배치는 난수를 쓰지 않고 고정 목록이나 규칙식으로 만들었습니다. 실행할 때마다 그림이
달라지면 PDF를 다시 만들 때 원고와 어긋난 것인지 난수 탓인지 구분할 수 없기 때문입니다.

중복 그룹은 없습니다. 처음에는 `record-not-world` = [6, 51]로 묶었습니다 — "자료는 세상 자체가 아니라
어떤 절차로 세상을 본 기록이다"라는 명제를 1.3에서 세우고 7.2에서 재진술하기 때문입니다. 그러나 51의
선수(6, 26) 중 26도 6을 선수로 두므로 51을 고른 경로에는 6이 반드시 따라옵니다. book-049와 같은
이유로 선수 관계를 그대로 두고 그룹 표시만 지웠습니다.

## 선수 관계 설계

1.2(자료 정의)를 2장의 뿌리로, 1.3(측정 절차)을 4장의 뿌리로 두고, 3장은 2.2에서, 5·7장은 3.1과
4.1에서 갈라집니다. 어느 후보 페이지도 선수 폐쇄가 9페이지를 넘지 않습니다.

- 폐쇄 5페이지 이하인 후보 페이지가 여섯 개 장을 덮습니다 (기준 3개 장).
- 후보 페이지 52개 전부가 폐쇄 15페이지 이하입니다 (기준 75%).

## 검증

`corpus_lib.validate_book()` → `validate_fragment.py` → `merge_fragments.py` →
`validate_manifest.py` → `selftest.py` 순으로 모두 통과했습니다.

- 53페이지(목차 1 + 본문 52), 7개 장, 내용 역할 5종 모두 사용
- `TEXT` 본문 46페이지가 500~543자(평균 517자, 합계 23,786자)로 전량 500자 이상
- `FRONT_MATTER`(목차)와 `aiRouteCandidatePage=false`가 정확히 일치
- 선수 관계가 후보 제외 페이지를 가리키지 않음, 위상 정렬로 53페이지 전체 방문
- PDF 페이지 53개, 텍스트 47개, 이미지 6개(p8,14,23,30,38,46) — `pdfcheck.py`로 확인
- PDF 실제 SHA-256이 manifest의 `pdfSha256`과 일치

첫 조각 검증에서 `duplicatePageGroups`를 [7, 51]로 잘못 적어 실패했습니다. 중복 표시를 단 것은
1.3의 첫 페이지(6)였고, 검증기가 manifest의 실제 그룹과 평가 데이터의 그룹을 대조해 걸러 냈습니다.
평가 쪽을 [6, 51]로 고쳐 통과했으나, 정본 병합 때 그 그룹 자체가 실현 불가능함이 드러나 지웠습니다
(위 「장 구성」 절).

## 평가 케이스: 소장·DEEP 시나리오

| 필드 | 값 |
| --- | --- |
| `caseId` | `case-book-050` |
| `purpose` | 이 책을 소장하고 있는데, 함께 움직인다는 것과 원인이라는 것을 어떻게 구분하는지, 그리고 표본이 어떻게 치우치는지를 제대로 익히고 싶다 |
| `owned` / `maxAdditionalInk` / `depth` | `true` / `null` / `DEEP` |
| `requiredConcepts` | 상관, 인과, 교란변수, 표본편향 |
| `helpfulConcepts` | 역인과, 생존편향, 비교집단 |
| `referencePageNumbers` | 2, 4, 6, 10, 12, 17, 19, 20, 21, 22, 23, 24, 26, 28, 29 |
| `irrelevantPageNumbers` | 42~46 (구간 선택과 기저효과 — 보여 주는 쪽의 왜곡이라 추론 구분을 익히려는 이 목적과 무관) |

정답 경로는 선수 전이 폐쇄와 같고 정확히 15페이지여서 DEEP 상한을 남김없이 씁니다. 자료 정의(4)와
측정 절차(6)에서 갈라져, 한 갈래는 상관(10, 12, 17)에서 인과 판별(19~24)로, 다른 갈래는
표본편향(26, 28, 29)으로 이어집니다. 필수 개념 `인과`를 `primaryConcepts`로 가진 후보는 23이므로 23을
경로에 넣고, 상관을 같은 깊이로 한 번 더 다루는 13을 `allowedAlternativePageNumbers`로 옮겨 상한
15페이지를 맞췄습니다.

시나리오는 DEEP을 골랐습니다. 이 책에서 실제로 필요한 경로가 두 갈래로 나뉘어 열다섯 페이지를
채우기 때문입니다. 당시 기준 15건의 분포는 DEEP 3건, 나머지 여섯 시나리오 각 2건이었고, 이 다섯 권을
뒤늦게 정본에 병합한 현재는 18건입니다.

## 재현 조건

`python3 tools/build050.py`로 원고와 조각을, `python3 tools/figures050.py`로 도표 SVG를 다시 만들 수
있습니다. PDF는 Chrome Headless 렌더링이라 다시 만들면 SHA-256이 바뀌므로 `manifest.json`의
`pdfSha256`을 함께 갱신해야 합니다.

## 검수

- 최종 검수자: 저장소 소유자
- 도표 6개는 렌더링 결과를 눈으로 확인했습니다. 구간별 그림은 각 구간의 값 범위에 맞춰 세로로 늘려
  그렸는데, 그리는 도구들이 실제로 그렇게 자동 조정하며 같은 자료가 구간에 따라 다르게 보이는
  이유의 절반이 이 자동 조정에 있기 때문입니다. 두 무리가 섞인 점그림은 본문의 조명·매출 사례와
  같은 방향이 나오도록 배치를 뒤집었습니다.
- 실존 작품·저자·본문을 모방하거나 인용하지 않았고, 사례의 상호·인물·지명은 모두 가상입니다.
- 외부 이미지 자산을 반입하지 않고 도표를 직접 작성했습니다.
- 개인을 식별할 수 있는 정보는 포함하지 않았습니다.

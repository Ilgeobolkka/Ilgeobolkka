# book-062 「무대조명 설계의 기초」 설계

[예술 카테고리 계획](./art-category-plan.md)의 62번을 만든 근거다. 정책·검증 계약은
[AI 경로 콘텐츠 코퍼스](../../ai-route-content-corpus.md)를 따르고, 이 문서는 그 계약 안에서 내린
선택과 이유만 적는다.

## 대상 도서

- `bookId` 62, 카테고리 예술. 저자·소개는 `src/main/resources/demo/books.json`의 기존 값을 유지한다.
- 제목은 `ai-route-v2` manifest의 `books[].title`이 정본이며 이 문서의 제목과 같다.
- 실존 극장·작품·인물을 옮기지 않는다. 무대는 가상의 「해든소극장」, 인물은 조명감독 도경과 배우 나린이다.
  예술 카테고리의 앞선 네 권(061 구도, 064 종이 조형, 066 벽화, 067 사운드)과 인물·공간이 겹치지 않는다.

## 개념 범위

계획 문서가 정한 범위(광원의 방향과 강도, 조명의 색온도, 조명 큐, 그림자와 대비)를 그대로 따른다.
같은 카테고리의 065(색채 지각)와 경계가 가장 가까우므로 **색을 켈빈 값이라는 물리량으로만** 다루고
색이 주는 정서적 반응은 다루지 않는다. 4장에서 "이 눈금이 관객의 감정을 재는 것이 아니라 광원의
물리적 성질을 재는 것"이라고 명시해 그 경계를 본문에도 남겼다.

067(영상 사운드)과는 매체가 다르고, 061(화면 구도)과는 다루는 대상이 화면이 아니라 광원이라 겹치지
않는다. 다만 61의 "화면 안에서 무엇을 보게 할지"라는 문제의식은 62의 1장과 닿아 있어, 62는 그 선택을
**빛이라는 도구로** 수행한다는 점을 도입에서 분명히 했다.

## 장 구성 (53페이지, 목차 1 + 본문 52)

```
1장 빛을 놓기 전에 정하는 것   p2–11   PREREQUISITE  조명의 역할·등기구·방향·세기·큐
2장 방향이 얼굴을 만든다       p12–19  CORE          정면광·측면광·역광·상부광·하부광
3장 세기와 대비               p20–27  CORE          밝기의 상대성·대비비·그림자·암전
4장 색온도라는 눈금            p28–35  CORE          켈빈·광원별 값·색필터·혼합
5장 큐를 짜는 일               p36–43  EXAMPLE       큐시트·전환 시간·장면 전환·리허설
6장 계획이 어긋나는 순간        p44–49  COUNTERPOINT  배우 동선·공간 제약·시각 순응
7장 결론: 빛은 무엇을 보게 할지 정한다  p50–53  CONCLUSION  네 변수 종합·설계 점검
```

책 전체를 **방향·세기·색온도·큐** 네 변수로 묶고 1장에서 넷을 모두 예고한 뒤 2~5장이 하나씩 펼친다.
6장은 그 네 값이 계획대로 가지 않는 세 경우를, 7장은 넷을 다시 하나로 모은다.

이미지 6개: p8(세기만 바꾼 세 무대), p14(방향에 따라 갈리는 얼굴), p23(같은 장면, 다른 대비),
p30(하나의 눈금 위에 놓인 빛들), p38(같은 곳에 닿는 세 가지 속도), p46(천장이 정하는 각도).
여섯 가운데 넷이 "조건을 고정하고 값 하나만 바꾼 비교"다. 빛이 닿는 영역은 노란 계열, 어둠은 회색
계열로 여섯 도표에서 같은 뜻으로 고정했다. 생성 스크립트는 [`figures062.py`](./tools/figures062.py)다.

중복 그룹 1개: `light-decides-what-is-seen` = [2, 50]. "조명은 밝히는 동시에 밝히지 않는 쪽을 정하는
일"이라는 명제를 1.1에서 세우고 7.1에서 책 전체를 지나온 언어로 재진술한다. 재진술 페이지(50)에는
선수를 두지 않았다. 짝(2)을 선수로 걸면 50을 고른 경로에 2가 반드시 따라와 중복 그룹 규칙을 어기기
때문이며, book-045·046이 쓴 처리와 같다.

## 선수 관계 설계

1.1(조명의 역할)을 1장 나머지 절의 뿌리로 두고, 2장은 1.3(방향)에서, 3장은 1.4(세기)에서, 4장은
1.2(등기구)에서, 5장은 1.5(큐)에서 갈라진다. 6장은 각 문제가 어긋나는 변수의 절에 붙였다.

- 어느 후보 페이지도 선수 폐쇄가 5페이지를 넘지 않는다.
- 폐쇄 5페이지 이하인 후보 페이지가 일곱 개 장을 모두 덮는다 (기준 3개 장).
- 후보 페이지 52개 전부가 폐쇄 15페이지 이하다 (기준 75%).

얕게 건 이유는 이 책의 개념이 서로 앞뒤 관계보다 병렬 관계에 가깝기 때문이다. 측면광을 이해하는 데
역광이 필요하지 않고, 색온도를 이해하는 데 큐가 필요하지 않다. 실제로 필요한 것은 1장의 기본 변수
정의뿐이라 그 절들만 뿌리로 두었다.

## 검증

`corpus_lib.validate_book()` → `validate_fragment.py` → `merge_fragments.py` → `validate_manifest.py`를
차례로 통과했다.

- 53페이지(48~72), 7개 장(최소 6), 내용 역할 5종 모두 사용
- `TEXT` 본문 46페이지가 427~588자(평균 510자, 합계 23,469자)로 전량 345자 이상 — 60초로 눌리는
  페이지가 없다
- `FRONT_MATTER`(목차)와 `aiRouteCandidatePage=false`가 정확히 일치
- 선수 관계가 후보 제외 페이지를 가리키지 않음, 위상 정렬로 53페이지 전체 방문
- PDF 페이지 53개, 텍스트 47개, 이미지 6개(p8,14,23,30,38,46) — `pdfcheck.py`로 확인
- PDF 실제 SHA-256이 manifest의 `pdfSha256`과 일치

초고는 페이지당 365~518자였다. 조판해 보니 A4 한 면이 절반쯤 비어 다른 권과 인상이 달라, 500자 미만
44페이지에 마지막 문단을 하나씩 더했다. 원고를 다시 쓰지 않고 `EXTRA` 문단만 더하는 방식은
build044.py가 쓴 것과 같다.

## 평가 케이스: 비소장·예산 5 시나리오

| 필드 | 값 |
| --- | --- |
| `caseId` | `case-book-062` |
| `purpose` | 이 책을 사지는 않았고, 빛이 어느 쪽에서 오느냐에 따라 배우의 얼굴이 어떻게 달라지는지만 먼저 보고 싶다 |
| `owned` / `maxAdditionalInk` / `depth` | `false` / `5` / `null` |
| `requiredConcepts` | 빛의 방향, 정면광, 측면광 |
| `helpfulConcepts` | 조명의 역할, 그림자, 역광, 상부광, 하부광 |
| `referencePageNumbers` | 2, 6, 12, 14, 15 |
| `irrelevantPageNumbers` | 28~31(색온도 눈금), 36~37·42~43(큐 기록과 리허설 절차) — 방향만 보려는 이 목적과 무관. 절 단위로 넣어 짝 페이지를 쪼개지 않는다 |

정답 경로는 선수 전이 폐쇄와 같고 정확히 5페이지여서 예산 5를 남김없이 쓴다. 조명의 역할(2)에서
방향(6)으로, 방향에서 정면광(12)과 측면광(14, 15)으로 갈라지는 최단 경로다.

시나리오는 예산 5를 골랐다. 계획 문서가 62번에 배정한 값이기도 하고, 병합 직전 정본에서 예산 5가
18건 가운데 1건뿐이라 가장 적게 쓰인 축이었다. 병합 후 19건의 분포는 예산 5와 예산 15가 각 2건,
나머지 다섯 시나리오가 각 3건이다.

## 재현 조건

1. `python3 build062.py` — 원고와 조각 생성 (PDF SHA 없이 실행하면 자리표시자를 넣는다)
2. `python3 figures062.py pdfbuild062` — 도표 6개 SVG 생성
3. Chrome Headless로 각 SVG를 794×1123 PNG로 렌더링
4. `python3 build_pdf_generic.py 62 8,14,23,30,38,46 pdfbuild062` — 조판 HTML 생성
5. Chrome Headless `--print-to-pdf`로 PDF 출력, `pdfcheck.py`로 구성 확인
6. PDF를 `fixtures/content/ai-route-v2/pdfs/`에 두고 SHA-256을 인자로 `build062.py` 재실행
7. `merge_fragments.py`로 정본에 병합

## 검수

- 여섯 도표를 PNG로 렌더링해 눈으로 확인했다. 첫 렌더에서 p14는 방향 표시와 부제가 겹쳤고, p46은
  그림자 길이 차이가 배우 뒤에 가려 보이지 않았으며, p8은 빛 웅덩이가 무대 밖으로 새어 세 무대의
  크기가 달라 보였다. 셋 다 고쳐 다시 렌더링했다.
- PDF의 목차 페이지와 본문 페이지를 Poppler로 이미지화해 조판을 확인했다. 목차 32줄이 한 페이지에
  들어간다.
- 공개 가이드 주제와 비공개 분석 텍스트를 서로 다른 문장으로 적었고, 주제문에 숫자를 쓰지 않았다.
- 본문·도표·평가 데이터에 실존 인물·작품·단체가 등장하지 않는다.

## 검토 반영

병합 뒤 세 갈래로 나눠 독립 검토를 받았다. 도메인 사실성, 평가 정답지, 카테고리 안 개념 경계다. 아래는 그
결과로 고친 것이고, 고치지 않기로 한 지적은 PR 본문에 적었다.

- 평가 정답지: `helpfulConcepts`에 상부광·하부광을 더했다. 목적이 "빛이 어느 쪽에서 오느냐"인데 위·아래 방향의
  개념이 required·helpful 어디에도 없어, 그 페이지를 고른 경로가 개념 점수를 받지 못했다.
- 평가 정답지: 무관 페이지에 p30을 더했다. 설계 문서는 28~31로 적었는데 실제 값에서 30만 빠져 같은 절이 갈려 있었다.
- 사실: "세기를 올리면 빛이 닿는 범위가 넓어진다"를 "눈에 보이는 범위가 넓어진다"로 고쳤다. 빛이 닿는 기하는
  세기와 무관하다.
- 사실: 색온도가 다른 두 빛의 밝기 비교에 "무대처럼 어두운 조도에서는"이라는 조건을 붙였다. 밝은 조도에서는
  반대 방향이다.
- 장 참조 오류 3건(p6·p7·p9의 "사장")을 이장·이장·삼장으로 고쳤다.
- 겹침: 6.3의 제작자 순응 대목이 065 6.2와 4단 구조까지 같아, 062는 관객 순응만 남기고 그 절을 다시 썼다.

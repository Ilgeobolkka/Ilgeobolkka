# book-070 「창작의 시작: 초안과 제약」 설계

[예술 카테고리 계획](./art-category-plan.md)의 70번을 만든 근거다. 이 권으로 예술 카테고리 10권이
모두 채워졌다. 정책·검증 계약은 [AI 경로 콘텐츠 코퍼스](../../ai-route-content-corpus.md)를 따르고,
이 문서는 그 계약 안에서 내린 선택과 이유만 적는다.

## 대상 도서

- `bookId` 70, 카테고리 예술. 저자·소개는 `src/main/resources/demo/books.json`의 기존 값을 유지한다.
- 제목은 `ai-route-v2` manifest의 `books[].title`이 정본이며 이 문서의 제목과 같다.
- 실존 인물·작품을 옮기지 않는다. 무대는 가상의 「첫줄 작업실」, 인물은 시온과 나루다.
  062~069의 인물과 겹치지 않는다.

## 개념 범위

계획 문서가 정한 범위(백지공포, 초안·스케치의 역할, 제약을 이용한 발상, 반복과 수정)를 그대로 따른다.
이 권은 예술 카테고리에서 **유일하게 매체를 특정하지 않는다.**

- 061~069는 각각 완성된 결과물의 원리를 다룬다. 구도, 조명, 쉼, 접기, 색, 벽화, 사운드, 균형,
  프레이밍이 모두 특정 매체의 기법이다.
- 070은 어떤 매체든 착수 단계에서 겪는 공통 과정을 다룬다. 그래서 사례가 특정 재료나 기법에 기대지
  않고, 다른 아홉 권이 다룬 기법 이야기를 되풀이하지 않는다.
- 1.4(재료와 도구)에서 도구가 결과를 정한다는 이야기가 나오지만, 어떤 도구를 어떻게 쓰는지는 다루지
  않고 "무엇으로 시작하느냐가 이미 첫 번째 결정"이라는 착수의 문제로만 다룬다.

## 장 구성 (51페이지, 목차 1 + 본문 50)

```
1장 시작하지 못하는 시간   p2–11   PREREQUISITE  시작의 저항·초안·제약·작업 조건·작업 단위
2장 초안을 만드는 법       p12–19  CORE          양 우선·변형·선별·초안의 범위
3장 제약을 고르기          p20–27  CORE          자기 제약·제약 유형·과도한 제약·제약 해제
4장 고쳐 나가기            p28–35  CORE          수정 우선순위·단일 변경·되돌리기·완료 판단
5장 작업실의 하루          p36–43  EXAMPLE       착수 절차·교착 대응·피드백·작업 기록
6장 방법이 통하지 않을 때  p44–49  COUNTERPOINT  마감·의욕 변동·방법의 적합성
7장 결론: 시작은 기술이다  p50–51  CONCLUSION    종합
```

1장이 다섯 개념을 세우고 2~4장이 초안·제약·수정으로 나누어 펼친다. 6장은 그 방법들이 통하지 않는 세
경우(마감, 의욕 저하, 개인차)를 다룬다. 7장은 두 페이지로 줄였다. 이 책은 5장 전체가 이미 실천 절차라
결론에서 점검 물음을 따로 두지 않아도 됐다.

이미지 6개: p8(조건이 다르면 다른 것이 나온다), p14(하나에서 갈라진 여섯), p23(좁혀야 보인다),
p30(무엇이 달라지게 했는가), p38(막혔을 때 여는 순서), p46(의욕은 오르내리고 작업은 이어진다).
과정을 다루는 책이라 여섯 도표가 모두 "무엇에서 무엇으로 가는가"를 그린다. 진행은 화살표, 남는 갈래는
굵은 선, 버려지는 갈래는 옅은 선으로 고정했다. 생성 스크립트는 [`figures070.py`](./tools/figures070.py)다.

중복 그룹 1개: `starting-is-a-skill` = [2, 50]. "시작하지 못하는 것은 의지가 아니라 상태의 문제"라는
명제를 1.1에서 세우고 7.1에서 책 전체를 지나온 언어로 재진술한다. 재진술 페이지(50)에는 선수를 두지
않았다. 짝(2)을 선수로 걸면 50을 고른 경로에 2가 반드시 따라와 중복 그룹 규칙을 어기기 때문이며,
book-062·063·065·068·069와 같은 처리다.

## 선수 관계 설계

1.1(시작의 저항)을 뿌리로 두고 1.2(초안)와 1.3(제약)이 갈라진다. 2장은 1.2에서, 3장은 1.3에서, 4장은
2.3(선별)에서, 5장은 1.5(작업 단위)에서 갈라진다. 4장을 2.3에 붙인 것은 고칠 것을 고르는 일이 초안을
고르는 일과 같은 판단이기 때문이다.

- 어느 후보 페이지도 선수 폐쇄가 8페이지를 넘지 않는다.
- 폐쇄 5페이지 이하인 후보 페이지가 일곱 개 장을 모두 덮는다 (기준 3개 장).
- 후보 페이지 50개 전부가 폐쇄 15페이지 이하다 (기준 75%).

가장 깊은 곳은 4.3(되돌리기)으로 4.2 → 4.1 → 2.3 → 2.1 → 1.2 → 1.1을 거친다. 되돌리기는 단일 변경을,
단일 변경은 수정 순서를, 수정 순서는 고르는 기준을 전제하므로 이 사슬은 실제 의존이다.

## 검증

`corpus_lib.validate_book()` → `validate_fragment.py` → `merge_fragments.py` → `validate_manifest.py`를
차례로 통과했다.

- 51페이지(48~72), 7개 장(최소 6), 내용 역할 5종 모두 사용
- `TEXT` 본문 44페이지가 412~496자(평균 458자, 합계 20,172자)
- `FRONT_MATTER`(목차)와 `aiRouteCandidatePage=false`가 정확히 일치
- 선수 관계가 후보 제외 페이지를 가리키지 않음, 위상 정렬로 51페이지 전체 방문
- PDF 페이지 51개, 텍스트 45개, 이미지 6개(p8,14,23,30,38,46) — `pdfcheck.py`로 확인
- PDF 실제 SHA-256이 manifest의 `pdfSha256`과 일치

초고는 333~483자로 하한이 정본 기준(345자)에 미달했다. 069와 같이 420자에 못 미친 40페이지에 `EXTRA`
문단을 더해 412~496자로 맞췄다.

## 평가 케이스: 소장·DEEP 시나리오

| 필드 | 값 |
| --- | --- |
| `caseId` | `case-book-070` |
| `purpose` | 이 책을 소장하고 있는데, 새 작업을 시작해 초안을 고르고 고쳐 나가는 절차 전체를 차근히 익히고 싶다 |
| `owned` / `maxAdditionalInk` / `depth` | `true` / `null` / `DEEP` |
| `requiredConcepts` | 초안, 양 우선, 선별, 수정 우선순위, 단일 변경 |
| `helpfulConcepts` | 시작의 저항, 되돌리기, 완료 판단, 변형 |
| `referencePageNumbers` | 2~5, 12, 13, 16, 17, 28~34 |
| `irrelevantPageNumbers` | 22·24~25(제약의 종류와 강도), 44~47(마감과 의욕 대응) — 착수와 수정 절차만 익히려는 이 목적과 무관 |

정답 경로는 선수 전이 폐쇄와 같고 정확히 15페이지여서 DEEP 상한을 남김없이 쓴다. 시작의 저항(2, 3)에서
초안(4, 5)으로, 초안에서 양 우선(12, 13)과 선별(16, 17)로, 선별에서 수정 절차(28~34)로 이어지는 하나의
긴 사슬이다. 이 책에서 가장 긴 갈래이고 DEEP은 그것을 담을 수 있는 유일한 깊이다.

시나리오는 계획 초안의 QUICK 대신 **소장·DEEP**을 골랐다. QUICK은 이미 4건으로 가장 많았고, 이 책은
착수부터 수정까지가 하나로 이어지는 구조라 다섯 페이지에 담을 수 없었다. 병합 후 24건의 분포는 소장
셋이 각 4건, 비소장 넷이 각 3건이다.

## 재현 조건

1. `python3 build070.py` — 원고와 조각 생성 (PDF SHA 없이 실행하면 자리표시자를 넣는다)
2. `python3 figures070.py pdfbuild070` — 도표 6개 SVG 생성
3. Chrome Headless로 각 SVG를 794×1123 PNG로 렌더링
4. `python3 build_pdf_generic.py 70 8,14,23,30,38,46 pdfbuild070` — 조판 HTML 생성
5. Chrome Headless `--print-to-pdf`로 PDF 출력, `pdfcheck.py`로 구성 확인
6. PDF를 `fixtures/content/ai-route-v2/pdfs/`에 두고 SHA-256을 인자로 `build070.py` 재실행
7. `merge_fragments.py`로 정본에 병합

## 검수

- 여섯 도표를 PNG로 렌더링해 눈으로 확인했다. p30은 위아래 두 줄의 대비가 도표의 전부라, 위 줄에서 세 곳이
  동시에 바뀌고 아래 줄에서 한 곳씩 바뀌는 것이 한눈에 보이는지를 중점으로 봤다.
- 공개 가이드 주제와 비공개 분석 텍스트를 서로 다른 문장으로 적었고, 주제문에 숫자를 쓰지 않았다.
- 본문·도표·평가 데이터에 실존 인물·작품·단체가 등장하지 않는다.

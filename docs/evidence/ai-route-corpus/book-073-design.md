# book-073 「재현과 원인 격리: 디버깅 방법론」 설계

[기술 카테고리 계획](./tech-category-plan.md)의 73번을 만든 근거다. 정책·검증 계약은
[AI 경로 콘텐츠 코퍼스](../../ai-route-content-corpus.md)를 따르고, 이 문서는 그 계약 안에서 내린
선택과 이유만 적는다.

## 대상 도서

- `bookId` 73, 카테고리 기술. 저자·소개는 `src/main/resources/demo/books.json`의 기존 값을 유지한다.
- 제목은 `ai-route-v2` manifest의 `books[].title`이 정본이며 계획 문서의 제목과 같다.
- 실존 회사·제품·도구 이름을 쓰지 않는다. 조사 도구도 '관찰 지점', '기록', '확인'처럼 뜻으로만
  적었고, 6장 사례의 화면과 자료도 일반 업무 용어로만 서술했다.

계획이 정한 범위(재현 가능한 최소 사례 만들기, 원인 격리, 관찰과 가설 검증)가 모두 들어갔다. 평가
시나리오도 계획대로 「비소장 · 예산 5」다.

## 개념 범위

이 책의 축은 **지금 이것은 관찰인가 짐작인가**와 **이 확인은 무엇을 가르는가**다. 앞의 물음이 조사의
바탕을 정하고 뒤의 물음이 다음 행동을 정한다. 재현(1.3), 최소 사례(2.1), 이분 탐색(3.2), 반증 가능한
가설(4.5)이 모두 이 두 물음의 도구로 배치된다.

계획이 지정한 카테고리 내부 경계를 지켰다.

- 75(로그)와 겹치지 않도록 기록을 **조사 중에 사람이 남기는 확인 기록**으로만 다뤘다. 로그 레벨,
  구조화된 로그, 수집 파이프라인은 나오지 않고, 4.2의 관찰 지점도 조사용 임시 장치로만 쓴다.
- 78(쿼리 성능)과 겹치지 않도록 성능 문제를 특정 영역으로 다루지 않는다. 이 책의 좁히기는 어떤
  종류의 문제에도 같은 절차로 적용되는 일반 방법론이다.
- 77(테스트)과 겹치지 않도록 2.7과 5.7의 사례 보존을 **재발 감지 장치**로만 적고 시험 전략·대체물·
  계약 검증은 다루지 않는다.
- 72(데이터 검증)와 겹치지 않도록 잘못된 값의 차단을 다루지 않고 이미 일어난 증상의 추적만 다룬다.
- 71·74·76·79·80의 소재는 등장하지 않는다.

## 장 구성 (50페이지, 목차 1 + 본문 49)

```
1장 문제를 문제로 만들기     p2–8    PREREQUISITE·COUNTERPOINT  증상과 원인·관찰과 짐작·재현
2장 재현 가능한 최소 사례    p9–15   CORE·COUNTERPOINT  최소 사례·축소 절차·변수 고정·사례 보존
3장 원인을 좁히는 방법       p16–22  CORE·COUNTERPOINT  원인 격리·이분 탐색·시간·자리·변경 실험
4장 관찰과 가설              p23–29  CORE·COUNTERPOINT  가설 검증·관찰의 영향·단일 변경·반증
5장 조사가 빗나가는 자리     p30–36  COUNTERPOINT·CORE  최근 변경 편향·원인과 계기·복합 원인
6장 한 문제를 좁혀 간 기록   p37–43  EXAMPLE            한 증상을 재현에서 수정까지 따라간 기록
7장 조사 판단 기준           p44–50  COUNTERPOINT·CONCLUSION  시간 배분·전략 선택·점검·인계
```

절은 장마다 일곱 개이고 절 하나가 페이지 하나다. 1.2가 이 권의 매듭이다. 관찰과 짐작을 갈라 적는
규칙이 1.5의 문제 기술, 4.1의 가설, 4.5의 반증 가능성, 5.5의 사전 배제, 7.5의 기록 취사로 이어진다.

6장은 앞 다섯 장의 절차를 한 증상에 순서대로 적용하는 장이다. 무엇을 보고 무엇을 정했는지를 적고,
6.5에서는 세운 가설 둘 가운데 하나가 기각되는 과정을 그대로 남겼다.

이미지 4개: p7(증상에서 원인으로), p13(줄이는 과정의 기록), p20(좁히는 두 방향),
p33(원인이 겹쳐 있을 때). 생성 스크립트는 [`figures073.py`](./tools/figures073.py)다.

이 권의 도표 문장 틀은 "제목 밑에 '…'가 한 줄로 적혀 있다"로 시작하고 "그림 맨 아래 줄에는 '…'가
있다"로 끝난다. 072("제목 아래에 … 적혀 있다")·074("제목 밑에 … 붙어 있다")와 다른 문장을 쓴다.
도표에는 시간과 횟수를 눈금으로 넣지 않았다 — 조사에 걸리는 시간은 문제마다 달라 숫자를 넣으면
본문에 없는 기준이 생긴다.

중복 그룹 1개: `keep-the-repro` = [15, 36]. "최소 사례를 남겨 두면 같은 문제가 다시 왔을 때 즉시
확인할 수 있다"를 2.7에서 사례 보존의 이유로 세우고 5.7에서 재발 감지 장치의 재료로 다시 쓴다.
15의 폐쇄는 [2, 4, 9, 15]이고 36의 폐쇄는 [2, 4, 9, 16, 23, 30, 31, 36]이라 서로를 지나지 않으며,
2.7을 선수로 삼는 절이 없어 둘을 함께 담는 후보도 없다.

## 선수 관계 설계

1.1이 뿌리이고 1.2·1.3이 곧바로 붙는다. 2장은 1.3 → 2.1에서, 3장은 2.1 → 3.1에서, 4장은
3.1 → 4.1에서, 5장은 4.1 → 5.1에서 시작한다. 개념이 증상 → 재현 → 사례 → 격리 → 가설로 이어지는
한 줄기라 각 장의 첫 절만 앞 장에 붙이고 나머지는 장 안에서 갈라지게 했다.

6장은 2.1에 붙였다. 사례가 재현과 축소에서 시작하기 때문이다. 7장은 각 절이 요약하는 장에 직접
붙였다(7.1·7.2는 3.1, 7.3은 3.2, 7.4는 4.3, 7.5는 4.7, 7.6은 7.4, 7.7은 7.2).

- 어느 후보 페이지도 선수 폐쇄가 10페이지를 넘지 않는다.
- 폐쇄 5페이지 이하인 후보 페이지가 여섯 개 장을 덮는다 (기준 3개 장).
- 후보 페이지 49개 전부가 폐쇄 15페이지 이하다 (기준 75%).

## 검증

`corpus_lib.validate_book()` → `validate_fragment.py` → `merge_fragments.py` → `validate_manifest.py`를
차례로 통과했다.

- 50페이지(48~72), 7개 장(최소 6), 내용 역할 5종 모두 사용
- `TEXT` 본문 45페이지가 344~401자(평균 365자, 합계 16,435자)
- `estimatedReadingSeconds`에 60초로 눌린 페이지가 하나도 없음
- `FRONT_MATTER`(목차 p1)와 `aiRouteCandidatePage=false`가 정확히 일치
- PDF 페이지 50개, 텍스트 46개, 이미지 4개(p7,13,20,33) — `pdfcheck.py`로 확인
- PDF 실제 SHA-256이 manifest의 `pdfSha256`과 일치 (657,637 bytes)
- 다른 권과 겹치는 일곱 어절이 하나도 없다

## 평가 케이스: 비소장·예산 5 시나리오

| 필드 | 값 |
| --- | --- |
| `caseId` | `case-book-073` |
| `purpose` | 지금 붙잡은 문제를 어디서부터 좁혀야 할지 몰라서, 재현을 만들고 원인을 격리하는 데 꼭 필요한 만큼만 짧게 짚고 싶다 |
| `owned` / `maxAdditionalInk` / `depth` | `false` / `5` / `null` |
| `requiredConcepts` | 증상과 원인, 재현, 최소 사례, 원인 격리, 가설 검증 |
| `helpfulConcepts` | 관찰과 짐작, 변수 고정, 이분 탐색, 문제 기술 |
| `referencePageNumbers` | 2, 4, 9, 16, 23 |
| `allowedAlternativePageNumbers` | 3, 5, 6, 10, 11, 17 |
| `irrelevantPageNumbers` | 30·33(최근 변경 편향·복합 원인), 38·40·42(재현 구성·구간 확인·원인 확정) |

정답 경로는 선수 폐쇄와 같고 다섯 페이지여서 예산 5를 정확히 채운다. 1.1 → 1.3 → 2.1 → 3.1 → 4.1의
한 줄기 사슬이고, 필수 개념 다섯이 이 다섯 페이지의 primary와 하나씩 대응한다.

**폐쇄를 상한과 같게 잡되 사슬로 만들었다.** 072는 같은 사슬 구조를 예산 0에서 여섯 페이지로 썼고,
073은 예산 5에서 다섯 페이지로 쓴다. 두 권이 같은 모양의 경로를 서로 다른 예산에서 만들어, 예산이
경로 길이를 어떻게 제한하는지 나란히 보이게 했다.

대체 여섯은 모두 폐쇄가 다섯 이하라 예산 안에서 갈아 끼울 수 있다. 셋은 정답의 짝이고(3·5·6은
1장의 다른 절), 10·11은 축소 절차와 변수 고정, 17은 이분 탐색으로 들어가는 첫 페이지다.

무관은 절 단위로 골랐다. 5.1·5.4는 조사가 빗나가는 자리의 이야기이고 6장의 셋은 한 증상의 진행 기록이다. 이 목적은 필요한 절차만 짧게 짚는 것이라 다섯 다 목적
밖이고, 필수·도움 개념을 primary로 달지 않으며, 정답·대체 어느 페이지도 이들을 선수로 거치지 않는다.

## 재현 조건

1. `python3 build073.py` — 원고와 조각 생성 (PDF SHA 없이 실행하면 자리표시자를 넣는다)
2. `python3 figures073.py pdfbuild073` — 도표 4개 SVG 생성
3. Chrome Headless로 각 SVG를 794×1123 PNG로 렌더링
4. `python3 build_pdf_generic.py 73 7,13,20,33 pdfbuild073` — 조판 HTML 생성
5. Chrome Headless `--print-to-pdf`로 PDF 출력, `pdfcheck.py`로 구성 확인
6. PDF를 `fixtures/content/ai-route-v2/pdfs/`에 두고 SHA-256을 인자로 `build073.py` 재실행
7. `merge_fragments.py 73`로 정본에 병합

## 검수

- 초고 45쪽 가운데 열다섯 쪽이 344자에 못 미쳐 `estimatedReadingSeconds`가 60초로 눌렸다. 각 쪽의
  마지막 문단에 한 문장씩 더해 344~401자로 맞췄다.
- 도표 네 장을 PNG로 렌더링해 눈으로 모두 확인했고 p13을 고쳤다. 맨 윗줄의 칸 열여섯 개가 오른쪽
  '증상 있음' 이름표를 덮고 있어 칸 너비와 간격을 줄였다.
- 도표를 그리면서 본문 설명 두 곳을 그림에 맞춰 고쳤다. p13은 넷째 줄의 칸이 셋째 줄보다 많아
  "아래로 갈수록 대체로 칸이 줄어"로 고쳤고, p20은 "확인할수록 두 끝 사이가 좁아진다"를 화살표의
  실제 위치를 적는 문장으로 바꿨다.
- 초고에서 039·072·074와 일곱 어절이 겹치는 자리가 다섯 나왔다. 점검 항목 마무리, 결론 도입, 기록의
  쓸모, 도표 도입 두 곳이다. 모두 다시 썼고, 도표 도입 문장은 이 권 전용 틀로 통일했다.
- 본문 수정 뒤 PDF를 다시 출력하고 SHA-256과 조각을 함께 갱신했다.
- 공개 가이드 주제와 비공개 분석 텍스트를 서로 다른 문장으로 적었고, 주제문에 숫자를 쓰지 않았다.
  50개 주제문과 50개 분석 텍스트에 중복이 없다.
- 본문·도표·평가 데이터에 실존 인물·작품·단체·제품이 등장하지 않는다.
- **리뷰 뒤 무관 페이지를 다시 골랐다.** 초고는 아홉 권이 모두 6장의 같은 다섯 페이지를
  무관으로 적어 평가 데이터가 권마다 구분되지 않았다. 이 권은 5장의 두 절과 6장의 세 절로
  바꿔 카테고리 안에서 겹치지 않는 세트가 되게 했다. 원고와 PDF는 바뀌지 않았다.
- 리뷰 뒤 7.7의 공개 주제문을 이 권의 것으로 바꿨다. 초고는 아홉 권이 같은 문장을 썼다.
- `ContentBatchConverterTest`의 코퍼스 재고 단언을 갱신했다. 도서 53→54, 페이지 2241→2291,
  이미지 255→259다.

# book-076 「기본값과 실패 경계의 설계」 설계

[기술 카테고리 계획](./tech-category-plan.md)의 76번을 만든 근거다. 정책·검증 계약은
[AI 경로 콘텐츠 코퍼스](../../ai-route-content-corpus.md)를 따르고, 이 문서는 그 계약 안에서 내린
선택과 이유만 적는다.

## 대상 도서

- `bookId` 76, 카테고리 기술. 저자·소개는 `src/main/resources/demo/books.json`의 기존 값을 유지한다.
- 제목은 `ai-route-v2` manifest의 `books[].title`이 정본이며 계획 문서의 제목과 같다.
- 실존 회사·제품·설정 파일 형식을 쓰지 않는다. 설정 층·상한·경계처럼 뜻으로만 적었고, 6장 사례의
  연동 상대도 일반 업무 용어로만 서술했다.

계획이 정한 범위(기본값 설계, 실패 경계, 설정 우선순위)가 모두 들어갔다. 평가 시나리오도 계획대로
「소장 · BALANCED」다.

## 개념 범위

이 책의 축은 **아무도 정하지 않으면 무엇이 쓰이는가**와 **잘 안 될 때 어디까지 번지는가**다. 앞의
물음이 기본값을 정하고(1장, 2장) 뒤의 물음이 경계를 정한다(3장, 4장). 5장의 값들은 두 물음이 만나는
자리이고, 6장은 한 연동에서 두 물음을 차례로 푼 기록이다.

계획이 지정한 카테고리 내부 경계를 지켰다.

- 73(디버깅)이 이미 일어난 문제를 사후에 좁히는 방법을 다루는 데 비해 76은 실패를 미리 예상해 경계를
  설계하는 사전 대비를 다룬다. 재현·가설·좁히기는 나오지 않는다.
- 74(함수와 모듈)와 겹치지 않도록 경계를 코드 구조가 아니라 **실패의 영향 범위**로만 썼다. 결합도·
  응집도·모듈 분해는 나오지 않는다.
- 72(데이터 검증)와 겹치지 않도록 값의 유효성은 다루지 않는다. 이 책의 값은 검증 대상이 아니라
  동작을 정하는 설정 값이다.
- 78(쿼리 성능)과 겹치지 않도록 5장의 값 조정을 성능 튜닝이 아니라 경계 임계값 설정으로만 다뤘다.
- 71·75·77·79·80의 소재는 등장하지 않는다.

## 장 구성 (50페이지, 목차 1 + 본문 49)

```
1장 기본값이 하는 일             p2–8    PREREQUISITE·COUNTERPOINT  기본값·안전한 기본값·암묵 동작
2장 설정과 우선순위              p9–15   CORE·COUNTERPOINT  설정 층·우선순위 규칙·값 출처·설정 난립
3장 실패를 다루는 경계           p16–22  CORE·COUNTERPOINT  실패 경계·빠른 실패·상한·재시도·은폐
4장 줄여서 버티기                p23–29  CORE·COUNTERPOINT  점진적 저하·기능 우선순위·과부하·고착
5장 경계를 정하는 값들           p30–36  CORE·COUNTERPOINT  임계값 근거·검증·상호작용·환경별·노후
6장 한 연동의 경계를 정한 기록   p37–43  EXAMPLE            상한 부재 장애에서 경계 설정까지
7장 경계 설계 판단               p44–50  COUNTERPOINT·CONCLUSION  방어 수준·실패 노출·점검·균형
```

절은 장마다 일곱 개이고 절 하나가 페이지 하나다. 1.3이 이 권의 매듭이다. 기본값은 그 값을 가장 적게
아는 사람에게 적용되므로 최선이 아니라 가장 덜 위험한 쪽으로 고른다는 원칙이 3.1의 실패 경계,
3.7의 실패 은폐, 5.5의 환경별 값, 7.1의 방어 수준으로 이어진다.

6장은 앞 다섯 장의 판단을 한 연동에 적용한다. 대기 상한이 설정되지 않아 도구의 기본값이 시스템 동작을
정하고 있던 상태에서 시작해, 상한과 재시도와 저하 대상을 정하고, 값이 실제로 걸리는지 확인하는 데서
상한이 둘이었다는 사실을 발견하는 과정을 그대로 적었다.

이미지 4개: p7(값이 정해지는 자리), p13(설정이 겹치는 모양), p20(실패가 번지는 길),
p26(부하에 따른 응답의 단계). 생성 스크립트는 [`figures076.py`](./tools/figures076.py)다.

이 권의 도표 문장 틀은 "제목 바로 아래에 '…'라는 한 줄이 있다"로 시작하고 "그림의 마지막 줄은
'…'이다"로 끝난다. 072·073·074·075·078과 각각 다른 문장을 쓴다. 도표에는 초와 건수를 눈금으로 넣지
않았다 — 알맞은 값은 시스템마다 달라 숫자를 넣으면 본문에 없는 기준이 생긴다.

중복 그룹 1개: `fail-loud-not-silent` = [22, 45]. "대신하는 값과 실제 값을 구분할 수 없게 만드는 것이
가장 나쁜 선택이다"를 3.7에서 실패 은폐의 결론으로 세우고 7.2에서 책 전체의 원칙으로 다시 쓴다.
22의 폐쇄는 [2, 4, 16, 22]이고 45의 폐쇄는 [2, 4, 44, 45]라 서로를 지나지 않으며, 3.7을 선수로 삼는
절이 없어 둘을 함께 담는 후보도 없다.

## 선수 관계 설계

1.1이 뿌리이고 1.2·1.3·2.1이 곧바로 붙는다. 3장은 1.3 → 3.1에서 시작하고 4장과 6장도 3.1에 붙으며,
5장은 4.1에 붙는다. 2장은 1.1에서 갈라져 나와 3장 이후와 독립적으로 읽힌다. 설정과 실패 경계가 서로
전제하지 않는 두 갈래라는 구조를 선수 관계에도 그대로 두었다.

7장은 각 절이 요약하는 장에 직접 붙였다(7.1·7.2는 1.3, 7.3은 2.7, 7.4는 3.2, 7.5는 5.6, 7.6은 4.3,
7.7은 7.2).

- 어느 후보 페이지도 선수 폐쇄가 9페이지를 넘지 않는다. 이 카테고리에서 가장 얕다.
- 폐쇄 5페이지 이하인 후보 페이지가 일곱 개 장을 모두 덮는다 (기준 3개 장).
- 후보 페이지 49개 전부가 폐쇄 15페이지 이하다 (기준 75%).

## 검증

`corpus_lib.validate_book()` → `validate_fragment.py` → `merge_fragments.py` → `validate_manifest.py`를
차례로 통과했다.

- 50페이지(48~72), 7개 장(최소 6), 내용 역할 5종 모두 사용
- `TEXT` 본문 45페이지가 344~383자(평균 359자, 합계 16,158자)
- `estimatedReadingSeconds`에 60초로 눌린 페이지가 하나도 없음
- `FRONT_MATTER`(목차 p1)와 `aiRouteCandidatePage=false`가 정확히 일치
- PDF 페이지 50개, 텍스트 46개, 이미지 4개(p7,13,20,26) — `pdfcheck.py`로 확인
- PDF 실제 SHA-256이 manifest의 `pdfSha256`과 일치 (646,678 bytes)
- 다른 권과 겹치는 일곱 어절이 하나도 없다

## 평가 케이스: 소장·BALANCED 시나리오

| 필드 | 값 |
| --- | --- |
| `caseId` | `case-book-076` |
| `purpose` | 이 책을 소장하고 있는데, 정하지 않았을 때 쓰이는 값과 잘 안 될 때 막는 자리를 균형 있게 정리하고 싶다 |
| `owned` / `maxAdditionalInk` / `depth` | `true` / `null` / `BALANCED` |
| `requiredConcepts` | 기본값, 안전한 기본값, 설정 우선순위, 실패 경계, 빠른 실패, 점진적 저하 |
| `helpfulConcepts` | 기본값의 효과, 우선순위 규칙, 대기 상한, 기능 우선순위 |
| `referencePageNumbers` | 2, 4, 9, 10, 16, 17, 18, 23, 24, 30 |
| `allowedAlternativePageNumbers` | 3, 5, 6, 11, 12, 19, 25, 31 |
| `irrelevantPageNumbers` | 33·36(값 상호작용·값 기록), 38·41·43(경계 결정·경계 검증·기록 정리) |

정답 경로는 선수 폐쇄와 같고 열 페이지여서 BALANCED 상한 10을 정확히 채운다. 1.1 → 1.3의 도입에서
설정(2.1 → 2.2), 실패 경계(3.1 → 3.2 → 3.3), 저하(4.1 → 4.2), 값(5.1)의 네 갈래로 갈라진다. 필수
개념 여섯이 각 갈래의 앞 페이지에 놓인다.

**같은 상한 10을 078과 다른 판정으로 채웠다.** 078은 비소장 예산 10에서 열 페이지를 쓰고 076은 소장
BALANCED에서 열 페이지를 쓴다. 상한 값이 같아도 소장 여부에 따라 판정 경로가 다르므로 두 사례가 짝이
된다. 카테고리 안에서 같은 길이를 두 판정으로 만든 짝은 073과 075(다섯 페이지)에 이어 두 번째다.

대체 여덟은 모두 폐쇄가 여섯 이하라 상한 안에서 갈아 끼울 수 있다. 셋은 정답의 짝이고(3·5·6은 1장의
다른 절), 11·12는 값 출처와 변경 범위, 19는 재시도, 25는 과부하 대응, 31은 처음 값과 조정으로 들어가는
첫 페이지다.

무관은 절 단위로 골랐다. 5.4·5.7은 값들을 함께 다루고 기록하는 관리 문제이고 6장의 셋은 한 연동의 진행 기록이다. 이 목적은 판단 기준을 균형 있게 정리하는 것이라
다섯 다 목적 밖이고, 필수·도움 개념을 primary로 달지 않으며, 정답·대체 어느 페이지도 이들을 선수로 거치지 않는다.

## 재현 조건

1. `python3 build076.py` — 원고와 조각 생성 (PDF SHA 없이 실행하면 자리표시자를 넣는다)
2. `python3 figures076.py pdfbuild076` — 도표 4개 SVG 생성
3. Chrome Headless로 각 SVG를 794×1123 PNG로 렌더링
4. `python3 build_pdf_generic.py 76 7,13,20,26 pdfbuild076` — 조판 HTML 생성
5. Chrome Headless `--print-to-pdf`로 PDF 출력, `pdfcheck.py`로 구성 확인
6. PDF를 `fixtures/content/ai-route-v2/pdfs/`에 두고 SHA-256을 인자로 `build076.py` 재실행
7. `merge_fragments.py 76`로 정본에 병합

## 검수

- 초고 45쪽 가운데 서른다섯 쪽이 344자에 못 미쳐 두 차례에 나눠 마지막 문단에 문장을 더했다.
- 도표 네 장을 PNG로 렌더링해 눈으로 모두 확인했고 둘을 고쳤다. p20은 굵은 화살표가 네모 가운데를
  지나며 글자를 덮어 네모 바깥 왼쪽으로 옮겼고, '상한과 경계' 이름표가 아래 네모와 겹쳐 선 위로
  올렸다. p26은 마지막 점선 단이 지면 오른쪽 밖으로 나가 단의 너비를 줄였다.
- 도표를 고치면서 본문 설명 한 곳도 함께 고쳤다. p20의 화살표는 이제 네모를 지나지 않고 바깥을
  따라 올라간다.
- 초고에서 074와 일곱 어절이 겹치는 자리가 하나 나왔다. 도표 도입 문장이라 이 권 전용 표현으로
  다시 썼고, PDF를 다시 출력해 SHA-256과 조각을 갱신했다.
- 공개 가이드 주제와 비공개 분석 텍스트를 서로 다른 문장으로 적었고, 주제문에 숫자를 쓰지 않았다.
  50개 주제문과 50개 분석 텍스트에 중복이 없다.
- 본문·도표·평가 데이터에 실존 인물·작품·단체·제품이 등장하지 않는다.
- **리뷰 뒤 무관 페이지를 다시 골랐다.** 초고는 아홉 권이 모두 6장의 같은 다섯 페이지를
  무관으로 적어 평가 데이터가 권마다 구분되지 않았다. 이 권은 5장의 두 절과 6장의 세 절로
  바꿔 카테고리 안에서 겹치지 않는 세트가 되게 했다. 원고와 PDF는 바뀌지 않았다.
- 리뷰 뒤 7.4·7.7의 공개 주제문을 이 권의 것으로 바꿨다. 초고의 두 문장이 다른 권과 겹쳤다.
- `ContentBatchConverterTest`의 코퍼스 재고 단언을 갱신했다. 도서 56→57, 페이지 2391→2441,
  이미지 268→272다.

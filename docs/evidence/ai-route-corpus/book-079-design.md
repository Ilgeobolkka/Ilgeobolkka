# book-079 「인터페이스 접근성: 시맨틱과 키보드 탐색」 설계

[기술 카테고리 계획](./tech-category-plan.md)의 79번을 만든 근거다. 정책·검증 계약은
[AI 경로 콘텐츠 코퍼스](../../ai-route-content-corpus.md)를 따르고, 이 문서는 그 계약 안에서 내린
선택과 이유만 적는다.

## 대상 도서

- `bookId` 79, 카테고리 기술. 저자·소개는 `src/main/resources/demo/books.json`의 기존 값을 유지한다.
- 제목은 `ai-route-v2` manifest의 `books[].title`이 정본이며 계획 문서의 제목과 같다.
- 실존 브라우저·보조 도구·표준 문서 이름을 쓰지 않는다. '읽어 주는 도구', '의미 요소'처럼 뜻으로만
  적었고, 6장 사례의 화면도 일반 업무 용어로만 서술했다.

계획이 정한 범위(의미 구조, 키보드 접근성, 대체 텍스트, 명도 대비)가 모두 들어갔다. 평가 시나리오도
계획대로 「비소장 · 예산 5」다.

## 개념 범위

이 책의 축은 **화면을 보지 않고도 같은 일을 할 수 있는가**다. 1.2에서 화면을 눈에 보이는 벌과 도구에
전달되는 벌로 나눈 뒤, 두 벌이 어긋나는 자리를 찾는 것이 나머지 장의 내용이다. 2장은 뜻을 담는 구조,
3장은 다닐 길, 4장은 보이지 않는 것을 말로 옮기는 방법, 5장은 보이는 것을 실제로 보이게 하는 값이다.

계획이 지정한 카테고리 내부 경계를 지켰다.

- 이 권은 계획이 "다른 아홉 권과 겹치지 않는 고유 영역"으로 배정한 사용자 인터페이스 접근성만
  다룬다. 다른 권의 개념을 끌어오지 않았다.
- 71(요청 처리)·74(모듈 구조)·77(테스트)의 소재가 등장하지 않는다. 6장의 확인 절차도 시험 전략이
  아니라 화면을 직접 써 보는 점검으로만 적었다.
- 76(실패 경계)과 겹치지 않도록 4.6~4.7의 오류·상태 전달을 실패 처리 설계가 아니라 **전달 여부**의
  문제로만 다뤘다.

## 장 구성 (50페이지, 목차 1 + 본문 49)

```
1장 접근성이라는 요구        p2–8    PREREQUISITE·COUNTERPOINT  이용 방식·의미 구조·범위 판단
2장 의미 구조                p9–15   CORE·COUNTERPOINT  의미 요소·제목·목록과 표·이름·흉내 낸 요소
3장 키보드 탐색              p16–22  CORE·COUNTERPOINT  초점 순서·초점 표시·가둠·건너뛰기
4장 대체 텍스트와 상태 전달  p23–29  CORE·COUNTERPOINT  대체 텍스트·장식·변화 알림·오류 전달
5장 색과 대비                p30–36  CORE·COUNTERPOINT  명도 대비·색 의존·크기·측정·배경 전환
6장 한 화면을 고친 기록      p37–43  EXAMPLE            신청서 화면 하나를 점검하고 고친 기록
7장 접근성 판단              p44–50  COUNTERPOINT·CONCLUSION  우선순위·의미 우선·점검·유지
```

절은 장마다 일곱 개이고 절 하나가 페이지 하나다. 1.3이 이 권의 매듭이다. 보이는 성질과 뜻을 가른 뒤,
그 구분이 2.1의 요소 선택, 3.2의 초점 순서, 4.1의 대체 텍스트, 5.2의 색 의존으로 이어진다.

6장은 확인 → 차단 해소 → 명명 → 오류 → 대비 → 재확인의 순서를 그대로 따라간다. 6.6에서 화면을 보지
않고 작성해 보다가 새 문제를 발견하는 대목이 이 권의 확인 방법을 가장 잘 보이는 자리다.

이미지 4개: p7(같은 화면의 두 가지 읽기), p13(화면 요소의 뜻과 이름), p20(초점이 지나는 길),
p26(그림에 붙는 설명의 갈래). 생성 스크립트는 [`figures079.py`](./tools/figures079.py)다.

이 권의 도표 문장 틀은 "제목 아래 한 줄로 '…'가 적혀 있다"로 시작하고 "그림 맨 끝 줄에는 '…'가
놓인다"로 끝난다. 072·073·074·075·076·077·078과 각각 다른 문장을 쓴다. 도표에는 대비 값과 크기를
눈금으로 넣지 않았다 — 기준 값은 글자 크기와 상황에 따라 달라 숫자를 넣으면 본문에 없는 기준이
생긴다.

중복 그룹 1개: `meaning-before-look` = [5, 45]. "보이는 벌과 전달되는 벌이 어긋나는 것은 겉모양을
먼저 만들고 뜻을 나중에 맞추기 때문이다"를 1.4에서 문제로 세우고 7.2에서 만드는 순서의 원칙으로 다시
쓴다. 5의 폐쇄는 [2, 4, 5]이고 45의 폐쇄는 [2, 3, 44, 45]라 서로를 지나지 않는다.

**중복 그룹을 세 페이지로 잘못 걸어 한 번 걸렸다.** 초고에서 5.2(색 의존)에도 같은 키를 달았는데,
5.2는 5.1을 거쳐 1.4를 선수로 갖기 때문에 자기 폐쇄 안에 짝이 들어왔다. `corpus_lib`의 중복 폐쇄
검사가 이를 잡았고 5.2의 키를 뺐다. 중복 그룹은 선수 관계로 이어진 두 페이지에 걸 수 없다.

## 선수 관계 설계

1.1이 뿌리이고 1.2·1.3이 곧바로 붙는다. 2장은 1.3 → 2.1에서, 3장과 4장은 2.1에서, 5장은 1.4에서
시작한다. 5장을 2장이 아니라 1.4에 붙인 것은 색과 대비가 의미 구조와 독립적인 갈래이기 때문이다.

6장은 3.1에 붙였고, 7장은 각 절이 요약하는 장에 직접 붙였다(7.1·7.2는 1.2, 7.3·7.6은 2.1,
7.4·7.5는 3.1, 7.7은 7.2).

- 어느 후보 페이지도 선수 폐쇄가 10페이지를 넘지 않는다.
- 폐쇄 5페이지 이하인 후보 페이지가 일곱 개 장을 모두 덮는다 (기준 3개 장).
- 후보 페이지 49개 전부가 폐쇄 15페이지 이하다 (기준 75%).

## 검증

`corpus_lib.validate_book()` → `validate_fragment.py` → `merge_fragments.py` → `validate_manifest.py`를
차례로 통과했다.

- 50페이지(48~72), 7개 장(최소 6), 내용 역할 5종 모두 사용
- `TEXT` 본문 45페이지가 346~401자(평균 362자, 합계 16,333자)
- `estimatedReadingSeconds`에 60초로 눌린 페이지가 하나도 없음
- `FRONT_MATTER`(목차 p1)와 `aiRouteCandidatePage=false`가 정확히 일치
- PDF 페이지 50개, 텍스트 46개, 이미지 4개(p7,13,20,26) — `pdfcheck.py`로 확인
- PDF 실제 SHA-256이 manifest의 `pdfSha256`과 일치 (674,873 bytes)
- 다른 권과 겹치는 일곱 어절이 하나도 없다

## 평가 케이스: 비소장·예산 5 시나리오

| 필드 | 값 |
| --- | --- |
| `caseId` | `case-book-079` |
| `purpose` | 화면을 키보드와 읽어 주는 도구로도 쓸 수 있게 만들려는데, 꼭 필요한 것만 짧게 짚고 싶다 |
| `owned` / `maxAdditionalInk` / `depth` | `false` / `5` / `null` |
| `requiredConcepts` | 접근성, 의미 구조, 의미 요소, 키보드 접근성, 대체 텍스트 |
| `helpfulConcepts` | 이용 방식, 제목 구조, 초점 순서, 명도 대비 |
| `referencePageNumbers` | 2, 4, 9, 16, 23 |
| `allowedAlternativePageNumbers` | 3, 5, 10, 11, 12, 17, 24, 30 |
| `irrelevantPageNumbers` | 34·36(저대비 관습·배경 전환), 39·41·42(명명 작업·대비 개선·재확인) |

정답 경로는 선수 폐쇄와 같고 다섯 페이지여서 예산 5를 정확히 채운다. 1.1 → 1.3 → 2.1에서 갈라져
3.1과 4.1로 이어지는 모양이라 사슬 하나가 아니라 두 갈래가 나오는 구성이다.

**같은 예산 5를 073과 다른 모양으로 채웠다.** 073은 다섯 페이지가 한 줄기 사슬이고 079는 앞의 셋이
사슬, 뒤의 둘이 갈래다. 같은 예산에서도 개념 구조에 따라 경로 모양이 달라진다는 것을 두 권이 나란히
보인다.

대체 여덟은 모두 폐쇄가 다섯 이하다. 둘은 정답의 짝이고(3·5는 1장의 다른 절), 10·11·12는 제목·목록·
버튼 구분, 17은 초점 순서, 24는 대체 텍스트 작성, 30은 명도 대비로 들어가는 첫 페이지다. 30을 넣은
것은 5장이 정답 경로에 없는 갈래여서 도움 개념 하나가 대체로만 닿기 때문이다.

무관은 절 단위로 골랐다. 5.5·5.7은 색을 다루는 관습과 두 벌 배경이라는 시각 설계 문제이고 6장의 셋은 한 화면의 수정 진행 기록이다. 이 목적은 필요한 것만 짧게
짚는 것이라 다섯 다 목적 밖이고, 필수·도움 개념을 primary로 달지 않으며, 정답·대체 어느 페이지도 이들을 선수로 거치지 않는다.

## 재현 조건

1. `python3 build079.py` — 원고와 조각 생성 (PDF SHA 없이 실행하면 자리표시자를 넣는다)
2. `python3 figures079.py pdfbuild079` — 도표 4개 SVG 생성
3. Chrome Headless로 각 SVG를 794×1123 PNG로 렌더링
4. `python3 build_pdf_generic.py 79 7,13,20,26 pdfbuild079` — 조판 HTML 생성
5. Chrome Headless `--print-to-pdf`로 PDF 출력, `pdfcheck.py`로 구성 확인
6. PDF를 `fixtures/content/ai-route-v2/pdfs/`에 두고 SHA-256을 인자로 `build079.py` 재실행
7. `merge_fragments.py 79`로 정본에 병합. 이미 병합한 뒤에 다시 만들 때는
   [도구 README의 되돌리기 절차](./tools/README.md#이미-병합한-도서를-다시-만들-때)를 먼저 따른다

## 검수

- **중복 그룹을 세 페이지에 걸어 `validate_book()`에서 걸렸다.** 위 「개념 범위」에 적은 대로 5.2의
  키를 빼서 해결했다. 선수로 이어진 두 페이지에 같은 키를 달면 그 후보는 어떤 예산으로도 고를 수
  없게 된다.
- 초고 45쪽 대부분이 344자에 못 미쳐 네 차례에 나눠 마지막 문단에 문장을 더했다. 346~401자로
  맞췄다.
- 도표 네 장을 PNG로 렌더링해 눈으로 모두 확인했고 고칠 자리는 없었다. 앞선 권들에서 겪은 두 줄
  이름표 순서와 지면 밖 넘침을 처음부터 피해 그렸다.
- 다른 권과 겹치는 일곱 어절이 하나도 없다. 이 카테고리에서 초고 단계부터 겹침이 없던 첫 권이다.
- 공개 가이드 주제와 비공개 분석 텍스트를 서로 다른 문장으로 적었고, 주제문에 숫자를 쓰지 않았다.
  50개 주제문과 50개 분석 텍스트에 중복이 없다.
- 본문·도표·평가 데이터에 실존 인물·작품·단체·제품이 등장하지 않는다.
- **리뷰 뒤 무관 페이지를 다시 골랐다.** 초고는 아홉 권이 모두 6장의 같은 다섯 페이지를
  무관으로 적어 평가 데이터가 권마다 구분되지 않았다. 이 권은 5장의 두 절과 6장의 세 절로
  바꿔 카테고리 안에서 겹치지 않는 세트가 되게 했다. 원고와 PDF는 바뀌지 않았다.
- 리뷰 뒤 7.7의 공개 주제문을 이 권의 것으로 바꿨다. 초고는 아홉 권이 같은 문장을 썼다.
- `ContentBatchConverterTest`의 코퍼스 재고 단언을 갱신했다. 도서 58→59, 페이지 2491→2541,
  이미지 276→280이다.

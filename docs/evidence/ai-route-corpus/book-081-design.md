# book-081 「비행기 없이 건넌 일곱 섬」 설계

[여행 카테고리 계획](./travel-category-plan.md)의 81번을 만든 근거다. 여행 카테고리에서 처음 만든
권이다. 정책·검증 계약은 [AI 경로 콘텐츠 코퍼스](../../ai-route-content-corpus.md)를 따르고, 이 문서는
그 계약 안에서 내린 선택과 이유만 적는다.

## 대상 도서

- `bookId` 81, 카테고리 여행. 저자·소개는 `src/main/resources/demo/books.json`의 기존 값을 유지한다.
- 제목은 `ai-route-v2` manifest의 `books[].title`이 정본이며 이 문서의 제목과 같다.
- 실존 국가·도시·지명을 쓰지 않는다. 무대는 가상의 「열두 섬 군도」이고 실제로 지나는 섬은
  첫물섬·등대섬·소금섬·먹물섬·그물섬·돌담섬·끝물섬 일곱이다. 인물은 첫물섬 매표소의 기연, 짐배 선장
  두호이며, 등대섬 민박 주인은 이름 없이 역할로만 적는다.
- 계획 문서에는 섬 이름이 넷만 정해져 있어 세 개(그물섬·돌담섬·끝물섬)를 새로 만들고 계획 문서에
  함께 적었다. 82~90번이 같은 이름을 쓰지 않게 하려는 것이다.

## 개념 범위

계획 문서가 정한 범위(배편 시간표, 물때, 환승 리듬, 결항)를 그대로 따른다. 이 권은 여행 카테고리에서
**이동 자체를 다루는 유일한 권**이다.

- 083(시장으로 읽는 도시)과 086(항구 마을의 새벽)은 한 장소에 머물며 그곳의 생활을 다룬다. 081은
  섬 사이를 계속 건너므로 도착한 섬에서 무엇을 보았는지는 5장의 사례에서도 최소한으로만 적었다.
- 082(기차)·085(해안도로)·089(도시 순환선)도 이동을 다루지만 수단이 다르다. 이 권의 고유한 재료는
  물때다. 시간표가 날마다 밀리고 접안 가능 시간이 조석에 묶이는 것은 배에만 있는 조건이라, 다른 이동
  수단 권과 겹칠 여지가 없다.
- 087(고원 마을의 우편)이 다루는 정보의 이동 속도는 4.4(현금과 연락)에서 통신 두절로 잠깐 닿지만,
  여기서는 여행자가 그 구간을 견디는 방법만 다루고 마을의 통신 체계는 다루지 않는다.

## 장 구성 (51페이지, 목차 1 + 본문 50)

```
1장 바다가 정하는 시각   p2–11   PREREQUISITE  물때·시간표·항로·배의 종류·선착장
2장 배를 갈아타기         p12–19  CORE          환승 여유·환승 실패·대기 시간·왕복 배편
3장 배가 뜨지 않는 날     p20–27  CORE          결항 기준·결항 예보·고립 대응·예비일
4장 짐과 몸               p28–35  CORE          뱃멀미·짐 꾸리기·섬의 보급·현금과 통신
5장 일곱 섬을 건넌 열흘   p36–43  EXAMPLE       구간 나누기·체류 시간·결항 사례·일정 회복
6장 계획이 통하지 않을 때 p44–49  COUNTERPOINT  계절 운항·비정기 편승·일정 축소
7장 결론: 바다에 맞추는 일정 p50–51 CONCLUSION  종합
```

1장이 다섯 개념을 세우고 2~4장이 환승·결항·몸으로 나누어 펼친다. 5장은 그 셋이 한 여정에서 어떻게
맞물리는지를 열흘의 기록으로 보이고, 6장은 앞 장의 방법이 통하지 않는 세 경우(계절이 바뀔 때, 정기선이
없는 섬, 일정을 줄여야 할 때)를 다룬다. 7장은 두 페이지다. 5장 전체가 이미 적용 사례라 결론에서 사례를
다시 들 필요가 없었다.

이미지 6개: p7(몇 번째로 들르는가), p14(여유가 버티는 데까지), p21(어느 배가 먼저 멈추는가),
p30(한 손이 남는가), p37(열흘 동안 지난 자리), p45(같은 항로의 두 계절). 이동을 다루는 책이라 여섯
도표가 모두 "시간 위에서 무엇이 어긋나는가"를 그린다. 시간 축은 늘 왼쪽에서 오른쪽으로, 계획대로 되는
쪽은 진한 색, 어긋나거나 사라지는 쪽은 옅은 색으로 고정했다. 생성 스크립트는
[`figures081.py`](./tools/figures081.py)다.

중복 그룹 1개: `sea-decides-the-schedule` = [2, 50]. "배는 시계가 아니라 바다에 맞춰 다닌다"는 명제를
1.1에서 세우고 7.1에서 책 전체를 지나온 언어로 재진술한다. 재진술 페이지(50)에는 선수를 두지 않았다.
짝(2)을 선수로 걸면 50을 고른 경로에 2가 반드시 따라와 중복 그룹 규칙을 어기기 때문이며,
book-062·063·065·068·069·070과 같은 처리다.

## 선수 관계 설계

1.1(물때)을 뿌리로 두고 1.2(시간표)와 1.4(배의 종류)가 갈라진다. 2장은 1.2에서, 3장은 1.1에서, 4장은
1.5(선착장)와 1.4에서, 5장은 2.1(환승 여유)과 3.3(발이 묶인 날)에서 갈라진다. 3장을 1.2가 아니라 1.1에
붙인 것은 결항이 시간표가 아니라 바다의 상태에서 나오기 때문이다.

- 어느 후보 페이지도 선수 폐쇄가 8페이지를 넘지 않는다.
- 폐쇄 5페이지 이하인 후보 페이지가 일곱 개 장을 모두 덮는다 (기준 3개 장).
- 후보 페이지 50개 전부가 폐쇄 15페이지 이하다 (기준 75%).

가장 깊은 곳은 6.3(줄여야 할 때)으로 3.4 → 3.1 → 1.1과 2.2 → 2.1 → 1.2 → 1.1을 함께 거친다. 일정을
줄이는 판단은 예비일이 있어야 성립하고 예비일은 결항과 환승 실패 둘을 모두 전제하므로, 이 사슬은 실제
의존이다. 3.4에만 선수 절을 둘 걸었고 나머지는 모두 하나다.

## 검증

`corpus_lib.validate_book()` → `validate_fragment.py` → `merge_fragments.py` → `validate_manifest.py`를
차례로 통과했다.

- 51페이지(48~72), 7개 장(최소 6), 내용 역할 5종 모두 사용
- `TEXT` 본문 44페이지가 417~486자(평균 442자, 합계 19,449자)
- `FRONT_MATTER`(목차)와 `aiRouteCandidatePage=false`가 정확히 일치
- 선수 관계가 후보 제외 페이지를 가리키지 않음, 위상 정렬로 51페이지 전체 방문
- PDF 페이지 51개, 텍스트 45개, 이미지 6개(p7,14,21,30,37,45) — `pdfcheck.py --book 81`으로 확인
- PDF 실제 SHA-256이 manifest의 `pdfSha256`과 일치

초고는 327~448자로 하한이 정본 기준(345자)에 미달했다. 069·070과 같이 420자에 못 미친 42페이지에
`EXTRA` 문단을 더해 417~486자로 맞췄다. 더한 문단은 모두 그 페이지의 내용을 실무 한 가지로 잇는
것이고, 앞 문단을 바꿔 말한 것이 아니다.

## 평가 케이스: 비소장·예산 0 시나리오

| 필드 | 값 |
| --- | --- |
| `caseId` | `case-book-081` |
| `purpose` | 군도를 배로만 건널 계획인데, 배 시각이 날마다 달라지는 까닭과 한 배가 여러 섬을 도는 순서를 알고 싶고, 갈아탈 때 시간을 얼마나 남겨야 놓치지 않는지를 이미 빌려 둔 앞부분 안에서 익히고 싶다 |
| `owned` / `maxAdditionalInk` / `depth` | `false` / `0` / `null` |
| `activeRentalPageNumbers` | 2~19 (1장과 2장 전체) |
| `requiredConcepts` | 물때, 배편 시간표, 항로, 기항 순서, 환승 여유, 환승 실패 |
| `helpfulConcepts` | 여객선, 대기 시간, 결항 기준, 선착장 |
| `referencePageNumbers` | 2~7, 12~15 |
| `irrelevantPageNumbers` | 28·29(뱃멀미), 32·33(섬의 보급), 34·35(현금과 통신) — 시간표와 환승만 익히려는 이 목적과 무관. 절 단위로 넣어 짝 페이지를 쪼개지 않는다 |
| `allowedAlternativePageNumbers` | 8, 16, 17, 18 |

정답 경로는 선수 전이 폐쇄와 같고 10페이지다. 물때(2, 3)에서 시간표(4, 5)로, 시간표에서 항로(6, 7)와
환승 여유(12, 13)로, 환승 여유에서 환승 실패(14, 15)로 이어진다. 예산 0이므로 이 열 페이지가 모두 대여
범위 안에 있어야 하고, 실제로 대여 18페이지가 폐쇄를 남김없이 덮어 추가 차감이 0이다.

대체 페이지 넷도 대여 범위 안에서 골랐다. 예산이 0인 사례에서 대여 밖 페이지를 대체로 적으면 고를 수
없는 페이지를 정답 대신 인정하는 셈이 된다. 기존 예산 0 사례 넷은 대여를 정답 경로와 똑같이 잡았고,
그래서 book-049·061의 대체 페이지는 대여 밖에 있다. 이 권은 대여를 절 단위로 두 장 전체까지 넓혀
정답보다 여덟 페이지 크게 잡았고, 그 여유 안에서 대체 페이지를 골랐다.

시나리오는 계획 문서가 배정한 **비소장·예산 0**을 그대로 썼다. 1장과 2장이 물때에서 환승까지 하나로
이어져 앞부분만 빌려도 목적을 채울 수 있는 구조라 예산 0에 맞는다. 병합 후 34건의 분포는 BALANCED가
6건, QUICK·DEEP·예산 0·예산 10이 각 5건, 예산 5·예산 15가 각 4건이다.

## 재현 조건

1. `python3 build081.py` — 원고와 조각 생성 (PDF SHA 없이 실행하면 자리표시자를 넣는다)
2. `python3 figures081.py pdfbuild081` — 도표 6개 SVG 생성
3. Chrome Headless로 각 SVG를 794×1123 PNG로 렌더링
4. `python3 build_pdf_generic.py 81 7,14,21,30,37,45 pdfbuild081` — 조판 HTML 생성
5. Chrome Headless `--print-to-pdf`로 PDF 출력, `pdfcheck.py --book 81`으로 구성 확인
6. PDF를 `fixtures/content/ai-route-v2/pdfs/`에 두고 SHA-256을 인자로 `build081.py` 재실행
7. `merge_fragments.py 81`로 정본에 병합
8. `sync_readme.py --add 81 여행`으로 fixture README의 수치와 표를 다시 계산

## 검수

- 여섯 도표를 PNG로 렌더링해 눈으로 확인하고 겹침 다섯 곳을 고쳤다. p7은 점선이 아래 줄의 다른 섬
  이름과 점을 지나가 두 줄 사이로 돌렸고, p21은 한계선 이름이 띠 설명과 겹쳐 오른쪽 끝으로 옮겼다.
  p14는 뒤 배의 줄이 비어 있어 출항 이후 구간을 그려 넣었다.
- 조판한 PDF의 목차와 본문 첫 장들을 열어 페이지 번호·머리글·문단 나눔을 확인했다.
- 공개 가이드 주제와 비공개 분석 텍스트를 서로 다른 문장으로 적었고, 주제문에 숫자를 쓰지 않았다.
- 본문·도표·평가 데이터에 실존 국가·도시·지명·인물이 등장하지 않는다.

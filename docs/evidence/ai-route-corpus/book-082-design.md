# book-082 「북쪽 기차의 창가 노트」 설계

[여행 카테고리 계획](./travel-category-plan.md)의 82번을 만든 근거다. 정책·검증 계약은
[AI 경로 콘텐츠 코퍼스](../../ai-route-content-corpus.md)를 따르고, 이 문서는 그 계약 안에서 내린
선택과 이유만 적는다.

## 대상 도서

- `bookId` 82, 카테고리 여행. 저자·소개는 `src/main/resources/demo/books.json`의 기존 값을 유지한다.
- 제목은 `ai-route-v2` manifest의 `books[].title`이 정본이며 이 문서의 제목과 같다.
- 실존 국가·도시·지명을 쓰지 않는다. 무대는 가상의 「북부 순환선」이고 역은 자작나무역·밀밭역·
  안개고개역·돌다리역·경계역이다. 인물은 차장 무경, 자작나무역 역무원 단해, 안개고개역 매점의
  설재이며 081의 인물(기연·두호·연화)과 겹치지 않는다.
- 계획 문서에는 역 이름이 셋만 정해져 있어 밀밭역·돌다리역을 새로 만들고 계획 문서에 함께 적었다.

## 개념 범위

계획 문서가 정한 범위(완행열차의 정차역, 창밖 풍경 변화, 환승, 지연)를 그대로 따른다.

- 081과 같은 이동 수단 계열이지만 시각을 미는 힘이 다르다. 081은 물때가, 082는 단선 구간의 교행과
  화물 취급이 시각을 민다. 그래서 081의 결항(뜨느냐 마느냐)에 대응하는 이 권의 축은 지연(얼마나
  늦느냐)이고, 둘은 대응이 아니라 다른 종류의 실패다.
- 085(해안도로)·089(도시 순환선)와도 갈린다. 085는 스스로 운전하므로 시각표가 없고, 089는 한 도시
  안의 짧은 순환이라 하루 단위다. 082만 정해진 시각표에 몸을 맞추는 여러 날의 이동을 다룬다.
- 이 권에만 있는 축은 2장의 창밖 관찰이다. 다른 아홉 권은 도착한 곳에서 무엇을 보는지를 다루지만
  082는 **이동하는 동안 무엇을 보고 적는지**를 다룬다.

## 장 구성 (51페이지, 목차 1 + 본문 50)

```
1장 느린 기차를 고르는 일   p2–11   PREREQUISITE  완행열차·정차역·시각표·창가 자리·선로 사정
2장 창밖을 읽기             p12–19  CORE          풍경 전환·창가 노트·빛의 방향·관찰 기록
3장 늦는 기차               p20–27  CORE          지연·지연 안내·연결 열차·지연 회복
4장 갈아타기와 내리기       p28–35  CORE          환승역·환승 간격·중간 하차·야간 운행
5장 북부 순환선의 나흘      p36–43  EXAMPLE       여정 구성·체류 판단·회차·구간 정리
6장 이 방법이 통하지 않을 때 p44–49 COUNTERPOINT  감편 운행·터널 구간·급행 선택
7장 결론: 느리게 가기로 정하는 일 p50–51 CONCLUSION 종합
```

1장이 다섯 전제를 세우고 2~4장이 관찰·지연·환승으로 나누어 펼친다. 6장은 앞 장의 방법이 통하지 않는
세 경우(계절 감편, 창밖이 없는 터널 구간, 급행이 나은 날)를 다루고, 특히 6.2는 이 책의 전제인
"창밖을 보려고 완행을 고른다"가 무효가 되는 구간을 정면으로 다룬다.

이미지 6개: p7(서는 곳과 지나치는 곳), p13(아홉 시간의 띠), p21(오 분이 이십 분이 되는 동안),
p30(십 분은 몇 분인가), p37(한 바퀴를 넷으로 끊다), p45(다섯 편과 세 편). 여섯 도표가 모두 시간이나
거리 축 위에서 무엇이 쌓이거나 사라지는지를 그린다. 진한 색은 계획대로 되는 쪽, 옅은 색은 잃거나
줄어드는 쪽으로 고정했다. 생성 스크립트는 [`figures082.py`](./tools/figures082.py)다.

중복 그룹 1개: `slow-is-a-choice` = [2, 50]. "완행이 느린 것은 속도가 아니라 서기 때문"이라는 명제를
1.1에서 세우고 7.1에서 여행 전체를 지나온 언어로 재진술한다. 재진술 페이지(50)에는 선수를 두지
않았다. 짝(2)을 선수로 걸면 50을 고른 경로에 2가 반드시 따라와 중복 그룹 규칙을 어기기 때문이며,
book-081과 같은 처리다.

## 선수 관계 설계

1.1(완행열차)을 뿌리로 두고 1.2(정차역)와 1.4(창가 자리)가 갈라진다. 2장은 1.2에서, 3장은
1.5(선로 사정)에서, 4장은 1.3(시각표)과 1.2에서, 5장은 2.2(창가 노트)와 4.3(중간 하차)에서
갈라진다. 3장을 1.5에 붙인 것은 지연이 시각표가 아니라 선로 조건에서 나오기 때문이다.

- 어느 후보 페이지도 선수 폐쇄가 9페이지를 넘지 않는다.
- 폐쇄 5페이지 이하인 후보 페이지가 일곱 개 장을 모두 덮는다 (기준 3개 장).
- 후보 페이지 50개 전부가 폐쇄 15페이지 이하다 (기준 75%).

가장 깊은 곳은 6.3(급행 선택)으로 3.4 → 3.3 → 3.1 → 1.5 → 1.3 → 1.2 → 1.1을 거친다. 완행을
포기하는 판단은 회복 가능성을 알아야 하고, 회복은 연결과 지연을, 지연은 선로 조건을 전제하므로 이
사슬은 실제 의존이다.

## 검증

`corpus_lib.validate_book()` → `validate_fragment.py` → `merge_fragments.py` → `validate_manifest.py`를
차례로 통과했다.

- 51페이지(48~72), 7개 장(최소 6), 내용 역할 5종 모두 사용
- `TEXT` 본문 44페이지가 415~493자(평균 440자, 합계 19,344자)
- `FRONT_MATTER`(목차)와 `aiRouteCandidatePage=false`가 정확히 일치
- 선수 관계가 후보 제외 페이지를 가리키지 않음, 위상 정렬로 51페이지 전체 방문
- PDF 페이지 51개, 텍스트 45개, 이미지 6개(p7,13,21,30,37,45) — `pdfcheck.py`로 확인
- PDF 실제 SHA-256이 manifest의 `pdfSha256`과 일치

초고는 334~460자로 하한이 정본 기준(345자)에 미달했다. 081과 같이 420자에 못 미친 42페이지에
`EXTRA` 문단을 더해 415~493자로 맞췄다.

## 평가 케이스: 비소장·예산 5 시나리오

| 필드 | 값 |
| --- | --- |
| `caseId` | `case-book-082` |
| `purpose` | 완행열차로 북부를 도는 계획인데, 급행을 두고 완행을 고르는 것이 무엇을 얻는 선택인지와 창밖이 바뀌는 자리를 알아보고 달리는 기차에서 무엇을 적을지 정하는 법을 빌려 둔 앞부분에 조금만 더해 익히고 싶다 |
| `owned` / `maxAdditionalInk` / `depth` | `false` / `5` / `null` |
| `activeRentalPageNumbers` | 2~9 (1장의 앞 네 절) |
| `requiredConcepts` | 완행열차, 정차역, 풍경 전환, 창가 노트, 관찰 기록 |
| `helpfulConcepts` | 열차 시각표, 창가 자리, 선로 사정, 지연 |
| `referencePageNumbers` | 2, 4, 12~15, 18 |
| `irrelevantPageNumbers` | 26·27(지연 회복), 34·35(야간 운행), 46·47(터널 구간) — 창밖 기록을 익히려는 이 목적과 무관. 절 단위로 넣어 짝 페이지를 쪼개지 않는다 |
| `allowedAlternativePageNumbers` | 5, 16, 17 |

정답 경로는 선수 전이 폐쇄와 같고 7페이지다. 그중 2와 4는 이미 빌린 범위 안이라 실제 차감은 5페이지
(12, 13, 14, 15, 18)이고 예산을 남김없이 쓴다. 완행열차(2)에서 정차역(4)으로, 정차역에서 풍경
전환(12, 13)으로, 전환에서 노트(14, 15)와 정리(18)로 이어지는 하나의 사슬이다.

대체 페이지 셋은 예산 안에서 실제로 바꿔 고를 수 있는 자리만 골랐다. 5는 대여 안이라 값이 들지 않고,
16·17은 선수 폐쇄가 대여 범위(8, 2)에 걸쳐 있어 18 대신 고르면 차감이 예산을 넘지 않는다. 예산이
정확히 맞아떨어지는 사례에서는 대체 페이지도 이 계산을 통과하는 것만 적어야 실현할 수 있는 정답이
된다.

시나리오는 계획 문서가 배정한 **비소장·예산 5**를 그대로 썼다. 1장을 빌린 독자가 2장만 더 열면
목적을 채우는 구조라 작은 예산에 맞는다. 병합 후 35건의 분포는 BALANCED 6건, QUICK·DEEP·예산 0·
예산 5·예산 10이 각 5건, 예산 15가 4건이다.

## 재현 조건

1. `python3 build082.py` — 원고와 조각 생성 (PDF SHA 없이 실행하면 자리표시자를 넣는다)
2. `python3 figures082.py pdfbuild082` — 도표 6개 SVG 생성
3. Chrome Headless로 각 SVG를 794×1123 PNG로 렌더링
4. `python3 build_pdf_generic.py 82 7,13,21,30,37,45 pdfbuild082` — 조판 HTML 생성
5. Chrome Headless `--print-to-pdf`로 PDF 출력, `pdfcheck.py`로 구성 확인
6. PDF를 `fixtures/content/ai-route-v2/pdfs/`에 두고 SHA-256을 인자로 `build082.py` 재실행
7. `merge_fragments.py 82`로 정본에 병합

## 검수

- 여섯 도표를 PNG로 렌더링해 눈으로 확인하고 네 곳을 고쳤다. p7은 안내 문구가 열 제목과 겹쳐 위로
  올렸고, p21은 양 끝 값 표시가 축과 다른 문구에 겹쳐 자리를 바꿨다. p30은 왼쪽 주석이 화면 밖으로
  나가 마지막 칸 위로 옮겼고, p37은 역 이름이 원에 겹치고 굵기 차이가 크기로 읽혀 이름을 바깥으로
  빼고 탄 구간과 타지 않은 구간만 실선·점선으로 구분했다.
- 조판한 PDF의 목차와 본문 첫 장을 열어 페이지 번호·머리글·문단 나눔을 확인했다.
- 공개 가이드 주제와 비공개 분석 텍스트를 서로 다른 문장으로 적었고, 주제문에 숫자를 쓰지 않았다.
- 본문·도표·평가 데이터에 실존 국가·도시·지명·인물이 등장하지 않는다.

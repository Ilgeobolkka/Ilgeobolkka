# book-083 「시장 냄새로 기억한 도시」 설계

[여행 카테고리 계획](./travel-category-plan.md)의 83번을 만든 근거다. 정책·검증 계약은
[AI 경로 콘텐츠 코퍼스](../../ai-route-content-corpus.md)를 따르고, 이 문서는 그 계약 안에서 내린
선택과 이유만 적는다.

## 대상 도서

- `bookId` 83, 카테고리 여행. 저자·소개는 `src/main/resources/demo/books.json`의 기존 값을 유지한다.
- 제목은 `ai-route-v2` manifest의 `books[].title`이 정본이며 이 문서의 제목과 같다.
- 실존 국가·도시·지명을 쓰지 않는다. 무대는 가상의 무역 도시 「재의 항」이고 시장은 새벽어시장·
  향신료골목·헌옷마당 셋이다. 인물은 어시장 중매인 초하와 향신료골목의 하람이고, 헌옷마당의 상인은
  이름 없이 역할로만 적는다. 081·082의 인물과 겹치지 않는다.

## 개념 범위

계획 문서가 정한 범위(새벽 시장의 냄새·소리로 도시 구역 읽기, 흥정, 계절 재료)를 그대로 따른다.

- 081·082가 이동을 다루는 반면 이 권은 한 도시에 머문다. 여행 카테고리에서 **정주 계열의 첫 권**이다.
- 086(새벽 항구의 첫 식사)과 가장 가깝다. 둘 다 새벽을 다루지만 086은 조업과 귀항이라는 생산 쪽을,
  083은 그것이 도시로 흩어지는 유통 쪽을 다룬다. 이 권에는 배를 타고 나가는 장면이 없고, 어시장도
  경매장 바닥에서만 본다.
- 088(비 오는 골목의 지도)과는 도시가 다르고 읽는 단서가 다르다. 088은 골목의 지형을 손으로 그리고,
  083은 냄새와 소리로 구역을 나눈다. 5.4에서 두 방식이 어긋나는 지점을 다루지만 지형 자체는 다루지
  않는다.

## 장 구성 (51페이지, 목차 1 + 본문 50)

```
1장 도시에 도착한 첫 새벽   p2–11   PREREQUISITE  무역 도시·장 서는 시각·시장 구역·냄새 지도·소리와 흐름
2장 새벽어시장               p12–19  CORE          새벽 경매·신선도 판단·도매와 소매·시장 밥집
3장 향신료골목               p20–27  CORE          향의 층·흥정·계절 재료·저울과 값
4장 헌옷마당                 p28–35  CORE          중고 유통·고르는 눈·파장·시장 둘레
5장 사흘 동안 세 시장        p36–43  EXAMPLE       첫날 동선·흥정 실패·휴장일·구역 대조
6장 시장으로 읽을 때 놓치는 것 p44–49 COUNTERPOINT  표본의 한계·여행자 가격·기억의 한계
7장 결론: 냄새로 남은 도시   p50–51  CONCLUSION    종합
```

1장이 다섯 전제를 세우고 2~4장이 세 시장을 하나씩 맡는다. 세 시장은 파는 물건이 아니라 물건이 머무는
시간(반나절·몇 달·몇 해)으로 갈리고, 그 차이가 거래 속도와 사람의 태도를 정한다는 것이 이 권의 축이다.
6장은 이 방법이 놓치는 것을 세 갈래로 적는다. 표본에서 빠지는 영역, 여행자에게만 붙는 값, 그리고
냄새로 기억한 것이 흐려진다는 약점이다.

이미지 6개: p7(물가에서 안쪽으로), p13(한 바닥의 세 시간대), p21(이백 걸음의 네 층),
p29(어디서 와서 어디로 가는가), p37(사흘의 순서), p45(본 것과 보지 않은 것). 여섯 도표가 모두 무엇이
어디서 어디로 가는지와 무엇을 보고 무엇을 못 보는지를 그린다. 본 것은 진한 색, 보지 못한 것은 옅은
색으로 고정했다. 생성 스크립트는 [`figures083.py`](./tools/figures083.py)다.

중복 그룹 1개: `market-as-a-lens` = [2, 50]. "도시를 시장이라는 한 장소로 읽는다"는 명제를 1.1에서
세우고 7.1에서 무엇을 포기한 선택이었는지로 재진술한다. 재진술 페이지(50)에는 선수를 두지 않았다.
짝(2)을 선수로 걸면 50을 고른 경로에 2가 반드시 따라와 중복 그룹 규칙을 어기기 때문이며,
book-081·082와 같은 처리다.

## 선수 관계 설계

1.1(재의 항)을 뿌리로 두고 1.2(장 서는 시각)와 1.4(냄새 지도)가 갈라진다. 2·4·6장은 1.3(세 시장)에서,
3장은 1.4에서, 5장은 2.1과 3.2와 1.2에서 갈라진다. 3장을 1.3이 아니라 1.4에 붙인 것은 향신료골목의
배열이 시장의 구분이 아니라 냄새의 세기에서 나오기 때문이다.

- 어느 후보 페이지도 선수 폐쇄가 7페이지를 넘지 않는다. 여행 카테고리에서 가장 얕다.
- 폐쇄 5페이지 이하인 후보 페이지가 일곱 개 장을 모두 덮는다 (기준 3개 장).
- 후보 페이지 50개 전부가 폐쇄 15페이지 이하다 (기준 75%).

세 시장이 서로 선수가 아니라 1장에서 각각 갈라지게 둔 것이 폐쇄를 얕게 만들었다. 어느 시장부터 읽어도
되게 하려는 구성이고, 그래서 예산 10에 세 시장 가운데 둘을 담을 수 있다.

## 검증

`corpus_lib.validate_book()` → `validate_fragment.py` → `merge_fragments.py` → `validate_manifest.py`를
차례로 통과했다.

- 51페이지(48~72), 7개 장(최소 6), 내용 역할 5종 모두 사용
- `TEXT` 본문 44페이지가 416~506자(평균 440자, 합계 19,380자)
- `FRONT_MATTER`(목차)와 `aiRouteCandidatePage=false`가 정확히 일치
- 선수 관계가 후보 제외 페이지를 가리키지 않음, 위상 정렬로 51페이지 전체 방문
- PDF 페이지 51개, 텍스트 45개, 이미지 6개(p7,13,21,29,37,45) — `pdfcheck.py --book 83`으로 확인
- PDF 실제 SHA-256이 manifest의 `pdfSha256`과 일치

초고는 327~506자로 하한이 정본 기준(345자)에 미달했다. 081·082와 같이 420자에 못 미친 41페이지에
`EXTRA` 문단을 더해 416~506자로 맞췄다.

## 평가 케이스: 비소장·예산 10 시나리오

| 필드 | 값 |
| --- | --- |
| `caseId` | `case-book-083` |
| `purpose` | 낯선 무역 도시에 사흘만 머무는데 시장 하나로 도시를 읽어 보고 싶다. 시장이 시각마다 무엇으로 바뀌는지와 냄새로 구역을 나누는 법, 경매와 좌판에서 값이 어떻게 갈리는지, 흥정이 무엇을 정하는 절차인지를 익히고 싶다 |
| `owned` / `maxAdditionalInk` / `depth` | `false` / `10` / `null` |
| `activeRentalPageNumbers` | 없음 (예산 0이 아닌 비소장 시나리오는 활성 대여를 두지 않는다) |
| `requiredConcepts` | 무역 도시, 장 서는 시각, 시장 구역, 냄새 지도, 새벽 경매, 도매와 소매, 흥정 |
| `helpfulConcepts` | 소리와 흐름, 신선도 판단, 향의 층, 계절 재료 |
| `referencePageNumbers` | 2, 4, 6, 8, 9, 12, 13, 16, 17, 22 |
| `irrelevantPageNumbers` | 28~31(헌옷마당의 유통과 선별), 48·49(기억의 한계) — 사흘 동안 시장으로 도시를 읽으려는 목적과 무관. 절 단위로 넣어 짝 페이지를 쪼개지 않는다 |
| `allowedAlternativePageNumbers` | 5, 14, 24 |

정답 경로는 선수 전이 폐쇄와 같고 정확히 10페이지여서 예산을 남김없이 쓴다. 처음에는 1.1 두
페이지를 활성 대여로 두고 경로를 11페이지로 잡았으나, 정본 「품질 평가 조건」이 활성 대여를 예산 0
시나리오에만 허용하므로 대여를 없애고 흥정을 22 한 페이지만 밟게 해 10페이지로 줄였다.

1장의 전제 넷(무역 도시·시각·구역·냄새)에서 어시장의 경매와 두 값으로, 다시 향신료골목의 흥정으로
이어지는 경로이며, 세 시장 가운데 둘을 담고 헌옷마당은 담지 않는다.

세 시장이 서로 선수가 아니어서 이 선택이 가능했다. 어느 한 시장을 반드시 거쳐야 다른 시장에 닿는
구조였다면 예산 10으로는 한 시장밖에 열지 못했을 것이다.

시나리오는 계획 문서가 배정한 **비소장·예산 10**을 그대로 썼다. 병합 후 36건의 분포는 QUICK·DEEP·
예산 0·예산 5·예산 10이 각 5건, BALANCED 6건, 예산 15 4건이다.

## 재현 조건

1. `python3 build083.py` — 원고와 조각 생성 (PDF SHA 없이 실행하면 자리표시자를 넣는다)
2. `python3 figures083.py pdfbuild083` — 도표 6개 SVG 생성
3. Chrome Headless로 각 SVG를 794×1123 PNG로 렌더링
4. `python3 build_pdf_generic.py 83 7,13,21,29,37,45 pdfbuild083` — 조판 HTML 생성
5. Chrome Headless `--print-to-pdf`로 PDF 출력, `pdfcheck.py --book 83`으로 구성 확인
6. PDF를 `fixtures/content/ai-route-v2/pdfs/`에 두고 SHA-256을 인자로 `build083.py` 재실행
7. `merge_fragments.py 83`으로 정본에 병합
8. `sync_readme.py --add 83 여행`으로 fixture README의 수치와 표를 다시 계산

## 검수

- 여섯 도표를 PNG로 렌더링해 눈으로 확인하고 세 곳을 고쳤다. p29는 되나가는 화살표의 이름표가 도시
  네모의 테두리에 걸쳐 바깥으로 뺐고, p45는 보지 못한 것의 이름 하나가 관찰 범위 타원에 겹쳐 옮겼다.
  p37은 첫날의 두 표시가 시각이 가까워 이름이 겹쳐, 표시마다 이름을 위아래로 번갈아 놓았다.
- 조판한 PDF의 목차와 본문 첫 장을 열어 페이지 번호·머리글·문단 나눔을 확인했다.
- 공개 가이드 주제와 비공개 분석 텍스트를 서로 다른 문장으로 적었고, 주제문에 숫자를 쓰지 않았다.
- 본문·도표·평가 데이터에 실존 국가·도시·지명·인물이 등장하지 않는다.

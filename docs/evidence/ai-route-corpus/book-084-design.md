# book-084 「지도 없는 숲길 사흘」 설계

[여행 카테고리 계획](./travel-category-plan.md)의 84번을 만든 근거다. 정책·검증 계약은
[AI 경로 콘텐츠 코퍼스](../../ai-route-content-corpus.md)를 따르고, 이 문서는 그 계약 안에서 내린
선택과 이유만 적는다.

## 대상 도서

- `bookId` 84, 카테고리 여행. 저자·소개는 `src/main/resources/demo/books.json`의 기존 값을 유지한다.
- 제목은 `ai-route-v2` manifest의 `books[].title`이 정본이며 이 문서의 제목과 같다.
- 실존 국가·지명을 쓰지 않는다. 무대는 가상의 「삼일숲」이고 지형지물은 갈림바위·마른개천·능선길이다.
  인물은 마을의 두란과 동행 시울이며 081~083의 인물과 겹치지 않는다.

## 개념 범위

계획 문서가 정한 범위(지도 없이 지형지물로 방향 잡기, 야영, 사흘의 걷는 리듬)를 그대로 따른다.

- 여행 카테고리에서 사람이 드문 자연 지형을 처음 다루는 권이다. 081~083이 배편·시각표·시장처럼 사람이
  만든 체계 안에서 움직였다면, 이 권에는 그런 체계가 없다. 시각표 대신 해가, 매표소 대신 마을 사람의
  말이 정보의 전부다.
- 090(사막)과 짝을 이루되 겹치지 않게 조건을 갈랐다. 이 권은 젖은 지형과 시야가 막힌 조건만 다루고
  밤하늘과 낮밤 온도차는 다루지 않는다. 3.3(숲의 밤)에서 밤을 다루지만 별이나 기온이 아니라 어둠의
  길이와 젖음만 다룬다.
- 085(해안도로)와도 갈린다. 085는 도로 위에서 스스로 운전하고, 084는 길이 없는 곳을 걷는다.

## 장 구성 (51페이지, 목차 1 + 본문 50)

```
1장 지도 없이 들어가기로 하다 p2–11  PREREQUISITE  지도 없이 걷기·방향 기준·지형지물·걷는 속도·짐과 물
2장 방향을 잃지 않는 법       p12–19 CORE          되짚기·갈림길 판단·능선과 계곡·조난 대응
3장 하룻밤을 나는 자리        p20–27 CORE          야영지 선택·물 구하기·숲의 밤·흔적 관리
4장 사흘을 걷는 몸            p28–35 CORE          하루 배분·몸의 신호·젖음 관리·복귀 계획
5장 삼일숲의 사흘             p36–43 EXAMPLE       첫날·둘째 날·셋째 날 기록·여정 정리
6장 이렇게 걸으면 안 되는 때  p44–49 COUNTERPOINT  적용 한계·단독 산행 위험·지도의 자리
7장 결론: 숲을 읽는 일        p50–51 CONCLUSION    종합
```

1장이 다섯 전제를 세우고 2~4장이 방향·야영·몸으로 나누어 펼친다. 이 권의 축은 "위치를 찾는 대신
관계를 세운다"이고, 그래서 2.1(되짚기)이 책 전체에서 가장 중요한 절이다. 6장은 이 방법이 통하지 않는
숲의 조건을 세 가지로 적고, 6.3에서 지도를 반대하지 않는다는 점을 분명히 한다.

이미지 6개: p7(걸어 둘 만한 것), p13(뒤를 보고 지나간다), p21(네 가지를 보고 정한다),
p30(하루의 네 토막), p37(사흘의 자리), p45(세 가지 조건). 여섯 도표가 모두 무엇을 남기고 무엇을
버리는지를 그린다. 쓰는 쪽은 진한 색, 버리는 쪽은 옅은 색으로 고정했다. 생성 스크립트는
[`figures084.py`](./tools/figures084.py)다.

중복 그룹 1개: `reading-not-locating` = [2, 50]. "지도가 있는 걸음은 위치를, 없는 걸음은 관계를
다룬다"는 명제를 1.1에서 세우고 7.1에서 사흘을 지나온 언어로 재진술한다. 재진술 페이지(50)에는 선수를
두지 않았다. 짝(2)을 선수로 걸면 50을 고른 경로에 2가 반드시 따라와 중복 그룹 규칙을 어기기 때문이며,
book-081~083과 같은 처리다.

## 선수 관계 설계

1.1(지도 없이)을 뿌리로 두고 1.2(방향 기준)와 1.4(걷는 속도)가 갈라진다. 2장은 1.3(지형지물)에서,
3장은 1.5(짐과 물)에서, 4장은 1.4와 1.5와 2.1에서, 5장은 2.2·3.2·2.3에서 갈라진다. 3장을 1.5에 붙인
것은 야영이 방향의 문제가 아니라 짐과 물의 문제이기 때문이다.

- 어느 후보 페이지도 선수 폐쇄가 8페이지를 넘지 않는다.
- 폐쇄 5페이지 이하인 후보 페이지가 일곱 개 장을 모두 덮는다 (기준 3개 장).
- 후보 페이지 50개 전부가 폐쇄 15페이지 이하다 (기준 75%).

가장 깊은 곳은 5.4(여정 정리)로 5.1 → 2.2 → 2.1 → 1.3 → 1.2 → 1.1을 거친다. 여정을 정리하려면 첫날의
기록이 있어야 하고, 기록은 갈림길 판단과 되짚기를, 그 둘은 지형지물과 방향 기준을 전제한다.

## 검증

`corpus_lib.validate_book()` → `validate_fragment.py` → `merge_fragments.py` → `validate_manifest.py`를
차례로 통과했다.

- 51페이지(48~72), 7개 장(최소 6), 내용 역할 5종 모두 사용
- `TEXT` 본문 44페이지가 409~504자(평균 435자, 합계 19,153자)
- `FRONT_MATTER`(목차)와 `aiRouteCandidatePage=false`가 정확히 일치
- 선수 관계가 후보 제외 페이지를 가리키지 않음, 위상 정렬로 51페이지 전체 방문
- PDF 페이지 51개, 텍스트 45개, 이미지 6개(p7,13,21,30,37,45) — `pdfcheck.py`로 확인
- PDF 실제 SHA-256이 manifest의 `pdfSha256`과 일치

초고는 317~504자로 하한이 정본 기준(345자)에 미달했다. 081~083과 같이 짧은 39페이지에 `EXTRA` 문단을
더해 409~504자로 맞췄다. 하한이 여행 카테고리에서 가장 낮은데, 여덟 페이지가 410자대에 걸쳐 있고
모두 60초로 눌리는 문턱(345자)에서는 충분히 떨어져 있어 그대로 두었다.

## 평가 케이스: 비소장·예산 15 시나리오

| 필드 | 값 |
| --- | --- |
| `caseId` | `case-book-084` |
| `purpose` | 지도를 구할 수 없는 숲에서 사흘을 걸을 계획이다. 무엇을 기준으로 방향을 잡고 어떤 지형지물을 기억에 걸어야 하는지, 갈림길에서 무엇을 보고 정하며 어디인지 모르게 되었을 때 어떻게 하는지, 그리고 잘 자리와 물을 어떻게 고르는지를 익히고 싶다 |
| `owned` / `maxAdditionalInk` / `depth` | `false` / `15` / `null` |
| `activeRentalPageNumbers` | 없음 |
| `requiredConcepts` | 방향 기준, 지형지물, 되짚기, 갈림길 판단, 조난 대응, 야영지 선택, 물 구하기 |
| `helpfulConcepts` | 지도 없이 걷기, 걷는 속도, 짐과 물, 숲의 밤 |
| `referencePageNumbers` | 2, 4, 6~8, 10, 12, 14, 15, 18~23 |
| `irrelevantPageNumbers` | 42·43(여정 정리), 46·47(단독 산행), 48·49(지도의 자리) — 사흘의 방향과 야영을 익히려는 목적과 무관. 절 단위로 넣어 짝 페이지를 쪼개지 않는다 |
| `allowedAlternativePageNumbers` | 13, 16, 24 |

정답 경로는 선수 전이 폐쇄와 같고 정확히 15페이지여서 예산을 남김없이 쓴다. 빌린 페이지가 없는
사례라 열다섯 페이지가 모두 차감이고, 여행 카테고리에서 유일하게 대여 없이 예산만으로 여는 사례다.

1장의 전제 넷에서 2장의 되짚기·갈림길·조난 대응으로, 다시 3장의 야영지와 물로 이어진다. 3장을
1.5(짐과 물)에 붙여 둔 덕분에 방향 계열과 야영 계열이 각각 1장에서 갈라져, 열다섯 페이지 안에 두 계열이
함께 들어왔다.

대체 페이지 셋은 선수 폐쇄가 정답 경로 안에 거의 들어 있는 것만 골랐다. 13은 그 자체만 더해지고,
16·17은 1.3에서 곧장 갈라져 예산 안에서 바꿔 고를 수 있다.

시나리오는 계획 문서가 배정한 **비소장·예산 15**를 그대로 썼다. 병합 후 37건의 분포는 BALANCED 6건,
QUICK·DEEP·예산 0·예산 5·예산 10·예산 15가 각 5건이다.

## 재현 조건

1. `python3 build084.py` — 원고와 조각 생성 (PDF SHA 없이 실행하면 자리표시자를 넣는다)
2. `python3 figures084.py pdfbuild084` — 도표 6개 SVG 생성
3. Chrome Headless로 각 SVG를 794×1123 PNG로 렌더링
4. `python3 build_pdf_generic.py 84 7,13,21,30,37,45 pdfbuild084` — 조판 HTML 생성
5. Chrome Headless `--print-to-pdf`로 PDF 출력, `pdfcheck.py`로 구성 확인
6. PDF를 `fixtures/content/ai-route-v2/pdfs/`에 두고 SHA-256을 인자로 `build084.py` 재실행
7. `merge_fragments.py 84`로 정본에 병합

## 검수

- 여섯 도표를 PNG로 렌더링해 눈으로 확인하고 네 곳을 고쳤다. p13은 '올 때' 상자가 갈라진 모양으로
  잘못 그려져 한 덩어리로 바로잡았고 주석 위치도 옮겼다. p21은 바람 설명이 천막에 겹쳐 위로 올렸고,
  p37은 되짚은 자리의 이름표가 화면 밖으로 나가 아래쪽으로 옮겼다.
- 조판한 PDF의 목차와 본문 첫 장을 열어 페이지 번호·머리글·문단 나눔을 확인했다.
- 공개 가이드 주제와 비공개 분석 텍스트를 서로 다른 문장으로 적었고, 주제문에 숫자를 쓰지 않았다.
- 본문·도표·평가 데이터에 실존 국가·지명·인물이 등장하지 않는다.

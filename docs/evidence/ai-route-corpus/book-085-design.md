# book-085 「바람이 강한 해안도로」 설계

[여행 카테고리 계획](./travel-category-plan.md)의 85번을 만든 근거다. 정책·검증 계약은
[AI 경로 콘텐츠 코퍼스](../../ai-route-content-corpus.md)를 따르고, 이 문서는 그 계약 안에서 내린
선택과 이유만 적는다.

## 대상 도서

- `bookId` 85, 카테고리 여행. 저자·소개는 `src/main/resources/demo/books.json`의 기존 값을 유지한다.
- 제목은 `ai-route-v2` manifest의 `books[].title`이 정본이며 이 문서의 제목과 같다.
- 실존 국가·지명을 쓰지 않는다. 무대는 가상의 「긴모래해안」이고 지점은 첫굽이·바람언덕·등대곶이다.
  인물은 자전거를 빌려준 해든 한 사람이고, 등대곶 찻집 주인은 이름 없이 역할로만 적는다.
  081~084의 인물과 겹치지 않는다.

## 개념 범위

계획 문서가 정한 범위(해안도로를 따라 바람·굽이·전망대를 지나는 이동)를 그대로 따른다.

- 081·082가 남이 운행하는 배와 기차를 탔다면 이 권은 스스로 달린다. 그 차이가 이 권의 전제이고,
  7장에서 "시각표가 없는 대신 바람의 시각표가 있었다"로 되받는다.
- 089(도시 순환선)와 갈리는 지점은 단위다. 089는 하루권으로 남의 노선을 도는 짧은 이동이고, 085는
  이틀 동안 자기 속도로 한 방향을 달린다. 085에는 정거장도 요금도 나오지 않는다.
- 084(숲)와도 갈린다. 084는 길이 없는 곳을 걷고 085는 포장된 도로 위를 달린다. 그래서 084의 축이
  방향 잡기라면 085의 축은 바람 하나다.

## 장 구성 (51페이지, 목차 1 + 본문 50)

```
1장 시각표가 없는 이동   p2–11   PREREQUISITE  자기 운전·해풍·굽이·노면 상태·하루 거리
2장 바람을 다루기         p12–19  CORE          맞바람·옆바람·바람 지형·멈춤 판단
3장 길이 만드는 조건      p20–27  CORE          굽이 읽기·오르내림·전망대·해안 마을
4장 하루를 짜기           p28–35  CORE          출발 시각·거리 배분·보급·잘 곳
5장 긴모래해안의 이틀     p36–43  EXAMPLE       첫날 구간·바람언덕·등대곶·이틀 정리
6장 이 방법이 통하지 않을 때 p44–49 COUNTERPOINT 바람이 막는 날·차와 자전거·다른 해안
7장 결론: 바람에 맞추는 길 p50–51 CONCLUSION    종합
```

1장이 다섯 전제를 세우고 2~4장이 바람·길·하루로 나누어 펼친다. 6.2는 이 책이 자전거의 속도에서만
성립한다는 것을 인정하고 어느 장이 차에도 남는지를 구분한다. 이 구분을 넣은 것은 계획 문서가 이 권에
"자기 운전"이라고만 적어 두어 수단이 둘로 열려 있기 때문이다.

이미지 6개: p9(어디로 달릴 것인가), p14(굽이를 돌면 바람이 바뀐다), p20(굽이가 알려 주는 것),
p31(곶은 아침에, 만은 오후에), p38(좁아지면 빨라진다), p44(어느 세기까지 갈 수 있는가). 여섯 도표가
모두 바람이 어디서 어떻게 오는지를 그리고, 바람은 늘 굵은 화살표로 고정했다. 생성 스크립트는
[`figures085.py`](./tools/figures085.py)다. 이미지 자리를 앞의 네 권(7·13·21·30·37·45)과 다르게 잡은
것은 이 권의 도표가 각 절의 첫 페이지가 아니라 설명이 끝난 자리에 놓여야 했기 때문이다.

중복 그룹 1개: `wind-is-the-timetable` = [2, 50]. "시각표가 없는 이동"이라는 전제를 1.1에서 세우고
7.1에서 그 전제가 틀렸다는 형태로 재진술한다. 재진술 페이지(50)에는 선수를 두지 않았다. 짝(2)을
선수로 걸면 50을 고른 경로에 2가 반드시 따라와 중복 그룹 규칙을 어기기 때문이며, book-081~084와 같은
처리다.

## 선수 관계 설계

1.1을 뿌리로 두고 1.2(해풍)·1.3(굽이)·1.5(하루 거리)가 나란히 갈라진다. 2장은 1.2에서, 3장은 1.3과
1.5에서, 4장은 1.5에서 갈라진다. 세 갈래를 1장에서 곧장 벌린 것은 이 권의 평가 시나리오가 QUICK이라
다섯 페이지 안에 목적을 채워야 하기 때문이다.

- 어느 후보 페이지도 선수 폐쇄가 6페이지를 넘지 않는다. 여행 카테고리에서 가장 얕다.
- 폐쇄 5페이지 이하인 후보 페이지가 일곱 개 장을 모두 덮는다 (기준 3개 장).
- 후보 페이지 50개 전부가 폐쇄 15페이지 이하다 (기준 75%).

## 검증

`corpus_lib.validate_book()` → `validate_fragment.py` → `merge_fragments.py` → `validate_manifest.py`를
차례로 통과했다.

- 51페이지(48~72), 7개 장(최소 6), 내용 역할 5종 모두 사용
- `TEXT` 본문 44페이지가 368~475자(평균 421자, 합계 18,504자)
- `FRONT_MATTER`(목차)와 `aiRouteCandidatePage=false`가 정확히 일치
- 선수 관계가 후보 제외 페이지를 가리키지 않음, 위상 정렬로 51페이지 전체 방문
- PDF 페이지 51개, 텍스트 45개, 이미지 6개(p9,14,20,31,38,44) — `pdfcheck.py --book 85`으로 확인
- PDF 실제 SHA-256이 manifest의 `pdfSha256`과 일치

초고가 293~439자로 앞의 네 권보다 짧아 43페이지에 `EXTRA` 문단을 더했다. 그래도 하한이 368자로 여행
카테고리에서 가장 낮다. 60초로 눌리는 문턱(345자)에서는 떨어져 있어 그대로 두었고, 이 권이 다른 권보다
짧은 것은 한 절이 다루는 것이 좁아 문단이 짧게 끊기기 때문이다.

## 평가 케이스: 소장·QUICK 시나리오

| 필드 | 값 |
| --- | --- |
| `caseId` | `case-book-085` |
| `purpose` | 이 책을 소장하고 있는데, 해안도로를 자전거로 달릴 계획이라 바람만 빠르게 익히고 싶다. 하루 안에서 바람이 어떻게 도는지와 앞에서 오는 바람과 옆에서 미는 바람을 각각 어떻게 다루는지를 알고 싶다 |
| `owned` / `maxAdditionalInk` / `depth` | `true` / `null` / `QUICK` |
| `requiredConcepts` | 자기 운전, 해풍, 맞바람, 옆바람 |
| `helpfulConcepts` | 굽이, 바람 지형, 멈춤 판단, 하루 거리 |
| `referencePageNumbers` | 2, 4, 12, 14, 15 |
| `irrelevantPageNumbers` | 24·25(전망대), 32·33(보급), 46·47(차와 자전거) — 바람만 익히려는 이 목적과 무관. 절 단위로 넣어 짝 페이지를 쪼개지 않는다 |
| `allowedAlternativePageNumbers` | 5, 13, 16 |

정답 경로는 선수 전이 폐쇄와 같고 정확히 5페이지여서 QUICK 상한을 남김없이 쓴다. 1.1에서 1.2로,
1.2에서 2.1로, 2.1에서 2.2로 내려가는 한 줄기이며 갈래가 없다. QUICK 상한 안에 목적을 담으려면 이렇게
한 줄기로 내려가는 경로가 필요했고, 그래서 2장의 순서를 맞바람 → 옆바람으로 두었다.

대체 페이지 셋은 바꿔 골라도 폐쇄가 다섯 페이지를 넘지 않는 것만 골랐다. 13은 2.1의 이어지는 설명이고,
5는 1.2의 두 번째 페이지이며, 16은 1.2에서 곧장 갈라지는 2.3의 첫 페이지다.

시나리오는 계획 문서가 배정한 **소장·QUICK**을 그대로 썼다. 병합 후 38건의 분포는 BALANCED·QUICK이
각 6건, DEEP·예산 0·예산 5·예산 10·예산 15가 각 5건이다.

## 재현 조건

1. `python3 build085.py` — 원고와 조각 생성 (PDF SHA 없이 실행하면 자리표시자를 넣는다)
2. `python3 figures085.py pdfbuild085` — 도표 6개 SVG 생성
3. Chrome Headless로 각 SVG를 794×1123 PNG로 렌더링
4. `python3 build_pdf_generic.py 85 9,14,20,31,38,44 pdfbuild085` — 조판 HTML 생성
5. Chrome Headless `--print-to-pdf`로 PDF 출력, `pdfcheck.py --book 85`으로 구성 확인
6. PDF를 `fixtures/content/ai-route-v2/pdfs/`에 두고 SHA-256을 인자로 `build085.py` 재실행
7. `merge_fragments.py 85`로 정본에 병합
8. `sync_readme.py --add 85 여행`으로 fixture README의 수치와 표를 다시 계산

## 검수

- 여섯 도표를 PNG로 렌더링해 눈으로 확인했다. p38에서 바람 화살표가 도로와 이름표를 가로질러 화살표
  자리를 도로 위아래로 나누고 이름표를 아래로 내렸다. 나머지 다섯은 그대로 두었다.
- 조판한 PDF의 구성을 `pdfcheck.py`로 확인했다.
- 공개 가이드 주제와 비공개 분석 텍스트를 서로 다른 문장으로 적었고, 주제문에 숫자를 쓰지 않았다.
- 본문·도표·평가 데이터에 실존 국가·도시·지명·인물이 등장하지 않는다.

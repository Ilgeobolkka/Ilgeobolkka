# book-086 「새벽 항구의 첫 식사」 설계

[여행 카테고리 계획](./travel-category-plan.md)의 86번을 만든 근거다. 정책·검증 계약은
[AI 경로 콘텐츠 코퍼스](../../ai-route-content-corpus.md)를 따르고, 이 문서는 그 계약 안에서 내린
선택과 이유만 적는다.

## 대상 도서

- `bookId` 86, 카테고리 여행. 저자·소개는 `src/main/resources/demo/books.json`의 기존 값을 유지한다.
- 제목은 `ai-route-v2` manifest의 `books[].title`이 정본이며 이 문서의 제목과 같다.
- 실존 국가·지명을 쓰지 않는다. 무대는 가상의 항구 마을 「자물목」이고 장소는 위판장·방파제·아침식당
  골목이다. 인물은 경매사 다율, 배 주인 온수, 아침식당의 갈래이며 081~085의 인물과 겹치지 않는다.

## 개념 범위

계획 문서가 정한 범위(항구 마을의 새벽 조업·귀항·위판·아침식사 문화)를 그대로 따른다.

- 083(시장 냄새로 기억한 도시)과 가장 가깝고, 그래서 경계를 먼저 그었다. 083은 물건이 도시로 흩어지는
  유통 쪽을, 086은 그 물건이 바다에서 올라오는 생산 쪽을 다룬다. 이 권에는 도시가 나오지 않고 마을
  하나만 나오며, 축은 시장이 아니라 배가 나가고 들어오는 시각이다.
- 081(배로 건너는 섬)과도 갈린다. 081은 여객선을 타고 이동하고 086은 어선이 나가고 들어오는 것을
  바라본다. 이 권에서 화자는 배를 한 번도 타지 않는다.
- 이 권에만 있는 축은 **일터를 구경한다는 것**이다. 4장 전체가 어디에 서고 언제 묻고 무엇을 찍지
  않을지를 다루며, 다른 아홉 권에는 이 문제가 없다.

## 장 구성 (51페이지, 목차 1 + 본문 50)

```
1장 자물목의 새벽       p2–11   PREREQUISITE  항구의 하루·출항 시각·조업 조건·위판장·마을 배치
2장 배가 들어오는 시간  p12–19  CORE          귀항 순서·하역·값매김·출하
3장 아침식당 골목       p20–27  CORE          밥집 시각·아침 차림·먹는 사람들·밥값
4장 여행자의 자리       p28–35  CORE          구경하는 자리·묻는 법·사진 예의·사는 법
5장 자물목의 하루       p36–43  EXAMPLE       새벽·아침·밥상·낮 기록
6장 이 마을이 아닌 항구 p44–49  COUNTERPOINT  휴어기·관광 항구·큰 항구
7장 결론: 새벽을 보는 일 p50–51 CONCLUSION    종합
```

1장이 다섯 전제를 세우고 2~3장이 물건과 사람의 순서를 따라가며, 4장이 관찰자의 자리를 따로 다룬다.
6장은 이 관찰이 성립하지 않는 세 조건(비조업기, 관광화된 항구, 대규모 항만)을 적는다. 6.2에서 이 책이
기록한 싼 아침이 여행자가 드물다는 조건 위에 있다는 것을 밝힌 것은, 이 기록이 광고로 읽히지 않게 하려는
것이다.

이미지 6개: p9(바다에서 도로까지), p15(물러나 있을 자리), p21(새벽 두 시부터 아홉 시까지),
p29(서도 되는 자리), p37(사흘의 새벽), p45(두 철의 하루). 여섯 도표가 모두 새벽의 순서를 그리고, 사람이
일하는 자리는 옅은 붉은색, 여행자가 설 수 있는 자리는 진한 초록으로 고정했다. 생성 스크립트는
[`figures086.py`](./tools/figures086.py)다.

중복 그룹 1개: `harbor-runs-on-night` = [2, 50]. "이 마을의 하루는 자정에 시작된다"는 명제를 1.1에서
세우고 7.1에서 일터를 구경한다는 관점으로 재진술한다. 재진술 페이지(50)에는 선수를 두지 않았다.
짝(2)을 선수로 걸면 50을 고른 경로에 2가 반드시 따라와 중복 그룹 규칙을 어기기 때문이며,
book-081~085와 같은 처리다.

## 선수 관계 설계

1.1을 뿌리로 두고 1.2(출항 시각)·1.4(위판장)·1.5(마을 배치)가 나란히 갈라진다. 2장은 1.2와 1.4에서,
3장과 4장은 1.5에서 갈라진다. 시각 계열(출항 → 귀항)과 장소 계열(위판장 → 값매김)을 1장에서 따로
벌려 두어, 평가 경로가 두 계열을 함께 담을 수 있게 했다.

- 어느 후보 페이지도 선수 폐쇄가 6페이지를 넘지 않는다.
- 폐쇄 5페이지 이하인 후보 페이지가 일곱 개 장을 모두 덮는다 (기준 3개 장).
- 후보 페이지 50개 전부가 폐쇄 15페이지 이하다 (기준 75%).

## 검증

`corpus_lib.validate_book()` → `validate_fragment.py` → `merge_fragments.py` → `validate_manifest.py`를
차례로 통과했다.

- 51페이지(48~72), 7개 장(최소 6), 내용 역할 5종 모두 사용
- `TEXT` 본문 44페이지가 367~482자(평균 411자, 합계 18,087자)
- `FRONT_MATTER`(목차)와 `aiRouteCandidatePage=false`가 정확히 일치
- 선수 관계가 후보 제외 페이지를 가리키지 않음, 위상 정렬로 51페이지 전체 방문
- PDF 페이지 51개, 텍스트 45개, 이미지 6개(p9,15,21,29,37,45) — `pdfcheck.py`로 확인
- PDF 실제 SHA-256이 manifest의 `pdfSha256`과 일치

초고가 294~392자로 짧아 44페이지 전부에 `EXTRA` 문단을 더했다. 085와 마찬가지로 하한이 370자 안팎인데,
60초로 눌리는 문턱(345자)에서는 떨어져 있다.

## 평가 케이스: 소장·BALANCED 시나리오

| 필드 | 값 |
| --- | --- |
| `caseId` | `case-book-086` |
| `purpose` | 이 책을 소장하고 있는데, 항구 마을에서 새벽 하루를 따라가 볼 계획이다. 배가 언제 나가고 어떤 순서로 돌아오는지, 위판장에서 값이 어떻게 매겨지는지, 아침식당이 언제 여는지를 이어서 익히고 싶다 |
| `owned` / `maxAdditionalInk` / `depth` | `true` / `null` / `BALANCED` |
| `requiredConcepts` | 항구의 하루, 출항 시각, 위판장, 귀항 순서, 값매김, 밥집 시각 |
| `helpfulConcepts` | 조업 조건, 하역, 마을 배치, 아침 차림 |
| `referencePageNumbers` | 2, 4, 5, 8, 10, 12, 13, 16, 17, 20 |
| `irrelevantPageNumbers` | 32·33(사진 예의), 46·47(관광 항구), 48·49(큰 항구) — 새벽의 순서를 따라가려는 목적과 무관. 절 단위로 넣어 짝 페이지를 쪼개지 않는다 |
| `allowedAlternativePageNumbers` | 9, 14, 21 |

정답 경로는 선수 전이 폐쇄와 같고 정확히 10페이지여서 BALANCED 상한을 남김없이 쓴다. 1장의 전제 넷에서
시각 계열(출항 → 귀항)과 장소 계열(위판장 → 값매김)로 갈라졌다가 3장의 밥집 시각에서 다시 만난다. 두
계열이 1장에서 각각 갈라져 있어야 열 페이지 안에 둘을 함께 담을 수 있었다.

시나리오는 계획 문서가 배정한 **소장·BALANCED**를 그대로 썼다. 병합 후 39건의 분포는 BALANCED가 7건,
QUICK이 6건, DEEP·예산 0·예산 5·예산 10·예산 15가 각 5건이다.

## 재현 조건

1. `python3 build086.py` — 원고와 조각 생성 (PDF SHA 없이 실행하면 자리표시자를 넣는다)
2. `python3 figures086.py pdfbuild086` — 도표 6개 SVG 생성
3. Chrome Headless로 각 SVG를 794×1123 PNG로 렌더링
4. `python3 build_pdf_generic.py 86 9,15,21,29,37,45 pdfbuild086` — 조판 HTML 생성
5. Chrome Headless `--print-to-pdf`로 PDF 출력, `pdfcheck.py`로 구성 확인
6. PDF를 `fixtures/content/ai-route-v2/pdfs/`에 두고 SHA-256을 인자로 `build086.py` 재실행
7. `merge_fragments.py 86`으로 정본에 병합

## 검수

- 여섯 도표를 PNG로 렌더링해 눈으로 확인했다. p45에서 좁은 구역의 이름이 칸 안에 들어가지 못해 위로
  빼고, 두 철을 잇는 화살표가 아래 줄의 글자를 가로질러 경로를 꺾어 옮겼다. 나머지 다섯은 그대로 두었다.
- 조판한 PDF의 구성을 `pdfcheck.py`로 확인했다.
- 공개 가이드 주제와 비공개 분석 텍스트를 서로 다른 문장으로 적었고, 주제문에 숫자를 쓰지 않았다.
- 본문·도표·평가 데이터에 실존 국가·지명·인물이 등장하지 않는다.

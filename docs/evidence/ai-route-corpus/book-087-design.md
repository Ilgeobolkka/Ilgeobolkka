# book-087 「고원 마을의 느린 우편」 설계

[여행 카테고리 계획](./travel-category-plan.md)의 87번을 만든 근거다. 정책·검증 계약은
[AI 경로 콘텐츠 코퍼스](../../ai-route-content-corpus.md)를 따르고, 이 문서는 그 계약 안에서 내린
선택과 이유만 적는다.

## 대상 도서

- `bookId` 87, 카테고리 여행. 저자·소개는 `src/main/resources/demo/books.json`의 기존 값을 유지한다.
- 제목은 `ai-route-v2` manifest의 `books[].title`이 정본이며 이 문서의 제목과 같다.
- 실존 국가·지명을 쓰지 않는다. 무대는 가상의 「윗바람고원」이고 마을은 구름마을과 돌담마을이다.
  인물은 우체부 마루, 구름마을의 세경, 돌담마을의 봉산이며 081~086의 인물과 겹치지 않는다.

## 개념 범위

계획 문서가 정한 범위(고원 마을의 느린 우편배달 리듬과 계절 고립)를 그대로 따른다.

- 다른 아홉 권이 사람과 물건의 이동을 다룬다면 이 권은 **소식이 이동하는 속도**를 다룬다. 그래서 이
  권에는 여행자가 어디로 가는지가 거의 나오지 않고 편지가 어디까지 가는지가 나온다.
- 086(항구 마을)과 대비되는 고지대 마을이다. 086이 하루 안의 시각표를 다룬다면 087은 일주일과 한 해
  단위의 주기를 다룬다. 두 권 다 마을 하나에 머물지만 시간의 단위가 다르다.
- 081(배편 시간표)과도 갈린다. 081의 주기는 여행자가 맞춰야 할 시간표이고, 087의 주기는 그 마을
  사람들의 생활이 이미 맞춰져 있는 시간표다. 이 권에서 여행자는 그 리듬을 따라다니기만 한다.

## 장 구성 (49페이지, 목차 1 + 본문 48)

```
1장 윗바람고원          p2–11   PREREQUISITE  고원의 조건·오르는 길·두 마을·우편배달·계절 고립
2장 우편이 오는 길      p12–19  CORE          집배 경로·배달 주기·오는 물건·나가는 물건
3장 느림이 만드는 것    p20–27  CORE          기다리는 시간·편지의 말·늦는 소식·급한 연락
4장 길이 끊기는 계절    p28–34  CORE          길 끊김·겨울 준비·묵는 우편·재개통
5장 사흘 동안 따라다닌 우편 p35–42 EXAMPLE    첫날·둘째 날·셋째 날 동행·동행 정리
6장 이 리듬이 바뀔 때   p43–47  COUNTERPOINT  길이 바뀌면·통신이 들어오면·인구 감소
7장 결론: 늦게 오는 소식 p48–49 CONCLUSION    종합
```

49페이지로 앞의 여섯 권보다 두 페이지 짧다. 4.1(길 끊김)과 6.2(통신이 들어오면)를 한 페이지로 둔
결과인데, 두 절 모두 앞 절의 조건을 한 번 더 적는 자리라 두 페이지로 늘리면 되풀이가 됐다.

이미지 6개: p7(며칠 걸려 닿는가), p13(다섯 자리와 나흘), p21(몇 번 보러 가는가),
p30(열린 계절과 닫힌 계절), p36(사흘의 동행), p44(무엇이 바뀌면 무엇이 바뀌는가). 여섯 도표가 모두
소식이 며칠 걸리는지를 그리고, 기다리는 구간은 옅은 색, 움직이는 구간은 진한 색으로 고정했다. 생성
스크립트는 [`figures087.py`](./tools/figures087.py)다.

중복 그룹 1개: `slow-news-is-a-structure` = [2, 48]. "이 고원에서는 모든 것이 묶음으로 온다"는 명제를
1.1에서 물자에 관해 세우고 7.1에서 소식에 관해 재진술한다. 재진술 페이지(48)에는 선수를 두지 않았다.
짝(2)을 선수로 걸면 48을 고른 경로에 2가 반드시 따라와 중복 그룹 규칙을 어기기 때문이며,
book-081~086과 같은 처리다.

## 선수 관계 설계

1.1을 뿌리로 두고 1.2(오르는 길)와 1.3(두 마을)이 갈라진다. 2장은 1.4(우편배달)에서, 3장은
2.2(배달 주기)에서, 4장은 1.5(계절 고립)에서, 5장은 2.2에서 갈라진다. 2장과 3장을 한 줄기로 이어
둔 것은 이 권의 평가 시나리오가 DEEP이라 열다섯 페이지짜리 긴 사슬이 필요했기 때문이다.

- 어느 후보 페이지도 선수 폐쇄가 9페이지를 넘지 않는다.
- 폐쇄 5페이지 이하인 후보 페이지가 다섯 개 장을 덮는다 (기준 3개 장).
- 후보 페이지 48개 전부가 폐쇄 15페이지 이하다 (기준 75%).

3장 전체가 2장 위에 얹혀 있어 3장의 페이지는 폐쇄가 6페이지 이상이다. 이것이 이 권에서 폐쇄 ≤5인 장이
다섯으로 줄어든 이유이고, 기준 세 개 장은 넘는다.

## 검증

`corpus_lib.validate_book()` → `validate_fragment.py` → `merge_fragments.py` → `validate_manifest.py`를
차례로 통과했다.

- 49페이지(48~72), 7개 장(최소 6), 내용 역할 5종 모두 사용
- `TEXT` 본문 42페이지가 359~499자(평균 401자, 합계 16,844자)
- `FRONT_MATTER`(목차)와 `aiRouteCandidatePage=false`가 정확히 일치
- 선수 관계가 후보 제외 페이지를 가리키지 않음, 위상 정렬로 49페이지 전체 방문
- PDF 페이지 49개, 텍스트 43개, 이미지 6개(p7,13,21,30,36,44) — `pdfcheck.py`로 확인
- PDF 실제 SHA-256이 manifest의 `pdfSha256`과 일치

## 평가 케이스: 소장·DEEP 시나리오

| 필드 | 값 |
| --- | --- |
| `caseId` | `case-book-087` |
| `purpose` | 이 책을 소장하고 있는데, 우편이 며칠 걸려 닿는 고원 마을에 오래 머물 계획이다. 편지가 어떤 자리들을 지나 며칠에 한 번 오는지, 그 주기가 기다림과 편지의 문장을 어떻게 바꾸는지, 그리고 정말 급할 때는 무엇을 쓰는지까지 차근히 익히고 싶다 |
| `owned` / `maxAdditionalInk` / `depth` | `true` / `null` / `DEEP` |
| `requiredConcepts` | 우편배달, 집배 경로, 배달 주기, 기다리는 시간, 편지의 말, 급한 연락 |
| `helpfulConcepts` | 고원의 조건, 두 마을, 늦는 소식, 계절 고립 |
| `referencePageNumbers` | 2, 6, 8, 9, 12~15, 20~24, 26, 27 |
| `irrelevantPageNumbers` | 29·30(겨울 준비), 43·44(길이 바뀌면), 46·47(인구 감소) — 우편의 리듬만 익히려는 목적과 무관. 절 단위로 넣어 짝 페이지를 쪼개지 않는다 |
| `allowedAlternativePageNumbers` | 7, 16, 25 |

정답 경로는 선수 전이 폐쇄와 같고 정확히 15페이지여서 DEEP 상한을 남김없이 쓴다. 1.1에서 1.3과
1.4를 지나 2장 전체를 거쳐 3장의 세 절까지 내려가는 하나의 긴 사슬이고, 여행 카테고리에서 가장 깊은
경로다. 4장(계절)과 5장(동행)은 이 경로에 들어오지 않는다 — 우편의 리듬을 익히려는 목적에는 한 해
단위의 이야기가 필요하지 않기 때문이다.

시나리오는 계획 문서가 배정한 **소장·DEEP**을 그대로 썼다. 병합 후 40건의 분포는 BALANCED가 7건,
QUICK·DEEP이 각 6건, 예산 0·예산 5·예산 10·예산 15가 각 5건이다.

## 재현 조건

1. `python3 build087.py` — 원고와 조각 생성 (PDF SHA 없이 실행하면 자리표시자를 넣는다)
2. `python3 figures087.py pdfbuild087` — 도표 6개 SVG 생성
3. Chrome Headless로 각 SVG를 794×1123 PNG로 렌더링
4. `python3 build_pdf_generic.py 87 7,13,21,30,36,44 pdfbuild087` — 조판 HTML 생성
5. Chrome Headless `--print-to-pdf`로 PDF 출력, `pdfcheck.py`로 구성 확인
6. PDF를 `fixtures/content/ai-route-v2/pdfs/`에 두고 SHA-256을 인자로 `build087.py` 재실행
7. `merge_fragments.py 87`로 정본에 병합

## 검수

- 여섯 도표를 PNG로 렌더링해 눈으로 확인하고 두 곳을 고쳤다. p30은 준비기의 물자 이름이 원에서 떨어져
  있어 연결선을 넣고 묵는 우편 기호가 겹쳐 간격을 벌렸다. p36은 사흘의 걸음이 모두 같은 방향으로 보여
  내려오는 날에 반대 방향 화살표를 넣었다.
- 조판한 PDF의 구성을 `pdfcheck.py`로 확인했다.
- 공개 가이드 주제와 비공개 분석 텍스트를 서로 다른 문장으로 적었고, 주제문에 숫자를 쓰지 않았다.
- 본문·도표·평가 데이터에 실존 국가·지명·인물이 등장하지 않는다.
- 닫힌 계절의 이야기는 모두 들은 이야기이고 본 이야기가 아니라는 점을 1.5와 4.3에 적어 두었다.

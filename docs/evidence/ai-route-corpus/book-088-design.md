# book-088 「비 오는 골목의 지도」 설계

[여행 카테고리 계획](./travel-category-plan.md)의 88번을 만든 근거다. 정책·검증 계약은
[AI 경로 콘텐츠 코퍼스](../../ai-route-content-corpus.md)를 따르고, 이 문서는 그 계약 안에서 내린
선택과 이유만 적는다.

## 대상 도서

- `bookId` 88, 카테고리 여행. 저자·소개는 `src/main/resources/demo/books.json`의 기존 값을 유지한다.
- 제목은 `ai-route-v2` manifest의 `books[].title`이 정본이며 이 문서의 제목과 같다.
- 실존 국가·도시·지명을 쓰지 않는다. 무대는 가상의 「먹구름시」이고 골목은 처마길·배수로길·우산장이다.
  인물은 우산 가게의 소하와 인쇄소의 한별이며 081~087의 인물과 겹치지 않는다.

## 개념 범위

계획 문서가 정한 범위(빗길 도시 골목의 미로 구조, 지도에 없는 골목을 손으로 그리기)를 그대로 따른다.

- 083(시장 냄새로 기억한 도시)과 같은 도시 정주 계열이라 경계를 분명히 했다. 도시가 다르고(재의 항과
  먹구름시) 읽는 단서가 다르다. 083은 냄새와 소리로 구역을 나누고 088은 골목의 지형을 손으로 그린다.
  이 권에는 시장이 나오지 않고 상행위도 다루지 않는다.
- 084(지도 없는 숲길)와도 갈린다. 084는 지도가 없는 채로 걷고 088은 지도를 만든다. 084의 축이 방향
  잡기라면 088의 축은 기록이다. 두 권 다 되짚기를 다루지만 084는 살아 나오기 위해, 088은 그린 것을
  확인하기 위해 되짚는다.
- 이 권에만 있는 축은 **비를 관찰 조건으로 쓰는 것**이다. 기울기와 배수와 처마와 미끄러움이 비 오는
  날에만 드러나고, 6.2에서 맑은 날에는 무엇을 놓치는지를 따로 적었다.

## 장 구성 (48페이지, 목차 1 + 본문 47)

```
1장 먹구름시의 골목       p2–11   PREREQUISITE  지도의 공백·골목의 폭·물길·처마·골목 입구
2장 비 오는 날의 골목     p12–19  CORE          빗길 통행·배수로·바닥 재질·빗소리
3장 손으로 그리는 지도    p20–27  CORE          그리는 기준·걸음 재기·기호·지도 수정
4장 길을 잃는 방식        p28–34  CORE          되돌아 나오기·막다른 길·순환 골목·길 묻기
5장 사흘 동안 그린 세 장  p35–41  EXAMPLE       첫 장·둘째 장·셋째 장·지도 합치기
6장 이 방법이 통하지 않는 곳 p42–46 COUNTERPOINT 재개발·맑은 날·남에게 주는 지도
7장 결론: 그리면서 걷기   p47–48  CONCLUSION    종합
```

48페이지다. 4.1(되돌아 나오기)과 5.3(셋째 장)과 6.1(재개발)을 한 페이지로 둔 결과인데, 세 절 모두 앞
절의 방법을 한 번 더 적용하는 자리라 두 페이지로 늘리면 되풀이가 됐다.

이미지 6개: p7(물이 가리키는 쪽), p16(젖으면 달라지는 바닥), p24(여덟 개의 기호),
p30(뚫렸는가 막혔는가), p36(처마길 한 장), p43(두 날의 같은 골목). p24와 p36은 이 책이 만든 기호와
그 기호로 그린 실제 지도를 그대로 옮긴 것이라, 본문에서 설명한 표기가 도표에서 확인된다. 생성
스크립트는 [`figures088.py`](./tools/figures088.py)다.

중복 그룹 1개: `draw-while-walking` = [2, 47]. "이 도시에서는 지도를 얻는 것이 아니라 만들어야 한다"는
명제를 1.1에서 세우고 7.1에서 걷는 방식에 관한 말로 재진술한다. 재진술 페이지(47)에는 선수를 두지
않았다. 짝(2)을 선수로 걸면 47을 고른 경로에 2가 반드시 따라와 중복 그룹 규칙을 어기기 때문이며,
book-081~087과 같은 처리다.

## 선수 관계 설계

1.1을 뿌리로 두고 1.2(골목의 폭)와 1.3(물길)이 갈라진다. 2장은 1.2와 1.3에서, 3장은 1.5(골목 입구)에서,
4장은 3.2(걸음 재기)와 1.5에서 갈라진다. 3장을 1.5에 붙인 것은 그리는 일이 골목에 들어가는 일부터
시작하기 때문이다.

- 어느 후보 페이지도 선수 폐쇄가 8페이지를 넘지 않는다.
- 폐쇄 5페이지 이하인 후보 페이지가 일곱 개 장을 모두 덮는다 (기준 3개 장).
- 후보 페이지 47개 전부가 폐쇄 15페이지 이하다 (기준 75%).

## 검증

`corpus_lib.validate_book()` → `validate_fragment.py` → `merge_fragments.py` → `validate_manifest.py`를
차례로 통과했다.

- 48페이지(48~72), 7개 장(최소 6), 내용 역할 5종 모두 사용
- `TEXT` 본문 41페이지가 384~495자(평균 413자, 합계 16,940자)
- `FRONT_MATTER`(목차)와 `aiRouteCandidatePage=false`가 정확히 일치
- 선수 관계가 후보 제외 페이지를 가리키지 않음, 위상 정렬로 48페이지 전체 방문
- PDF 페이지 48개, 텍스트 42개, 이미지 6개(p7,16,24,30,36,43) — `pdfcheck.py`로 확인
- PDF 실제 SHA-256이 manifest의 `pdfSha256`과 일치

## 평가 케이스: 비소장·예산 10 시나리오

| 필드 | 값 |
| --- | --- |
| `caseId` | `case-book-088` |
| `purpose` | 지도에 골목이 그려져 있지 않은 도시에 며칠 머물면서 직접 골목 지도를 그려 보고 싶다. 비 오는 날 골목에서 물이 어느 쪽으로 흐르는지와 배수로를 어떻게 읽는지, 그리고 걸음으로 재어 종이에 옮기는 방법을 이어서 익히고 싶다 |
| `owned` / `maxAdditionalInk` / `depth` | `false` / `10` / `null` |
| `activeRentalPageNumbers` | 없음 (예산 0이 아닌 비소장 시나리오는 활성 대여를 두지 않는다) |
| `requiredConcepts` | 지도의 공백, 골목의 폭, 물길, 빗길 통행, 배수로, 그리는 기준, 걸음 재기 |
| `helpfulConcepts` | 처마, 골목 입구, 기호, 바닥 재질 |
| `referencePageNumbers` | 2, 4, 6, 10, 12~15, 20, 22 |
| `irrelevantPageNumbers` | 33·34(길 묻기), 42(재개발), 45·46(남에게 주는 지도) — 직접 그리는 방법을 익히려는 목적과 무관. 절 단위로 넣어 짝 페이지를 쪼개지 않는다 |
| `allowedAlternativePageNumbers` | 5, 11, 21 |

정답 경로는 선수 전이 폐쇄와 같고 정확히 10페이지여서 예산을 남김없이 쓴다. 처음에는 1.1 두
페이지를 활성 대여로 두고 경로를 11페이지로 잡았으나, 정본 「품질 평가 조건」이 활성 대여를 예산 0
시나리오에만 허용하므로 대여를 없애고 걸음 재기를 22 한 페이지만 밟게 해 10페이지로 줄였다.

1장의 전제 넷(공백·폭·물길·입구)에서 2장의 빗길 통행과 배수로로, 다시 3장의 그리는 기준과 걸음
재기로 이어진다. 기호(3.3)와 수정(3.4)은 경로에 들어오지 않는다 — 예산 10으로는
그리기 시작하는 데까지만 닿는다.

시나리오는 계획 문서가 배정한 **비소장·예산 10**을 그대로 썼다. 병합 후 41건의 분포는 BALANCED가 7건,
QUICK·DEEP·예산 10이 각 6건, 예산 0·예산 5·예산 15가 각 5건이다.

## 재현 조건

1. `python3 build088.py` — 원고와 조각 생성 (PDF SHA 없이 실행하면 자리표시자를 넣는다)
2. `python3 figures088.py pdfbuild088` — 도표 6개 SVG 생성
3. Chrome Headless로 각 SVG를 794×1123 PNG로 렌더링
4. `python3 build_pdf_generic.py 88 7,16,24,30,36,43 pdfbuild088` — 조판 HTML 생성
5. Chrome Headless `--print-to-pdf`로 PDF 출력, `pdfcheck.py`로 구성 확인
6. PDF를 `fixtures/content/ai-route-v2/pdfs/`에 두고 SHA-256을 인자로 `build088.py` 재실행
7. `merge_fragments.py 88`로 정본에 병합

## 검수

- 여섯 도표를 PNG로 렌더링해 눈으로 확인하고 p7을 두 번 고쳤다. 물 화살표를 늘어놓는 함수가 세로
  화살표를 가로로, 가로 화살표를 세로로 퍼뜨려 골목 밖에 화살표가 찍혔다. 함수를 고쳐 방향에 맞게
  늘어놓았다.
- 조판한 PDF의 구성을 `pdfcheck.py`로 확인했다.
- 공개 가이드 주제와 비공개 분석 텍스트를 서로 다른 문장으로 적었고, 주제문에 숫자를 쓰지 않았다.
- 본문·도표·평가 데이터에 실존 국가·도시·지명·인물이 등장하지 않는다.
- 3.1에 사람이 사는 집의 위치는 그리지 않는다고 적어 두었다. 골목 지도가 남의 생활을 적는 도구가 되지
  않게 하려는 것이다.

# book-089 「열두 정거장의 하루」 설계

[여행 카테고리 계획](./travel-category-plan.md)의 89번을 만든 근거다. 정책·검증 계약은
[AI 경로 콘텐츠 코퍼스](../../ai-route-content-corpus.md)를 따르고, 이 문서는 그 계약 안에서 내린
선택과 이유만 적는다.

## 대상 도서

- `bookId` 89, 카테고리 여행. 저자·소개는 `src/main/resources/demo/books.json`의 기존 값을 유지한다.
- 제목은 `ai-route-v2` manifest의 `books[].title`이 정본이며 이 문서의 제목과 같다.
- 실존 국가·도시·지명을 쓰지 않는다. 무대는 가상 도시의 순환선 「고리선」이고 정거장은 열둘이다.
  인물은 안내소의 유안 한 사람이고, 찻집 주인은 이름 없이 역할로만 적는다. 081~088의 인물과
  겹치지 않는다.

## 개념 범위

계획 문서가 정한 범위(순환선을 하루권으로 타고 열두 정거장을 도는 도시 여행)를 그대로 따른다.

- 082(북부 순환선)와 같은 순환선이라 단위를 갈랐다. 082는 나흘에 걸쳐 도는 장거리 완행이고 089는
  하루권으로 한 도시 안을 도는 짧은 이동이다. 089에는 잠자리도 결항도 나오지 않고 대신 배차 간격과
  체류 시간의 배분만 나온다.
- 083·088과 같은 도시가 무대이지만 이 권은 노선 위에 머문다. 083이 시장, 088이 골목이라면 089는
  정거장과 그 사이다. 도시의 어느 한 곳을 깊이 보지 않고 열둘을 훑는 것이 이 권의 방식이다.
- 이 권에만 있는 축은 **하루권이라는 표**다. 값 판단이 사라지고 시간 판단만 남는다는 것이 1.1의
  전제이고, 4장 전체가 그 표의 셈을 다룬다.

## 장 구성 (49페이지, 목차 1 + 본문 48)

```
1장 고리선과 하루권       p2–11   PREREQUISITE  하루권·순환선·정거장 목록·배차 간격·운행 시간
2장 어디서 내릴지 정하기  p12–19  CORE          내릴 곳 고르기·체류 배분·도는 방향·역방향 환승
3장 정거장 사이           p20–27  CORE          차창 관찰·앉는 자리·혼잡 시간·환승 시간
4장 하루권을 쓰는 셈      p28–35  CORE          본전 계산·표 사용·하루권의 한계·이틀째 계획
5장 고리선의 하루         p36–43  EXAMPLE       오전·오후·저녁 기록·하루 정리
6장 이 방법이 통하지 않을 때 p44–47 COUNTERPOINT 직선 노선·표가 없을 때·하루의 한계
7장 결론: 하루로 도는 일  p48–49  CONCLUSION    종합
```

초고에서는 절마다 한 페이지씩만 써서 38페이지가 나왔다. 하한(48)에 미달해 한 페이지짜리 절 열 곳에
두 번째 페이지를 채우고 4.1에 도표를 하나 더해 49페이지로 맞췄다. 늘린 열 페이지는 모두 앞 페이지의
원칙을 현장에서 어떻게 쓰는지를 적은 것이고, 같은 말을 되풀이하지 않았다.

이미지 6개: p7(열둘을 셋으로 나누다), p15(타는 시간과 머무는 시간), p21(같은 구간, 두 시각),
p29(네 번을 넘기면), p37(하루의 한 바퀴 반), p44(되돌아가는 두 가지 길). 순환선은 늘 원으로 그리고
머무는 시간은 진한 색, 타고 기다리는 시간은 옅은 색으로 고정했다. 생성 스크립트는
[`figures089.py`](./tools/figures089.py)다.

중복 그룹 1개: `one-ticket-one-day` = [2, 48]. "하루권은 값을 아끼는 물건이 아니라 판단을 바꾸는
물건"이라는 명제를 1.1에서 세우고 7.1에서 시간에 관한 말로 재진술한다. 재진술 페이지(48)에는 선수를
두지 않았다. 짝(2)을 선수로 걸면 48을 고른 경로에 2가 반드시 따라와 중복 그룹 규칙을 어기기 때문이며,
book-081~088과 같은 처리다.

## 선수 관계 설계

1.1을 뿌리로 두고 1.2(순환선)와 1.5(운행 시간)가 갈라진다. 2장과 6.1은 1.2에서, 3장은 1.4(배차
간격)에서, 4장은 1.5에서 갈라진다. 평가가 QUICK이라 다섯 페이지 안에 목적을 담아야 해서 1.2 →
1.3 → 2.1로 곧장 내려가는 줄기를 만들고 나머지를 옆으로 벌렸다.

- 어느 후보 페이지도 선수 폐쇄가 7페이지를 넘지 않는다.
- 폐쇄 5페이지 이하인 후보 페이지가 일곱 개 장을 모두 덮는다 (기준 3개 장).
- 후보 페이지 48개 전부가 폐쇄 15페이지 이하다 (기준 75%).

## 검증

`corpus_lib.validate_book()` → `validate_fragment.py` → `merge_fragments.py` → `validate_manifest.py`를
차례로 통과했다.

- 49페이지(48~72), 7개 장(최소 6), 내용 역할 5종 모두 사용
- `TEXT` 본문 42페이지가 374~449자(평균 395자, 합계 16,575자)
- `FRONT_MATTER`(목차)와 `aiRouteCandidatePage=false`가 정확히 일치
- 선수 관계가 후보 제외 페이지를 가리키지 않음, 위상 정렬로 49페이지 전체 방문
- PDF 페이지 49개, 텍스트 43개, 이미지 6개(p7,15,21,29,37,44) — `pdfcheck.py --book 89`으로 확인
- PDF 실제 SHA-256이 manifest의 `pdfSha256`과 일치

## 평가 케이스: 소장·QUICK 시나리오

| 필드 | 값 |
| --- | --- |
| `caseId` | `case-book-089` |
| `purpose` | 이 책을 소장하고 있는데, 낯선 도시에서 하루권으로 순환선을 돌 계획이라 어디서 내릴지 정하는 법만 빠르게 익히고 싶다. 하루권이 무엇을 바꾸는 표인지와 순환선의 성질, 그리고 정거장을 어떻게 나누는지를 알고 싶다 |
| `owned` / `maxAdditionalInk` / `depth` | `true` / `null` / `QUICK` |
| `requiredConcepts` | 하루권, 순환선, 정거장 목록, 내릴 곳 고르기 |
| `helpfulConcepts` | 배차 간격, 운행 시간, 체류 배분, 도는 방향 |
| `referencePageNumbers` | 2, 4, 6, 12, 13 |
| `irrelevantPageNumbers` | 22·23(앉는 자리), 34·35(이틀째 계획), 46·47(표가 없을 때) — 어디서 내릴지 정하는 법만 익히려는 목적과 무관. 절 단위로 넣어 짝 페이지를 쪼개지 않는다 |
| `allowedAlternativePageNumbers` | 5, 7, 16 |

정답 경로는 선수 전이 폐쇄와 같고 정확히 5페이지여서 QUICK 상한을 남김없이 쓴다. 하루권(2)에서
순환선(4)으로, 순환선에서 정거장 목록(6)으로, 거기서 내릴 곳 고르기(12, 13)로 내려가는 한 줄기다.
085와 마찬가지로 QUICK 상한 안에 목적을 담으려면 갈래 없는 줄기가 필요했다.

시나리오는 계획 문서가 배정한 **소장·QUICK**을 그대로 썼다. 병합 후 42건의 분포는 QUICK이 7건,
BALANCED가 7건, DEEP·예산 10이 각 6건, 예산 0·예산 5·예산 15가 각 5건이다.

## 재현 조건

1. `python3 build089.py` — 원고와 조각 생성 (PDF SHA 없이 실행하면 자리표시자를 넣는다)
2. `python3 figures089.py pdfbuild089` — 도표 6개 SVG 생성
3. Chrome Headless로 각 SVG를 794×1123 PNG로 렌더링
4. `python3 build_pdf_generic.py 89 7,15,21,29,37,44 pdfbuild089` — 조판 HTML 생성
5. Chrome Headless `--print-to-pdf`로 PDF 출력, `pdfcheck.py --book 89`으로 구성 확인
6. PDF를 `fixtures/content/ai-route-v2/pdfs/`에 두고 SHA-256을 인자로 `build089.py` 재실행
7. `merge_fragments.py 89`로 정본에 병합
8. `sync_readme.py --add 89 여행`으로 fixture README의 수치와 표를 다시 계산

## 검수

- 여섯 도표를 PNG로 렌더링해 눈으로 확인하고 p44를 고쳤다. 반대 방향과 계속 돌기의 이름표가 서로
  반대쪽에 붙어 있어 경로와 맞바꾸고, 직선 노선의 화살표와 이름표가 겹쳐 위로 올렸다.
- 조판한 PDF의 구성을 `pdfcheck.py`로 확인했다.
- 공개 가이드 주제와 비공개 분석 텍스트를 서로 다른 문장으로 적었고, 주제문에 숫자를 쓰지 않았다.
- 본문·도표·평가 데이터에 실존 국가·도시·지명·인물이 등장하지 않는다.
- 6.3에 하루로 본 것은 도시가 아니라 그 노선이 지나는 자리들이라고 적어 두었다. 제목이 도시 이름이
  아니라 열두 정거장인 이유이기도 하다.

# book-091 「하루를 작게 나누는 기술」 설계

[자기계발 카테고리 계획](./self-help-category-plan.md)의 91번을 만든 근거다. 자기계발 카테고리에서
처음 만든 권이다. 정책·검증 계약은 [AI 경로 콘텐츠 코퍼스](../../ai-route-content-corpus.md)를 따르고,
이 문서는 그 계약 안에서 내린 선택과 이유만 적는다.

## 대상 도서

- `bookId` 91, 카테고리 자기계발. 제목·저자·소개는 `src/main/resources/demo/books.json`의 기존 값을
  유지한다. 자기계발은 제목 갱신 대상 50권(과학·경제·철학·예술·기술)에 들지 않는다.
- 제목은 `ai-route-v2` manifest의 `books[].title`이 정본이며 이 문서의 제목과 같다.
- 실존 인물·단체를 옮기지 않는다. 무대는 가상의 편집 사무실 「낮은책상」, 인물은 유하와 태오다.

## 개념 범위

계획 문서가 정한 원리(하루를 실행 가능한 단위로 분할하기)와 하위 개념(작업 분해, 최소실행단위,
시간블록, 전환비용)을 그대로 따른다. 이 권은 **일을 시작하기 전에 그 크기를 정하는 시점**만 다룬다.

- 92(미루는 마음)는 쪼갠 일도 왜 미루게 되는지를 다루므로 이 권은 감정·동기를 설명에 쓰지 않는다.
  1.1에서 실행되지 않는 하루의 원인을 의지에서 떼어 내는 것이 그 경계다.
- 94(기록)와 97(회고)은 이미 한 일을 남기고 되짚는 활동이다. 이 권에서 목록과 이월(5.4)이 나오지만
  기록을 습관으로 만드는 방법이나 지난 주를 해석하는 방법은 다루지 않는다.
- 99(측정)는 한 일의 결과를 확인하는 문제다. 이 권의 완료 조건(2.2)은 결과를 재는 지표가 아니라
  작업을 어디서 멈출지 정하는 착수 시점의 기준이다.
- 예술 070도 착수를 다루지만 그쪽은 창작물의 초안과 제약이고, 이 권은 하루에 든 일의 크기와 배치다.
  두 권 모두 작업 단위를 말하는 자리가 있어 인물·무대·사례를 완전히 다르게 잡았다.

## 장 구성 (51페이지, 목차 1 + 본문 50)

```
1장 하루가 흩어지는 이유    p2–11   PREREQUISITE  큰 덩어리·최소실행단위·하루의 용량·전환비용·계획 오차
2장 일을 쪼개는 법          p12–19  CORE          작업 분해·완료 조건·분해 단위 크기·탐색형 작업
3장 시간을 묶는 법          p20–27  CORE          시간블록·블록 길이·묶음 처리·여유 블록
4장 순서를 정하는 법        p28–35  CORE          우선순위 기준·작업 의존·시작 블록·자투리 배치
5장 어떤 하루               p36–43  EXAMPLE       하루 목록·블록 실행·끼어들기 대응·이월
6장 계획이 무너질 때        p44–49  COUNTERPOINT  과잉 분해·긴 몰입·통제 밖 일정
7장 결론: 오늘 할 수 있는 크기로  p50–51  CONCLUSION  종합
```

1장이 다섯 개념을 세우고 2~4장이 쪼개기·배치·순서로 나누어 펼친다. 5장은 그 셋이 하루 안에서 어떻게
이어지는지를 아침 목록부터 저녁 이월까지 한 사람의 하루로 보인다. 6장은 방법이 통하지 않는 세 경우
(과잉 분해, 나눌 수 없는 일, 시간 통제권이 없는 날)를 다룬다. 7장은 두 페이지다. 5장 전체가 이미 실천
절차라 결론에 절차를 다시 두지 않았다.

이미지 6개: p8(다시 붙는 데 걸리는 시간), p16(같은 일, 세 가지 굵기), p24(같은 일을 모아 두면),
p31(무엇이 무엇을 기다리는가), p37(목록 한 장), p45(어느 지점을 넘으면 늦어진다). 하루의 시간을 다루는
책이라 띠 그림이 겹치기 쉬워서 여섯 도표의 형식을 선그래프·상자 비교·띠·의존 그래프·서식·곡선으로
모두 다르게 잡았다. 공통 약속은 둘이다. 잃는 시간은 빗금, 고른 자리는 굵은 테두리다. 생성 스크립트는
[`figures091.py`](./tools/figures091.py)다.

중복 그룹 1개: `work-sized-not-willed` = [2, 50]. "하루가 흩어지는 것은 의지가 아니라 적어 둔 일의
크기 때문"이라는 명제를 1.1에서 세우고 7.1에서 책 전체를 지나온 언어로 재진술한다. 재진술 페이지(50)에는
선수를 두지 않았다. 짝(2)을 선수로 걸면 50을 고른 경로에 2가 반드시 따라와 중복 그룹 규칙을 어기기
때문이며, book-062·063·065·068·069·070과 같은 처리다.

## 선수 관계 설계

1.1(큰 덩어리)을 뿌리로 두고 1.2(최소실행단위)와 1.3(하루의 용량)이 갈라진다. 2장과 5장은 쪼개기 쪽
(1.2 → 2.1)에서, 3장과 4.3~4.4는 그릇 쪽(1.3 → 3.1)에서 갈라진다. 4.1은 2.2(완료 조건)에 붙였다.
무엇을 먼저 할지 고르려면 각 줄에 끝이 붙어 있어야 하기 때문이다. 6장의 세 절은 각각 자기가 반박하는
방법(2.3, 3.2, 3.4)에 붙였다.

- 어느 후보 페이지도 선수 폐쇄가 7페이지를 넘지 않는다.
- 폐쇄 5페이지 이하인 후보 페이지가 일곱 개 장을 모두 덮는다 (기준 3개 장).
- 후보 페이지 50개 전부가 폐쇄 15페이지 이하다 (기준 75%).

가장 깊은 곳은 4.2(작업 의존)와 6.3(통제 밖 일정)으로 각각 7페이지를 거친다. 의존 관계를 읽으려면
먼저 순서 기준이 있어야 하고, 순서 기준은 완료 조건과 작업 분해를 전제하므로 이 사슬은 실제 의존이다.

## 검증

`corpus_lib.validate_book()` → `validate_fragment.py` → `merge_fragments.py` → `validate_manifest.py`를
차례로 통과했다.

- 51페이지(48~72), 7개 장(최소 6), 내용 역할 5종 모두 사용
- `TEXT` 본문 44페이지가 352~443자(평균 381자, 합계 16,747자)로 전량 345자 이상
- `FRONT_MATTER`(목차)와 `aiRouteCandidatePage=false`가 정확히 일치
- 선수 관계가 후보 제외 페이지를 가리키지 않음, 위상 정렬로 51페이지 전체 방문
- PDF 페이지 51개, 텍스트 45개, 이미지 6개(p8,16,24,31,37,45) — `pdfcheck.py`로 확인
- PDF 실제 SHA-256이 manifest의 `pdfSha256`과 일치

초고에서 세 페이지(38·42·47)가 345자에 못 미쳤다. `EXTRA` 문단을 붙이지 않고 book-024와 같이 마지막
문단을 늘려 고쳤다. 세 페이지 모두 마지막 문단이 판단의 근거를 한 줄 덜 적고 있어서, 늘린 문장이 새
소재가 아니라 그 근거다.

## 평가 케이스: 비소장·예산 0 시나리오

| 필드 | 값 |
| --- | --- |
| `caseId` | `case-book-091` |
| `purpose` | 이 책 앞부분을 빌려 뒀다. 목록에 크게 적어 둔 일을 오늘 바로 손댈 수 있는 크기로 쪼개고 어디서 끝낼지 정하는 기준을 빌린 범위 안에서 익히고 싶다. 하루 시간표를 다시 짜는 일까지는 아직 필요 없다 |
| `owned` / `maxAdditionalInk` / `depth` | `false` / `0` / `null` |
| `activeRentalPageNumbers` | 2~5, 10~19 (14페이지) |
| `requiredConcepts` | 최소실행단위, 작업 분해, 완료 조건, 분해 단위 크기 |
| `helpfulConcepts` | 큰 덩어리, 탐색형 작업, 계획 오차 |
| `referencePageNumbers` | 2, 4, 5, 12~19 (11페이지) |
| `irrelevantPageNumbers` | 20~27(3장 전체) — 시간표 배치는 이 목적 밖이라고 목적문에 적었다. 절 단위로 넣어 짝 페이지를 쪼개지 않는다 |
| `allowedAlternativePageNumbers` | 3, 11 |

정답 경로는 선수 폐쇄와 같은 11페이지이고 전부 활성 대여 안에 있어 추가 차감이 0이다. 예산 0 사례는
`폐쇄 ⊆ activeRentalPageNumbers`를 만족해야 하므로 대여 목록을 폐쇄에 맞춰 잡되, book-011과 달리
대여를 폐쇄보다 세 페이지(3, 10, 11) 넓게 잡았다. 그래야 예산 없이도 고를 수 있는 대체 페이지가
남는다. 3은 1.1의 이어지는 설명이고 11은 계획 오차를 예상에 넣는 방법이라, 둘 다 정답의 한 자리를
대신해도 목적을 채운다.

시나리오는 계획 문서가 91번에 배정한 **비소장·예산 0**을 그대로 썼다. 이 책은 1~2장만으로 목적을
채울 수 있는 구조라 좁은 예산에 맞고, 3장 이후가 통째로 목적 밖이 되어 무관 페이지를 절 단위로 잡기도
쉬웠다.

## 재현 조건

1. `python3 build091.py` — 원고와 조각 생성 (PDF SHA 없이 실행하면 자리표시자를 넣는다)
2. `python3 figures091.py pdfbuild091` — 도표 6개 SVG 생성
3. Chrome Headless로 각 SVG를 794×1123 PNG로 렌더링
4. `python3 build_pdf_generic.py 91 8,16,24,31,37,45 pdfbuild091` — 조판 HTML 생성
5. Chrome Headless `--print-to-pdf`로 PDF 출력, `pdfcheck.py`로 구성 확인
6. PDF를 `fixtures/content/ai-route-v2/pdfs/`에 두고 SHA-256을 인자로 `build091.py` 재실행
7. `merge_fragments.py 91`로 정본에 병합

## 검수

- 인물 이름은 1.1(도입 장면)과 5장(사례 장)에만 두고, 개념을 설명하는 나머지 장에서는 일반 진술로
  바꿨다. 가상 인물의 습관으로 포장된 지침은 이름을 빼도 내용이 그대로여서 이름이 하는 일이 없다.
- 여섯 도표를 PNG로 렌더링해 눈으로 확인했다. p24는 초안에서 묶은 하루의 경계를 셋으로 적었는데
  실제로 세어 보니 둘이었다. 도표와 본문·분석 텍스트를 모두 둘로 고쳤다. p8은 처음에 p24와 같은 띠
  그림이었다가, 두 도표가 같은 말을 하게 되어 몰입이 떨어졌다 다시 오르는 선그래프로 바꿨다.
- 공개 가이드 주제와 비공개 분석 텍스트를 서로 다른 문장으로 적었고, 주제문에 숫자를 쓰지 않았다.
- 본문·도표·평가 데이터에 실존 인물·작품·단체가 등장하지 않는다.
- 본문의 수치(사십오 분에서 아흔 분, 하루 세 시간대)는 낮은책상 사무실이라는 가상 무대에서 두 사람이
  세어 본 값으로만 적었고, 일반적인 연구 결과로 제시하지 않았다.

않게 지켜야 할 선은 위 "개념 범위"에 적은 네 가지다.

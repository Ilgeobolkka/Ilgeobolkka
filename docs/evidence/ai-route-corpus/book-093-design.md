# book-093 「집중을 위한 빈칸 만들기」 설계

[자기계발 카테고리 계획](./self-help-category-plan.md)의 93번을 만든 근거다. 정책·검증 계약은
[AI 경로 콘텐츠 코퍼스](../../ai-route-content-corpus.md)를 따르고, 이 문서는 그 계약 안에서 내린
선택과 이유만 적는다. 앞 권은 [book-092](./book-092-design.md)다.

## 대상 도서

- `bookId` 93, 카테고리 자기계발. 제목·저자·소개는 `src/main/resources/demo/books.json`의 기존 값을
  유지한다.
- 제목은 `ai-route-v2` manifest의 `books[].title`이 정본이며 이 문서의 제목과 같다.
- 실존 인물·단체를 옮기지 않는다. 무대는 가상의 공유 사무실 「세 번째 책상」, 인물은 미르와 하람이다.
  091·092의 인물과 겹치지 않는다.

## 개념 범위

계획 문서가 정한 원리(주의를 분산시키는 요소를 줄여 집중할 여백을 만들기)와 하위 개념(환경 설계,
알림·트리거 제거, 물리적 여백, 단일 과업 원칙)을 그대로 따른다. 이 권은 **일하는 동안의 물리적·디지털
환경 통제**만 다룬다.

- 091은 일의 크기와 시간 배치, 092는 착수 전의 감정이다. 93은 이미 앉아서 일하는 동안을 다루므로 세
  권이 같은 하루의 서로 다른 국면을 맡는다. 1.1 두 번째 페이지에 이 순서를 명시하고, 앞의 두 문제가
  풀리지 않은 상태에서는 환경 조정이 듣지 않는다고 적었다.
- 091의 전환비용과 이 권의 주의 회복이 닿는다. 091은 **내가 일을 바꿀 때** 드는 값을 시간 배치의 근거로
  썼고, 93은 **밖에서 신호가 올 때**의 복귀 비용을 방해 제거의 근거로 쓴다. 같은 현상을 원인 쪽에서
  나눠 잡은 것이라 대응도 묶음 배치와 신호 차단으로 갈린다.
- 092의 자발적 이탈과 1.3이 닿는다. 92는 착수 전의 회피이고 93의 1.3은 작업 도중의 이탈이며, 대응도
  협상이 아니라 갈 곳을 없애는 환경 조치다.
- 94(기록)와는 5.1의 방해 기록에서 스칠 수 있으나, 여기서는 며칠짜리 측정 도구로만 쓰고 습관화는 다루지
  않는다. 5.1 본문에 며칠만 하면 된다고 적어 경계를 두었다.

## 장 구성 (50페이지, 목차 1 + 본문 49)

```
1장 주의가 새는 자리          p2–11   PREREQUISITE  집중의 조건·방해 요소·자발적 이탈·주의 회복·여백
2장 화면 정리하기             p12–19  CORE          알림 제거·트리거 제거·화면 단순화·도구 축소
3장 책상 정리하기             p20–27  CORE          시야 정리·물리적 여백·소리 환경·공간 분리
4장 한 번에 하나              p28–35  CORE          단일 과업 원칙·대기 목록·사람 방해 대응·주의 지속 한계
5장 어떤 오전                 p36–42  EXAMPLE       방해 관찰·환경 조정·잔여 방해·변화 관찰
6장 빈칸이 도움이 되지 않을 때 p43–48 COUNTERPOINT  과도한 차단·협업 요구·통제 밖 환경
7장 결론: 빈칸은 만들어야 생긴다 p49–50 CONCLUSION  종합
```

1장이 방해의 구조와 여백 개념을 세우고, 2~3장이 화면과 책상이라는 두 공간을 각각 정리하며, 4장이 공간이
아니라 과업 쪽의 방해를 다룬다. 5장은 한 사람이 세 주에 걸쳐 방해를 재고 하나씩 걷어 낸 과정을 따라간다.
6장은 지나친 차단, 협업이 필요한 일, 자리를 바꿀 수 없는 조건이라는 세 반례를 둔다.

이미지 4개: p8(같은 세 시간, 다른 결과), p16(화면에 남은 것), p27(같은 책상, 두 자리), p36(세어 본
오전). 형식을 가로 막대 비교·화면 목업 대비·평면도·기록지로 모두 다르게 잡았다. 091이 쓴 띠 그림과
선그래프, 092가 쓴 흐름도와 대응표를 피해 자기계발 카테고리 안에서도 형식이 겹치지 않게 했다. 생성
스크립트는 [`figures093.py`](./tools/figures093.py)다.

중복 그룹 1개: `focus-is-a-condition` = [2, 49]. "집중은 마음가짐이 아니라 조건"이라는 명제를 1.1에서
세우고 7.1에서 재진술한다. 재진술 페이지(49)에는 선수를 두지 않았다. 짝(2)을 선수로 걸면 49를 고른
경로에 2가 반드시 따라와 중복 그룹 규칙을 어기기 때문이며, 091·092와 같은 처리다.

## 선수 관계 설계

1.1(집중의 조건)을 뿌리로 두고 1.2(방해 요소)와 1.5(여백)가 갈라진다. 2장은 1.2에서, 3장은 1.5에서,
4장은 1.1에서 바로 갈라진다. 3장을 1.5에 붙인 것은 책상 정리의 기준이 방해 목록이 아니라 여백 개념이기
때문이다.

- 어느 후보 페이지도 선수 폐쇄가 6페이지를 넘지 않는다.
- 폐쇄 5페이지 이하인 후보 페이지가 일곱 개 장을 모두 덮는다 (기준 3개 장).
- 후보 페이지 49개 전부가 폐쇄 15페이지 이하다 (기준 75%).

6장의 세 절은 각각 반박 대상에 붙였다. 6.1(과도한 차단)은 3.3(소리 환경), 6.2(협업 요구)는 4.3(사람
방해 대응), 6.3(통제 밖 환경)은 3.1(시야 정리)이다.

## 검증

`corpus_lib.validate_book()` → `validate_fragment.py` → `merge_fragments.py` → `validate_manifest.py`를
차례로 통과했다.

- 50페이지(48~72), 7개 장(최소 6), 내용 역할 5종 모두 사용
- `TEXT` 본문 45페이지가 347~433자(평균 389자, 합계 17,525자)로 전량 345자 이상
- `FRONT_MATTER`(목차)와 `aiRouteCandidatePage=false`가 정확히 일치
- 선수 관계가 후보 제외 페이지를 가리키지 않음, 위상 정렬로 50페이지 전체 방문
- PDF 페이지 50개, 텍스트 46개, 이미지 4개(p8,16,27,36) — `pdfcheck.py`로 확인
- PDF 실제 SHA-256이 manifest의 `pdfSha256`과 일치

초고는 312~391자로 마흔다섯 페이지 가운데 서른이 하한에 미달했다. 091·092처럼 마지막 문단을 늘리는
방식으로는 서른 페이지를 손보기 어려워, book-025·028·029가 쓴 `EXTRA` 문단 방식으로 바꿨다. 더한 문단은
모두 그 페이지 주제의 실무 조건 한 가지이고 다른 페이지의 내용을 되풀이하지 않는다.

## 평가 케이스: 비소장·예산 10 시나리오

| 필드 | 값 |
| --- | --- |
| `caseId` | `case-book-093` |
| `purpose` | 일하는 동안 자꾸 딴 데로 새는데 의지 문제만은 아닌 것 같다. 화면과 책상에서 주의를 가져가는 것들을 어떻게 줄이는지 익히고 싶다. 일을 한 번에 하나만 하는 방법까지는 지금 필요 없다 |
| `owned` / `maxAdditionalInk` / `depth` | `false` / `10` / `null` |
| `activeRentalPageNumbers` | 없음 |
| `requiredConcepts` | 집중의 조건, 방해 요소, 알림 제거, 트리거 제거, 물리적 여백 |
| `helpfulConcepts` | 여백, 시야 정리, 주의 회복, 소리 환경 |
| `referencePageNumbers` | 2, 4, 10, 12~15, 20, 22, 23 |
| `irrelevantPageNumbers` | 28~35(4장 전체) — 목적문이 한 번에 하나만 하는 방법은 지금 필요 없다고 밝힌 부분이다. 절 단위로 넣어 짝 페이지를 쪼개지 않는다 |
| `allowedAlternativePageNumbers` | 17, 19, 25 |

정답 경로는 2.1·2.2·3.2의 두 번째 페이지 셋을 씨앗으로 잡은 선수 폐쇄이고 정확히 10페이지라 예산을
남김없이 쓴다. 화면 쪽(1.2 → 2.1 → 2.2)과 책상 쪽(1.5 → 3.1 → 3.2)이라는 두 갈래가 1.1에서 만나는
구조라, 목적문이 말하는 "화면과 책상" 두 곳을 한 경로에 담을 수 있다.

무관 페이지를 4장으로 잡으면서 `helpfulConcepts`에서 단일 과업 원칙을 뺐다. 무관 페이지의
`primaryConcepts`에 도움 개념을 달면 정답표가 스스로와 어긋난다는 정본 조건 때문이다. 대체 페이지 셋은
각각 2.3·2.4·3.3의 두 번째 페이지이고 폐쇄가 5페이지라 예산 10 안에서 실제로 고를 수 있다.

## 재현 조건

1. `python3 build093.py` — 원고와 조각 생성 (PDF SHA 없이 실행하면 자리표시자를 넣는다)
2. `python3 figures093.py pdfbuild093` — 도표 4개 SVG 생성
3. Chrome Headless로 각 SVG를 794×1123 PNG로 렌더링
4. `python3 build_pdf_generic.py 93 8,16,27,36 pdfbuild093` — 조판 HTML 생성
5. Chrome Headless `--print-to-pdf`로 PDF 출력, `pdfcheck.py`로 구성 확인
6. PDF를 `fixtures/content/ai-route-v2/pdfs/`에 두고 SHA-256을 인자로 `build093.py` 재실행
7. `merge_fragments.py 93`으로 정본에 병합

## 검수

- 인물 이름은 1.1(도입 장면)과 5장(사례 장)에만 두고, 개념을 설명하는 나머지 장에서는 일반 진술로
  바꿨다. 가상 인물의 습관으로 포장된 지침은 이름을 빼도 내용이 그대로여서 이름이 하는 일이 없다.
- 네 도표를 PNG로 렌더링해 눈으로 확인했다. p36은 초안에서 막대 색 배분이 본문과 어긋나 밖에서 온 방해가
  여덟 개로 그려졌다. 본문이 적은 여섯·아홉에 맞춰 행별 배분을 다시 정했다.
- 공개 가이드 주제와 비공개 분석 텍스트를 서로 다른 문장으로 적었고, 주제문에 숫자를 쓰지 않았다.
- 본문·도표·평가 데이터에 실존 인물·작품·단체·제품이 등장하지 않는다. 특정 앱이나 서비스 이름을 쓰지
  않고 알림·메신저·탭 같은 일반 명칭만 썼다.
- 집중 시간이나 회복 시간의 수치는 가상 인물이 자기 기록에서 얻은 값으로만 적었고 연구 결과로 제시하지
  않았다.

# book-094 「기록이 습관이 되는 순간」 설계

[자기계발 카테고리 계획](./self-help-category-plan.md)의 94번을 만든 근거다. 정책·검증 계약은
[AI 경로 콘텐츠 코퍼스](../../ai-route-content-corpus.md)를 따르고, 이 문서는 그 계약 안에서 내린
선택과 이유만 적는다. 앞 권은 [book-093](./book-093-design.md)이다.

## 대상 도서

- `bookId` 94, 카테고리 자기계발. 제목·저자·소개는 `src/main/resources/demo/books.json`의 기존 값을
  유지한다.
- 제목은 `ai-route-v2` manifest의 `books[].title`이 정본이며 이 문서의 제목과 같다.
- 실존 인물·단체를 옮기지 않는다. 무대는 가상의 동물병원 「초록발」, 인물은 나윤과 유안이다.
  091~093의 인물과 겹치지 않는다.

## 개념 범위

계획 문서가 정한 원리(기록을 최소 마찰로 만들어 반복되게 하기)와 하위 개념(트리거-행동-보상 고리,
최소 기록 단위, 기록의 마찰 줄이기)을 그대로 따른다. 습관 형성 일반론이 아니라 **기록이라는 한 가지
행동**에 한정한다.

- 97(주간 회고)은 이미 쌓인 기록을 되짚어 해석하는 활동이다. 94는 기록을 만드는 시점만 다루며,
  4장의 다시 읽기도 해석이 목적이 아니라 습관 고리의 보상 자리를 채우는 장치로만 쓴다.
- 99(측정)는 기록에서 지표를 만드는 일이다. 94는 무엇을 셀지 다루지 않고, 오히려 2.4에서 연속 일수 같은
  숫자를 세지 않는 편이 낫다는 쪽으로 간다.
- 091의 대기 목록·093의 방해 기록과 소재가 스칠 수 있으나, 그쪽은 각각 하루 계획과 환경 측정의 도구로
  쓰이는 일회성 기록이고 이 권은 기록 자체를 반복 가능한 행동으로 만드는 방법이다.
- 092의 실행 의도(신호와 행동을 문장으로 묶기)와 3장이 닿는다. 92는 미루는 일 일반에 적용하는 문장
  형식이고, 94는 기록에 한정해 신호가 갖춰야 할 세 조건(매일 있음, 끝이 분명함, 손이 빔)까지 좁힌다.

## 장 구성 (50페이지, 목차 1 + 본문 49)

```
1장 기록이 끊기는 자리   p2–11   PREREQUISITE  기록의 중단·트리거-행동-보상·마찰·기록 대상·기록의 목적
2장 마찰 줄이기          p12–19  CORE          도구 접근성·최소 기록 단위·무분류 기록·결손 허용
3장 신호 만들기          p20–27  CORE          기록 시점·행동 연결·장소 신호·신호 유지
4장 이어지게 하기        p28–35  CORE          보상·재독·재개·보관과 폐기
5장 어떤 기록            p36–42  EXAMPLE       실패 사례·축소 적용·지속 관찰·점진 확장
6장 기록이 짐이 될 때    p43–48  COUNTERPOINT  기록 과잉·비기록 영역·기록 부담
7장 결론: 남는 것은 이어진 기록뿐이다 p49–50 CONCLUSION 종합
```

1장이 습관의 세 요소와 마찰 개념을 세우고, 2~4장이 그 셋을 하나씩 채운다. 행동을 가볍게 하고(2장),
신호를 만들고(3장), 보상 자리를 만드는(4장) 순서다. 5장은 같은 사람이 세 번 실패하고 네 번째에 이어 간
과정을 따라간다. 6장은 기록이 과해지는 세 경우를 다룬다.

이미지 4개: p5(세 부분이 이어진 고리), p15(같은 하루, 세 가지 양식), p23(어디에 붙일 것인가),
p40(네 번의 시도). 형식을 순환 고리·노트 지면 비교·조건 대조표·달력 격자로 모두 다르게 잡았고,
091~093이 쓴 형식과도 겹치지 않는다. 생성 스크립트는 [`figures094.py`](./tools/figures094.py)다.

중복 그룹 1개: `written-beats-well-written` = [2, 49]. "적히지 않는 기록은 아무리 좋은 형식이어도 남는
것이 없다"는 명제를 1.1에서 세우고 7.1에서 재진술한다. 재진술 페이지(49)에는 선수를 두지 않았다.
091~093과 같은 처리다.

## 선수 관계 설계

1.1(기록의 중단)을 뿌리로 두고 1.2(고리)·1.3(마찰)·1.4(기록 대상)가 갈라진다. 2장은 1.3에서, 3장과
4장은 1.2에서, 5장은 1.3에서 갈라진다. 2장을 마찰에 붙이고 3·4장을 고리에 붙인 것은 각 장이 실제로
전제하는 개념이 다르기 때문이다.

- 어느 후보 페이지도 선수 폐쇄가 7페이지를 넘지 않는다.
- 폐쇄 5페이지 이하인 후보 페이지가 일곱 개 장을 모두 덮는다 (기준 3개 장).
- 후보 페이지 49개 전부가 폐쇄 15페이지 이하다 (기준 75%).

가장 깊은 곳은 6.3(기록 부담)으로 4.4 → 4.2 → 4.1 → 1.2 → 1.1을 거친다. 쌓인 기록의 무게는 보관과
폐기를 전제하고, 그것은 다시 읽기와 보상 자리를 전제하므로 이 사슬은 실제 의존이다.

## 검증

`corpus_lib.validate_book()` → `validate_fragment.py` → `merge_fragments.py` → `validate_manifest.py`를
차례로 통과했다.

- 50페이지(48~72), 7개 장(최소 6), 내용 역할 5종 모두 사용
- `TEXT` 본문 45페이지가 346~438자(평균 391자, 합계 17,612자)로 전량 345자 이상
- `FRONT_MATTER`(목차)와 `aiRouteCandidatePage=false`가 정확히 일치
- 선수 관계가 후보 제외 페이지를 가리키지 않음, 위상 정렬로 50페이지 전체 방문
- PDF 페이지 50개, 텍스트 46개, 이미지 4개(p5,15,23,40) — `pdfcheck.py`로 확인
- PDF 실제 SHA-256이 manifest의 `pdfSha256`과 일치

초고는 296~394자로 마흔다섯 페이지 가운데 서른아홉이 하한에 미달했다. 093과 같이 `EXTRA` 문단으로
채웠다. 이 권은 문단마다 한 가지만 말하는 짧은 호흡으로 쓰다 보니 초고가 특히 짧았다.

## 평가 케이스: 비소장·예산 15 시나리오

| 필드 | 값 |
| --- | --- |
| `caseId` | `case-book-094` |
| `purpose` | 기록을 여러 번 시작했다가 늘 몇 주 만에 그만뒀다. 이번에는 이어지게 만들고 싶어서 적는 부담을 줄이는 방법과 언제 적을지 정하는 방법을 처음부터 익히고 싶다. 기록이 짐이 되는 경우까지는 지금 필요 없다 |
| `owned` / `maxAdditionalInk` / `depth` | `false` / `15` / `null` |
| `activeRentalPageNumbers` | 없음 |
| `requiredConcepts` | 트리거-행동-보상, 마찰, 도구 접근성, 최소 기록 단위, 행동 연결, 보상 |
| `helpfulConcepts` | 기록의 중단, 기록 시점, 무분류 기록, 결손 허용 |
| `referencePageNumbers` | 2, 4~7, 12~15, 20, 22, 23, 28, 29 |
| `irrelevantPageNumbers` | 43~48(6장 전체) — 목적문이 기록이 짐이 되는 경우는 지금 필요 없다고 밝힌 부분이다. 절 단위로 넣어 짝 페이지를 쪼개지 않는다 |
| `allowedAlternativePageNumbers` | 9, 17, 25 |

정답 경로는 습관 고리의 세 자리를 각각 덮는 씨앗 여섯 개의 선수 폐쇄이고 14페이지다. 예산 15에 한 자리를
남기는데, 이 책은 마찰(2장)·신호(3장)·보상(4장) 세 갈래를 모두 지나야 목적이 채워져서 한 갈래만 깊게
파는 경로로는 목적문을 만족할 수 없다. 15를 꽉 채우지 않은 것은 세 갈래의 첫 절만 골라도 목적이
채워지기 때문이고, 남은 한 자리는 대체 페이지가 들어갈 여지로 남겼다.

## 재현 조건

1. `python3 build094.py` — 원고와 조각 생성 (PDF SHA 없이 실행하면 자리표시자를 넣는다)
2. `python3 figures094.py pdfbuild094` — 도표 4개 SVG 생성
3. Chrome Headless로 각 SVG를 794×1123 PNG로 렌더링
4. `python3 build_pdf_generic.py 94 5,15,23,40 pdfbuild094` — 조판 HTML 생성
5. Chrome Headless `--print-to-pdf`로 PDF 출력, `pdfcheck.py`로 구성 확인
6. PDF를 `fixtures/content/ai-route-v2/pdfs/`에 두고 SHA-256을 인자로 `build094.py` 재실행
7. `merge_fragments.py 94`로 정본에 병합

## 검수

- 인물 이름은 1.1(도입 장면)과 5장(사례 장)에만 두고, 개념을 설명하는 나머지 장에서는 일반 진술로
  바꿨다. 가상 인물의 습관으로 포장된 지침은 이름을 빼도 내용이 그대로여서 이름이 하는 일이 없다.
- 네 도표를 PNG로 렌더링해 눈으로 확인했다. p40은 초안에서 격자 여든넉 칸이 화면 오른쪽 밖으로 나가
  칸 크기를 줄였고, 셋째·넷째 줄의 채운 칸 수가 본문과 어긋나 본문에 적은 아홉 칸과 예순 칸에 맞췄다.
  p5는 위쪽 노드의 예시 글자가 제목 구분선에 닿아 원 가까이로 당겼다.
- 공개 가이드 주제와 비공개 분석 텍스트를 서로 다른 문장으로 적었고, 주제문에 숫자를 쓰지 않았다.
- 본문·도표·평가 데이터에 실존 인물·작품·단체·제품이 등장하지 않는다. 기록 도구도 특정 앱 이름 없이
  종이 노트와 화면으로만 적었다.
- 동물병원을 무대로 쓰되 진료 내용이나 처치 방법을 구체적으로 적지 않았다. 기록의 대상이 무엇인지만
  가리키고 의학적 판단으로 읽힐 서술은 두지 않았다.

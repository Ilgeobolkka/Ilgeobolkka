# book-095 「완벽하지 않은 시작의 힘」 설계

[자기계발 카테고리 계획](./self-help-category-plan.md)의 95번을 만든 근거다. 정책·검증 계약은
[AI 경로 콘텐츠 코퍼스](../../ai-route-content-corpus.md)를 따르고, 이 문서는 그 계약 안에서 내린
선택과 이유만 적는다. 앞 권은 [book-094](./book-094-design.md)다.

## 대상 도서

- `bookId` 95, 카테고리 자기계발. 제목·저자·소개는 `src/main/resources/demo/books.json`의 기존 값을
  유지한다.
- 제목은 `ai-route-v2` manifest의 `books[].title`이 정본이며 이 문서의 제목과 같다.
- 실존 인물·단체를 옮기지 않는다. 무대는 가상의 시민 강좌 모임 「목요일 교실」, 인물은 하윤과 강우다.
  091~094의 인물과 겹치지 않는다.

## 개념 범위

계획 문서가 정한 원리(초안 상태로 시작해 반복해서 고쳐나가기)와 하위 개념(초안주의, 완벽주의 함정,
최소기능 버전, 반복 개선)을 그대로 따른다.

- 092도 완벽주의를 다루지만 그쪽은 **미루는 이유**로서의 완벽주의이고, 이 권은 **낮은 완성도로
  착수하는 형식**이다. 1.2 두 번째 페이지에 이 경계를 적었다. 왜 그런 마음이 드는지는 다루지 않고
  그 마음을 그대로 둔 채 만드는 형식만 바꾼다.
- 예술 070도 초안을 다루지만 그쪽은 창작에서 제약을 걸어 발상을 여는 이야기다. 95는 제약을 다루지 않고
  완성도 기준과 반복 주기만 다루며, 무대도 창작이 아니라 일상 업무(강좌 준비)로 잡았다.
- 091의 완료 조건과 3.3의 종료 기준이 닿는다. 091은 하루의 작업 단위에 끝을 붙이는 이야기이고, 95는
  여러 바퀴를 도는 개선을 언제 멈출지의 문제라 층위가 다르다.
- 094의 결손 허용과는 반대 방향이다. 94는 빠진 날을 그대로 두는 이야기이고 95의 의도적 생략은 만들 것을
  미리 빼기로 정하는 이야기다.

## 장 구성 (50페이지, 목차 1 + 본문 49)

```
1장 완성해야 시작할 수 있다는 생각 p2–11  PREREQUISITE  완성 기준의 함정·완벽주의 함정·초안주의·완성의 정의·수정 가능성
2장 낮은 완성도로 시작하기        p12–19 CORE          완성도 기준·최소기능 버전·의도적 생략·상태 표시
3장 반복해서 고치기               p20–27 CORE          반복 주기·수정 초점·종료 기준·가역성
4장 남에게 보이기                 p28–35 CORE          조기 공유·피드백 요청·피드백 선별·비공개 초안
5장 어떤 강좌                     p36–42 EXAMPLE       과잉 준비 사례·초안 적용·반복 관찰·정착
6장 초안으로 시작하면 안 될 때    p43–48 COUNTERPOINT  비가역 작업·초안 고착·신뢰 비용
7장 결론: 고칠 수 있는 것을 먼저 만든다 p49–50 CONCLUSION 종합
```

1장이 착수를 막는 기준의 구조와 초안 개념을 세우고, 2장이 만드는 형식, 3장이 고치는 절차, 4장이 남과의
관계를 다룬다. 5장은 넉 달을 준비만 하다가 삼 주 만에 첫 강의를 연 뒤 네 회차를 도는 과정을 따라간다.
6장은 이 방식의 전제가 성립하지 않는 세 경우를 둔다. 6.1 두 번째 페이지에는 안전이 걸린 일에 이 방식을
쓰지 않는다고 명시했다.

이미지 4개: p7(꺼내 놓으면 보인다), p15(얇게 전체를 만든다), p21(세 바퀴), p39(같은 넉 달). 형식을
흐릿함과 또렷함의 대비·격자 배분·계단·두 시간선으로 모두 다르게 잡았고, 091~094가 쓴 형식과도 겹치지
않는다. 생성 스크립트는 [`figures095.py`](./tools/figures095.py)다.

중복 그룹 1개: `fixable-before-good` = [2, 49]. "머릿속에만 있는 완성 기준은 준비할수록 함께 올라간다"는
명제를 1.1에서 세우고 7.1에서 재진술한다. 재진술 페이지(49)에는 선수를 두지 않았다. 091~094와 같은
처리다.

## 선수 관계 설계

1.1(완성 기준의 함정)을 뿌리로 두고 1.2(완벽주의 함정)와 1.3(초안주의)이 갈라진다. 2장과 5장은 1.2에서,
3장은 1.5(수정 가능성)에서, 4장은 1.3에서 갈라진다. 3장을 1.5에 붙인 것은 반복 개선이 고칠 수 있는
형태를 전제하기 때문이다.

- 어느 후보 페이지도 선수 폐쇄가 7페이지를 넘지 않는다.
- 폐쇄 5페이지 이하인 후보 페이지가 일곱 개 장을 모두 덮는다 (기준 3개 장).
- 후보 페이지 49개 전부가 폐쇄 15페이지 이하다 (기준 75%).

6장의 세 절은 각각 반박 대상에 붙였다. 6.1(비가역 작업)은 3.4(가역성), 6.2(초안 고착)는 2.4(상태 표시),
6.3(신뢰 비용)은 4.1(조기 공유)이다.

## 검증

`corpus_lib.validate_book()` → `validate_fragment.py` → `merge_fragments.py` → `validate_manifest.py`를
차례로 통과했다.

- 50페이지(48~72), 7개 장(최소 6), 내용 역할 5종 모두 사용
- `TEXT` 본문 45페이지가 346~434자(평균 380자, 합계 17,107자)로 전량 345자 이상
- `FRONT_MATTER`(목차)와 `aiRouteCandidatePage=false`가 정확히 일치
- 선수 관계가 후보 제외 페이지를 가리키지 않음, 위상 정렬로 50페이지 전체 방문
- PDF 페이지 50개, 텍스트 46개, 이미지 4개(p7,15,21,39) — `pdfcheck.py`로 확인
- PDF 실제 SHA-256이 manifest의 `pdfSha256`과 일치

초고는 272~368자로 마흔다섯 페이지 가운데 서른여섯이 하한에 미달해 093·094와 같이 `EXTRA` 문단으로
채웠다.

## 평가 케이스: 소장·QUICK 시나리오

| 필드 | 값 |
| --- | --- |
| `caseId` | `case-book-095` |
| `purpose` | 이 책을 소장하고 있는데, 몇 달째 준비만 하고 손대지 못한 일이 있다. 오늘 낮은 완성도로라도 일단 만들어 내는 방법만 빠르게 보고 싶다. 남에게 보여 주고 의견을 받는 단계까지는 아직 필요 없다 |
| `owned` / `maxAdditionalInk` / `depth` | `true` / `null` / `QUICK` |
| `requiredConcepts` | 완성 기준의 함정, 완벽주의 함정, 완성도 기준, 최소기능 버전 |
| `helpfulConcepts` | 초안주의, 의도적 생략, 반복 주기, 수정 초점 |
| `referencePageNumbers` | 2, 4, 12, 14, 15 |
| `irrelevantPageNumbers` | 28~35(4장 전체) — 목적문이 남에게 보이는 단계는 아직 필요 없다고 밝힌 부분이다. 절 단위로 넣어 짝 페이지를 쪼개지 않는다 |
| `allowedAlternativePageNumbers` | 7, 13, 17 |

정답 경로는 2.2(최소기능 버전)의 두 번째 페이지 하나를 씨앗으로 잡은 선수 폐쇄이고 정확히 다섯 페이지라
QUICK 상한을 남김없이 쓴다. 1.1(완성 기준) → 1.2(완벽주의) → 2.1(완성도 기준) → 2.2(최소기능 버전)로
이어지는 사슬이 목적문의 "오늘 일단 만들어 내는 방법"에 그대로 대응한다.

무관 페이지를 4장으로 잡으면서 `helpfulConcepts`에서 조기 공유를 뺐다. 무관 페이지의
`primaryConcepts`에 도움 개념을 달 수 없다는 정본 조건 때문이다. 대체 페이지 셋은 1.3·2.1·2.3의 나머지
페이지이고 폐쇄가 3~5페이지라 QUICK 상한 안에서 실제로 고를 수 있다.

## 재현 조건

1. `python3 build095.py` — 원고와 조각 생성 (PDF SHA 없이 실행하면 자리표시자를 넣는다)
2. `python3 figures095.py pdfbuild095` — 도표 4개 SVG 생성
3. Chrome Headless로 각 SVG를 794×1123 PNG로 렌더링
4. `python3 build_pdf_generic.py 95 7,15,21,39 pdfbuild095` — 조판 HTML 생성
5. Chrome Headless `--print-to-pdf`로 PDF 출력, `pdfcheck.py`로 구성 확인
6. PDF를 `fixtures/content/ai-route-v2/pdfs/`에 두고 SHA-256을 인자로 `build095.py` 재실행
7. `merge_fragments.py 95`로 정본에 병합

## 검수

- 네 도표를 PNG로 렌더링해 눈으로 확인했다. p21은 초안에서 계단이 오른쪽으로 내려가고 설명 상자가 아래
  안내문과 겹쳐, 단의 높이와 화살표 자리를 다시 잡았다.
- 공개 가이드 주제와 비공개 분석 텍스트를 서로 다른 문장으로 적었고, 주제문에 숫자를 쓰지 않았다.
- 본문·도표·평가 데이터에 실존 인물·작품·단체가 등장하지 않는다.
- 낮은 완성도로 시작하라는 주장이 안전이나 신뢰가 걸린 일까지 번지지 않게 6장에 세 절을 두고, 6.1
  두 번째 페이지에서 손실이 남에게 가는 일에는 쓰지 않는다고 명시했다.

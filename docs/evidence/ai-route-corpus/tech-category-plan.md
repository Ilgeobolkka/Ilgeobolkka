# 기술 카테고리(bookId 71~80) 개념 배분 계획

SCRUM-485 90권 확장의 기술 카테고리 담당분입니다. 정본이 요구하는 "같은 개념을 표현만 바꿔
반복하지 않고" 조건을 카테고리 단위로 지키기 위해, 10권 착수 전에 각 권의 핵심 개념 범위를 먼저
고정합니다. 저자·소개는 `src/main/resources/demo/books.json`의 기존 값을 유지하고, 제목은 카테고리 톤에
맞게 갱신한 같은 파일의 값을 따릅니다.
형식은 [`economics-category-plan.md`](./economics-category-plan.md)를 따릅니다.

실존 회사·제품·프레임워크·언어 이름은 쓰지 않고, 특정 기술 스택에 종속되지 않는 일반적인
소프트웨어 원리로 서술합니다("서비스", "요청", "함수", "기록"처럼 중립적인 용어를 씁니다).

## 카테고리 내부 선수 관계

권 사이의 개념 의존은 만들지 않습니다. 정본은 선수 관계를 "같은 도서·콘텐츠 버전 안"으로만
허용하므로, 카테고리 내 다른 책을 선수로 지정할 수 없습니다. 대신 자연스러운 학습 순서를 권
배치로만 반영합니다.

```
71 (요청 처리 흐름) → 74 (함수·모듈 구조) → 72 (데이터 검증)
73 (버그 관찰) → 75 (로그) → 78 (느린 쿼리)
76 (안전한 기본값) → 77 (테스트와 계약)
79 (접근성)은 독립적으로 배치
80 (배포 점검표)은 마무리 성격으로 마지막에 배치
```

## 평가 시나리오 배분

일곱 시나리오(비소장 예산0/5/10/15, 소장 QUICK/BALANCED/DEEP)를 10권에 최소 한 번씩 배분합니다.

| bookId | 시나리오 | 비고 |
| --- | --- | --- |
| 71 | 비소장·예산10 | 요청 흐름을 넓게 훑어볼 여유 예산 |
| 72 | 비소장·예산0 | 이미 대여한 페이지 안에서만 확인 (`activeRentalPageNumbers` 필요) |
| 73 | 비소장·예산5 | 재현에 필요한 핵심만 좁게 |
| 74 | 비소장·예산15 | 구조 원리를 넓게 탐색 |
| 75 | 소장·QUICK | 로그 개념을 빠르게 훑음 |
| 76 | 소장·BALANCED | 기본값·실패 경계를 균형 있게 |
| 77 | 소장·DEEP | 테스트와 계약을 깊게 |
| 78 | 비소장·예산10 (반복) | 느린 쿼리 원인을 넓게 탐색 |
| 79 | 비소장·예산5 (반복) | 접근성 점검 항목만 좁게 |
| 80 | 소장·DEEP (반복) | 배포 전 점검을 깊게 재확인 |

일곱 시나리오 모두 최소 한 번씩 포함(예산0=72, 예산5=73·79, 예산10=71·78, 예산15=74,
QUICK=75, BALANCED=76, DEEP=77·80).

## 제작 순서

71 → 74 → 72 → 73 → 75 → 78 → 76 → 77 → 79 → 80

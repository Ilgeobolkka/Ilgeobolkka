# SCRUM-466 C04 AI 콘텐츠 원자적 적재 인계

[C04 leaf](../../implementation/ai-route/content/C04-atomic-import.md)의 인계 항목을
[Q01 평가 runner](../../implementation/ai-route/release/Q01-evaluation-runner.md) 담당자에게 넘기기 위한
문서입니다. 정책은 재정의하지 않고 정본의 값과 확인 방법만 모읍니다.

## 적재 명령

Poppler 경로와 버전(`26.05.0`)을 먼저 확인한 뒤
[배포 가이드](../../deployment.md#콘텐츠-변환적재)와 같은 형태로 비웹 배치를 실행합니다.

```bash
SPRING_PROFILES_ACTIVE=content-import \
CONTENT_IMPORT_MANIFEST=<ai-route-v2 manifest 경로> \
PDFTOTEXT_COMMAND="$(command -v pdftotext)" \
PDFTOPPM_COMMAND="$(command -v pdftoppm)" \
OPENAI_PROJECT_ID=... OPENAI_API_KEY=... OPENAI_DATA_POLICY_VERSION=OPENAI_DEFAULT_RETENTION_V1 \
./gradlew bootRun
```

- 진입점은 `ContentImportRunner`이고 완료 로그에 `manifestSha256`, 도서 수, 페이지 수를 남깁니다.
- `OPENAI_*` 세 값은 `OpenAiProperties.validateForContentImport()`가 Embeddings 호출 전에 검증합니다.
  manifest의 `dataPolicyVersion`과 다르면 DB 변경과 외부 호출 전에 실패합니다.
- `manifest.json` 옆에 `evaluation.json`이 있어야 합니다(`AiRouteContentImportPreparer`).

## contentVersion과 배치 식별자

| 항목 | 값·위치 |
| --- | --- |
| `contentVersion` | `ai-route-v2` (`ContentManifest.AI_ROUTE_CONTENT_VERSION`) |
| 배치 식별자 | 입력 manifest 파일 바이트의 SHA-256 |
| 결과 디렉터리 | `var/content/pages/<manifestSha256>/` |
| 결과 manifest | 위 디렉터리의 `manifest.json` = `AiRouteContentResultManifest` |

결과 manifest에는 `dataPolicyVersion`, `embeddingModel`, `embeddingDimensions`와 페이지별
`analysisInputSha256`·`embeddingSha256`이 들어갑니다. Q01의 report 재사용 판정이 쓰는 manifest SHA-256은
이 파일과 완료 로그 양쪽에서 얻을 수 있습니다.

같은 manifest로 다시 적재해도 **Embeddings는 매번 다시 호출합니다** — 배치 디렉터리 재사용은 파일
게시 단계의 판정이라 호출을 건너뛰지 않습니다. 그리고 재호출한 vector가 이전 게시와 한 바이트라도
다르면 `embeddingSha256`이 달라져 기존 배치 디렉터리를 덮어쓰지 않고 적재 전체를 중단합니다
(DB는 그대로 두는 fail-closed). 재적재는 비용이 다시 들고, 결과가 흔들리면 실패한다고 보면 됩니다.

## manifest·DB 일치 확인 쿼리

```sql
-- 1) 적재된 contentVersion과 지원 상태 집계 (지원은 모두 false여야 한다)
SELECT content_version, ai_route_supported, COUNT(*)
FROM book
WHERE content_version = 'ai-route-v2'
GROUP BY content_version, ai_route_supported;

-- 2) manifest의 모델·차원이 DB 후보 페이지와 같은지
SELECT p.embedding_model, p.embedding_dimensions, COUNT(*)
FROM book_page p
JOIN book b ON b.id = p.book_id
WHERE b.content_version = 'ai-route-v2'
  AND p.ai_route_candidate = 1
GROUP BY p.embedding_model, p.embedding_dimensions;

-- 3) ERD 계약 위반 페이지 (0건이어야 한다)
SELECT p.book_id, p.page_number
FROM book_page p
JOIN book b ON b.id = p.book_id
WHERE b.content_version = 'ai-route-v2'
  AND ((p.ai_route_candidate = 1
        AND (p.ai_analysis_text IS NULL OR p.ai_public_guide_topic IS NULL
             OR p.estimated_reading_seconds IS NULL OR p.estimated_reading_seconds <= 0
             OR p.embedding_model IS NULL OR p.embedding_dimensions IS NULL
             OR p.embedding_dimensions <= 0 OR p.embedding_json IS NULL
             OR JSON_LENGTH(p.embedding_json) <> p.embedding_dimensions
             OR p.duplicate_group_keys IS NULL))
       OR (p.ai_route_candidate = 0
           AND (p.embedding_model IS NOT NULL OR p.embedding_dimensions IS NOT NULL
                OR p.embedding_json IS NOT NULL)));

-- 4) 도서별 페이지 수가 manifest 합계와 같은지
SELECT b.id, b.total_page_count, COUNT(p.id) AS stored_pages
FROM book b LEFT JOIN book_page p ON p.book_id = b.id
WHERE b.content_version = 'ai-route-v2'
GROUP BY b.id, b.total_page_count
HAVING b.total_page_count <> COUNT(p.id);

-- 5) 선수 관계가 후보 페이지만 가리키는지 (0건이어야 한다)
SELECT r.book_id, r.prerequisite_page_number
FROM ai_route_prerequisite r
LEFT JOIN book_page p
  ON p.book_id = r.book_id AND p.page_number = r.prerequisite_page_number
WHERE p.id IS NULL OR p.ai_route_candidate = 0;
```

## support false 보장 지점

- `ContentPageWriter.updateAiBooks()`의 `UPDATE book SET ... ai_route_supported = FALSE`가
  적재 대상 도서 전체에 대해 무조건 실행됩니다. 재적재로 기존 `true`가 들어와도 내려갑니다.
- 회귀 고정: `AiRouteContentImportMySqlIntegrationTest`가 적재 전 `ai_route_supported = TRUE`로 만든 뒤
  적재 후 `false`를 단언합니다.
- 활성화(`true` 전환)는 C04 범위 밖이며 Q02가 담당합니다.

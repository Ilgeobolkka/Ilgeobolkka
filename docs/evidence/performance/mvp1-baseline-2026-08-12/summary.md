다중 세션 로그아웃은 보완된 harness의 clean Git SHA
`0203b7e8497ee7fe8e3c710cefcbec7a068c820b`에서 다시 실행했다. `setup()`이 대상 독자의 페이지를 먼저 열어
대여·차감·서재·현재 세션을 만든 뒤 20개 VU가 같은 계정으로 동시에 로그아웃했고, SQL 대조에서 준비된
업무 기록은 유지되면서 현재 세션만 0이 됨을 확인했다.

## 브라우저 cold·warm cache 3쌍

새 browser context의 첫 탐색을 cold, 같은 context의 동일 경로 반복을 warm으로 측정했다.

| 쌍 | 공개 cold | 공개 warm | 공개 cold/warm 전송량 | 보호 cold | 보호 warm |
| --- | ---: | ---: | ---: | ---: | ---: |
| 1 | 330ms | 193ms | 329,581 / 329,581 bytes | 162ms | 175ms |
| 2 | 186ms | 113ms | 329,581 / 329,581 bytes | 209ms | 96ms |
| 3 | 119ms | 119ms | 329,581 / 329,581 bytes | 270ms | 100ms |
| 중앙값 | 186ms | 119ms | 329,581 / 329,581 bytes | 209ms | 100ms |

- 공개 CSS·JS는 cold와 warm 모두 `no-cache, no-store, max-age=0, must-revalidate`였고 전송량이 줄지
  않았다.
- 보호 페이지 콘텐츠 API는 cold와 warm 모두 `private, no-store`여서 보호 콘텐츠 cache 계약을
  지켰다.
- browser generator CPU 최대가 97.73%여서 같은 context의 상대적 cache·bytes 근거만 사용한다. 절대
  탐색 시간은 서버 용량 기준선으로 사용하지 않는다.

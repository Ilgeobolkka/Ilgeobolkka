# MVP1 최종 성능 요약

## 판정 경계

이 결과는 Apple M5 로컬 Docker Desktop의 코드 회귀 기준선이다. 운영 트래픽 예측, 운영 SLO, 운영 최대
RPS 또는 인스턴스 용량 보증이 아니다. 정식 부하는 Git SHA
`f3a62809099ba660ce980b006d71c833bbd849fa`, clean 작업 트리, 동일 패키징 JAR과 고정 Compose image에서
실행했다.

### 실패·무효 실행과 재실행

- 첫 Spike `20260813T051801Z-final-spike`는 HTTP 오류·dropped가 0이었지만 `잉크 차감 일치` check가
  73,353건 중 1건 실패해 exit code 99였다. JAR·데이터·자원 변경이나 상태 누출 등 Runbook 무효 조건은
  확인되지 않았으므로 **무효가 아니라 실패 실행**이다. 당시 로그에는 실패 flow·기대값·실제값이 없어
  원인을 사후 복원할 수 없다. 데이터를 복원한 같은 계획의 재실행은 통과했지만 원인이나 설정 변경이
  없었으므로 첫 실패는 잔여 위험으로 유지한다.
- 첫 Soak `20260813T053846Z-final-soak`도 95,687건 중 같은 check 1건이 실패해 exit code 99로 무효다.
  `vuStride=6`이 최대 24 VU의 임시 확장 구간에서 신규 독자 slot을 충돌시킬 수 있는 harness 조건이었다.
  제품 코드는 바꾸지 않고 `vuStride=24`, `cycles=13`으로 독립 slot을 부여해 데이터를 복원한 뒤 30분
  전체를 재실행했다.
- 실패·무효 summary와 로그는 삭제하지 않았고 [artifact-manifest.md](./artifact-manifest.md)에 별도로
  연결했다. 후속 하네스는 같은 계약 실패가 재발하면 flow·독자·페이지·기대값·실제값·VU iteration을
  기록한다. 후속 통합 JAR의 진단 Spike는 통과했지만 과거 실패 원인이나 정식 성능 수치로 사용하지 않는다.

## 브라우저 cold·warm 3쌍

새 browser context의 첫 탐색을 cold, 같은 context에서 같은 경로를 반복한 탐색을 warm으로 측정했다.

| 쌍 | 공개 cold | 공개 warm | 공개 cold/warm 전송량 | 보호 cold | 보호 warm |
| --- | ---: | ---: | ---: | ---: | ---: |
| 1 | 316ms | 36ms | 329,581 / 329,581 bytes | 129ms | 151ms |
| 2 | 192ms | 117ms | 329,581 / 329,581 bytes | 277ms | 209ms |
| 3 | 181ms | 97ms | 329,581 / 329,581 bytes | 235ms | 139ms |
| 중앙값 | 192ms | 97ms | 329,581 / 329,581 bytes | 235ms | 151ms |

- 공개 CSS·JS는 cold·warm 모두 `no-cache, no-store, max-age=0, must-revalidate`였고 전송량이 줄지 않았다.
- 보호 콘텐츠 API는 cold·warm 모두 `private, no-store`였으며 응답 상태는 200이었다.
- feature checks 15/15가 통과했다. browser 내부 요청 실패율은 1/184였지만 추적 대상 자산·보호 API의
  상태와 cache 계약은 모두 통과했고, 기준선도 2/185였다.
- browser generator CPU 평균 95.405%, 최대 100.82%였다. 따라서 같은 context 안의 cold/warm 전송량과
  cache 계약만 유효 근거로 사용하고 절대 탐색 시간은 서버 용량이나 전후 성능 개선으로 사용하지 않는다.

지연·오류·자원·SQL 불변식 게이트는 재실행 결과에서 충족했다. 그러나 첫 Spike 기능 실패 원인은 확인하지
못했고, 같은 계획의 재실행과 후속 진단이 통과해도 과거 실패를 지우지는 못한다. 따라서 5단계 실행은
조건부 통과로 종료하되 최종 정확성·품질 게이트는 **미달**로 판정한다. 전체 목표의 지연 30% 단축 또는
지속 처리량 1.5배 향상은 달성하지 않았다. 추가 상태 인프라의 진입 근거가 없다는 구조 판정은 유지한다.
상세 비교와 구조 판정은 [comparison.md](./comparison.md)에 기록했다.

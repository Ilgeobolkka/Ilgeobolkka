# SCRUM-424 전체 Gradle·Compose·실행 검증 근거

> 2026-08-04 KST 기준 로컬에서 실행 가능한 자동·런타임·브라우저 게이트는 모두 통과했다.

### 빈 환경 격리 재검증

기존 `ilgeobolkka_mysql-data`를 보존하면서 빈 환경 조건을 확인하기 위해 Compose 프로젝트
`scrum424-validation`, 호스트 포트 33308과 전용 볼륨 `scrum424-validation_mysql-data`를 사용했다.

민감한 DB 계정 값은 Git에서 제외된 `.env`에서 그대로 주입하고, 비민감 연결 주소만 다음과 같이
전용 포트로 덮어썼다.

```bash
scrum424_db_url="jdbc:mysql://localhost:33308/ilgeobolkka?allowPublicKeyRetrieval=true&sslMode=DISABLED"
scrum424_test_db_url="jdbc:mysql://localhost:33308/ilgeobolkka_test?allowPublicKeyRetrieval=true&sslMode=DISABLED"

DB_PORT=33308 docker compose -p scrum424-validation config -q
DB_PORT=33308 docker compose -p scrum424-validation up -d --wait
DB_PORT=33308 docker compose -p scrum424-validation exec -T mysql \
  sh /docker-entrypoint-initdb.d/01-create-test-database.sh

DB_URL="$scrum424_db_url" \
TEST_DB_URL="$scrum424_test_db_url" \
RUN_CONTENT_IMPORT_INTEGRATION=true \
PDFTOTEXT_COMMAND="$PDFTOTEXT_COMMAND" \
PDFTOPPM_COMMAND="$PDFTOPPM_COMMAND" \
./gradlew clean test

TEST_DB_URL="$scrum424_test_db_url" ./gradlew check
TEST_DB_URL="$scrum424_test_db_url" ./gradlew build
DB_URL="$scrum424_db_url" \
  .github/scripts/boot-smoke.sh build/libs/Ilgeobolkka-0.0.1-SNAPSHOT.jar
DB_URL="$scrum424_db_url" ./gradlew bootRun

DB_PORT=33308 docker compose -p scrum424-validation down -v
```

- 새 MySQL 8.4.10 컨테이너에서 개발 DB와 `_test` DB가 처음 생성됐다.
- 일반 애플리케이션 DB에는 Flyway V1 성공 기록 1건만 있고 `book`·`reader`는 각각 0건이었다.
- 이 `_test` DB에서 전체 변환을 포함한 `./gradlew clean test`가 54초에 통과했다.
- 이어서 `./gradlew check`, `./gradlew build`, 패키징 JAR 브라우저 smoke를 통과했다.
- 같은 빈 일반 DB로 `./gradlew bootRun`을 실행해 2.274초 시작, `/api/smoke` 204와 빈 도서 목록 API
  200을 확인했다.
- 검증 뒤 전용 컨테이너·네트워크·볼륨만 `docker compose -p scrum424-validation down -v`로 제거했다.
  기존 `ilgeobolkka-mysql-1`과 `ilgeobolkka_mysql-data`는 그대로 유지했다.

## 실행 중 발견한 비제품 오류

테스트 DB 이름을 확인하는 첫 보조 SQL에서 `SHOW DATABASES LIKE CONCAT(...)`을 사용해 MySQL
`ERROR 1064 (42000)`이 한 번 발생했다. 애플리케이션이나 데이터 변경 전의 읽기 전용 확인 문장이며,
`INFORMATION_SCHEMA.SCHEMATA` 조회로 `ilgeobolkka_test`를 재확인했다. 제품 테스트와 출시 게이트의
실패는 아니다.

`bootRun`은 정상 시작과 HTTP·브라우저 확인을 마친 뒤 `SIGINT`로 종료했으므로 실행 프로세스의 최종
종료 코드는 130이다.

`clean test`의 테스트 소스 컴파일에서는 `Some input files use or override a deprecated API.` 안내가
출력됐다. 컴파일·테스트·검사·패키징은 모두 성공했으며 이번 최종 검증에서 기존 deprecated API 사용을
범위 밖 코드 수정으로 확장하지 않았다.

## 별도 출시 검증 범위

실제 PortOne 테스트 채널의 결제 성공, 서버 재조회, 서명 웹훅과 중복 전달 멱등성은 SCRUM-425가 독립
소유한다. SCRUM-425는 SCRUM-424의 선행 이슈나 종료 조건이 아니며, 제품 전체의 PortOne 출시 게이트를
판정할 때 별도로 완료해야 한다.

새 제품 기능, 운영 AWS 배포, 스키마 변경, 테스트 약화는 수행하지 않았다.

# 읽어볼까 MVP 제품 요구사항

## 1. 문서 상태

- 상태: 합의 완료
- 제품명: 읽어볼까
- 제공 형태: 반응형 웹
- 구현 상태: 제품·도메인·프런트엔드 계약과 기반 골격 완료, 핵심 도메인 기능 구현 전
- 백엔드 기술 스택: Java 21, Spring Boot 4.1.0
- 운영 데이터베이스: Amazon RDS for MySQL 8.x
- 프런트엔드 기술 스택: Thymeleaf, Bootstrap 5.3, Vanilla JavaScript
- 애플리케이션 구성: 프런트엔드와 API를 같은 Spring Boot 실행물에서 same-origin으로 제공

## 2. 문제와 가설

책 전체를 한 번에 구매하기 부담스럽거나 필요한 일부부터 읽고 싶은 독자에게는 전체 금액을 먼저
지불하는 방식이 진입 장벽이 될 수 있습니다.

읽어볼까는 독자가 실제로 열람 확정한 페이지에만 50P를 사용하고, 전체 페이지의 90%를 열람 확정하면
온라인 소장으로 전환합니다. 독자가 최초 확정 페이지만 차감되고 재열람은 무료라는 규칙을 이해한다면
이 과금 방식을 신뢰할 것이라는 가설을 검증합니다.

## 3. MVP 목표

1. 소장 전 처음 열람 확정한 페이지에만 50P를 정확히 차감합니다.
2. 같은 페이지의 재열람에는 추가 포인트를 차감하지 않습니다.
3. 현재 포인트 잔액과 모든 포인트 내역의 합계를 일치시킵니다.
4. 열람 확정 페이지 수가 실제 확정 행 수와 일치하고 소장 기준에 도달하면 즉시 소장으로 전환합니다.
5. 소장한 도서의 남은 페이지를 추가 차감 없이 제공합니다.
6. 잔액 부족, 중복 요청, 동시 요청, 서버 오류에서도 잘못된 차감이나 진행 상태를 만들지 않습니다.
7. 100권 규모의 목록과 검색에서 원하는 책을 찾고 읽을 수 있게 합니다.
8. 소규모 사용자 검증으로 최초 차감과 재열람 규칙의 이해 여부를 확인합니다.

매출, 결제 전환율, 추천 성과는 이번 MVP의 성공 기준이 아닙니다.

## 4. 대상 독자

책 전체를 구매하기는 부담스럽지만 필요한 부분부터 읽어보고 싶은 일반 독자를 대상으로 합니다.
학생, 연구자, 특정 연령대 등으로 대상을 더 좁히지 않습니다.

## 5. 핵심 정책

### 5.1 포인트와 소장

- 서비스 내부 단위는 포인트입니다.
- 향후 실제 충전에서는 1원 = 1P 비율을 사용하고 1,000원 단위로만 충전합니다.
- MVP에는 PG와 실제 충전 기능이 없습니다.
- 도서 가격, 원가, 최대 총 차감 포인트를 저장하거나 화면·API에 표시하지 않습니다.
- 모든 도서의 모든 페이지에 50P의 전역 고정 단가를 적용하며 부분 차감은 없습니다.
- 독자·도서별 `confirmedPageCount`는 서로 다른 열람 확정 페이지 수이며 `ConfirmedPage` 행 수와 같습니다.
- 소장 기준 페이지 수는 `ceil(totalPageCount × 0.9)`로 계산합니다.
- 소장 전 미확정 페이지를 열람 확정하면 50P를 차감하고 `confirmedPageCount`를 1 증가시킵니다.
- 증가한 `confirmedPageCount`가 소장 기준 페이지 수 이상이면 같은 트랜잭션에서 소장 상태가 됩니다.
- 소장 여부는 두 페이지 수로 계산하고 별도의 `ownedAt`은 저장하지 않습니다.
- 소장한 도서는 아직 열람 확정하지 않은 페이지도 잔액 검사와 차감 없이 읽을 수 있습니다.
- 소장 후 새 페이지를 열람 확정하면 `ConfirmedPage`, `confirmedPageCount`, 마지막 위치만 갱신합니다.
- 소장은 서비스 안에서 모든 페이지를 읽는 권한이며 원본 PDF 다운로드, 인쇄, 오프라인 이용을 제공하지 않습니다.
- 포인트에는 유효기간이 없습니다.
- 페이지 차감 취소와 환불은 지원하지 않습니다.

### 5.2 열람 확정

- 아직 열람 확정되지 않은 페이지를 열면 서버가 페이지 열림 시각을 기록합니다.
- 독자가 같은 페이지를 유지한 채 6초가 지나면 열람 확정 요청을 보낼 수 있습니다.
- 서버 기준 경과 시간이 6초 이상일 때만 요청을 승인합니다.
- 탭 전환, 창 최소화, 다른 앱 사용은 6초 경과를 취소하지 않습니다.
- 6초 전에 페이지를 넘기거나 뷰어를 종료하면 열람 확정되지 않고 포인트도 차감되지 않습니다.
- 소장 전 같은 사용자·도서·페이지 조합에는 최초 한 번만 50P를 차감합니다.
- 이미 열람 확정된 페이지는 잔액과 관계없이 다시 읽을 수 있습니다.
- 소장한 도서의 미확정 페이지도 6초 후 확정 기록을 남기지만 포인트는 차감하지 않습니다.

### 5.3 차감 실패

- 소장 전 미확정 페이지를 열기 전에 잔액이 50P 이상인지 확인합니다.
- 잔액이 49P 이하면 페이지를 보여주지 않고 열람을 차단합니다.
- 이미 열람 확정된 페이지와 소장한 도서의 페이지에는 잔액 검사를 적용하지 않습니다.
- 6초 후 차감 처리에 실패하면 해당 페이지를 열람 확정하지 않습니다.
- 실패 화면에서 뷰어를 일시 차단하고 재시도 기능을 제공합니다.
- 사용자가 모르는 시점에 나중에 자동 차감하지 않습니다.
- 같은 차감 요청을 재시도해도 중복 차감되지 않아야 합니다.

### 5.4 계정과 인증

- 이메일은 앞뒤 공백을 제거하고 소문자로 정규화해 저장·조회합니다.
- 대소문자만 다른 동일 이메일의 중복 가입을 허용하지 않습니다.
- 비밀번호는 최소 8자, UTF-8 최대 64바이트입니다.
- 비밀번호에는 영문, 숫자, 공백이 아닌 ASCII 특수문자가 각각 한 개 이상 포함되어야 합니다.
- 한글 등 다른 문자는 추가로 허용하지만 영문 조건을 대신하지 않습니다.
- 비밀번호는 입력값을 변경하거나 잘라 저장하지 않고 적응형 단방향 함수로 인코딩합니다.
- 로그인 세션은 마지막 요청 후 2시간 동안 활동이 없으면 만료됩니다.
- 자동 로그인과 Remember Me는 제공하지 않습니다.
- 회원가입·로그인·로그아웃을 포함한 상태 변경 요청에 CSRF 검증을 적용합니다.

## 6. 사용자 흐름

### 6.1 계정

1. 사용자는 이메일과 비밀번호로 회원가입합니다.
2. 일반 회원가입 사용자의 초기 포인트는 0P이며 지급 내역도 없습니다.
3. 이메일과 비밀번호로 로그인하고 로그아웃할 수 있습니다.
4. 로그인 성공 시 세션 ID를 교체하고, 로그아웃 시 로그인 세션과 열람 세션을 무효화합니다.
5. 소셜 로그인, 비밀번호 찾기, 회원 탈퇴는 제공하지 않습니다.

핵심 과금·소장 흐름은 로컬·시연 환경의 10,000P 시연 계정으로 검증합니다. 0P 시연 계정은 잔액 부족
흐름을 검증합니다. 운영 환경에는 시연 계정을 만들지 않고, 시연 계정 비밀번호는 환경변수로만 주입합니다.

### 6.2 도서 탐색

1. AI가 작성한 가상 더미 도서 100권을 제목 가나다순으로 봅니다.
2. 한 페이지에 10권을 표시하고 1부터 시작하는 페이지 번호로 이동합니다.
3. 검색어 앞뒤 공백을 제거하고 제목 또는 저자를 대소문자 구분 없이 부분 일치 검색합니다.
4. 빈 검색어는 전체 목록을 조회하고 `%`, `_`는 와일드카드가 아닌 일반 문자로 처리합니다.
5. 결과는 `title ASC, id ASC`로 정렬하고 10권씩 표시합니다.
6. 0 이하의 페이지 번호는 거부하고 전체 범위를 초과한 양수는 빈 목록과 페이지 정보를 반환합니다.
7. 목록에서 표지, 제목과 저자를 확인합니다.
8. 책 상세에서 표지, 제목, 저자, 짧은 소개와 전체 페이지 수를 확인합니다.
9. 로그인한 독자의 상세 화면에는 `열람 확정 페이지 수 / 소장 기준 페이지 수`와 소장 여부를 표시합니다.
10. 상세 화면에는 도서 가격, 최대 총 차감 포인트, 소장까지 남은 페이지 수, 평점, 리뷰, 판매량을 표시하지 않습니다.

### 6.3 최초 열람 동의

1. 독자가 특정 도서를 처음 읽으려 할 때 동의 화면을 표시합니다.
2. 안내에는 처음 열람 확정한 페이지마다 50P가 차감되고, 전체 페이지의 90% 이상을 열람 확정하면
   소장으로 전환되며 이후 페이지는 추가 차감되지 않는다는 뜻을 포함합니다.
3. 같은 페이지의 재열람에는 추가 차감이 없음을 알립니다.
4. 도서별 최대 총 차감 포인트와 내부 판정 기준인 6초는 동의 문구에 노출하지 않습니다.
5. 동의하지 않으면 뷰어에 들어갈 수 없습니다.
6. 동의는 사용자·도서별 최초 한 번만 받습니다.

### 6.4 뷰어

1. 원본 PDF 전체가 아니라 현재 페이지 이미지만 제공합니다.
2. 애플리케이션의 same-origin 전용 이미지 API가 인증된 독자와 현재 열람 세션·페이지를 검증한 뒤
   비공개 S3 또는 로컬 파일의 이미지를 대신 전달합니다.
3. 이전 페이지, 다음 페이지, 페이지 번호 직접 이동을 제공합니다.
4. 앞 페이지의 열람 여부와 관계없이 어느 페이지로든 이동할 수 있습니다.
5. 사용자당 하나의 온라인 열람 세션만 허용합니다.
6. 새 뷰어가 열리면 기존 열람 세션을 교체합니다.
7. 뷰어를 닫으면 브라우저 타이머와 진행 중 요청을 취소하며, 서버는 확정 요청이 없는 페이지를 자동 차감하지 않습니다.
8. 브라우저 종료 감지나 별도 종료 API에 의존하지 않고 남은 세션 행은 다음 뷰어 오픈 또는 로그아웃 때 정리합니다.
9. 오프라인 열람, 원본 다운로드, 인쇄를 제공하지 않습니다.
10. DRM과 화면 캡처 방지는 적용하지 않습니다.
11. 초기 화면은 페이지 너비에 맞춰 표시합니다.
12. 이전·다음 이동은 키보드로 조작할 수 있고 모든 조작 버튼에 명확한 포커스와 접근 가능한 이름을 제공합니다.

### 6.5 내 서재

- 한 페이지 이상 열람 확정된 책을 자동으로 추가합니다.
- 책 제목, 마지막 열람 확정 페이지, `열람 확정 페이지 수 / 소장 기준 페이지 수`와 소장 여부를 표시합니다.
- 다시 들어가면 마지막 열람 확정 페이지에서 시작합니다.
- 소장한 책은 포인트 잔액과 관계없이 모든 페이지를 열 수 있습니다.
- 소장까지 남은 페이지 수는 별도로 표시하지 않습니다.
- 별도 서재 담기 기능은 없습니다.

### 6.6 포인트 내역

- 사용자는 자신의 포인트 지급과 차감 내역만 조회할 수 있습니다.
- 페이지 차감 내역에는 책 제목, 페이지 번호, 50P 차감, 차감 시각, 차감 후 잔액을 표시합니다.
- 한 페이지에 10개씩 `occurredAt DESC, id DESC` 순서로 보여줍니다.
- 페이지 번호 검증과 범위 초과 처리는 도서 목록과 같습니다.
- 포인트 내역은 수정하거나 삭제하지 않습니다.

| --- | --- |

| AUTH-004 | 로그인 세션은 2시간 비활성 시 만료되며 로그인 시 ID 교체, 로그아웃 시 로그인·열람 세션 무효화와 CSRF 검증을 적용한다. |
| CAT-001 | AI가 작성한 가상 더미 도서 100권을 `title ASC, id ASC`로 10권씩 제공한다. |

| BILL-001 | 같은 페이지를 유지한 6초를 서버 시간으로 검증해 열람 확정한다. |
| BILL-002 | 소장 전 사용자·도서·페이지별 최초 한 번만 50P를 차감한다. |
| BILL-003 | 탭 전환이나 창 최소화는 열람 확정 시간을 취소하지 않는다. |
| BILL-004 | 6초 전 페이지 이동이나 뷰어 종료에는 포인트를 차감하지 않는다. |
| BILL-005 | 소장 전 미확정 페이지 진입 시 잔액이 50P 미만이면 차단한다. |
| BILL-006 | 차감 실패 시 열람을 확정하지 않고 명시적 재시도를 요구한다. |
| OWN-001 | `confirmedPageCount`는 독자·도서별 `ConfirmedPage` 행 수와 같아야 한다. |
| OWN-002 | `confirmedPageCount`가 `ceil(totalPageCount × 0.9)` 이상이면 소장 상태다. |
| OWN-003 | 소장한 도서는 모든 페이지를 잔액과 관계없이 추가 차감 없이 제공하고 확정 진도는 계속 기록한다. |
| LIB-001 | 최초 열람 확정된 도서를 내 서재에 추가하고 마지막 확정 페이지, 확정 페이지 수와 소장 상태를 제공한다. |
| PTS-001 | 모든 포인트 증감을 내역으로 남기고 현재 잔액과 합계를 일치시킨다. |
| PTS-002 | 사용자가 페이지별 차감 상세를 조회할 수 있게 한다. |
| PTS-003 | 포인트 내역을 `occurredAt DESC, id DESC`로 10개씩 제공한다. |

## 8. 초기 데이터

### 8.1 도서

- 실존 작품을 바탕으로 하지 않고 AI가 작성한 가상 더미 도서 본문, 표지와 메타데이터 100권
- 90% 올림 경계를 검증할 수 있도록 전체 페이지 수가 10, 11, 101인 도서를 각각 한 권 이상 포함
- 더미 도서 본문은 PDF로 만들고 각 PDF는 페이지별 이미지로 미리 변환
- 더미 도서는 MVP 시연과 검증에만 사용하며 공개 배포 전에는 AI 생성 자산을 포함한 실제 사용 자산별 권리 상태를 다시 확인

### 8.2 사용자

| 용도 | 초기 포인트 | 추가 조건 |
| --- | ---: | --- |
| 정상 차감 검증 | 10,000P | 테스트 포인트 지급 +10,000P 내역 포함 |
| 잔액 부족 검증 | 0P | 지급 내역 없음 |

- 시연 계정은 로컬·시연 환경에서만 만들고 운영 환경에는 생성하지 않습니다.
- 시연 계정 비밀번호는 `DEMO_NORMAL_PASSWORD`, `DEMO_EMPTY_PASSWORD` 환경변수로 주입하며 저장소에 기록하지 않습니다.
- 관리자 계정과 관리자 기능은 초기 데이터에 포함하지 않습니다.

## 9. MVP 제외 범위

- PG 결제와 실제 포인트 충전
- 관리자 계정, 도서 운영 백오피스
- 도서 등록, 수정, 판매 중지, 재판매, 삭제
- 도서 가격, 최대 총 차감 포인트와 책별 페이지 단가
- 소장 전 무료 미리보기와 과금 제외 페이지
- 회원 탈퇴와 비밀번호 찾기
- 자동 로그인, Remember Me, 로그인 횟수 제한과 계정 잠금
- 리뷰, 평점, 추천, 판매량
- 장르 필터, 검색 자동완성, 본문 검색, 정렬 선택
- 목차, 책갈피, 메모, 하이라이트
- 확대·축소, 글꼴, 줄간격, 다크 모드
- 화면 판독기용 본문 텍스트 레이어와 OCR
- PDF 다운로드, 인쇄, 오프라인 읽기
- DRM과 화면 캡처 방지
- 네이티브 모바일 앱
- 환불과 과금 분쟁 처리

이미지 전용 본문은 화면 판독기와 저시력 사용자에게 충분한 독서 접근성을 제공하지 못하며 이를 MVP의
명시적 한계로 둡니다.

## 10. 고도화 후보

1. 실제 PG 결제 성공 후 1원 = 1P, 1,000원 단위 포인트 자동 충전
2. 도서 등록과 판매 상태를 관리하는 별도 백오피스
3. 무료 또는 과금 제외 페이지
4. 목차와 여러 책갈피
5. 확대·축소, OCR·본문 텍스트 레이어와 모바일 뷰어 접근성 개선
6. 포인트 환불과 분쟁 처리

## 11. 성공 판정

다음 조건을 모두 통과하면 초기 MVP의 목표를 달성한 것으로 봅니다.

1. 소장 전 처음 열람 확정된 페이지에만 50P가 차감됩니다.
2. 같은 페이지의 재열람과 중복 요청에서 추가 차감이 발생하지 않습니다.
3. `confirmedPageCount`가 실제 `ConfirmedPage` 행 수와 항상 일치합니다.
4. 열람 확정 페이지 수가 소장 기준에 도달하면 소장으로 판정됩니다.
5. 소장한 도서의 모든 페이지를 포인트 차감 없이 읽고 진도를 계속 기록할 수 있습니다.
6. 포인트 내역의 합계와 현재 잔액이 항상 일치합니다.
7. 소장 전 잔액이 50P 미만이면 새로운 미확정 페이지의 열람이 차단됩니다.
8. 사용자 검증 참가자 5명 중 4명 이상이 최초 확정 페이지만 50P가 차감되고 재열람은 무료임을 정확히 설명합니다.

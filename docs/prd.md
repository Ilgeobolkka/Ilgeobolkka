# 읽어볼까 MVP 제품 요구사항

## 1. 문서 상태

- 상태: 합의 완료
- 제품명: 읽어볼까
- 제공 형태: 반응형 웹
- 구현 상태: 구현 전
- 백엔드 기술 스택: Java 21, Spring Boot 4.1.0
- 운영 데이터베이스: Amazon RDS for MySQL 8.x
- 프런트엔드 기술 스택: Thymeleaf, Bootstrap 5.3, Vanilla JavaScript
- 애플리케이션 구성: 프런트엔드와 API를 같은 Spring Boot 실행물에서 same-origin으로 제공

## 2. 문제와 가설

책 전체를 구매하기 부담스럽거나 필요한 일부만 읽고 싶은 독자에게는 전체 도서 가격을 먼저 지불하는 방식이 진입 장벽이 될 수 있습니다.

읽어볼까는 독자가 실제로 열람 확정한 페이지만 포인트로 차감하면 더 적은 부담으로 책을 시작할 수 있고, 페이지별 차감 내역이 투명하면 이 과금 방식을 신뢰할 것이라는 가설을 검증합니다.

## 3. MVP 목표

1. 처음 읽은 페이지에만 정확히 포인트를 차감합니다.
2. 같은 페이지의 재열람에는 추가 포인트를 차감하지 않습니다.
3. 현재 포인트 잔액과 모든 포인트 내역의 합계를 일치시킵니다.
4. 잔액 부족, 중복 요청, 서버 오류에서도 잘못된 차감을 만들지 않습니다.
5. 100권 규모의 목록과 검색에서 원하는 책을 찾고 읽을 수 있게 합니다.

매출, 결제 전환율, 추천 성과는 이번 MVP의 성공 기준이 아닙니다.

## 4. 대상 독자

책 전체를 구매하기는 부담스럽지만 필요한 부분부터 읽어보고 싶은 일반 독자를 대상으로 합니다. 학생, 연구자, 특정 연령대 등으로 대상을 더 좁히지 않습니다.

## 5. 핵심 정책

### 5.1 포인트

- 서비스 내부 단위는 포인트입니다.
- 향후 PG 결제에서는 1원 = 1P로 충전합니다.
- MVP에는 PG와 실제 충전 기능이 없습니다.
- 모든 도서의 모든 페이지에 50P의 전역 고정 단가를 적용합니다.
- 책별 가격과 전체 책 가격은 존재하지 않습니다.
- 포인트에는 유효기간이 없습니다.
- 페이지 차감 취소와 환불은 지원하지 않습니다.

### 5.2 열람 확정

- 아직 열람 확정되지 않은 페이지를 열면 서버가 페이지 열림 시각을 기록합니다.
- 독자가 같은 페이지를 유지한 채 6초가 지나면 열람 확정 요청을 보낼 수 있습니다.
- 서버 기준 경과 시간이 6초 이상일 때만 요청을 승인합니다.
- 탭 전환, 창 최소화, 다른 앱 사용은 6초 경과를 취소하지 않습니다.
- 6초 전에 페이지를 넘기거나 뷰어를 종료하면 열람 확정되지 않고 포인트도 차감되지 않습니다.
- 같은 사용자·도서·페이지 조합에는 최초 한 번만 50P를 차감합니다.
- 이미 열람 확정된 페이지는 잔액과 관계없이 다시 읽을 수 있습니다.

### 5.3 차감 실패

- 새 페이지를 열기 전에 포인트가 50P 이상인지 확인합니다.
- 잔액이 부족하면 페이지를 보여주지 않고 열람을 차단합니다.
- 6초 후 차감 처리에 실패하면 해당 페이지를 열람 확정하지 않습니다.
- 실패 화면에서 뷰어를 일시 차단하고 재시도 기능을 제공합니다.
- 사용자가 모르는 시점에 나중에 자동 차감하지 않습니다.
- 같은 차감 요청을 재시도해도 중복 차감되지 않아야 합니다.

## 6. 사용자 흐름

### 6.1 계정

1. 사용자는 이메일과 비밀번호로 회원가입합니다.
2. 일반 회원가입 사용자의 초기 포인트는 0P입니다.
3. 이메일과 비밀번호로 로그인하고 로그아웃할 수 있습니다.
4. 소셜 로그인, 비밀번호 찾기, 회원 탈퇴는 제공하지 않습니다.

### 6.2 도서 탐색

1. AI가 작성한 가상 더미 도서 100권을 제목 가나다순으로 봅니다.
2. 한 페이지에 10권을 표시하고 페이지 번호로 이동합니다.
3. 하나의 검색어로 제목 또는 저자를 부분 일치 검색합니다.
4. 검색 결과도 제목 가나다순, 10권씩 표시합니다.
5. 책 상세에서 표지, 제목, 저자, 짧은 소개, 전체 페이지 수를 확인합니다.
6. 상세 화면에는 페이지 단가, 전체 책 가격, 평점, 리뷰, 판매량을 표시하지 않습니다.

### 6.3 최초 열람 동의

1. 독자가 특정 도서를 처음 읽으려 할 때 동의 화면을 표시합니다.
2. 안내 문구는 페이지당 50P가 자동 차감된다는 사실을 포함합니다.
3. 내부 판정 기준인 6초는 동의 문구에 노출하지 않습니다.
4. 동의하지 않으면 뷰어에 들어갈 수 없습니다.
5. 동의는 사용자·도서별 최초 한 번만 받습니다.

### 6.4 뷰어

1. 원본 PDF 전체가 아니라 현재 페이지 이미지만 제공합니다.
2. 이전 페이지, 다음 페이지, 페이지 번호 직접 이동을 제공합니다.
3. 앞 페이지의 열람 여부와 관계없이 어느 페이지로든 이동할 수 있습니다.
4. 사용자당 하나의 온라인 열람 세션만 허용합니다.
5. 새 뷰어가 열리면 기존 열람 세션을 종료합니다.
6. 오프라인 열람, 원본 다운로드, 인쇄를 제공하지 않습니다.
7. DRM과 화면 캡처 방지는 적용하지 않습니다.
8. 초기 화면은 페이지 너비에 맞춰 표시합니다.

### 6.5 내 서재

- 한 페이지 이상 열람 확정된 책을 자동으로 추가합니다.
- 책 제목과 마지막 열람 확정 페이지를 표시합니다.
- 다시 들어가면 마지막 열람 확정 페이지에서 시작합니다.
- 누적 사용 포인트는 내 서재에 표시하지 않습니다.
- 별도 서재 담기 기능은 없습니다.

### 6.6 포인트 내역

- 사용자는 자신의 포인트 지급과 차감 내역만 조회할 수 있습니다.
- 페이지 차감 내역에는 책 제목, 페이지 번호, 차감 포인트, 차감 시각, 차감 후 잔액을 표시합니다.
- 최신 내역부터 페이지네이션해 보여줍니다.
- 포인트 내역은 수정하거나 삭제하지 않습니다.

## 8. 초기 데이터

### 8.1 도서

- 실존 작품을 바탕으로 하지 않고 AI가 작성한 가상 더미 도서 본문, 표지, 메타데이터 100권
- 더미 도서 본문은 PDF로 만들고 각 PDF는 페이지별 이미지로 미리 변환
- 더미 도서는 MVP 시연과 검증에만 사용하며, 공개 배포 전에는 AI 생성 자산을 포함한 실제 사용 자산별 권리 상태를 다시 확인

### 8.2 사용자

| 용도 | 초기 포인트 | 추가 조건 |
| --- | ---: | --- |
| 정상 차감 검증 | 10,000P | 테스트 포인트 지급 +10,000P 내역 포함 |
| 잔액 부족 검증 | 0P | 지급 내역 없음 |

관리자 계정과 관리자 기능은 초기 데이터에 포함하지 않습니다.

## 9. MVP 제외 범위

- PG 결제, 실제 포인트 충전, 결제 취소
- 관리자 계정, 도서 운영 백오피스
- 도서 등록, 수정, 판매 중지, 재판매, 삭제
- 책별 페이지 단가, 전체 책 가격
- 무료 미리보기와 과금 제외 페이지
- 회원 탈퇴와 비밀번호 찾기
- 리뷰, 평점, 추천, 판매량
- 장르 필터, 검색 자동완성, 본문 검색, 정렬 선택
- 목차, 책갈피, 메모, 하이라이트
- 확대·축소, 글꼴, 줄간격, 다크 모드
- PDF 다운로드, 인쇄, 오프라인 읽기
- DRM과 화면 캡처 방지
- 네이티브 모바일 앱
- 환불과 과금 분쟁 처리

## 10. 고도화 후보

1. 실제 PG 결제 성공 후 포인트 자동 충전
2. 도서 등록과 판매 상태를 관리하는 별도 백오피스
3. 무료 또는 과금 제외 페이지
4. 목차와 여러 책갈피
5. 확대·축소와 모바일 뷰어 접근성 개선
6. 책별 가격 정책
7. 포인트 환불과 분쟁 처리

## 11. 성공 판정

다음 네 조건을 모두 통과하면 초기 MVP의 목표를 달성한 것으로 봅니다.

1. 처음 열람 확정된 페이지에만 정확히 50P가 차감됩니다.
2. 같은 페이지의 재열람과 중복 요청에서 추가 차감이 발생하지 않습니다.
3. 포인트 내역의 합계와 현재 잔액이 항상 일치합니다.
4. 잔액 부족 시 새로운 페이지의 열람이 차단됩니다.

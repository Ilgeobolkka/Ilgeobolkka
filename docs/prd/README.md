# 읽어볼까 PRD 색인

이 디렉터리는 제품 요구사항의 정본입니다. 서비스의 이유, 제품 정책, MVP 범위가 바뀌면 아래에서 역할에 맞는 문서 한 곳만 수정합니다.

## PRD 문서

| 문서 | 관리하는 내용 |
| --- | --- |
| [제품 개요](./product-overview.md) | 해결하려는 문제, 대상 사용자, 제품 가설, 핵심 경험 |
| [제품 정책](./product-policy.md) | 원본 PDF 페이지, 잉크, 열람·대여, 카테고리, 콘텐츠 제공 정책 |
| [MVP 목표](./mvp-goals.md) | MVP 범위, 기능 요구사항, 성공 조건, 제외 범위 |

## 구현 계약

| 문서 | 역할 | 현재 상태 |
| --- | --- | --- |
| [API 명세](../api/api-contract.md) | 클라이언트가 관찰하는 HTTP 계약 | 새 잉크·대여 정책 반영 완료, 구현 필요 |
| [데이터 모델](../data/erd.md) | 현재 목표 엔티티, 관계, 제약 | 목표 모델 작성 완료, 구현 반영 필요 |
| [테스트 전략](../test-strategy.md) | 제품 불변식과 필수 검증 시나리오 | 현재 정본 |
| [ADR 목록](../adr/README.md) | 결정의 근거, 대안, 대체 이력 | 현재 결정 반영 |

[제품 정책](./product-policy.md), [API 명세](../api/api-contract.md), [테스트 전략](../test-strategy.md)과 현재 유효한 ADR은 서로 다른 역할의 현재 정본입니다.
문서 사이에 충돌이 생기면 구현을 진행하지 않고 어느 계약을 변경할지 먼저 확인합니다.

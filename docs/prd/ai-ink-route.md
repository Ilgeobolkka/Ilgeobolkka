# AI 잉크 경로 2차 MVP

[PRD 색인](./README.md)으로 돌아갑니다. 이 문서는 기존 페이지 대여 MVP 이후 제공하는 AI 잉크 경로의
제품 범위와 정책 정본입니다. 잉크 가격·30일 대여·온라인 소장 정책은
[제품 정책](./product-policy.md)을 그대로 따릅니다.

## 목적

AI 잉크 경로는 독자가 선택한 한 권에서 독서 목적과 추가 잉크 예산에 맞는 페이지 순서를 제안합니다.
관련도가 높은 페이지만 나열하지 않고 선수 개념, 읽기 순서, 내용 중복과 개념·사례·반론·결론의 균형을
고려해 예산 안에서 이해하기 좋은 경로를 구성합니다.

핵심 메시지는 다음과 같습니다.

> 책을 전부 읽지 않아도, 필요한 지식까지 가는 길은 만들 수 있습니다.

## 2차 MVP 범위

### 포함

- 로그인한 독자가 AI 경로 지원 도서 한 권과 최대 추가 잉크를 선택합니다.
- 독서 목적을 정규화 후 Unicode code point 기준 최대 200자의 자유 입력으로 받습니다.
- 목적 관련도, 개념 포괄성, 페이지 연결성, 중복과 순서를 반영한 경로 하나를 생성합니다.
- 경로와 페이지별 예상 독서 시간, 비용 상태, 선수 개념 여부와 검수된 공개 메타데이터 기반 AI 페이지
  가이드를 제공합니다.
- 사용자가 선택한 경로를 저장하고 내 서재에서 이어 읽게 합니다.
- 같은 책에 여러 경로를 보존하되 하나만 현재 읽는 경로로 지정합니다.
- 경로 열람 완료 후 선택형 만족도 피드백을 받습니다.
- 소설을 제외한 기존 시연 도서 90권을 AI 경로 지원 콘텐츠로 재제작합니다.

### 제외

- 이해 미션과 잉크백
- 잉크 환급·대여 취소·보상을 포함하는 페이지 보험
- AI 경로와 온라인 소장 가격 비교 또는 소장 추천
- 여러 책을 가로지르는 경로
- 소설의 AI 경로
- 사용자별 독서 속도 학습
- 동시에 여러 예산 경로를 생성하는 비교 화면
- AI 답변, 페이지 원문·요약·결론 미리보기

시연 도서 90권의 재제작 계약은 [AI 경로 콘텐츠 코퍼스](../ai-route-content-corpus.md)에 정의합니다.

## 사용자와 지원 도서

- 비로그인 사용자는 도서 상세에서 기능 소개를 볼 수 있지만 경로를 생성할 수 없습니다.
- 경로 생성은 로그인 사용자만 가능하며 서버의 잉크 잔액·활성 대여·온라인 소장을 기준으로 계산합니다.
- 2차 MVP에서는 소설 10권을 제외한 90권을 지원합니다. 카테고리 이름만으로 런타임 지원 여부를
  추론하지 않습니다.
- 도서·콘텐츠 버전별 AI 경로 지원 여부를 영속화합니다. 콘텐츠 완전성, 외부 전송 권리와
  [지원 데이터 정책 프로필](../evidence/openai-data-policy/README.md)을 확인한 비소설 콘텐츠만 지원하며,
  조건을 확인하지 못한 도서는 OpenAI 호출 전에 거부합니다.
- 콘텐츠 적재·평가·일반 생성은 같은 전용 OpenAI 프로젝트를 사용합니다. 프로젝트의 월간 지출 한도와 실제
  데이터 제어가 콘텐츠의 지원 프로필과 같거나 더 엄격한지 배포 전에 확인하되 별도 런타임 승인 해시나
  주기적 원격 증명 작업은 만들지 않습니다.
- 비소설 90권은 도서별 대표 목적 1개를 같은 비웹 평가 경로로 실행해 아래 품질 기준을 통과한 뒤 지원합니다.
  평가용 별도 DB나 사용자·결제 기록을 만들지 않고, 평가 입력에 예산과 권한 시나리오를 직접 제공합니다.

## 독서 목적과 예산 입력

### 독서 목적

- 입력을 Unicode NFC로 정규화한 뒤 Java 21이 지원하는 Unicode `White_Space` 속성 문자의 연속 구간을
  ASCII 공백 `U+0020` 하나로 바꾸고 앞뒤 공백을 제거합니다. 대소문자와 공백이 아닌 문자는 바꾸지
  않습니다.
- 위 정규화 결과를 Unicode code point 기준으로 세어 빈 입력은 거부하고 최대 200자로 제한합니다.
  외부 요청과 임시·저장 경로는 모두 이 정규화 결과를 사용합니다.
- 입력은 외부 AI에 대한 명령이 아니라 독서 목적 데이터로 취급합니다.
- 정규화해 저장한 목적은 서버 템플릿의 이스케이프 출력이나 DOM `textContent`로만 표시하고 HTML 요소·
  속성·스크립트로 해석하지 않습니다.
- 질문이나 명령 형태여도 답변·요약을 생성하지 않고 페이지 경로만 반환합니다.
- OpenAI 요청의 고정 지시문과 구조화 출력 스키마는 서버가 관리하고, 정규화한 독서 목적은 별도 사용자 입력
  블록에만 넣습니다. 목적 문자열을 시스템·개발자 지시문에 이어 붙이지 않으며 목적 내용이 지시문이나 출력
  스키마를 바꿀 수 없습니다.

### 비소장 도서

- 예산은 추천 페이지 수가 아니라 새로 차감될 잉크의 상한입니다.
- 입력 범위는 `0..현재 잉크 잔액`, 기본값은 `min(10, 현재 잉크 잔액)`입니다.
- 5·10·15잉크 중 현재 잔액 이하 값과 `보유 잉크 전부`를 빠른 선택으로 제공합니다.
- 빠른 선택은 입력값만 채우며 사용자가 생성 버튼을 누르면 선택한 예산 경로 하나만 생성합니다.
- 활성 대여 페이지는 0잉크이므로 경로의 총 페이지 수가 예산보다 많을 수 있습니다.

### 소장 도서

- 잉크 입력 대신 `빠른`, `균형`, `깊이`를 선택합니다.
- 빠른 경로는 최대 5페이지, 균형 경로는 최대 10페이지, 깊이 경로는 최대 15페이지입니다.
- 관련 페이지가 부족하면 상한보다 적게 추천합니다. 모든 페이지의 추가 비용은 0잉크입니다.

## 경로 생성 정책

- 입력 예산은 목표 사용량이 아니라 상한입니다. 관련 페이지가 부족하면 예산을 채우지 않습니다.
- 목적과 충분히 관련된 페이지가 없으면 `NO_RELEVANT_PAGES` 사유로 경로를 만들지 않고 그 사실을
  안내합니다.
- 관련 페이지는 있지만 현재 열람 권한과 선택한 추가 잉크 예산으로 유효한 경로를 만들 수 없으면, 유효한
  경로를 만들기 위한 최소 추가 잉크를 `INSUFFICIENT_BUDGET` 사유와 함께 안내합니다. 0잉크뿐 아니라 선택
  예산이 이 최소값보다 작은 모든 비소장 요청에 적용합니다.
- 후보 선택은 목적 관련도와 개념 포괄성, 선수 개념, 읽기 순서, 페이지 연결성, 중복, 사례·반론·결론의
  균형을 고려합니다.
- 이미지 페이지도 후보에 포함합니다. 화면용 이미지와 별도로 외부에 노출하지 않는 AI 분석 텍스트를
  사용합니다.
- 정규화한 독서 목적은 콘텐츠 적재 때 사용한 것과 같은 임베딩 모델·차원으로 요청 시 변환하고, 저장된
  페이지 임베딩과 비교해 후보를 선택합니다.
- 보정되지 않은 관련도·포괄성 백분율은 사용자에게 표시하지 않습니다.
- 목표 응답 시간은 10초 이내이며 20초를 넘으면 실패 처리합니다. 스트리밍과 부분 경로는 제공하지
  않습니다. 한 번의 검증 재시도를 포함한 전체 요청 제한이 20초입니다.
- AI 출력은 페이지 번호, 정성적 관련도, 선수 개념 여부와 역할 열거값으로 제한합니다. 서버는 검색 후보와
  같은 도서·콘텐츠 버전의 검증된 선수 그래프에서 계산한 전이적 선수 페이지 폐쇄의 합집합을 요청별 허용
  페이지 집합으로 고정합니다. 모든 출력 페이지가 이 집합에 속하는지 먼저 검증하고, 같은 책에 존재해도 검색
  후보와 선수 폐쇄에 없는 페이지는 전체 응답과 함께 거부합니다. 이어서 도서·페이지 번호, 중복, 순서, 예산과
  지원 상태를 검증하고 스키마 밖 자유 문구를 거부합니다.
- 외부 AI는 사용자별 잉크·대여·소장 상태를 받지 않고 목적 관련도, 선수 관계와 읽기 순서를 반영한 후보
  경로를 만듭니다. 서버는 검수된 선수 관계를 기준으로 후보 경로를 순회합니다. 비소장 도서는 선수 페이지가
  모두 포함되고 현재 권한으로 계산한 누적 추가 비용이 예산 안인 페이지만 최종 경로에 포함하며, 소장 도서는
  같은 선수 조건에서 선택한 깊이의 페이지 수 상한까지만 포함합니다. 비용 때문에 선수를 제외하면 그 선수에
  의존하는 페이지도 제외하며, 상한을 채우기 위해 무관한 페이지를 추가하지 않습니다.
- 콘텐츠 적재는 도서·콘텐츠 버전 안의 선수 관계를 `선수 페이지 -> 의존 페이지` 방향 그래프로 검사합니다.
  존재하지 않는 페이지·다른 도서나 콘텐츠 버전 참조, 자기 참조 또는 방향 순환이 하나라도 있으면 해당
  콘텐츠 버전을 지원하지 않고 외부 호출과 DB 변경 전에 전체 적재를 실패시킵니다.
- 검증 실패 시 남은 전체 제한 시간 안에서 한 번 재시도하고 다시 실패하면 임시 결과도 만들지 않습니다.
- 외부 API·서버 오류에는 경로와 잉크 상태를 변경하지 않고 재시도를 제공합니다.

### 후보·prompt 정책 v1

- 후보 정책 `air-candidate-v1`은 같은 도서·콘텐츠 버전과 같은 임베딩 모델·차원의 모든 지원 페이지를
  애플리케이션 메모리에서 exact cosine으로 비교합니다. vector가 유한 실수가 아니거나 zero norm이면 관련도 0으로 대체하지 않고 실패합니다.
- cosine similarity가 `0.30` 이상인 페이지만 남기고 반올림하지 않은 similarity 내림차순, `pageNumber` 오름차순으로 정렬한
  최초 30개를 후보로 고정합니다. 정확히 `0.30`인 페이지는 포함하고 similarity가 같을 때만 `pageNumber`를 비교합니다.
- `TEXT`와 `IMAGE` 페이지에 같은 기준을 적용합니다. 이미지 페이지도 검수된 분석 text와 같은 모델·차원의 vector가 있어야 합니다.
- 후보별 전이적 선수 페이지 폐쇄는 30개를 고른 뒤 같은 도서·콘텐츠 버전의 검증된 그래프에서 추가합니다.
  선수 페이지에는 similarity `0.30`과 30개 상한을 다시 적용하지 않습니다.
  similarity 후보가 한 개도 없으면 Responses를 호출하지 않고 `NO_RELEVANT_PAGES`를 반환합니다.
- prompt는 `src/main/resources/openai/ai-route/route-generation-prompt-v1.md`, strict JSON Schema는
  `src/main/resources/openai/ai-route/route-proposal-v1.schema.json`에 둡니다. 환경 변수·DB·원격 prompt로 대체하지 않습니다.
- `promptVersion`은 `air-route-prompt-v1:sha256:<64자리 소문자 hex>`, `schemaVersion`은
  `air-route-schema-v1:sha256:<64자리 소문자 hex>`입니다. `<64자리 소문자 hex>`는 각 classpath resource의
  UTF-8 원본 byte 전체를 별도 정규화 없이 SHA-256으로 계산합니다.
- Responses의 `text.format.type`은 `json_schema`, `name`은 `ai_route_proposal_v1`이고 `strict=true`입니다.
  schema의 최상위 객체는 `items` 배열 하나만 허용하며 배열은 1~72개입니다. 이 상한은 [AI 경로 콘텐츠 코퍼스](../ai-route-content-corpus.md#도서-제작-기준)의 지원 도서별 최대 페이지 수와 같으며,
  코퍼스의 최대 페이지 수를 변경할 때 schema 계약과 version도 함께 갱신합니다. 각 item은 `pageNumber` 양의 정수, `HIGH|MEDIUM` relevance,
  prerequisite boolean, `PREREQUISITE|CORE|EXAMPLE|COUNTERPOINT|CONCLUSION` role을 모두 필수로 가집니다.
  최상위와 item 객체는 `additionalProperties=false`이며 중복·실재·허용 집합·순서는 서버가 다시 검증합니다.
- F05의 malformed model output 또는 G03의 semantic invalid output만 최초 20초 제한의 남은 시간 안에서 즉시 한 번 재시도합니다.
  재시도는 정규화 목적, 확정 후보의 값과 순서, 선수 그래프 snapshot, model,
  `candidatePolicyVersion`, `promptVersion`, `schemaVersion`을 그대로 사용한 새 Responses 요청이며
  `previous_response_id`와 최초 응답 원문을 사용하지 않습니다.
- refusal, incomplete, HTTP·timeout·공급자 한도 오류는 검증 재시도 대상이 아닙니다.
  두 번째 invalid output은 부분 결과 없이 전체 실패하고 외부 API·서버 오류의 사용자 재시도는 기존 멱등·실패 계약을 따릅니다.
- 후보 임계값 변경을 검토할 때는 같은 content·evaluation revision과
  임베딩 모델, cosine 계산, 30개 상한·동점 규칙을 고정하고 `0.35`, `0.40`, `0.45`를 비교합니다.
  선수 페이지 폐쇄를 추가하기 전 후보의 `primaryConcepts[]`와 평가 정답의 `requiredConcepts[]`를 대소문자를 구분한 문자열 완전 일치로 비교합니다.
  90건의 전체 필수 개념 수를 분모로, 하나 이상의 후보에 정확히 일치한 필수 개념 수를 분자로 사용하며
  trim·Unicode 정규화·부분 문자열·의미 유사도 비교는 적용하지 않습니다.
  같은 도서의 전체 페이지 `primaryConcepts[]`에 정확히 일치하지 않는 필수 개념이 하나라도 있으면 평가 데이터 불일치로 임계값 비교를 실패합니다.
  두 배열은 같은 저장소에서 관리하는 검수 데이터이므로, 정규화로 표기 불일치를 숨기지 않고 평가 데이터 오류로 드러내기 위해 완전 일치로 비교합니다.
  재현율 95% 이상을 유지하는 가장 높은 임계값만 새 후보 정책 version의 검토값으로 선택합니다.
  세 값이 모두 미달하면 `0.30`을 유지하고 중간값을 임의로 채택하지 않습니다.
- v1의 후보 값, resource 내용 또는 schema 계약을 바꾸면 기존 식별자를 재사용하지 않고 v2로 올린 뒤 대표 목적 90개를 전체 재평가합니다.
  평가 정답을 후보·prompt 입력에 넣거나, 재시도에서 후보·정책을 바꾸거나, 버전이 다른 평가 결과를 재사용하지 않습니다.

## AI 페이지 가이드

AI 페이지 가이드는 페이지를 열기 전에 표시하는 짧은 선택 이유입니다. 원문이나 요약을 미리 제공하지
않으면서 독자가 잉크 사용 여부를 판단하게 합니다.

각 경로 항목은 다음 정보를 제공합니다.

- 원본 PDF 페이지 번호
- 목적 관련도 `높음` 또는 `보통`
- 선수 개념 필요 여부
- 예상 독서 시간
- 경로 안에서의 역할: 핵심 개념, 선수 개념, 사례, 반론 또는 결론
- 추가 비용 상태: `1잉크`, `활성 대여`, `온라인 소장`
- 한두 문장의 AI 페이지 가이드

AI 페이지 가이드는 사람이 미리 검수한 페이지별 공개 가이드 주제와 AI가 선택한 경로 역할을 서버의 고정
템플릿에 넣어 만듭니다. 외부 AI가 만든 자유 문구, 비공개 분석 텍스트와 페이지 본문은 가이드 문구의 직접
입력으로 사용하지 않습니다. 공개 가이드 주제에는 페이지의 결론·수치·사례 결과·원문 문구를 넣지 않습니다.

## 저장과 생명주기

임시 생성 결과의 조회·저장과 저장 경로의 목록·상세·현재 경로 지정·삭제·진행 기록·피드백은 모두 로그인한
소유자에게만 허용합니다. 서버는 모든 작업에서 인증 계정과 저장된 소유자를 함께 조회하며, 목록은 인증
계정의 경로만 검색합니다. 다른 독자의 식별자를 받은 경우 존재 여부를 구분하지 않고 상태와 콘텐츠를
반환하거나 변경하지 않습니다.

1. 클라이언트는 생성 요청마다 UUID 멱등 키를 만듭니다. 서버는 계정·키를 유일하게 저장하고 도서·콘텐츠
   버전·정규화한 목적·예산 또는 깊이가 같은 재시도에는 15분 동안 최초 상태와 결과를 반환합니다. 같은 키의
   입력이 다르면 거부합니다.
2. 정상 경로의 소유자·입력과 페이지 결과는 생성 완료부터 15분 동안만 임시 보관하고, 클라이언트에는
   불투명한 `generationId`와 표시용 결과만 제공합니다. 임시 결과는 페이지 접근권한이나 잉크 차감을 만들지
   않습니다. 관련 경로가 없으면 같은 기간 동안 `noRouteReason`과 `minimumRequiredInk`만 결과로
   보관합니다.
3. 독자가 `이 경로로 읽기`를 선택하면 클라이언트는 `generationId`만 보냅니다. 서버는 임시 결과의
   소유자·도서·콘텐츠 버전·만료와 페이지 구성을 다시 검증하며 클라이언트가 보낸 페이지·순서·가이드
   문구는 받지 않습니다. 현재 대여·소장 권한으로 다시 계산한 추가 잉크가 임시 결과의 생성 예산을 넘으면
   저장하지 않습니다. 이때 임시 결과는 소비하지 않고 원래 만료 시각까지 남으며, 최초 거부를 기록해 이후
   저장을 막는 상태도 두지 않습니다. 독자에게는 권한 상태가 바뀌었음을 안내해 경로를 다시 생성하게 합니다.
4. 15분이 지나면 임시 목적·결과와 멱등 상태를 함께 삭제합니다. 이후 서버는 해당 UUID의 과거 사용 여부를
   판별하거나 결과를 재현하지 않으며 같은 키가 다시 오면 새 요청으로 취급합니다. 클라이언트는 다시 생성할
   때 새 멱등 키를 사용합니다. 만료되거나 다른 독자에게 속한 `generationId`는 저장할 수 없습니다.
5. 검증을 통과해 독자가 선택한 경로만 기한 없는 저장 경로로 전환합니다. 서버는 `generationId`를
   원자적으로 한 번만 소비해 임시 결과의 정규화한 독서 목적과 페이지 구성을 저장 경로로 옮기고 임시
   결과를 제거합니다. 원래 만료 시각까지는 멱등 키·요청 지문·저장 경로 식별자만 남겨 생성 요청 재시도에도
   저장된 경로를 반환합니다. 같은 `generationId`의 저장 재시도에는 저장 경로가 있으면 처음 만든 경로를
   반환하며 중복 경로를 만들거나 현재 경로 지정을 다시 바꾸지 않습니다. 경로가 먼저 삭제됐다면 최소 멱등
   상태를 소비 완료로 바꾸고 재시도로 되살리지 않습니다.
6. 같은 책에 목적이 다른 경로를 여러 개 보존하되 하나만 현재 경로로 지정합니다. `generationId`를 처음
   소비해 저장한 새 경로는 같은 트랜잭션에서 기존 현재 경로를 해제하고 현재 경로가 됩니다. 이후 같은
   `generationId`의 재시도는 기존 경로만 반환하며, 그 사이 독자가 선택한 다른 현재 경로를 바꾸지 않습니다.
   같은 독자·도서의 저장, 현재 경로 변경과 현재 경로 삭제는 직렬화하며 어떤 완료 시점에도 현재 경로는 최대
   하나입니다.
7. 경로의 페이지와 추천 순서는 저장 뒤 자동 변경하지 않습니다.
8. 활성 대여·소장 상태에 맞춰 예상 추가 잉크만 조회 시점마다 다시 계산합니다.
9. 독자가 명시적으로 다시 만들기를 선택한 경우에만 새 경로를 생성합니다.
10. 저장한 경로는 독자가 삭제할 수 있습니다. 삭제하면 목적, 경로 항목, 진행 상태와 피드백을 지우되
   페이지 대여와 잉크 내역은 보존하고 환불하지 않습니다. 현재 경로를 삭제하고 같은 책의 다른 경로가
   남으면 가장 최근에 저장한 경로를 현재 경로로 지정하며, 남은 경로가 없으면 현재 경로도 없습니다.

## 열람과 과금

- 경로 생성·미리보기·저장만으로 페이지를 열거나 잉크를 차감하지 않습니다.
- 경로 안의 권한 없는 페이지를 독자가 직접 열 때만 기존 정책대로 1잉크를 차감하고 30일 대여를
  시작합니다.
- 활성 대여와 온라인 소장 페이지의 추가 비용은 0잉크입니다.
- 버튼에 `다음 경로 페이지 · 1잉크로 열기`, `대여 중`, `소장 도서`처럼 현재 비용 상태를 표시합니다.
- 경로 읽기 모드의 이전·다음은 원본의 연속 페이지가 아니라 추천 경로 순서를 따릅니다.
- 원본 순서 이동은 별도 조작으로 제공하고 경로 밖 권한 없는 페이지의 1잉크 비용을 표시합니다.
- 추천 순서는 강제하지 않습니다. 선수 개념 페이지를 건너뛸 때 안내한 뒤 독자가 계속 열 수 있습니다.
- 잔액 부족 시 페이지 콘텐츠를 제공하지 않고 기존 이용권 구매 흐름으로 안내합니다.
- 경로 저장 뒤 대여 만료로 예상 비용이 늘거나 잔액을 넘더라도 페이지를 자동 교체하지 않습니다.

## 진행과 피드백

- 경로 항목은 경로 읽기 화면에서 해당 페이지 콘텐츠를 성공적으로 제공한 뒤 열람 완료로 표시합니다.
- 활성 대여·소장 페이지도 경로 선택만으로 완료 처리하지 않습니다.
- 체류 시간·스크롤·페이지 이동만으로 완독이나 이해를 추정하지 않습니다.
- 모든 경로 항목을 한 번 이상 열면 `경로 열람 완료`로 표시합니다.
- 완료 후 `도움이 됐어요`, `보통이에요`, `도움이 안 됐어요` 중 하나를 선택적으로 받습니다.
- 피드백은 잉크 보상과 연결하지 않습니다.

## 예상 독서 시간

- 사용자별 속도를 학습하지 않고 페이지 콘텐츠 길이와 형식을 기준으로 근삿값을 계산합니다.
- 텍스트 페이지는 글자 수, 이미지·표·수식 페이지는 분석된 복잡도 구간을 사용합니다.
- 페이지별 최소 예상 시간은 1분이며 경로 전체 시간은 페이지 예상 시간의 합입니다.
- 화면에는 `약 24분`처럼 근삿값임을 표시합니다.

## 생성 횟수와 실패

- 경로 생성은 잉크를 사용하지 않으며 OpenAI 호출을 시작한 새 요청은 성공·실패와 관계없이 계정당 UTC 날짜
  기준 최대 10회입니다.
- 생성 횟수는 매일 `00:00 UTC`에 초기화합니다.
- 서버는 첫 OpenAI 호출 직전에 계정·UTC 날짜별 횟수를 MySQL에서 원자적으로 증가시킵니다. 진행 중 요청도
  포함하므로 동시 요청으로 한도를 넘을 수 없습니다. 입력 검증에서 거부된 요청은 횟수에 포함하지 않습니다.
- 15분 안의 같은 멱등 키 재시도는 저장된 상태·결과 또는 최초 오류를 반환하고 횟수를 추가하지 않습니다.
  보관 상태가 만료된 뒤에는 같은 키와 새 키 모두 새 요청 한 건으로 계산하되 클라이언트는 새 키를 사용합니다.
- 남은 생성 횟수를 화면에 표시합니다.
- 생성 횟수를 잉크로 구매하는 기능은 제공하지 않습니다.
- 한도 초과는 `429 AI_ROUTE_DAILY_LIMIT_EXCEEDED`와 다음 UTC 날짜까지의 `Retry-After`로 응답합니다.
- OpenAI의 지출·사용량 한도 또는 크레딧 소진 오류는 공급자 조직·프로젝트·비용 정보를 노출하지 않는
  `503 AI_ROUTE_PROVIDER_BUDGET_UNAVAILABLE`로 변환합니다. 도서 탐색과 기존 뷰어는 계속 제공합니다.

## 개인정보와 콘텐츠 보호

- 콘텐츠 적재의 Embeddings API에는 외부 전송 권리와 데이터 보관 조건을 확인한 페이지 분석 텍스트만
  전달합니다. 런타임 Embeddings API에는 정규화한 독서 목적만 전달하며 두 입력을 섞지 않습니다.
- Responses API에는 독서 목적과 경로 생성에 필요한 후보 페이지 분석 텍스트만 전달합니다. 추가 잉크 예산,
  잉크 잔액과 페이지별 대여·소장 상태는 서버에서만 사용합니다.
- 이메일, 잉크 잔액, 결제 정보, 대여·소장 내역과 뷰어 세션 ID는 전달하지 않습니다.
- 경로 구성은 OpenAI Responses API에 `store=false`로 요청하고 Conversations·Background mode·호스팅
  도구는 사용하지 않습니다. `store=false`는 응답 애플리케이션 상태 저장만 끄며 악용 모니터링과 프롬프트
  캐시 조건을 바꾸지 않습니다. 페이지 임베딩은 콘텐츠 적재 때 사전 생성하고 독서 목적 임베딩은 경로 생성
  요청마다 같은 모델·차원으로 생성합니다.
- 2차 MVP 화면에는 목적과 후보 분석 텍스트가 OpenAI로 전송되고, 기본 악용 모니터링에서 고객 콘텐츠가
  원칙적으로 최대 30일 보관되지만 법률·안전상 필요하면 더 길어질 수 있으며 비-ZDR GPT-5.6 요청에서는
  원문이 아닌 입력 파생 key/value tensor가 최대 24시간 남을 수 있음을 안내합니다. 근거와 확인일은
  [OpenAI 데이터 정책 프로필](../evidence/openai-data-policy/README.md)을 따릅니다.
- 공개 AI 시연 콘텐츠는 위 보관 조건을 허용합니다. 실제 출판 콘텐츠는 외부 전송 권리와 적용할 OpenAI
  데이터 제어를 함께 확인한 경우에만 지원합니다.
- 콘텐츠 적재·평가·일반 생성은 같은 전용 OpenAI 프로젝트의 서비스 계정 API 키를 사용합니다. 출시 직전과
  모델·엔드포인트·프로젝트 데이터 제어 변경 시 위 근거를 다시 확인하고, 조건이 달라졌으면 사용자 안내와
  콘텐츠 지원 조건을 먼저 갱신합니다.
- 독서 목적과 외부 AI 요청·응답 원문은 애플리케이션 로그에 남기지 않습니다.
- 분석 텍스트, 임베딩과 원본 콘텐츠는 API 응답에 포함하지 않습니다.

## 품질과 출시 기준

도서별 대표 목적과 정답 데이터는 [AI 경로 콘텐츠 코퍼스](../ai-route-content-corpus.md)를 따릅니다. 비소설
90권에 목적 1개씩을 두고 비소장 예산 0·5·10·15와 소장 빠른·균형·깊이 시나리오가 모두 포함되게 배정합니다.
정답은 런타임 추천 입력에 사용하지 않으며 정확한 페이지 일치보다 필수 개념, 선수 관계, 균형, 중복과 예산
준수를 평가합니다. 이 데이터는 독립적인 통계 추정치가 아니라 MVP 회귀 기준입니다. 아래 수치가 2차 MVP
출시 판정의 단일 정본이며 다른 문서는 계산·검증 방법만 정의합니다.

- 잉크 예산 초과, 선차감과 무단 본문 노출: 0건
- 전체 필수 개념 포함률: 80% 이상
- 무관하거나 의미가 중복된 추천 페이지: 20% 이하
- 필수 선수 관계 위반률: 5% 이하
- 필수 개념 수, 전체 추천 페이지 수와 필수 선수 관계 수는 각 비율의 분모로서 모두 1 이상이어야 합니다.
  하나라도 0이면 품질 수치를 계산하지 않고 평가 실패로 처리해 지원 활성화를 중단합니다.
- 사람 검수에서 목적 달성에 유용하다고 평가한 대표 경로: 80% 이상
- 90개 모두 외부 API·서버·시간 제한 실패 없이 최종 경로를 반환
- 90개 서버 측 전체 처리 시간의 95백분위인 오름차순 86번째 값: 10초 이하, 20초 초과 0건
- 평가 결과에 콘텐츠 manifest와 평가 데이터의 Git 리비전, 임베딩·경로 모델, 후보 정책·prompt·schema
  버전을 기록합니다. 콘텐츠 manifest·평가 데이터·임베딩 모델·경로 모델·후보 정책·prompt·schema 중
  하나라도 바뀌면 기존 평가 결과를 재사용하지 않고 90개 전체를 다시 평가합니다.
- 사용자 완료 피드백의 `도움이 됐어요`: 70% 이상을 출시 차단이 아닌 운영 관찰 지표로 측정

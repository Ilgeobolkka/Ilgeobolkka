# AI 잉크 경로 2차 MVP

[PRD 색인](./README.md)으로 돌아갑니다. 이 문서는 기존 페이지 대여 MVP 이후 제공하는 AI 잉크 경로의
제품 범위와 정책 정본입니다. 잉크 가격·30일 대여·온라인 소장 정책은
[제품 정책](./product-policy.md)을 그대로 따릅니다.

## 목적

AI 잉크 경로는 독자가 선택한 한 권에서 독서 목적과 추가 잉크 예산에 맞는 페이지 순서를 제안합니다.
관련도가 높은 페이지만 나열하지 않고 선수 개념, 읽기 순서, 내용 중복과 개념·사례·반론·결론의 균형을
고려해 예산 안에서 이해하기 좋은 경로를 구성합니다.

핵심 메시지는 다음과 같습니다.

> 책을 전부 읽지 않아도, 필요한 지식까지 가는 길은 만들 수 있습니다.

## 2차 MVP 범위

### 포함

- 로그인한 독자가 AI 경로 지원 도서 한 권과 최대 추가 잉크를 선택합니다.
- 독서 목적을 정규화 후 Unicode code point 기준 최대 200자의 자유 입력으로 받습니다.
- 목적 관련도, 개념 포괄성, 페이지 연결성, 중복과 순서를 반영한 경로 하나를 생성합니다.
- 경로와 페이지별 예상 독서 시간, 비용 상태, 선수 개념 여부와 검수된 공개 메타데이터 기반 AI 페이지
  가이드를 제공합니다.
- 사용자가 선택한 경로를 저장하고 내 서재에서 이어 읽게 합니다.
- 같은 책에 여러 경로를 보존하되 하나만 현재 읽는 경로로 지정합니다.
- 경로 열람 완료 후 선택형 만족도 피드백을 받습니다.
- 소설을 제외한 기존 시연 도서 90권을 AI 경로 지원 콘텐츠로 재제작합니다.

### 제외

- 이해 미션과 잉크백
- 잉크 환급·대여 취소·보상을 포함하는 페이지 보험
- AI 경로와 온라인 소장 가격 비교 또는 소장 추천
- 여러 책을 가로지르는 경로
- 소설의 AI 경로
- 사용자별 독서 속도 학습
- 동시에 여러 예산 경로를 생성하는 비교 화면
- AI 답변, 페이지 원문·요약·결론 미리보기

시연 도서 90권의 재제작 계약은 [AI 경로 콘텐츠 코퍼스](../ai-route-content-corpus.md)에 정의합니다.

## 사용자와 지원 도서

- 비로그인 사용자는 도서 상세에서 기능 소개를 볼 수 있지만 경로를 생성할 수 없습니다.
- 경로 생성은 로그인 사용자만 가능하며 서버의 잉크 잔액·활성 대여·온라인 소장을 기준으로 계산합니다.
- 2차 MVP에서는 소설 10권을 제외한 90권을 지원합니다. 카테고리 이름만으로 런타임 지원 여부를
  추론하지 않습니다.
- 외부 전송 권리나 적용할 데이터 보관 조건을 확인하지 못한 도서는 `EVALUATABLE`이나 `PUBLIC`로
  전환하지 않으며, 생성 요청이 들어와도 OpenAI 호출 전에 거부합니다.
- 도서·콘텐츠 버전별 AI 경로 상태를 `UNSUPPORTED`, `EVALUATABLE`, `PUBLIC`으로 영속화합니다. 콘텐츠
  완전성, 외부 전송 권리와 데이터 보관 조건을 통과한 비소설 콘텐츠만 `EVALUATABLE`로 표시하며 일반
  사용자의 생성 요청은 `PUBLIC`에만 허용합니다.
- 콘텐츠 적재·평가·일반 생성은 원격 상태를 확인한 같은 전용 OpenAI 프로젝트를 사용합니다. 프로젝트 ID,
  실효 데이터 제어와 그 제어에서 파생한 프롬프트 캐시 허용 정책의 `openAiPolicyHash`가 콘텐츠 요구
  조건과 다르거나 1시간 원격 증명이 만료됐으면 상태와 관계없이 OpenAI 호출 전에 거부합니다. 공식 관리
  API로 읽을 수 없는 학습용 데이터 공유 비활성 여부는 조직 관리자가 적재·평가·공개 서버 시작과 키 교체
  전에 별도 `dataSharingDisabledEvidence`로 확인하며, 증거가 없거나 대상 프로젝트가 다르면 해당 단계를
  중단합니다.
- 같은 전용 OpenAI 프로젝트에는 월간 hard spend limit을 활성화합니다. 조직 관리자는 프로젝트 ID, 월간
  한도, hard limit 활성 여부, 확인 시각과 확인자를 `openAiHardSpendLimitEvidence`로 남기며 콘텐츠 적재·
  평가·공개 서버 시작과 키 교체 전에 대상 프로젝트가 다르거나 증거가 없거나 hard limit이 꺼져 있으면 해당
  단계를 중단합니다. 공급자 한도는 적용 전파 중 소액을 초과할 수 있으므로 애플리케이션 전역 외부 실행
  한도를 별도로 적용합니다. hard spend limit 변경 전에는 AI 경로를 비활성화하고 새 활성 증거를 확인한 뒤에만
  다시 활성화합니다.
- 같은 프로젝트에서 데이터 제어·캐시 정책만 바뀌면 현재 정책 해시와 공개 승인값의 불일치로 일반 생성을
  먼저 실패 폐쇄합니다. 새 원격 증명과 데이터 공유 비활성 확인이 있고 모든 `PUBLIC` 콘텐츠가 새 정책을
  허용하며 `generationConfigHash`가 그대로일 때만 비웹 정책 재승인 작업이 승인 `openAiPolicyHash`를 한
  트랜잭션에서 교체합니다. 프로젝트 ID가 바뀌면 새 프로젝트에서 콘텐츠 적재와 품질 평가를 다시 통과해야
  합니다.
- 공개 지원 전 품질 평가는 아직 HTTP 트래픽을 받지 않는 공개 후보 시연 DB를 트랜잭션 일관 스냅샷으로
  복제한 접근 제한 평가 DB에서 비웹 `ai-route-evaluation` 배치가 운영 생성 서비스와 같은 후보 검색·경로
  구성·서버 검증을 호출해 수행합니다. 평가는 공개 서버에 배포할 패키징 JAR로 실행하고 JAR SHA-256을
  `generationConfigHash`에 포함합니다. 공개 후보 DB와 평가 DB는 같은 MySQL 버전·스키마 마이그레이션을
  사용하고 콘텐츠 manifest SHA, 콘텐츠 배치 ID, 도서·페이지·분석 텍스트·분석 메타데이터·임베딩·선수
  그래프의 정규화 해시와 마이그레이션 체크섬으로 만든 `evaluationSourceHash`가 일치해야 합니다. 배치는
  공개 지원 상태 검사만
  우회하고 콘텐츠 완전성, 권리·보관 조건, 계정·애플리케이션 전역 생성 횟수, 외부 전송과 출력 검증은
  우회하지 않습니다. 평가용 계정·잉크·원장·대여·소장·결제와 런타임 상태는 평가 DB에만 만들며
  애플리케이션 삭제 경로로 개별 삭제하지
  않습니다. 사람 검수에 필요한 임시 산출물의 보관·접근·삭제는
  [AI 경로 콘텐츠 코퍼스](../ai-route-content-corpus.md#잠금-holdout-품질-평가-조건)를 따릅니다. 개발·회귀
  목적과 겹치지 않고 `holdoutDatasetVersion`·`holdoutDatasetHash`·`generationArtifactHash`·
  `generationConfigHash`·`evaluationSourceHash`·`evaluationGitRevision` 사전 봉인 전까지 개발자가 볼 수 없는
  잠금 holdout 270개만 출시 지표에 사용합니다.
  품질 게이트 통과와 최종 사람 판정과 자동 지표를 재검증할 수 있는 정제 평가 증거에 평가 코드·사람 판정
  기준·PRD 품질 임계값의 `evaluationGitRevision`, `holdoutDatasetVersion`과 `holdoutDatasetHash`를 포함해
  접근 제한 저장소에 보존하고 읽기 검증을 마친 뒤 임시 검수 산출물을 삭제하고 평가 DB 전체를 폐기해 둘의
  부재를 검증합니다. 공개 전환 시 평가 계약 경로의 현재 파일 내용이 해당 Git 리비전과 같고 잠금 holdout
  해시, 평가·배포 JAR 바이트, 공개 후보 DB의 `evaluationSourceHash`, `generationConfigHash`와
  `openAiPolicyHash`가 평가 증거와 여전히 같은지 다시 확인한 뒤 같은 후보 DB 트랜잭션에서 평가 Git 리비전,
  holdout 버전·해시와 두 승인 해시를 저장하고 비소설 90권을 `PUBLIC`로 일괄 전환합니다.
  평가 데이터가 들어간 DB는 공개하지 않고 전환한 공개 후보 DB와 평가한 JAR만 시연 서버에 연결합니다.

## 독서 목적과 예산 입력

### 독서 목적

- 입력을 Unicode NFC로 정규화한 뒤 Java 21이 지원하는 Unicode `White_Space` 속성 문자의 연속 구간을
  ASCII 공백 `U+0020` 하나로 바꾸고 앞뒤 공백을 제거합니다. 대소문자와 공백이 아닌 문자는 바꾸지
  않습니다.
- 위 정규화 결과를 Unicode code point 기준으로 세어 빈 입력은 거부하고 최대 200자로 제한합니다.
  외부 요청, 임시·저장 경로와 멱등 입력 HMAC은 모두 이 정규화 결과의 UTF-8 바이트를 사용합니다.
- 입력은 외부 AI에 대한 명령이 아니라 독서 목적 데이터로 취급합니다.
- 정규화해 저장한 목적은 서버 템플릿의 이스케이프 출력이나 DOM `textContent`로만 표시하고 HTML 요소·
  속성·스크립트로 해석하지 않습니다.
- 질문이나 명령 형태여도 답변·요약을 생성하지 않고 페이지 경로만 반환합니다.
- OpenAI 요청의 고정 지시문과 구조화 출력 스키마는 서버가 관리하고, 정규화한 독서 목적은 별도 사용자 입력
  블록에만 넣습니다. 목적 문자열을 시스템·개발자 지시문에 이어 붙이지 않으며 목적 내용이 지시문이나 출력
  스키마를 바꿀 수 없습니다.

### 비소장 도서

- 예산은 추천 페이지 수가 아니라 새로 차감될 잉크의 상한입니다.
- 입력 범위는 `0..현재 잉크 잔액`, 기본값은 `min(10, 현재 잉크 잔액)`입니다.
- 5·10·15잉크 중 현재 잔액 이하 값과 `보유 잉크 전부`를 빠른 선택으로 제공합니다.
- 빠른 선택은 입력값만 채우며 사용자가 생성 버튼을 누르면 선택한 예산 경로 하나만 생성합니다.
- 활성 대여 페이지는 0잉크이므로 경로의 총 페이지 수가 예산보다 많을 수 있습니다.

### 소장 도서

- 잉크 입력 대신 `빠른`, `균형`, `깊이`를 선택합니다.
- 빠른 경로는 최대 5페이지, 균형 경로는 최대 10페이지, 깊이 경로는 최대 15페이지입니다.
- 관련 페이지가 부족하면 상한보다 적게 추천합니다. 모든 페이지의 추가 비용은 0잉크입니다.

## 경로 생성 정책

- 입력 예산은 목표 사용량이 아니라 상한입니다. 관련 페이지가 부족하면 예산을 채우지 않습니다.
- 목적과 충분히 관련된 페이지가 없으면 경로를 만들지 않고 그 사실을 안내합니다.
- 관련 페이지는 있지만 현재 열람 권한과 선택한 추가 잉크 예산으로 유효한 경로를 만들 수 없으면, 유효한
  경로를 만들기 위한 최소 추가 잉크를 안내합니다. 0잉크뿐 아니라 선택 예산이 이 최소값보다 작은 모든
  비소장 요청에 적용합니다.
- 후보 선택은 목적 관련도와 개념 포괄성, 선수 개념, 읽기 순서, 페이지 연결성, 중복, 사례·반론·결론의
  균형을 고려합니다.
- 이미지 페이지도 후보에 포함합니다. 화면용 이미지와 별도로 외부에 노출하지 않는 AI 분석 텍스트를
  사용합니다.
- 정규화한 독서 목적은 콘텐츠 적재 때 사용한 것과 같은 임베딩 모델·차원으로 요청 시 변환하고, 저장된
  페이지 임베딩과 비교해 후보를 선택합니다.
- 보정되지 않은 관련도·포괄성 백분율은 사용자에게 표시하지 않습니다.
- 목표 응답 시간은 10초 이내이며 20초를 넘으면 실패 처리합니다. 스트리밍과 부분 경로는 제공하지
  않습니다. 한 번의 검증 재시도를 포함한 전체 요청 제한이 20초입니다.
- 경로 구성 Responses API에는 `service_tier=default`를 명시하며 `auto` 또는 생략값을 허용하지 않습니다.
  요청 티어를 `generationConfigHash`와 `latencyProfile`에 포함하고 응답의 실효 `service_tier`가
  `default`인지 검증합니다. 다르면 모델 출력 전체를 거부하고 임시 결과를 만들지 않습니다.
- AI 출력은 페이지 번호, 정성적 관련도, 선수 개념 여부와 역할 열거값으로 제한합니다. 서버는 검색 후보와
  같은 도서·콘텐츠 버전의 검증된 선수 그래프에서 계산한 전이적 선수 페이지 폐쇄의 합집합을 요청별 허용
  페이지 집합으로 고정합니다. 모든 출력 페이지가 이 집합에 속하는지 먼저 검증하고, 같은 책에 존재해도 검색
  후보와 선수 폐쇄에 없는 페이지는 전체 응답과 함께 거부합니다. 이어서 도서·페이지 번호, 중복, 순서, 예산과
  지원 상태를 검증하고 스키마 밖 자유 문구를 거부합니다.
- 외부 AI는 사용자별 잉크·대여·소장 상태를 받지 않고 목적 관련도, 선수 관계와 읽기 순서를 반영한 후보
  경로를 만듭니다. 서버는 검수된 선수 관계를 기준으로 후보 경로를 순회합니다. 비소장 도서는 선수 페이지가
  모두 포함되고 현재 권한으로 계산한 누적 추가 비용이 예산 안인 페이지만 최종 경로에 포함하며, 소장 도서는
  같은 선수 조건에서 선택한 깊이의 페이지 수 상한까지만 포함합니다. 비용 때문에 선수를 제외하면 그 선수에
  의존하는 페이지도 제외하며, 상한을 채우기 위해 무관한 페이지를 추가하지 않습니다.
- 콘텐츠 적재는 도서·콘텐츠 버전 안의 선수 관계를 `선수 페이지 -> 의존 페이지` 방향 그래프로 검사합니다.
  존재하지 않는 페이지·다른 도서나 콘텐츠 버전 참조, 자기 참조 또는 방향 순환이 하나라도 있으면 해당
  콘텐츠 버전을 지원하지 않고 외부 호출과 DB 변경 전에 전체 적재를 실패시킵니다.
- 검증 실패 시 남은 전체 제한 시간 안에서 한 번 재시도하고 다시 실패하면 임시 결과도 만들지 않습니다.
- 외부 API·서버 오류에는 경로와 잉크 상태를 변경하지 않고 재시도를 제공합니다.

## 저장과 생명주기

임시 생성 결과의 조회·저장과 저장 경로의 목록·상세·현재 경로 지정·삭제·진행 기록·피드백은 모두 로그인한
소유자에게만 허용합니다. 서버는 모든 작업에서 인증 계정과 저장된 소유자를 함께 조회하며, 목록은 인증
계정의 경로만 검색합니다. 다른 독자의 식별자를 받은 경우 존재 여부를 구분하지 않고 상태와 콘텐츠를
반환하거나 변경하지 않습니다.

1. 서버는 첫 정상 결과 슬롯을 예약한 서버 시각의 UTC 날짜를 `quotaDate`로 고정하고 계정·멱등 키별 생성
   요청에 입력 HMAC, HMAC 키 버전, `quotaDate`, 단조 증가하는 `attemptVersion`과 `IN_PROGRESS`, `ROUTE`, `NO_ROUTE`,
   `FAILED`, `EXPIRED` 상태를 기록합니다. 멱등 상태는 자정을 넘는 재시도도 원래 요청을 찾을 수 있도록
   최소한 `quotaDate` 다음 UTC 날짜가 끝날 때까지 보존합니다. `ROUTE`의 정규화한 독서 목적,
   소유자·도서·콘텐츠 버전·생성 예산 또는
   깊이와 페이지 결과는 생성 완료 시각부터 15분 동안만 임시 보관하고 클라이언트에는 불투명한
   `generationId`와 표시용 결과만 제공합니다. 임시 결과는 저장 경로가 아니며 페이지 접근권한이나 잉크
   차감을 만들지 않습니다. `NO_ROUTE`는 독서 목적 원문을 보관하지 않고 입력 HMAC, `noRouteReason`과 최초
   응답의 `minimumRequiredInk`를 종결 상태로 기록합니다. `noRouteReason`은 관련 후보가 없는
   `NO_RELEVANT_PAGES` 또는 현재 열람 권한과 선택 예산으로 유효한 경로를 만들 수 없는
   `MINIMUM_INK_REQUIRED`입니다. `minimumRequiredInk`는 후자에서 최초 계산한 유효 경로의 최소 추가 잉크인
   양의 정수이고 선택 예산보다 커야 합니다. 전자에서는 `null`이며 두 경우 모두 `generationId`는 없습니다.
   이후 대여·소장·잔액이 바뀌어도 같은 멱등 키에는 저장한 사유와 최초 값을 재현하고 현재 상태로 다시
   계산하지 않습니다.
   입력 HMAC는 배포 비밀키를 사용한 HMAC-SHA-256입니다. 메시지는 고정 순서의
   `ai-route-idempotency-v1`, `accountId`, `bookId`, `contentVersion`, `purpose`, `mode`, `value` 일곱 필드를
   각각 `4바이트 unsigned big-endian UTF-8 바이트 길이 + UTF-8 바이트`로 인코딩해 이어 붙입니다.
   `accountId`·`bookId`와 잉크 예산은 앞자리 0 없는 10진 ASCII, `purpose`는 위 정규화 결과,
   `mode`는 `INK_BUDGET` 또는 `OWNED_DEPTH`, 깊이 `value`는 `FAST`, `BALANCED`, `DEEP` 중 하나를
   사용합니다. 비밀키는 저장소나 DB에 기록하지 않고 배포 비밀로 주입하며 키 버전만 상태에 남깁니다. 키
   교체 시 이전 버전으로 만든 멱등 상태가 모두 삭제될 때까지 이전 키를 보존합니다.
2. 독자가 `이 경로로 읽기`를 선택하면 클라이언트는 `generationId`만 보냅니다. 서버는 임시 결과의
   소유자·도서·콘텐츠 버전·만료와 페이지 구성을 다시 검증하며 클라이언트가 보낸 페이지·순서·가이드
   문구는 받지 않습니다. 현재 대여·소장 권한으로 다시 계산한 추가 잉크가 임시 결과의 생성 예산을 넘으면
   저장하지 않고 권한 상태가 바뀌었음을 안내해 다시 생성하게 합니다.
3. UTC 날짜가 바뀌어도 `generationId`의 15분 유효기간은 줄어들지 않습니다. 유효기간 안의 같은 멱등 키
   생성 재시도는 원래 `quotaDate`의 결과를 반환하고 새 날짜의 생성 횟수나 외부 실행 시도를 소비하지
   않습니다. 15분이 지나면 정규화한 독서 목적과 페이지 결과를 함께 제거하고 멱등 상태를 `EXPIRED`로
   전환합니다. 입력 HMAC와 HMAC 키 버전만 함께 남겨 같은 키를 다시 실행하지 않고 만료로 거부합니다.
   다시 생성하려면 새 멱등 키를 사용하며 새 요청은 당시 UTC 날짜의 생성 횟수에 포함합니다. 만료되거나
   다른 독자에게 속한 `generationId`는 저장할 수 없습니다. 멱등 상태 보존 기간이 끝나면 상태·입력 HMAC·
   HMAC 키 버전을 함께 삭제합니다.
4. 검증을 통과해 독자가 선택한 경로만 기한 없는 저장 경로로 전환합니다. 서버는 `generationId`를
   원자적으로 한 번만 소비해 임시 결과의 정규화한 독서 목적과 페이지 구성을 저장 경로로 옮기고 임시
   결과를 제거합니다. 같은 `generationId`의 저장 재시도에는 저장 경로가 있으면 처음 만든 경로를 반환하며
   중복 경로를 만들거나 현재 경로 지정을 다시 바꾸지 않습니다. 경로가 먼저 삭제됐다면 임시 결과도 없으므로
   재시도로 되살리지 않고 거부합니다.
5. 같은 책에 목적이 다른 경로를 여러 개 보존하되 하나만 현재 경로로 지정합니다. `generationId`를 처음
   소비해 저장한 새 경로는 같은 트랜잭션에서 기존 현재 경로를 해제하고 현재 경로가 됩니다. 이후 같은
   `generationId`의 재시도는 기존 경로만 반환하며, 그 사이 독자가 선택한 다른 현재 경로를 바꾸지 않습니다.
   같은 독자·도서의 저장, 현재 경로 변경과 현재 경로 삭제는 직렬화하며 어떤 완료 시점에도 현재 경로는 최대
   하나입니다.
6. 경로의 페이지와 추천 순서는 저장 뒤 자동 변경하지 않습니다.
7. 활성 대여·소장 상태에 맞춰 예상 추가 잉크만 조회 시점마다 다시 계산합니다.
8. 독자가 명시적으로 다시 만들기를 선택한 경우에만 새 경로를 생성합니다.
9. 저장한 경로는 독자가 삭제할 수 있습니다. 삭제하면 목적, 경로 항목, 진행 상태와 피드백을 지우되
   페이지 대여와 잉크 내역은 보존하고 환불하지 않습니다. 현재 경로를 삭제하고 같은 책의 다른 경로가
   남으면 가장 최근에 저장한 경로를 현재 경로로 지정하며, 남은 경로가 없으면 현재 경로도 없습니다.

## 열람과 과금

- 경로 생성·미리보기·저장만으로 페이지를 열거나 잉크를 차감하지 않습니다.
- 경로 안의 권한 없는 페이지를 독자가 직접 열 때만 기존 정책대로 1잉크를 차감하고 30일 대여를
  시작합니다.
- 활성 대여와 온라인 소장 페이지의 추가 비용은 0잉크입니다.
- 버튼에 `다음 경로 페이지 · 1잉크로 열기`, `대여 중`, `소장 도서`처럼 현재 비용 상태를 표시합니다.
- 경로 읽기 모드의 이전·다음은 원본의 연속 페이지가 아니라 추천 경로 순서를 따릅니다.
- 원본 순서 이동은 별도 조작으로 제공하고 경로 밖 권한 없는 페이지의 1잉크 비용을 표시합니다.
- 추천 순서는 강제하지 않습니다. 선수 개념 페이지를 건너뛸 때 안내한 뒤 독자가 계속 열 수 있습니다.
- 잔액 부족 시 페이지 콘텐츠를 제공하지 않고 기존 이용권 구매 흐름으로 안내합니다.
- 경로 저장 뒤 대여 만료로 예상 비용이 늘거나 잔액을 넘더라도 페이지를 자동 교체하지 않습니다.

## 진행과 피드백

- 경로 항목은 경로 읽기 화면에서 해당 페이지 콘텐츠를 성공적으로 제공한 뒤 열람 완료로 표시합니다.
- 활성 대여·소장 페이지도 경로 선택만으로 완료 처리하지 않습니다.
- 체류 시간·스크롤·페이지 이동만으로 완독이나 이해를 추정하지 않습니다.
- 모든 경로 항목을 한 번 이상 열면 `경로 열람 완료`로 표시합니다.
- 완료 후 `도움이 됐어요`, `보통이에요`, `도움이 안 됐어요` 중 하나를 선택적으로 받습니다.
- 피드백은 잉크 보상과 연결하지 않습니다.

## 예상 독서 시간

- 사용자별 속도를 학습하지 않고 페이지 콘텐츠 길이와 형식을 기준으로 근삿값을 계산합니다.
- 텍스트 페이지는 글자 수, 이미지·표·수식 페이지는 분석된 복잡도 구간을 사용합니다.
- 페이지별 최소 예상 시간은 1분이며 경로 전체 시간은 페이지 예상 시간의 합입니다.
- 화면에는 `약 24분`처럼 근삿값임을 표시합니다.

## 생성 횟수와 실패

- 경로 생성은 잉크를 사용하지 않으며 경로 또는 관련 경로 없음으로 끝난 정상 결과는 계정당 UTC 날짜 기준
  최대 10회입니다.
- 생성 횟수는 매일 `00:00 UTC`에 초기화합니다.
- 클라이언트가 생성 요청마다 UUID 멱등 키를 만들고 서버는 멱등 상태 보존 기간에 같은 계정·키를 한
  요청으로 처리합니다. 같은 키에 다른 도서·목적·예산 또는 깊이를 보내면 거부합니다.
- 서버는 외부 API 호출 전에 최초 요청의 `quotaDate`별 슬롯을 MySQL에서 원자적으로 예약합니다. 진행 중
  예약도 10회 한도에 포함하므로 동시 요청으로 한도를 넘을 수 없습니다.
- 관련 경로가 없다는 정상 결과는 생성 횟수에 포함합니다.
- 같은 멱등 키의 진행 중 요청, 15분 안의 `ROUTE` 또는 보존 중인 `NO_ROUTE`를 재사용하면 UTC 자정을
  넘더라도 새 생성 횟수나 외부 실행 시도를 소비하지 않습니다. `FAILED` 상태의 재실행은 현재 UTC 날짜가
  원래 `quotaDate`와 같을 때만 허용하며, 정상 결과 슬롯을 다시 원자적으로 예약하고 `attemptVersion`을
  증가시켜야 다시 `IN_PROGRESS`가 됩니다. 슬롯을 다시 얻지 못하면 외부 API를 호출하지 않습니다. 날짜가
  바뀌면 새 멱등 키를 요구합니다.
- 정상 결과 한도와 별도로 실제 OpenAI 호출을 시작하는 외부 생성 실행은 계정·`quotaDate`당 최대
  20회입니다. 서버는 첫 OpenAI 호출 직전에 해당 `quotaDate`의 시도 슬롯을 원자적으로 소비하고, 실행이
  시작된 뒤의 외부 API·출력 검증·서버 오류에도 돌려주지 않습니다. `FAILED`인 같은 멱등 키를 다시 실행해도
  새 시도 한 건을 소비하며, 20회를 모두 사용하면 외부 호출 전에 그날의 재시도 한도를 안내합니다.
- 일반 HTTP 생성의 외부 실행에는 계정 한도와 별도로 UTC 날짜 기준 애플리케이션 전역 한도를 적용합니다.
  같은 공개 애플리케이션 DB를 사용하는 모든 인스턴스와 재시작·롤링 배포는 `(quotaDate)`별 같은 전역 카운터
  행과 DB에 등록한 승인 전역 한도 값을 공유하며 배포 버전이나 프로세스 시작으로 사용량을 초기화하지
  않습니다. 각 서버에 주입한 양의 정수 한도 값은 시작과 외부 호출 전에 DB 승인값과 정확히 일치해야 하며,
  없거나 1 미만이거나 다르면 AI 경로가 활성화된 서버를 시작하지 않고 OpenAI를 호출하지 않습니다. 전역
  한도에는 서로 다른 계정의 실행을 모두 합산하고 첫 OpenAI 호출 직전에 DB 승인값을 기준으로 MySQL에서
  소비합니다. 별도 평가 DB의 비웹 배치도 그 DB의 승인값과 날짜별 전역 카운터를 사용하고 주입값 불일치에는
  시작하지 않습니다. 한도 변경은 AI 경로를 비활성화한 상태의 비웹 작업으로 승인값을 갱신하며 당일 사용량을
  초기화하지 않습니다.
- 첫 OpenAI 호출 직전에 계정과 전역 외부 실행 슬롯을 한 트랜잭션에서 함께 소비합니다. 둘 중 하나라도
  부족하면 두 실행 슬롯을 모두 소비하지 않고 정상 결과 예약을 즉시 해제하며 현재 `attemptVersion`의 멱등
  상태를 `FAILED`로 전이한 뒤 원인에 맞는 `429`를 반환합니다. 이미 시작한 실행의 두 슬롯은 외부 API·출력
  검증·서버 오류에도 돌려주지 않습니다. 이 실패들은 정상 결과용 예약만 해제하고 정상 생성 횟수에는 포함하지
  않습니다. 외부 호출 전에 끝난 입력 오류와 서버 오류도 외부 실행 시도를 소비하지 않습니다. 프로세스
  중단으로 남은 진행 중 정상 결과용 예약은 생성 시작 1분 뒤 해당 `attemptVersion`을 무효화하고 다음 요청에서
  해제합니다. 결과와 실패 전이는 상태가 `IN_PROGRESS`이고 작업이 시작할 때 받은 `attemptVersion`이 현재 값과
  같을 때만 조건부로 반영합니다. 복구 뒤 도착한 이전 버전 작업의 성공·실패는 경로, 멱등 상태와 두 생성
  횟수를 변경하지 않습니다.
- 남은 생성 횟수를 화면에 표시합니다.
- 생성 횟수를 잉크로 구매하는 기능은 제공하지 않습니다.
- 계정 정상 결과 한도는 `429 AI_ROUTE_DAILY_RESULT_LIMIT_EXCEEDED`, 계정 외부 실행 한도는
  `429 AI_ROUTE_DAILY_ATTEMPT_LIMIT_EXCEEDED`, 애플리케이션 전역 외부 실행 한도는
  `429 AI_ROUTE_GLOBAL_ATTEMPT_LIMIT_EXCEEDED`와 다음 UTC 날짜까지의 `Retry-After`로 응답합니다. 이미
  종결된 같은 멱등 키의 재현은 새 슬롯을 쓰지 않으므로 위 한도 뒤에도 원래 응답을 반환합니다.
- OpenAI가 `organization_spend_limit_exceeded`, `project_spend_limit_exceeded`,
  `organization_usage_limit_exceeded` 또는 `credit_balance_exhausted`를 반환하면 외부 실행 시도는 소비한 채
  정상 결과 예약만 해제하고, 공급자 조직·프로젝트·비용·크레딧 정보를 노출하지 않는
  `503 AI_ROUTE_PROVIDER_BUDGET_UNAVAILABLE`로 변환합니다. 도서 탐색과 기존 뷰어는 계속 제공합니다.
- Responses API 응답의 실효 `service_tier`가 `default`가 아니면 외부 실행 시도는 소비한 채 정상 결과
  예약을 해제하고 현재 멱등 시도를 `FAILED`로 끝냅니다. 모델 출력은 사용하지 않으며 외부 API·서버 오류와
  같은 재시도 가능한 서비스 실패로 응답합니다.

## 개인정보와 콘텐츠 보호

- 콘텐츠 적재의 Embeddings API에는 외부 전송 권리와 데이터 보관 조건을 확인한 페이지 분석 텍스트만
  전달합니다. 런타임 Embeddings API에는 정규화한 독서 목적만 전달하며 두 입력을 섞지 않습니다.
- Responses API에는 독서 목적과 경로 생성에 필요한 후보 페이지 분석 텍스트만 전달합니다. 추가 잉크 예산,
  잉크 잔액과 페이지별 대여·소장 상태는 서버에서만 사용합니다.
- 이메일, 잉크 잔액, 결제 정보, 대여·소장 내역과 뷰어 세션 ID는 전달하지 않습니다.
- 경로 구성은 OpenAI Responses API에 `store=false`로 요청하고 Conversations·Background mode·호스팅
  도구는 사용하지 않습니다. `store=false`는 응답 애플리케이션 상태 저장만 끄며 악용 모니터링과 프롬프트
  캐시 조건을 바꾸지 않습니다. 페이지 임베딩은 콘텐츠 적재 때 사전 생성하고 독서 목적 임베딩은 경로 생성
  요청마다 같은 모델·차원으로 생성합니다.
- 2차 MVP 화면에는 목적과 후보 분석 텍스트가 OpenAI로 전송되고, 기본 악용 모니터링에서 고객 콘텐츠가
  최대 30일 보관될 수 있으며 비-ZDR GPT-5.6 요청에서는 원문이 아닌 입력 파생 key/value tensor가 최대
  24시간 프롬프트 캐시 애플리케이션 상태로 남을 수 있음을 안내합니다. 데이터 공유 학습에는 별도로 참여하지
  않습니다.
- 공개 AI 시연 콘텐츠는 최대 30일 악용 모니터링과 최대 24시간 파생 캐시를 허용합니다. 실제 출판
  콘텐츠는 외부 전송 권리를 확보하고 적용할 OpenAI 데이터 제어와 파생 캐시 허용 조건을 함께 확인합니다.
  기본 제어는 두 보관을 모두 허용할 때, Modified Abuse Monitoring은 고객 콘텐츠의 악용 모니터링 제외와
  최대 24시간 파생 캐시를 허용할 때만 사용합니다. 공급자 측 고객 콘텐츠 애플리케이션 상태 보관을 허용하지
  않는 콘텐츠는 Zero Data Retention 프로젝트에서만 지원합니다. GPT-5.6의
  `prompt_cache_options.ttl`은 최소 캐시 수명이며 최대 보관 제한으로 취급하지 않습니다.
- 콘텐츠 적재·평가·일반 생성은 프로젝트 소속을 확인한 서비스 계정 API 키만 사용합니다. 콘텐츠 적재,
  평가, 공개 서버 시작과 키 교체 직전에 OpenAI 프로젝트의 원격 상태를 갱신해 drift가 없는지 확인하고
  프로젝트 ID·실효 데이터 제어와 캐시 허용 정책으로 `openAiPolicyHash`를 만듭니다. 공개 서버의 별도 비웹
  작업은 1시간 안에 원격 증명을 갱신합니다. 프로젝트 소속이나 정책을 증명하지 못하거나 증명이 정확히
  만료되면 OpenAI를 호출하지 않습니다. 학습용 데이터 공유 비활성은 자동 해시에 넣지 않고 조직 관리자
  확인 증거로 분리합니다. 데이터 공유 설정을 바꾸려면 먼저 AI 경로를 비활성화하며 새 비활성 확인 증거가
  있기 전에는 다시 활성화하지 않습니다.
- 같은 프로젝트의 정책만 바뀐 경우에는 일반 생성을 실패 폐쇄한 상태에서 새 정책이 모든 공개 콘텐츠의
  권리·보관 조건을 만족하는지 다시 검증하고, 생성 설정이 바뀌지 않았을 때만 승인 정책 해시를 원자적으로
  갱신합니다. 일부 콘텐츠라도 새 정책을 허용하지 않으면 기존 승인값을 유지하고 OpenAI 호출을 재개하지
  않습니다. 프로젝트 ID 변경은 이 정책 전환 절차로 처리하지 않습니다.
- GPT-5.6의 explicit 모드와 명시적 breakpoint가 없는 요청을 캐시 비활성화 근거로 사용하는 대안은 공식
  프롬프트 캐시 문서와 데이터 제어 문서의 표현이 일치하기 전까지 채택하지 않습니다. 공급자 측 고객 콘텐츠
  애플리케이션 상태 보관 금지 조건은 계속 Zero Data Retention으로만 충족합니다.
- 독서 목적과 외부 AI 요청·응답 원문은 애플리케이션 로그에 남기지 않습니다.
- 분석 텍스트, 임베딩과 원본 콘텐츠는 API 응답에 포함하지 않습니다.

## 품질과 출시 기준

도서별 개발·회귀 데이터와 잠금 holdout 평가 데이터는
[AI 경로 콘텐츠 코퍼스](../ai-route-content-corpus.md)를 따릅니다. 개발·회귀 지표는 조정에 사용하고 출시
판정과 분리해 보고합니다. 아래 출시 수치는 `holdoutDatasetVersion`·`holdoutDatasetHash`·
`generationArtifactHash`·`generationConfigHash`·`evaluationSourceHash`·`evaluationGitRevision` 사전 봉인
전까지 개발자가 보지 않은 잠금 holdout에만 적용하며
정확한 페이지 일치보다 필수 개념, 선수 관계, 균형, 중복과 예산 준수를 평가합니다. 아래 수치가
2차 MVP 출시 판정의 단일 정본이며 다른 문서는 계산·검증 방법만 정의합니다.

- 잠금 holdout 270개 대표 목적은 비소장 예산 0·5·10·15, 소장 빠른·균형·깊이의 7개 시나리오에 고정
  배정합니다.
  예산 0 시나리오는 정답 데이터가 지정한 활성 대여만 사용하고, 나머지 비소장 시나리오는 활성 대여가
  없습니다. 전체 지표 외에 각 시나리오가 최소 38개 목적을 포함하고 사람 검수 `유용` 70% 이상이어야
  합니다. 같은 도서의 대표 목적 3개는 서로 다른 평가 독자에게 배정해 한 목적의 소장·대여가 다른 목적의
  시나리오에 영향을 주지 않아야 합니다.
- 잉크 예산 초과, 선차감과 무단 본문 노출: 0건
- 필수 개념 평균 포함률: 80% 이상
- 무관하거나 의미가 중복된 추천 페이지: 20% 이하
- 필수 선수 관계 위반률: 5% 이하
- 필수 개념 수, 전체 추천 페이지 수와 필수 선수 관계 수는 각 비율의 분모로서 모두 1 이상이어야 합니다.
  하나라도 0이면 품질 수치를 계산하지 않고 평가 실패로 처리해 `PUBLIC` 전환을 중단합니다.
- 사람 검수에서 목적 달성에 유용하다고 평가한 대표 경로: 80% 이상
- 도서별 대표 목적 3개를 모두 평가하고 그중 2개 이상이 사람 검수에서 `유용`이어야 하며, 도서별 잉크 예산
  초과·선차감·무단 본문 노출은 0건이어야 합니다. 한 권이라도 실패하면 90권 일괄 공개 활성화를
  중단합니다.
- [AI 경로 콘텐츠 코퍼스의 고정 지연 측정 프로토콜](../ai-route-content-corpus.md#잠금-holdout-품질-평가-조건)로
  측정한 270개 경로 생성의 서버 측 전체 처리 시간을 오름차순으로 정렬한 257번째 값인 95백분위: 10초
  이하이고 20초 초과로 실패 처리된 요청 0건. 평가와 공개 배포의 `latencyProfile`이 일치하고 평가 요청과
  270개 응답의 서비스 티어가 모두 `default`여야 합니다. 270개가 모두 최종 `ROUTE` 또는 `NO_ROUTE`여야
  하며 시간과 관계없이 `FAILED`가 하나라도 있으면 지표를 계산하지 않고 평가 실행 전체를 무효화합니다.
- 평가에 사용한 실행 JAR의 SHA-256 `generationArtifactHash`, 경로 모델·추론 설정·Responses API의 명시적
  `service_tier=default`·프롬프트·출력 스키마·후보 선택·서버 경로 정책을 결합한 `generationConfigHash`와 원격 확인한
  `openAiPolicyHash`가 `PUBLIC`
  공개 승인값 및 일반 생성의 현재 값과 정확히 일치. 평가는 이후 공개 서버에 배포할 바로 그 JAR 바이트로
  실행하며 JAR을
  다시 빌드하거나 한 바이트라도 바꾸면 새 평가와 공개 승인이 필요
- 평가 DB와 공개 후보 DB의 `evaluationSourceHash`가 평가 전·공개 전환 직전에 정확히 일치
- 같은 전용 OpenAI 프로젝트의 `dataSharingDisabledEvidence`·`openAiHardSpendLimitEvidence`가 유효하고,
  공개 서버와 격리 평가 배치에 각각 1 이상의 DB 승인 애플리케이션 전역 외부 실행 한도가 기록되며 모든
  인스턴스·배치의 주입값이 해당 승인값과 일치
- 잠금 holdout의 정규 직렬화 SHA-256이 평가 증거의 `holdoutDatasetHash`와 일치하고, 버전이 공개 승인값의
  `holdoutDatasetVersion`과 일치. holdout 콘텐츠 접근 전에 버전·해시를 콘텐츠 열람 없이 확인해
  `generationArtifactHash`·`generationConfigHash`·`evaluationSourceHash`·`evaluationGitRevision`과 함께 여섯
  값을 모두 봉인하고, 결과를 본 뒤 하나라도 바꿨다면 해당 세트를 폐기하고 새 잠금 holdout으로 전체 평가
- 평가 계약 경로에 미커밋·미추적 변경이 없고, 공개 전환 시 시나리오 배정과 지표 계산 코드·사람 판정 기준·
  이 절의 품질 임계값이 평가 증거의 `evaluationGitRevision`과 정확히 일치
- 사용자 완료 피드백의 `도움이 됐어요`: 70% 이상을 출시 차단이 아닌 운영 관찰 지표로 측정

## 기술 결정

외부 AI와 임베딩 검색 구조는
[ADR-0015](../adr/application/0015-harden-openai-ai-route-generation.md)를 따릅니다. HTTP 경로와

# 제품 정책

[PRD 색인](./README.md)으로 돌아갑니다. 이 문서는 가격·기간·상태 전이와 접근 권한 같은 제품 규칙의
정본입니다. 용어의 의미는 [도메인 용어](../../CONTEXT.md)를 따릅니다.

## 원본 PDF 페이지와 콘텐츠

- 전체 페이지 수와 대여 페이지 번호는 원본 PDF를 기준으로 합니다.
- 글자 크기나 화면 확대·축소로 표시 형태가 달라져도 페이지 수, 페이지 번호와 잉크 사용량은 변하지 않습니다.
- 실제 사용 콘텐츠의 원본 PDF는 서버 내부에만 보관하고 브라우저에 직접 제공하지 않습니다.
- 실존 작품·권리 제한 자료·개인정보가 없는 AI 시연 PDF는 MVP fixture로 Git에 둘 수 있지만,
  애플리케이션 JAR·배포 이미지·정적 자산에 포함하거나 HTTP로 제공하지 않습니다.
- PDF를 페이지 단위로 처리하고 변환 결과에는 원본 PDF의 페이지 번호를 함께 저장합니다.
- 일반 본문 페이지는 텍스트로 추출합니다.
- 표·수식·삽화처럼 구조 유지가 필요하거나 텍스트 추출이 어렵고 원본 배치가 중요한 페이지는 전체를
  이미지로 렌더링합니다.
- 한 페이지는 텍스트 또는 이미지 중 한 형식으로 제공합니다. 페이지 내부에서 텍스트와 이미지를 섞는
  하이브리드 콘텐츠는 고도화 후보입니다.
- 페이지 변환 과정은 페이지 번호 연결, 문단·글자 순서, 표·수식·삽화 보존, 이미지 화질과 저장 용량을
  검증합니다.
- 인증과 온라인 소장 또는 페이지 대여 권한을 확인한 뒤 요청한 한 페이지 콘텐츠만 제공합니다.

## 프로그램 화폐와 페이지 이용권

- 잉크는 읽어볼까 프로그램 안에서 페이지 대여에 사용하는 내부 화폐입니다.
- `1페이지 = 1잉크`입니다.
- 기본 페이지 이용권은 100잉크를 1,000원에 제공하며 실질적인 페이지당 금액은 10원입니다.
- 잉크는 카테고리와 도서에 상관없이 모든 책의 페이지 대여에 사용할 수 있습니다.
- 도서별·카테고리별 잉크 단가와 전용 이용권은 두지 않습니다.
- 구매하거나 지급받은 잉크에는 사용 기한이 없고 시간이 지나도 만료되지 않습니다.
- 일반 회원가입 사용자의 초기 잉크는 0입니다.
- 이용권 결제 성공 후 백엔드는 100잉크 지급과 잉크 내역 생성을 함께 처리합니다.
- 결제는 PortOne V2 테스트 채널에서만 수행하며 백엔드가 결제 상태·금액·통화를 다시 조회해 검증한
  경우에만 성공으로 처리합니다.
- 모든 잉크 지급과 차감을 변경 불가능한 내역으로 남깁니다.
- 페이지 대여 취소와 사용한 잉크 환불은 MVP에서 지원하지 않습니다.
- 잉크는 도서 온라인 소장 결제에 사용할 수 없습니다.

## 페이지 열기와 30일 대여

- 사용자가 소장하지 않은 도서의 페이지를 처음 열면 즉시 1잉크를 차감하고 해당 페이지의 30일 대여를
  시작합니다.
- 페이지를 여는 행위가 잉크 차감 경계이며 체류 시간, 열람 완료 또는 다음 페이지 이동을 기다리지 않습니다.
- 대여 기간은 차감이 완료된 서버 시각부터 30일입니다.
- 활성 대여는 `serverNow < expiresAt`일 때이며, `serverNow >= expiresAt`이면 만료로 판단합니다.
- 예를 들어 7월 25일 14시에 시작한 대여는 8월 24일 14시 전까지 유효하고 그 시각부터 만료입니다.
- 활성 대여 중 같은 페이지를 다시 열면 잉크를 추가로 차감하지 않습니다.
- 만료된 페이지를 다시 열면 1잉크를 차감하고 새로운 30일 대여를 시작합니다.
- 대여 시작·만료 시각은 독자·도서·원본 PDF 페이지별로 따로 저장합니다.
- 활성 대여 페이지는 잉크 잔액이 0이어도 다시 열 수 있습니다.
- 활성 대여와 온라인 소장이 없는 페이지는 잉크 잔액이 1 미만이면 콘텐츠를 제공하지 않고 이용권
  구매를 안내합니다.

## 페이지 열기 처리 순서와 원자성

백엔드는 페이지 열기 요청을 다음 순서로 처리합니다.

1. 로그인, 열람 세션, 도서와 원본 PDF 페이지 번호의 유효성을 확인합니다.
2. 해당 도서를 온라인 소장했다면 잉크와 대여를 확인하지 않고 페이지 콘텐츠를 제공합니다.
3. 해당 페이지에 활성 대여가 있으면 잉크를 차감하지 않고 페이지 콘텐츠와 만료 시각을 제공합니다.
4. 둘 다 아니면 잉크 계정을 잠그고 온라인 소장과 활성 대여 여부를 다시 확인합니다.
5. 여전히 권한이 없으면 잉크 잔액을 확인합니다.
6. 잉크가 1 이상이면 1잉크 차감, 잉크 내역, 30일 대여 기록과 마지막 열람 위치를 하나의 트랜잭션으로
   저장한 뒤 콘텐츠를 제공합니다.
7. 잉크가 부족하면 상태를 바꾸지 않고 콘텐츠도 제공하지 않으며 이용권 구매가 필요하다는 결과를
   반환합니다.

- 같은 페이지 열기 요청이 동시에 여러 번 들어오면 잠금 뒤 소장·활성 대여를 다시 확인해 한 번만
  차감합니다.
- 소장 결제 완료도 같은 독자의 `InkAccount`를 잠근 뒤 처리해 새 페이지 대여와 순서를 하나로 정합니다.
  소장이 먼저 반영되면 차감하지 않고, 대여가 먼저 반영되면 1잉크 차감 뒤 소장을 부여하며 이미 완료된
  대여의 잉크는 환불하지 않습니다.
- 차감, 잉크 내역, 대여 기록과 마지막 위치는 함께 성공하거나 함께 실패해야 합니다.
- 응답 유실 뒤 같은 요청을 재시도해도 이미 생성된 활성 대여를 재사용하고 중복 차감하지 않습니다.
- 잉크만 차감되고 대여 기록이 없거나 대여 기록만 있고 잉크 내역이 없는 상태를 허용하지 않습니다.

## 도서 원가와 온라인 소장

- 모든 도서는 0보다 큰 고정 도서 원가를 원화 단위로 가집니다.
- 도서 원가는 목록과 상세 화면에서 독자가 확인할 수 있습니다.
- 온라인 소장은 잉크가 아니라 도서에 정해진 원가를 원화로 직접 결제해 얻습니다.
- 소장 결제 성공을 백엔드가 검증한 경우에만 독자·도서별 온라인 소장 기록을 생성합니다.
- 같은 결제 결과나 소장 요청이 반복되어도 소장 기록과 결제 반영은 한 번만 처리합니다.
- 이미 온라인 소장한 도서에는 새 소장 결제 시도를 만들지 않습니다.
- 같은 독자·도서에 `PENDING` 소장 결제가 있으면 새 결제 ID를 만들지 않고 기존 준비 정보를 반환합니다.
  기존 시도가 `FAILED`일 때만 새 `paymentId`로 다시 준비합니다.
- 소장 결제는 잉크 잔액과 잉크 내역을 변경하지 않습니다.
- 페이지 대여에 사용한 잉크는 도서 원가에서 공제하지 않고 소장 금액으로 누적하지 않습니다.
- 온라인 소장한 도서는 모든 페이지를 잉크 잔액, 페이지 대여 여부와 만료 시각에 관계없이 읽을 수
  있습니다.
- 온라인 소장에는 사용 기간이 없습니다.
- 소장 전에 만든 페이지 대여와 잉크 내역은 이력으로 보존하되, 소장 후 접근 권한에는 영향을 주지 않습니다.
- 온라인 소장은 서비스 안의 열람 권한이며 원본 PDF 다운로드, 인쇄와 오프라인 파일 소유를 포함하지
  않습니다.
- 소장 취소와 환불은 MVP에서 지원하지 않습니다.

## 결제 시도와 완료

- 잉크 이용권과 소장 결제는 API와 저장 기록을 분리하고, 공통 PortOne 연동만 재사용합니다.
- 준비 요청마다 서버가 고유한 `paymentId`를 발급하고 예상 금액과 함께 `PENDING` 결제 시도를 먼저
  기록합니다.
- 브라우저 완료 요청과 서명을 검증한 PortOne `Transaction.Paid` 웹훅은 같은 멱등 완료 처리를 사용하며
  어느 요청이 먼저 도착할지 가정하지 않습니다. `Transaction.Failed`는 서버 재조회로 최종 실패를 확인합니다.
- 서버가 PortOne에서 `PAID` 상태, `paymentId`, 예상 금액과 `KRW` 통화를 다시 확인한 경우에만 결제
  시도를 `PAID`로 바꿉니다.
- 최초 `PAID` 전이와 잉크 지급 또는 온라인 소장 생성은 같은 DB 트랜잭션에서 처리합니다.
- PortOne이 최종 실패를 반환하거나 결제 금액·통화·식별자가 준비 기록과 다르면 `FAILED`로 기록합니다.
- 웹훅 서명 실패, 알 수 없는 웹훅 유형, PortOne 조회 장애와 아직 완료되지 않은 결제 상태는 결제 시도를
  바꾸지 않습니다. 조회 장애는 재시도 가능한 오류로 응답하고 그 밖의 정상 서명 미지원 이벤트는 무시합니다.
- `FAILED` 결제를 다시 시도하면 새 `paymentId`를 발급합니다.
- `PENDING`과 `FAILED`는 감사·재시도·멱등성 판단을 위해 보존하며 MVP에서 자동 삭제하지 않습니다.
- MVP는 PortOne V2 테스트 채널까지만 구현합니다. 운영 실결제, 취소, 환불, 분쟁과 chargeback은
  범위에 포함하지 않습니다.

## 카테고리와 탐색

- 카테고리는 도서를 찾기 위한 분류이며 잉크의 사용 범위, 대여와 소장 자격을 제한하지 않습니다.
- 도서 목록과 검색 결과는 카테고리를 우선해 정렬합니다.
- 안정적인 페이지네이션을 위해 같은 카테고리 안에서는 `title ASC, id ASC`를 사용합니다.
- 검색어는 앞뒤 공백만 제거하고 내부 공백은 유지합니다. 빈 검색어는 전체 목록으로 처리합니다.
- 제목과 저자를 영문 대소문자 구분 없이 부분 일치 검색하고 `%`, `_`는 일반 문자로 처리합니다.
- 초기 카테고리 이름은 콘텐츠 메타데이터로 관리하고 별도 필터와 사용자 정렬 선택은 제공하지 않습니다.

## 계정과 인증

- 이메일은 앞뒤 공백을 제거하고 소문자로 정규화해 저장·조회합니다.
- 정규화한 이메일은 비어 있지 않은 일반적인 이메일 형식이어야 하며 최대 255자입니다.
- 대소문자만 다른 동일 이메일의 중복 가입을 허용하지 않습니다.
- 비밀번호는 최소 8자, UTF-8 최대 64바이트입니다.
- 비밀번호에는 영문, 숫자, 공백이 아닌 ASCII 특수문자가 각각 한 개 이상 포함되어야 합니다.
- 한글 등 다른 문자는 추가로 허용하지만 영문 조건을 대신하지 않습니다.
- 비밀번호는 입력값을 변경하거나 잘라 저장하지 않고 적응형 단방향 함수로 인코딩합니다.
- 로그인 세션은 마지막 요청 후 2시간 동안 활동이 없으면 만료됩니다.
- 회원가입은 계정과 0잉크 계좌만 생성하고 로그인 세션을 만들지 않습니다. 가입 후 사용자가 별도로
  로그인해야 하며 자동 로그인과 Remember Me는 제공하지 않습니다.
- 회원가입·로그인·로그아웃을 포함한 상태 변경 요청에 CSRF 검증을 적용합니다.
- 브라우저가 서버에 직접 제출하는 Thymeleaf 폼은 hidden CSRF 필드를 사용하고, JavaScript `fetch`는
  서버가 렌더링한 `_csrf`와 `_csrf_header` meta 태그를 읽어 헤더로 전달합니다. 로그인·로그아웃 뒤에는
  페이지를 다시 렌더링해 새 토큰을 받고 별도 CSRF 토큰 API는 만들지 않습니다.

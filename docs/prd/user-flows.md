# 사용자 흐름

[PRD 색인](./README.md)으로 돌아갑니다. 이 문서는 화면과 사용자 행동의 순서를 설명하며 가격·기간·정렬
값은 [제품 정책](./product-policy.md), HTTP 형식은 [API 계약](../api-spec.md)을 따릅니다.

## 계정과 잉크 구매

1. 사용자는 이메일과 비밀번호로 회원가입한 뒤 로그인 화면에서 별도로 로그인합니다.
2. Thymeleaf 폼은 hidden CSRF 필드를, JavaScript 요청은 페이지의 CSRF meta 태그를 사용합니다.
3. 잉크가 부족하면 페이지 이용권 구매 화면으로 이동합니다.
4. 백엔드는 `PENDING` 결제 시도와 PortOne V2 테스트 채널 호출 정보를 만듭니다.
5. 브라우저가 PortOne V2 결제를 마치면 완료 API를 호출하고, PortOne은 별도로 웹훅을 보낼 수 있습니다.
6. 백엔드는 먼저 도착한 요청에서 결제를 다시 조회하고 검증해 한 번만 100잉크 지급과 내역을 기록합니다.
7. 사용자는 지급된 잉크와 내역을 확인하고 페이지 대여를 계속합니다.

## 도서 탐색

1. 사용자는 카테고리 기준으로 정렬된 도서 목록을 페이지 단위로 봅니다.
2. 제목 또는 저자 검색으로 도서를 찾습니다.
3. 목록에서 카테고리, 표지, 제목, 저자와 도서 원가를 확인합니다.
4. 상세에서 짧은 소개, 원본 PDF 전체 페이지 수, 도서 원가와 자신의 온라인 소장 여부를 확인합니다.
5. 검색 정규화·정렬·페이지 범위는 [기능 요구사항](./requirements.md)의 `CAT-*`를 따릅니다.

## 뷰어

1. 독자가 페이지를 선택하면 프런트엔드는 해당 페이지 열기 요청만 보냅니다.
2. 프런트엔드는 체류 시간, 열람 완료와 잉크 차감 여부를 판단하지 않습니다.
3. 백엔드가 온라인 소장, 활성 대여 재사용 또는 새 대여를 확인한 경우에만 페이지 콘텐츠를 표시합니다.
4. 대여 페이지에는 응답의 잉크 잔액과 페이지 대여 만료 시각을 표시합니다.
5. 소장 도서에는 잉크 차감과 대여 만료가 없다는 상태를 표시합니다.
6. 잉크 부족과 오류 메시지를 표시하고 필요하면 페이지 이용권 구매 화면으로 이동합니다.
7. 이전 페이지, 다음 페이지, 페이지 번호 직접 이동을 제공합니다.
8. 사용자당 하나의 온라인 열람 세션만 허용하며 새 뷰어가 열리면 기존 열람 세션을 교체합니다.
9. 새 뷰어가 받은 `viewerSessionId`는 해당 탭의 `sessionStorage`에 두고 페이지 이동과 콘텐츠 요청의
   `X-Viewer-Session-Id` 헤더로 보냅니다. 교체된 탭은 안내 후 더 이상 콘텐츠를 표시하지 않습니다.
10. 글자 크기나 확대·축소를 바꿔도 원본 PDF 페이지 번호와 대여 단위는 유지합니다.
11. 이전·다음 이동은 키보드로 조작할 수 있고 모든 조작 버튼에 명확한 포커스와 접근 가능한 이름을
    제공합니다.

## 프런트엔드와 백엔드 책임

프런트엔드는 다음을 담당합니다.

- 사용자가 선택한 페이지의 열람 요청
- 열람 성공 시 텍스트 또는 이미지 페이지 표시
- 잉크 부족과 오류 메시지 표시
- 잉크 잔액, 마지막 열람 페이지의 대여 만료 시각과 온라인 소장 상태 표시
- 페이지 이용권 구매와 도서 원가 직접 결제 화면 이동

백엔드는 다음을 담당합니다.

- 원본 PDF 페이지 번호, 로그인·세션과 콘텐츠 접근 권한 검증
- 온라인 소장 여부와 페이지별 활성 대여 확인
- 서버 시각 기준 대여 만료 판정
- 필요한 경우 잉크 잔액 확인과 차감
- 대여 시작·만료 시각, 잉크 내역과 마지막 열람 위치 저장
- PortOne V2 결제 상태·금액·통화 재조회와 웹훅 서명 검증
- 도서 원가와 원화 결제 결과 검증, 온라인 소장 기록 저장
- 중복·동시 요청의 중복 차감·중복 소장 방지와 트랜잭션 원자성
- 권한이 없는 페이지와 원본 PDF 접근 차단

## 온라인 소장 결제

1. 독자는 목록이나 상세 화면에서 도서 원가를 확인합니다.
2. 소장하기를 선택하면 도서 원가의 원화 결제 화면으로 이동합니다.
3. 이미 소장했다면 결제를 시작하지 않습니다. 진행 중인 소장 결제가 있으면 기존 준비 정보를 재사용하고,
   확정 실패한 뒤에만 새 `paymentId`를 만듭니다.
4. 브라우저 완료 요청 또는 서명을 검증한 웹훅이 도착하면 백엔드가 PortOne 결제 상태·금액·통화를
   다시 조회합니다.
5. 검증에 성공한 첫 요청만 결제를 `PAID`로 바꾸고 온라인 소장 기록과 모든 페이지 접근 권한을 함께
   부여합니다.
6. 소장 결제 전후의 잉크 잔액과 잉크 내역은 바뀌지 않습니다.
7. 결제 실패, 금액 불일치와 중복 결제 결과에는 잘못된 소장 기록을 만들지 않습니다.

## 내 서재

- 한 페이지 이상 대여했거나 온라인 소장한 책을 자동으로 추가합니다.
- 책 제목, 카테고리, 마지막 열람 페이지와 온라인 소장 상태를 표시합니다.
- 마지막 열람 페이지의 대여 시작·만료 시각과 활성·만료 상태를 표시합니다.
- 온라인 소장 도서는 마지막 페이지의 대여 시각 대신 기간 제한 없는 소장 상태를 표시합니다.
- 다시 들어가면 마지막 열람 페이지를 선택합니다.
- 별도 서재 담기 기능은 없습니다.

## 잉크 내역과 소장 결제 내역

- 사용자는 자신의 이용권 지급과 페이지 대여 차감 내역만 잉크 내역에서 조회할 수 있습니다.
- 페이지 차감 내역에는 책 제목, 원본 PDF 페이지 번호, 차감량, 대여 시작·만료 시각과 차감 후 잔액을
  표시합니다.
- 완료된 소장 결제 내역은 잉크 내역과 분리해 최신순 10개씩 제공하고 도서 제목, 도서 원가, 결제 시각과
  현재 소장 상태를 표시합니다. `PENDING`·`FAILED`는 결제 결과 화면에만 표시합니다.
- 잉크 내역과 완료된 소장 결제 내역은 수정하거나 삭제하지 않습니다.

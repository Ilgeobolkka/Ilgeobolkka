# 읽어볼까 MVP 테스트 전략

## 1. 목적

이 문서는 [기능 요구사항](./prd/requirements.md), [초기 MVP 성공 조건](./prd/mvp-goals.md#성공-판정)과
[AI 잉크 경로 2차 MVP 성공 조건](./prd/ai-ink-route.md#품질과-출시-기준)을 어떻게 검증할지 정의합니다.
가격·기간과 상태 전이의 정본은 [제품 정책](./prd/product-policy.md)이며, 이 문서의 수치는 테스트 입력과
기대 결과입니다.

## 2. 검증 우선순위

1. 잉크 잔액과 변경 불가능한 내역의 일치, 사용 기한 없음
2. 활성 대여 재사용과 만료 후 재대여의 시간 경계
3. 새 대여 1건과 1잉크 차감 1건의 원자성
4. 도서 원가 결제와 온라인 소장 기록의 일치
5. 소장 결제와 잉크 잔액·내역의 완전한 분리
6. 소장 도서의 기간·잉크 제한 없는 페이지 접근
7. 동시·중복·재시도 요청의 중복 차감·중복 소장 방지
8. 원본 PDF 페이지 번호와 텍스트·이미지 콘텐츠의 정합성
9. 인증·열람 세션과 페이지 콘텐츠 접근제어
10. 카테고리 우선 목록, 검색, 내 서재와 접근성
11. PortOne V2 테스트 채널의 서버 재조회, 웹훅 서명과 멱등 완료
12. AI 경로 생성·미리보기·저장의 무과금과 서버 생성 결과 신뢰 경계
13. AI 생성 횟수의 동시성·멱등성, 외부 전송과 공개 가이드의 콘텐츠 보호
14. 비소설 90권의 대표 목적에 대한 추천 품질과 응답 시간

빠른 도메인 테스트부터 MySQL 통합 테스트, 브라우저 기반 사용자 흐름 테스트 순으로 실행합니다.

## 3. 공통 테스트 데이터

공통 시연 데이터의 정본은 [MVP 초기 데이터](./prd/mvp-goals.md#초기-데이터)입니다. 아래 이름은 테스트
시나리오에서 해당 데이터를 짧게 참조하기 위한 별칭입니다.

### 사용자

- Reader A: 정상 대여 기술 검증 전용 100잉크 계정
- Reader B: 잉크 부족 기술 검증 전용 0잉크 계정
- Reader C: 온라인 소장 기술 검증 전용 계정이며, 0잉크이고 Book A를 온라인 소장
- Reader A의 잉크 내역: 테스트 이용권 지급 +100잉크
- Reader C의 소장 결제 내역: Book A 도서 원가의 원화 결제 완료
- 일반 회원가입 사용자: 0잉크, 지급·소장 내역 없음
- 세 검증 계정의 공통 비밀번호: `DEMO_VALIDATION_PASSWORD` 환경변수로 주입하고 테스트와 저장소에
  원문 기록 금지

### 도서와 콘텐츠

- AI가 작성하고 제목·저자·카테고리가 서로 다른 가상 더미 도서 100권
- 모든 도서에 0보다 큰 고정 도서 원가
- 카테고리 우선 정렬과 같은 카테고리의 `title ASC, id ASC` 동률 정렬을 확인할 수 있는 데이터
- 제목 검색 일치, 저자 검색 일치, 검색 불일치, `%`와 `_`가 포함된 데이터
- 영문 대소문자와 앞뒤·내부 공백 보존을 확인할 제목·저자 데이터
- 원본 PDF 페이지 수와 변환 콘텐츠 수가 같은 도서
- 문단·글자 순서를 확인할 텍스트 페이지
- 표·수식·삽화와 원본 배치를 확인할 이미지 페이지
- 첫·중간·마지막 페이지 번호 연결을 확인할 표본
- `ai-route-v2`의 비소설 90권은 각각 48~72페이지이고 소설 10권은 초기 PDF·SHA-256·페이지 수를
  유지하는 콘텐츠
- AI 경로 지원 페이지의 비공개 분석 텍스트와, 원문·결론·수치·사례 결과가 없는 검수된 공개 가이드 주제
- 지원 도서별 대표 목적 1개인 전체 90개와 런타임 입력에 포함되지 않는 정답 평가 데이터
- 도서·콘텐츠 버전별 AI 경로 지원 여부와 외부 전송 권리·보관 조건

### 시간

- 주입한 고정 `Clock`과 UTC `Instant`
- 활성 대여: `rentedAt=2026-07-25T05:00:00Z`, `expiresAt=2026-08-24T05:00:00Z`
- 페이지마다 시작 시각이 다른 대여 데이터
- 잉크 무기한 보존 검증용 수년 뒤의 고정 시각
- UTC 날짜 변경 전후와 생성 임시 결과 만료 15분 전후의 고정 시각

## 4. 핵심 불변식

### INV-001 잉크 보존

현재 잉크 잔액은 모든 잉크 지급에서 모든 페이지 대여 차감을 뺀 값과 같아야 합니다. 잉크에는 만료
이벤트가 없고 시간이 지난다는 이유로 잔액이나 내역이 바뀌지 않습니다.

### INV-002 활성 대여 중복 차감 금지

`serverNow < expiresAt`인 독자·도서·페이지에는 재열람 횟수와 관계없이 새 잉크 차감과 대여 기록을
만들지 않습니다.

### INV-003 차감과 대여의 원자성

새 대여에서는 잉크 1개 차감, 잉크 내역, `PageRental` 기록과 마지막 열람 위치가 모두 성공하거나 모두
실패해야 합니다. 페이지 콘텐츠는 트랜잭션 성공 뒤에만 제공합니다.

### INV-004 음수 잔액 금지

어떤 동시 요청과 재시도에서도 잉크 잔액은 0 아래로 내려가면 안 됩니다.

### INV-005 변경 불가능한 잉크 내역

생성된 잉크 지급과 차감 내역은 수정하거나 삭제하지 않습니다.

### INV-006 대여 기간 경계

대여는 서버 시각 기준 `rentedAt <= serverNow < expiresAt`에서만 활성입니다. `expiresAt`은
`rentedAt + 30일`이며 정확히 만료 시각부터 새 대여가 필요합니다.

### INV-007 페이지별 독립 기간

한 페이지의 대여 시작·재열람·만료가 다른 페이지의 `rentedAt`과 `expiresAt`을 바꾸지 않습니다.

### INV-008 원본 PDF 페이지 정합성

`Book.totalPageCount`는 원본 PDF 페이지 수와 같고, 각 서비스 페이지 번호는 같은 번호의 변환 콘텐츠
하나와 연결됩니다. 표시 배율과 글자 크기는 이 연결과 잉크 차감 단위를 바꾸지 않습니다.

### INV-009 콘텐츠 권한 선행

인증과 현재 열람 세션을 확인한 뒤, 온라인 소장 또는 활성·신규 대여 중 하나가 성립해야만 텍스트·이미지
콘텐츠를 제공합니다. 내부 저장소 주소와 원본 PDF는 제공하지 않습니다.

### INV-010 잉크 사용 기한 없음

구매하거나 지급받은 잉크는 보유 기간과 마지막 사용 시각에 관계없이 유지됩니다. 페이지 대여
`expiresAt`, 로그인 세션 만료와 잉크 잔액은 서로 영향을 주지 않습니다.

### INV-011 도서 원가 결제와 잉크 분리

온라인 소장은 도서 원가와 일치하는 원화 결제 성공으로만 생성합니다. 소장 결제는 잉크 잔액과 잉크
내역을 바꾸지 않고, 페이지 대여에 사용한 잉크도 도서 원가에서 공제하거나 소장 금액으로 누적하지 않습니다.

### INV-012 온라인 소장 권한

온라인 소장한 도서는 모든 페이지를 잉크 잔액, 활성 대여와 만료 시각에 관계없이 제공합니다. 같은
독자·도서의 소장 기록은 하나이며 기간 만료 상태를 갖지 않습니다.

### INV-013 결제 검증과 멱등 완료

잉크 이용권과 소장 결제는 서버가 만든 `PENDING` 시도에서 시작합니다. 브라우저 완료와 서명 검증된
웹훅은 PortOne V2 결제를 다시 조회하며, 상태·식별자·금액·통화가 모두 맞는 첫 요청만 `PAID` 전이와
잉크 또는 소장 권한을 같은 트랜잭션에서 한 번 반영합니다.

### INV-014 AI 경로 생성 무과금

AI 경로 생성·미리보기·임시 보관·저장만으로 페이지 콘텐츠, `PageRental`, 잉크 차감과 잉크 내역을 만들지
않습니다. 기존 온라인 소장 또는 활성 대여 여부는 예상 비용만 바꿉니다.

### INV-015 생성 결과 신뢰 경계

모델 출력의 모든 페이지는 검색 후보와 서버가 같은 도서·콘텐츠 버전의 검증된 선수 그래프에서 계산한
전이적 선수 페이지 폐쇄의 합집합에 속해야 합니다. 같은 책에 존재해도 허용 집합 밖이면 전체 출력을
거부합니다. 서버는 UUID 멱등 키에 대응하는 임시 결과와 `NO_ROUTE`를 15분 보관합니다. 클라이언트는 서버가
발급한 15분 유효 `generationId`만 저장 요청에 사용할 수 있고, 서버는 소유자·도서·콘텐츠 버전·만료와
검증된 경로를 다시 확인합니다. 생성 ID는 원자적으로 한 번만 저장하되 같은 저장 재시도에는 기존 경로를
반환합니다. 만료하면 임시 입력·결과·멱등 상태를 함께 삭제합니다.

### INV-016 생성 횟수 원자성과 멱등성

OpenAI 호출을 시작하는 새 요청은 성공·실패와 관계없이 계정과 UTC 날짜별 최대 10회로 원자적으로
계수합니다. 같은 멱등 키의 15분 내 재조회는 저장된 상태·결과 또는 최초 오류를 반환하고 추가 계수하지
않습니다. 만료 정리 뒤에는 과거 키를 보존하지 않으므로 같은 키도 새 요청으로 계수하며 클라이언트는 새 키를
사용합니다. 계정 한도는 `429 AI_ROUTE_DAILY_LIMIT_EXCEEDED`, 공급자의
spend·usage limit과 선불 크레딧 소진은 `503 AI_ROUTE_PROVIDER_BUDGET_UNAVAILABLE`로 변환합니다.

### INV-017 AI 페이지 가이드 콘텐츠 보호

외부 AI는 페이지 번호와 정해진 열거값만 반환합니다. 사용자에게 보이는 가이드는 검수된 공개 가이드 주제와
서버 템플릿으로만 만들며 비공개 분석 텍스트, 모델 자유 문구, 원문·요약·결론·수치·사례 결과를 포함하지
않습니다.

### INV-018 외부 AI 데이터 경계

콘텐츠 적재의 Embeddings API에는 합의된 보관 조건과 외부 전송 권리를 확인한 페이지 분석 텍스트만,
런타임 Embeddings API에는 독서 목적만 전달해 페이지 벡터와 같은 모델·차원의 요청 벡터를 만듭니다.
Responses API에는 독서 목적과 후보 분석 텍스트만 전달하며 `store=false`를 사용합니다. 독자 식별·예산·
잉크·결제·권한·세션 정보는 전송하지 않고 목적과 외부 요청·응답 원문을 애플리케이션 로그에 남기지
않습니다. 공급자 보관 조건과 콘텐츠 허용 기준은 확인 날짜와 공식 URL을 기록한
[OpenAI 데이터 정책 프로필](./evidence/openai-data-policy/README.md)을 따릅니다.

### INV-019 공급자 비용과 정책 확인

전용 OpenAI 프로젝트에 월간 지출 한도를 설정합니다. 출시 전과 모델·엔드포인트·프로젝트 데이터 제어가
바뀔 때 공식 문서를 다시 확인해 근거 문서의 날짜·출처와 개인정보 안내·콘텐츠 허용 조건을 갱신합니다.
공개 AI 경로는 기본 비활성화하고 활성화 시 전용 프로젝트 ID·API 키·지원 데이터 정책 프로필이 모두 있어야
합니다. 적재는 manifest·환경 설정, 평가는 manifest·DB·환경 설정, 일반 서버는 DB·환경 설정의 프로필이
같아야 합니다.

### INV-020 대표 목적 품질 회귀

비소설 90권마다 대표 목적 하나를 두고 같은 생성 구성요소를 비웹으로 실행합니다. 사용자 계정·잉크 원장·
대여·소장·결제·별도 평가 DB는 만들지 않고 시나리오에 필요한 권한 상태는 평가 입력으로 직접 제공합니다.
결과의 재현 정보와 전체 재평가 대상은
[품질과 출시 기준](./prd/ai-ink-route.md#품질과-출시-기준)을, 재평가 환경과 지원 활성화 순서는
[재평가와 지원 활성화 순서](./prd/ai-ink-route.md#재평가와-지원-활성화-순서)를 따릅니다.

### INV-021 AI 경로 소유권

임시 생성 결과의 조회·저장과 저장 경로의 목록·상세·현재 경로 지정·삭제·진행 기록·피드백은 인증된 소유자만
조회하거나 변경할 수 있습니다. 목록은 인증된 독자의 경로만 반환합니다. 다른 독자의 식별자를 사용한 요청은
존재 여부, 독서 목적, 페이지 구성과 진행 상태를 노출하지 않고 어떤 상태도 변경하지 않습니다.

## 6. 경계값과 실패 주입

### 시간

- 잉크 지급 후 수년 경과: 잔액·내역 유지
- `expiresAt - 1ms`: 활성 대여, 추가 차감 없음
- `expiresAt`: 만료, 새 1잉크 차감과 30일 대여
- 온라인 소장 후 임의 시간 경과: 소장 상태 유지
- 로그인 세션 마지막 활동 후 1시간 59분 59초: 유지
- 로그인 세션 마지막 활동 후 2시간 이상: 만료, 잉크·소장 상태 유지

애플리케이션이 판정하는 시간 경계 테스트는 실제 대기하지 않고 주입한 `Clock`을 사용합니다. 단, 애플리케이션
`Clock`을 사용하지 않는 서블릿 컨테이너의 `HttpSession` 비활성 만료는 테스트 세션에만 1초 제한을 적용하고
짧게 실제 대기한 뒤 보호 API의 `401` 응답을 확인합니다.

### 잉크와 동시성

- 잔액 0: 새 페이지 대여 차단, 활성 대여·소장 페이지 허용
- 잔액 1: 정확히 새 페이지 한 개 대여 가능
- 같은 페이지 동시 요청 10회: 총 1잉크와 대여 1건
- 서로 다른 페이지 동시 요청, 잔액 1: 한 페이지만 대여되고 잔액은 0
- 같은 도서의 소장 완료와 새 페이지 대여 동시 요청: 같은 `InkAccount` 잠금으로 순서화하고 선행 결과에
  따라 0 또는 1잉크 차감, 이미 완료된 대여는 환급하지 않음
- 응답 유실 후 재시도: 기존 활성 대여 반환, 추가 차감 없음

### 소장 결제

- 도서 원가 0과 음수: 거부
- 도서 원가와 결제 금액 정확히 일치: 소장 성공
- 1원 부족·초과, 다른 도서 결제 결과: 소장 거부
- 같은 결제 식별자 동시 요청: 결제 반영과 소장 각각 1건
- 이미 소장한 도서의 결제 준비: `409 BOOK_ALREADY_OWNED`
- 같은 독자·도서의 기존 `PENDING`: 기존 결제 준비 정보 재사용
- 같은 독자·도서에 `FAILED`만 존재: 새 `paymentId` 생성
- 소장 처리 중 DB 오류: 결제 결과 처리 상태와 소장 기록의 부분 반영 없음

### PortOne V2 결제 완료

- `PENDING` 생성 뒤 브라우저 완료와 웹훅 도착 순서 교차
- 웹훅 서명 누락·불일치: `400`, 상태 변경과 도메인 효과 없음
- 정상 서명의 미지원 이벤트: `200`, 상태 변경과 도메인 효과 없음
- `Transaction.Failed`: 서버 재조회로 최종 실패를 확인한 경우만 `FAILED`
- PortOne 조회 일시 장애: 재시도 가능한 `5xx`, `PENDING` 유지
- PortOne 조회 결과 미완료 상태: 정상 응답, `PENDING` 유지
- 정상 서명 처리 대상의 비 UUID `paymentId`: `200`, PortOne 조회·상태 변경·도메인 효과 없음
- UUID 형식이지만 내부 준비 기록이 없는 정상 서명 웹훅: 재전송을 허용하는 `404`, 상태 변경과 도메인 효과 없음
- 금액 1원 부족·초과, `KRW` 외 통화, 다른 `paymentId`: `FAILED`, 지급 거부
- 같은 완료 요청 동시 10회: 결제 `PAID` 전이와 잉크·소장 효과 각각 1건
- 완료 트랜잭션 실패: 결제 상태와 도메인 효과 모두 롤백
- 실패 후 재시도: 이전 시도 보존, 새 `paymentId` 사용

## 7. 보안 및 콘텐츠 전달 확인

- 비밀번호 원문과 DB 접속 정보·시연 계정 자격 증명이 코드, 문서, 로그, 오류 응답에 없어야 합니다.
- 비밀번호는 `DelegatingPasswordEncoder`의 BCrypt 형식으로 저장해야 합니다.
- 로그인 실패 응답은 이메일 존재 여부를 구분하지 않아야 합니다.
- 로그인 성공 시 세션 ID가 교체되고 로그아웃 시 로그인·열람 세션이 무효화되어야 합니다.
- 브라우저가 서버에 직접 제출하는 Thymeleaf 폼은 CSRF hidden field를,
  `fetch`는 페이지의 `_csrf`, `_csrf_header` meta 태그를 사용해야 하며 토큰 없는 상태 변경 요청은 처리되지 않아야 합니다.
- 로그인·로그아웃 뒤에는 새 페이지를 렌더링해 새 CSRF 토큰을 사용하고 별도 토큰 API를 두지 않아야 합니다.
- PortOne API secret과 웹훅 secret은 브라우저, 로그, 오류 응답에 노출되지 않아야 합니다.
- `/api/**` 응답의 `X-Request-Id`와 요청·실패 로그의 `requestId`가 같아야 합니다. 로그에는 요청 바디·쿼리·
  헤더·쿠키·예외 원문과 로그인 세션 ID·`viewerSessionId`·내부 저장소 경로가 없어야 합니다.
- 웹훅 서명과 PortOne 서버 재조회 검증 없이 이용권 지급과 온라인 소장을 만들지 않아야 합니다.
- 원본 PDF와 내부 저장소 주소를 직접 내려주는 공개 경로가 없어야 합니다.
- 애플리케이션은 본인의 소장 또는 대여 권한을 확인한 요청 페이지 외 콘텐츠를 제공하지 않아야 합니다.
- 다른 사용자의 페이지 대여, 온라인 소장, 내 서재와 잉크 내역을 조회할 수 없어야 합니다.
- AI 경로 저장은 서버가 발급한 본인 소유의 유효한 `generationId`만 받아야 하며 클라이언트가 보낸
  목적·페이지·순서·가이드 문구를 신뢰하지 않아야 합니다.
- 모델 출력 페이지는 검색 후보와 서버가 계산한 같은 콘텐츠 버전의 선수 페이지 폐쇄에 모두 속해야 하며,
  같은 책에 존재하는 유효한 페이지라도 이 허용 집합 밖이면 거부해야 합니다.
- 임시 결과의 조회·저장과 저장 경로의 목록·상세·현재 지정·삭제·진행·피드백은 인증된 소유자에게만
  허용해야 하며, 목록은 인증된 독자의 경로만 반환하고 다른 독자의 식별자에는 존재 여부와 경로 내용을
  노출하거나 상태를 변경하지 않아야 합니다.
- 임시 생성 결과와 멱등 상태는 15분 뒤 함께 삭제되어야 합니다.
- `NO_ROUTE`의 `noRouteReason`과 예산 부족일 때의 `minimumRequiredInk`도 같은 15분 동안만 임시
  보관해야 합니다.
- 콘텐츠 적재의 OpenAI Embeddings 요청에는 권리·보관 조건을 확인한 페이지 분석 텍스트만, 런타임
  Embeddings 요청에는 정규화한 독서 목적만 있어야 하며 두 입력을 섞지 않아야 합니다. 런타임 모델·차원은
  콘텐츠 버전의 페이지 벡터와 같아야 합니다. Responses 요청은 `store=false`와 독서 목적·후보 분석
  텍스트만 포함하고 독자 식별·예산·잉크·결제·권한·세션 정보를 포함하지 않아야 하며 외부 요청·응답 원문은
  애플리케이션 로그에 없어야 합니다. 독서 목적은 고정 지시문·구조화 출력 스키마와 분리된 사용자 입력
  블록에만 있어야 하며 명령형 목적도 시스템·개발자 지시문을 바꾸지 않아야 합니다. 데이터 제어가 콘텐츠의
  외부 전송 권리·보관 조건과 맞지 않으면 외부 호출 전에 거부해야 합니다.
- OpenAI 보관 정책은 출시 전과 모델·엔드포인트·프로젝트 데이터 제어 변경 때 공식 출처에서 다시 확인하고,
  확인 날짜와 URL을 [데이터 정책 프로필](./evidence/openai-data-policy/README.md)의 날짜별 근거에 기록해야
  합니다.
- 전용 OpenAI 프로젝트의 월간 지출 한도를 설정하고 공급자 비용 한도 오류에 조직·프로젝트·비용·크레딧
  정보를 노출하지 않아야 합니다.
- AI 페이지 가이드는 검수된 공개 주제와 서버 템플릿에서만 생성되고 모델 자유 문구나 비공개 분석 텍스트를
  포함하지 않아야 합니다.
- AI 경로 지원 대상이 아니거나 외부 전송 권리·데이터 보관 조건이 누락·거부된 콘텐츠는 일반 생성의 OpenAI 호출
  전에 거부되어야 하며, 적재·활성화도 외부 호출이나 부분 변경 없이 실패해야 합니다.
- DRM과 화면 캡처 방지는 검증 범위가 아닙니다.

### 공통 ES Module 브라우저 검증

공통 JavaScript는 별도 Node.js 테스트 런타임을 추가하지 않고 패키징한 애플리케이션의 실제 브라우저에서
검증합니다.
`.github/scripts/boot-smoke.sh`는 설치된 Chrome 또는 Chromium에서 `.github/browser-smoke`의 fixture를
실행합니다. fixture는 smoke 실행 중에만 정적 경로로 연결하고 운영 JAR에는 포함하지 않습니다.

1. `/books`에서 `request-json.js`를 동적 import하고 `/api/books?page=1`, `/api/smoke`를 호출해 JSON
   응답과 `204`의 `null` 반환을 확인합니다.
2. 다른 origin URL, JSON이 아닌 성공·실패 응답과 네트워크 실패를 호출해
   `CROSS_ORIGIN_REQUEST`, `INVALID_RESPONSE`, `NETWORK_ERROR`와 HTTP 상태·`X-Request-Id` 보존을
   확인합니다.
3. 상태 변경 요청에서 페이지의 `_csrf`, `_csrf_header`가 실제 요청 헤더에 포함되고, meta 태그를 제거한
   같은 요청은 `MISSING_CSRF_TOKEN`으로 전송 전에 중단되는지 확인합니다.
4. 로그아웃 성공과 서버 오류 응답을 각각 발생시켜 두 경우 모두 `/books`가 새로 렌더링되고, 내비게이션과
   CSRF 토큰이 서버의 실제 인증 상태와 일치하는지 확인합니다. 요청이 전송되지 않은 네트워크·CSRF 준비
   오류는 현재 화면에서 오류를 표시하고 다시 시도할 수 있어야 합니다.
5. 오류 안내가 `textContent`로 표시되고 공통 오류 영역으로 포커스가 이동하며, `401`·`403`만으로 자동
   이동하지 않는지 확인합니다.
6. `/ink`에서 잔액과 `GRANT`·`DEDUCTION` 원장, 10건 고정 페이지 이동을 확인합니다. 결제 화면은
   PortOne 모듈 실패, 결제창 이탈, `PAID`·`PENDING`·`FAILED`·503을 각각 주입해 결제 영역 안내와
   재시도 경로를 검증하며, 결제창 이탈 시 완료 API를 호출하거나 새 `PENDING`을 만들지 않아야 합니다.
7. 결제가 활성화된 비운영 `/ink`와 `/books/{bookId}` 응답에는 PortOne 고정 출처와
   `https://payment-gateway-sandbox.tosspayments.com`을 `frame-src`로 허용한 결제 CSP 하나만, 일반 화면과
   결제 비활성·운영 환경의 결제 화면에는 외부 출처가 없는 기본 CSP 하나만 포함되는지 확인합니다.

## 8. 변환과 AI 경로 품질 확인

구체적인 변환 명령, 표본 manifest와 보존된 근거는
[콘텐츠 변환과 품질 검증](./content-conversion.md)을 따릅니다.

- `initial-v1`은 공개 가능한 시연 PDF 100권과 manifest의 도서 항목 100개가 전체 400페이지를 구성하고
  `bookId`, PDF SHA-256과 페이지 수가 실제 파일과 일치해야 합니다.
- `ai-route-v2`는 비소설 90권이 각각 48~72페이지이고 소설 10권의 PDF·SHA-256·페이지 수가 `initial-v1`과
  같으며, manifest 합계와 실제 전체 페이지 수가 일치해야 합니다.
- `ai-route-v2`의 모든 지원 페이지에는 분석 텍스트, 검수된 공개 가이드 주제, 예상 독서 시간 입력값과
  콘텐츠 버전에 묶인 모델·차원의 임베딩이 정확히 하나씩 있어야 합니다. 선수 관계와 중복 그룹 소속 목록
  필드도 페이지마다 하나씩 있어야 하지만 구성원은 각각 0개 이상이고, 루트·고유 페이지의 빈 목록을
  허용해야 합니다. 이 데이터는 `BookPage`와 같은 적재 트랜잭션에서 반영되어야 합니다.
- 모든 선수 관계는 같은 도서·콘텐츠 버전의 존재하는 페이지를 `선수 페이지 -> 의존 페이지` 방향으로만
  참조해야 합니다. 다른 도서·콘텐츠 버전 참조, 자기 참조와 방향 순환은 위상 정렬 검증에서 외부 호출과 DB
  변경 전에 거부되어야 합니다.
- `ai-route-v2` 입력 manifest에는 임베딩 모델·차원과 분석 입력 SHA-256이 있어야 합니다. 이 결정적 입력이
  바뀌면 manifest SHA와 출력 경로가 바뀌어야 합니다.
- 반복 변환은 고정한 시연 PDF에서 시작하고 기존 합성 페이지 규칙으로 PDF를 다시 만들지 않아야 합니다.
- `Book.totalPageCount`, 원본 PDF 페이지 수와 변환 콘텐츠 수가 일치해야 합니다.
- 모든 서비스 페이지 번호가 1부터 중복·누락 없이 원본 PDF의 같은 페이지 번호에 연결되어야 합니다.
- 모든 페이지는 `TEXT` 또는 `IMAGE` 중 정확히 하나이며, `TEXT` 본문과 `IMAGE` 경로·파일 중 선택된
  산출물이 비어 있지 않아야 합니다. 빈 텍스트 추출 결과는 `IMAGE`로 변환해야 합니다.
- 텍스트 페이지는 문단, 문장과 글자 순서가 원본의 읽기 순서와 맞아야 합니다.
- 이미지 페이지는 표, 수식, 삽화와 원본 배치가 잘리지 않고 읽을 수 있어야 합니다.
- 자동 검증을 모두 통과하기 전에는 DB를 변경하지 않으며 실패 후 기존 시연 콘텐츠가 유지되어야 합니다.
- 적재 전후 같은 `(bookId, pageNumber)`의 `BookPage.id`가 유지되고 없는 페이지만 추가되어야 합니다.
  예상하지 않은 기존 페이지가 있으면 삭제하지 않고 전체 적재가 실패해야 합니다.
- 100권 전체의 위험 요소를 고려해 카테고리별 대표 도서 한 권씩 총 10권을 선정하고, 선정한 10권의
  첫·중간·마지막과 위험 페이지를 수동 검수해 파일 크기를 기록합니다.
- 시연 PDF·manifest와 변환 산출물이 `bootJar`와 배포 이미지에 포함되지 않아야 합니다.
- 최초 동결이 끝난 뒤 합성 페이지 생성 코드와 기존 페이지 PNG가 런타임 classpath에 남지 않아야 합니다.
- 실제 데스크톱 뷰어 크기의 표시 품질은 SCRUM-406에서 같은 표본으로 확인했으며,
  결과는 `docs/evidence/content-quality/quality-samples.json`의 `viewerInspection`에 기록했습니다.

AI 경로 품질 평가는 [AI 경로 콘텐츠 코퍼스](./ai-route-content-corpus.md)의 대표 목적 90건을
같은 생성 구성요소로 비웹 실행해 확인합니다.

- 비소설 90권마다 대표 목적 하나가 있고 7개 사용 시나리오가 코퍼스 기준에 맞게 포함되어야 합니다.
- 평가는 별도 평가 DB, 사용자 계정, 잉크 원장, 대여·소장·결제 기록을 만들지 않습니다. 시나리오에 필요한
  권한 상태는 평가 입력으로 직접 제공합니다.
- 필수 개념 포함률은 전체 필수 개념 수, 무관·중복 비율은 전체 추천 페이지 수, 선수 순서 위반률은 모든 필수
  선수 관계 수를 분모로 계산합니다. 분모가 0인 지표가 있으면 평가 데이터 오류로 실패합니다.
- 관련 경로 없음은 필수 개념 포함 0개와 `유용하지 않음`으로 계산합니다.
- 지정한 한 명의 검수자가 경로 유용성을 판정합니다.
- 90건 모두 `ROUTE`로 끝나야 합니다. 유효한 서버 처리 시간을 오름차순으로 정렬한
  86번째 값을 95백분위로 사용하며 10초 이하이고 20초 초과 실패는 0건이어야 합니다.
- 평가 데이터가 런타임 후보 검색이나 경로 구성 입력에 포함되지 않았음을 확인합니다.
- 결과에는 PRD가 정한 재현 정보를 기록하고, 기존 결과의 재사용 여부는
  [품질과 출시 기준](./prd/ai-ink-route.md#품질과-출시-기준)의 재평가 조건으로 검증합니다.
- 전체 지표가 [AI 잉크 경로 PRD의 품질과 출시 기준](./prd/ai-ink-route.md#품질과-출시-기준)을
  모두 통과한 경우에만 비소설 90권을 AI 경로 지원 대상으로 활성화하고 소설 10권은 지원하지 않습니다.
- 재평가의 수행 환경, 콘텐츠 재적재 포함 여부에 따른 활성화와 자동 전환 금지는
  [재평가와 지원 활성화 순서](./prd/ai-ink-route.md#재평가와-지원-활성화-순서)를 판정 기준으로 삼고,
  증거는 [Q03 출시 회귀](./implementation/ai-route/release/Q03-release-regression.md)의 지원 활성화
  시점·자동 전환 부재 확인 절차로 남깁니다.

## 9. 출시 게이트

### 초기 MVP

초기 MVP 구현 완료 판정에는 최소한 다음 증거가 필요합니다.

1. `docker compose config -q` 통과
2. `docker compose up -d --wait`로 MySQL 8.4 준비
3. `INV-001`~`INV-013`과 AI 경로를 제외한 필수 시나리오 테스트 통과
4. `./gradlew test`, `./gradlew check`, `./gradlew build` 통과
5. 패키징한 애플리케이션을 MySQL 8.4에 실제로 연결해 부팅하고 `GET /api/smoke`의 `204`와 민감정보 없는
   부팅 로그 확인
6. 잉크 무기한 보존과 잔액·내역 합계 대조 통과
7. 활성·만료 대여 시간 경계, 중복·동시 요청과 실패 주입 검증
8. PortOne V2 테스트 채널의 준비·서버 재조회·웹훅 서명·멱등 완료와 소장·잉크 분리 검증
9. 원본 PDF 페이지 번호, 텍스트·이미지 변환 품질과 접근제어 검증
10. 브라우저에서 로그인부터 잉크 구매·대여·재열람·원가 결제 소장까지 핵심 흐름 통과

### AI 잉크 경로 2차 MVP

AI 잉크 경로 2차 MVP 구현 완료 판정에는 초기 MVP 게이트의 회귀 검증과 함께 다음 증거가 필요합니다.

1. `INV-014`~`INV-021`과 모든 `T-AIR-*` 필수 시나리오 통과
2. `ai-route-v2` 콘텐츠 완전성·외부 전송 권리·보관 조건 확인
3. 대표 목적 90건의 비웹 평가가 PRD의 품질·지연 기준을 통과하고 PRD가 정한 재현 정보를 기록했는지 확인
4. 출시 전 확인 날짜와 공식 URL이 있는 OpenAI 데이터 정책 근거, 해당 근거와 일치하는 개인정보 안내 확인
5. 공개 기능 기본 비활성화, 활성화·AI 배치의 OpenAI 프로젝트 ID·API 키·데이터 정책 프로필 필수 검증과
   단계별 프로필 일치, 전용 프로젝트 월간 지출 한도와 출시 증거, 계정별 UTC 날짜당 10회 원자적 한도와
   공급자 비용 오류의 `503` 변환 확인
6. 패키징한 애플리케이션에서 비소설 지원 도서의 생성·저장·열람·삭제 흐름과 비-AI 기능 회귀 통과

부팅 smoke는 CI에서 애플리케이션·DB·HTTP 경계를 확인하는 검사이며 운영 관측 기능이 아닙니다. 이 검사를
위해 Actuator 의존성을 추가하지 않습니다. 운영 환경의 health·readiness·metrics가 필요해지면 노출 경로와
보안 정책을 포함해 별도 결정합니다.

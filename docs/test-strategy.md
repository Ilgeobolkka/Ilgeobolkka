# 읽어볼까 MVP 테스트 전략

## 1. 문서 상태와 목적

- 상태: 현재 정책 반영 완료
- 기준일: 2026-07-25
- 대상 정책: `1페이지 = 1잉크`, 페이지 열기 즉시 차감, 페이지별 30일 대여

이 문서는 MVP가 반드시 지켜야 할 검증 계약의 정본입니다.
기능 범위와 성공 조건은 [`MVP 목표`](./prd/mvp-goals.md), 정확한 제품 규칙은 [`제품 정책`](./prd/product-policy.md),
HTTP 요청·응답은 [`API 명세`](./api/api-contract.md), 동시성·데이터·콘텐츠 결정은 다음 ADR을 따릅니다.

- [`ADR-0019`](./adr/active/billing/0019-charge-ink-when-page-opens.md): 페이지 열기 즉시 차감
- [`ADR-0020`](./adr/active/billing/0020-use-universal-ink-page-pass.md): 공통 잉크 이용권
- [`ADR-0021`](./adr/active/billing/0021-rent-each-page-for-thirty-days.md): 페이지별 30일 대여
- [`ADR-0022`](./adr/active/billing/0022-serialize-page-rental-with-pessimistic-locks.md): 비관적 잠금과 원자성
- [`ADR-0023`](./adr/active/content/0023-use-pdf-page-mapped-hybrid-content.md): 페이지별 혼합 콘텐츠
- [`ADR-0024`](./adr/active/validation/0024-validate-hybrid-page-content.md): 콘텐츠 유형별 검증
- [`ADR-0025`](./adr/active/data/0025-model-ink-rental-and-page-content.md): 목표 데이터 모델

가장 중요한 검증 대상은 화면 디자인이 아니라 잉크 보존, 중복 차감 방지, 정확한 대여 만료, 트랜잭션 원자성과 콘텐츠 접근 통제입니다.

## 2. 검증 우선순위와 테스트 수준

### 우선순위

1. 잉크 잔액과 변경 불가능한 내역의 일치
2. 차감·내역·대여·마지막 위치의 트랜잭션 원자성
3. 페이지별 30일 대여와 만료 후 재대여
4. 동일·서로 다른 페이지의 동시 요청과 중복 차감 방지
5. 원본 PDF 페이지와 변환 콘텐츠의 일치 및 접근 통제
6. 단일 열람 세션, 내 서재와 이어 읽기
7. 카테고리 목록, 검색, 도서 상세와 계정 기능

### 테스트 수준

| 수준 | 검증 대상 | 원칙 |
| --- | --- | --- |
| 단위 테스트 | 잉크 계산, 대여 유효성, 만료 시각, 입력 검증 | 외부 시스템 없이 빠르게 모든 경계값을 검증 |
| MySQL 통합 테스트 | 행 잠금, 트랜잭션 롤백, 동시 요청, 인덱스·제약 | H2로 대체하지 않고 MySQL 8.4 사용 |
| API 계약 테스트 | 인증·인가, 요청·응답, 오류 상태와 필드 | API 명세의 정확한 경로·상태를 검증 |
| 콘텐츠 적재 테스트 | 페이지 수·번호·유형·원본 매핑 | 모든 도서를 자동 전수 검사 |
| 브라우저 테스트 | 회원가입부터 열람·재열람·내역 조회 | 배포 환경에서 핵심 흐름 검증 |
| 수동 시각 검증 | 텍스트 순서, 표·수식·삽화, 가독성 | 고정 manifest의 대표·위험 표본 사용 |

시간 테스트에서 실제로 30일을 기다리거나 `Thread.sleep`을 사용하지 않습니다.
애플리케이션이 주입받는 서버 `Clock` 또는 동등한 시간 공급자를 고정·이동해 같은 테스트를 반복 실행할 수 있게 합니다.

## 3. 공통 테스트 데이터

### 사용자

| 사용자 | 초기 잉크 | 초기 내역 | 주된 용도 |
| --- | ---: | --- | --- |
| Reader A | 3잉크 | 테스트 잉크 지급 `+3` | 정상 차감, 재열람, 재대여 |
| Reader B | 0잉크 | 없음 | 잔액 부족 |
| Reader C | 1잉크 | 테스트 잉크 지급 `+1` | 잔액 경계와 동시 차감 |

테스트 잉크 수는 제품의 판매 단위나 사용하지 않은 잉크 유효기간을 뜻하지 않습니다. 각 테스트가 작은 숫자로 잔액·내역을 명확히 검증하기 위한 fixture입니다.

각 자동화 테스트는 시작할 때 필요한 사용자·도서·잉크·대여 상태를 직접 준비하고 종료 뒤 영향을 남기지 않습니다.
앞 테스트의 실행 순서나 결과에 의존하지 않으며, 동시성 테스트도 전용 사용자를 사용해 다른 테스트와 잉크 계정 잠금을 공유하지 않습니다.

### 도서와 페이지

- 서로 다른 카테고리·제목·저자를 가진 가상 도서
- 제목 검색만 일치하는 도서, 저자 검색만 일치하는 도서, 검색되지 않는 도서
- 전체 페이지 수가 서로 다른 원본 PDF
- 표지를 원본 PDF 과금 페이지와 별도로 가진 도서
- `TEXT`, `IMAGE`, `HYBRID` 유형을 각각 포함한 도서
- 작은 글자, 표, 수식, 삽화와 복잡한 배치가 있는 품질 위험 페이지
- 전체 적재 검증용 가상 더미 도서 100권

카테고리 목록과 같은 카테고리 안의 세부 순서는 제품 정책상 아직 미정입니다.
정확한 정렬 순서 테스트는 초기 데이터 작업에서 순서를 확정한 뒤 fixture에 고정합니다.
그전에는 목록이 정해진 카테고리 순서로 묶이고 페이지 사이에 누락·중복이 없는지만 검증합니다.

### 기준 시각

- 기본 서버 시각: `2026-07-25T01:00:00Z`
- 기본 만료 시각: 차감 성공 시각에서 정확히 30일 뒤인 `2026-08-24T01:00:00Z`
- 데이터베이스와 애플리케이션 저장 시각: UTC

## 4. 핵심 불변식

### INV-001 잉크 보존

현재 잉크 잔액은 모든 지급 내역의 합계에서 모든 차감 내역의 합계를 뺀 값과 같아야 합니다.

### INV-002 음수 잔액 금지

잔액 부족, 동시 요청과 재시도에서도 잉크 잔액은 0 아래로 내려가면 안 됩니다.

### INV-003 차감과 대여의 원자성

잉크 잔액 변경, 차감 내역 생성, 페이지 대여 기록 생성과 마지막 열람 위치 갱신은 모두 성공하거나 모두 실패해야 합니다.

### INV-004 유효한 대여의 중복 차감 금지

같은 독자·도서·페이지에 유효한 대여가 있으면 요청 횟수와 동시성에 관계없이 새 차감 내역과 대여 기록을 만들지 않습니다.

### INV-005 대여와 차감 내역의 일대일 대응

성공한 `PageRental` 한 건에는 1잉크 `DEDUCTION` 내역 한 건이 연결되어야 하고, 페이지 차감 내역에도 대여 기록 한 건이 연결되어야 합니다.

### INV-006 정확한 대여 기간

모든 대여는 `expiresAt = startedAt + 30일`을 만족합니다.
서버 현재 시각이 `expiresAt`보다 이를 때만 유효하고, 같거나 늦으면 만료된 것으로 판단합니다.

### INV-007 대여 구간 비중첩

같은 독자·도서·페이지의 재대여는 이전 대여가 만료된 뒤에만 시작되며 두 대여의 유효 구간이 겹치지 않습니다.

### INV-008 내역과 대여 이력 불변

생성된 잉크 내역과 과거 페이지 대여 기록은 수정하거나 삭제하지 않습니다. 재대여는 기존 만료 시각을 덮어쓰지 않고 새 기록을 생성합니다.

### INV-009 페이지 매핑과 접근 통제

원본 PDF의 `1..totalPageCount`는 같은 번호의 `BookPage` 한 건과 정확히 대응합니다.
인증·동의와 대여 조건을 통과하지 않은 사용자는 원본 PDF나 페이지 콘텐츠를 받을 수 없습니다.

### INV-010 단일 열람 세션

독자 한 명에게 유효한 온라인 열람 세션은 최대 하나이며 교체된 세션은 잉크 차감이나 페이지 제공을 일으킬 수 없습니다.

### 유형별 수동 시각 검증

- 모든 도서의 첫·중간·마지막 페이지를 확인합니다.
- 작은 글자, 표·수식·삽화, 가는 선과 복잡한 배치 페이지를 manifest로 고정합니다.
- 텍스트 페이지는 원본과 문단·글자 순서, 누락과 중복을 비교합니다.
- 이미지 페이지는 원본 배치, 표·수식·삽화 식별 가능 여부, 번짐과 저장 용량을 비교합니다.
- 혼합 페이지는 텍스트와 이미지의 순서, 겹침, 누락과 중복을 비교합니다.
- 모바일 `360×800`과 데스크톱 `1280×800`에서 초기 화면 가독성을 확인합니다.
- 변환 도구·설정이나 원본 PDF가 바뀌면 같은 표본으로 다시 검증하고 결과를 기록합니다.

## 7. 경계값 요약

### 시간

- `now < expiresAt`: 유효한 재열람, 차감 0
- `now = expiresAt`: 만료, 재대여 차감 1
- `now > expiresAt`: 만료, 재대여 차감 1
- 시작 시각이 다른 두 페이지: 각각 독립된 `startedAt + 30일`
- 애플리케이션·DB 시간대: UTC

### 잉크

- 잔액 0: 새 대여 차단
- 잔액 1: 새 페이지 한 건 대여 후 잔액 0
- 잔액 0 + 유효한 대여: 추가 차감 없이 재열람
- 같은 페이지 동시 요청 10개: 차감 1건
- 잔액 1 + 서로 다른 페이지 동시 요청 2개: 성공 1건, 잔액 0

### 페이지

- `pageNumber = 0` 또는 음수: 잘못된 요청
- `pageNumber = 1`: 첫 페이지
- `pageNumber = totalPageCount`: 마지막 페이지
- `pageNumber = totalPageCount + 1`: 존재하지 않는 페이지
- 표지: 페이지 번호와 잉크 차감 대상이 아님

## 8. MVP에서 검증하지 않는 정책

다음 기능은 미결정이거나 MVP 제외 범위이므로 테스트에서 임의의 기대값을 만들지 않습니다.

- 실제 PG 결제와 `100잉크 = 1,000원` 결제 처리
- 사용하지 않은 유료·무료 잉크의 유효기간과 차감 순서
- 잉크 만료 전 알림
- 페이지 또는 도서 소장 전환
- 환불과 과금 분쟁
- DRM과 화면 캡처 방지
- 무중단 배포

잉크 부족 안내에서 `100잉크 = 1,000원` 상품 정보를 표시하는 화면은 검증할 수 있지만 실제 결제 성공·실패나 자동 충전을 테스트하지 않습니다.

## 9. 실행 절차와 출시 게이트

### 자동 검증 명령

```bash
docker compose config -q
docker compose up -d --wait
./gradlew test
./gradlew check
./gradlew build
```

- 변경한 기능의 테스트를 먼저 좁게 실행한 뒤 전체 `test`와 `check`를 실행합니다.
- DB 잠금·트랜잭션·동시성 테스트는 Compose MySQL 8.4를 사용합니다.
- 의존성·리소스·패키징에 영향이 있으면 `build`까지 실행합니다.
- 실행 설정이나 시작 과정이 바뀌면 `./gradlew bootRun`으로 정상 시작을 확인한 뒤 종료합니다.
- `check`는 현재 정적 분석 플러그인이 없으므로 린트 통과라고 표현하지 않습니다.

### 출시 게이트

다음 증거가 모두 있어야 MVP 구현을 완료로 판정합니다.

1. 모든 핵심 불변식 테스트 통과
2. 필수 자동화 시나리오 통과
3. MySQL에서 동일·서로 다른 페이지 동시 요청과 트랜잭션 실패 주입 통과
4. 원본 PDF와 100권 전체 `BookPage`의 수·번호·유형 자동 검사 통과
5. 고정 콘텐츠 표본의 유형별 수동 품질 검증 통과
6. 원본 PDF, 다른 독자의 페이지·잉크 내역과 교체된 세션의 접근 차단 통과
7. 회원가입부터 도서 탐색, 최초 대여, 재열람·재대여, 내 서재와 잉크 내역 조회까지 브라우저 핵심 흐름 통과
8. API 명세의 성공 응답 필드, 오류 상태와 오류 코드 계약 테스트 통과
9. `./gradlew test`, `./gradlew check`와 필요한 `build`·`bootRun` 검증 통과

실행한 명령, 통과·실패 테스트 수, 수동 검증 결과와 생략한 검증 사유를 완료 보고에 그대로 남깁니다.
